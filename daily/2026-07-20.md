### 1.1 GPT-5.6 used a prompt to close a 30-year gap in convex optimization: HN 7/18, but formalization group 找到 proof 本身的 gap

### 1.3 Setting up your spare Mac for Claude Code to control: HN 7/18, ykdojo 的 step-by-step guide 揭露 Claude Code 「**always-on + phone-controlled + computer use**」 模式

[HN 7/18 thread](https://news.ycombinator.com/item?id=48959392) + [ykdojo 完整 26KB guide](https://ykdojo.github.io/claude-controls-mac/) + [GitHub repo ykdojo/claude-controls-mac](https://github.com/ykdojo/claude-controls-mac) + [作者另一個 container 替代 safeclaw](https://github.com/ykdojo/safeclaw) —— ykdojo (Adyen, ex-Stripe / GitHub) 7/18 發表 26KB step-by-step guide,把 spare Mac 變成 always-on Claude Code 可以完全控制的 machine,支援 **computer use** (click / drag / app control), 從手機透過 Claude app 跟 spare Mac 上的 Claude Code 對話,或從 main Mac 透過 SSH 控制。

具體 setup(從 [作者 26KB guide](https://ykdojo.github.io/claude-controls-mac/)):**(a) Hardware** — 一台 spare Mac + 一台 main Mac (同 Wi-Fi);**(b) Account** — 在 spare Mac 上建 fresh local account, **no personal data + no Apple ID signed in**, agent 「**nothing sensitive to reach**」;**(c) Connection** — main Mac SSH 到 spare Mac, Claude app 從 phone 控制 spare Mac 上的 Claude Code;**(d) Computer use** — 透過 Claude Code 的 computer use mode 讓 agent 控制 Unity 等只能在 Mac 跑的 app (container 做不到);**(e) Subscription 整合** — 用 Claude subscription usage 而不是 API, 跟平常 Claude Max / Pro plan 共用 quota。**為什麼不用 container**(作者自答):container 還是在 main machine 上跑, network request 經 main machine, 而且 Unity 等 Mac-only app 沒辦法在 container 跑 —— 「**control agent with broad permissions is safer on a machine that has nothing to lose**」。

對開發者的意義:這是 [Claude Code v2.1.187+ skill marketplace](/daily/2026-07-16) + [Claude Code v2.1.191 /rewind](/agents/2026-07-15) 之後,**第一個 production-grade 「**Claude Code on dedicated always-on hardware**」** 的具體 reference 公開 blueprint。對企業 IT 採購:「**dedicated Mac mini / Mac Studio 作為 Claude Code always-on runner**」 是 2026 H2 enterprise agent 部署的 concrete baseline, 對 [LM Studio Bionic 7/16 on-prem local agent](/daily/2026-07-19) 的「**local agent 不需 API egress**」 路線的「**cloud Claude Code + dedicated Mac**」 互補 variant。

### 1.6 A Study of Microsoft's Early 2026 Rollout of Claude Code and GitHub Copilot CLI: arXiv 2607.01418 7/13 揭露 24% more PRs, paper 自己 acknowledge 「**PR 數 ≠ productivity**」

[HN 7/13 thread](https://news.ycombinator.com/item?id=48899321) + [arXiv 2607.01418 完整 paper](https://arxiv.org/abs/2607.01418) + [Microsoft Research authors Emerson Murphy-Hill + Jenna Butler + Alexandra Savelieva](https://arxiv.org/search/cs?searchtype=author&query=Murphy-Hill,+E) —— Microsoft Research 的 Emerson Murphy-Hill (著名 software engineering empirical researcher) 等 7/1 釋出 arXiv 2607.01418 22-page paper, 對 Microsoft tens of thousands engineers 的 early-2026 Claude Code + Copilot CLI 部署做 4-month window 的 longitudinal study。

具體發現(從 [arXiv 2607.01418 abstract](https://arxiv.org/abs/2607.01418)):**(1) First use spread primarily through social networks** — 不是 top-down deployment, 是 engineer 之間的 social network 傳播, 對企業 IT 採購 「**rollout strategy 必須 treat visible peer use as central**」 是 new 維度;**(2) Retention associated more with engineers' coding activity than with demographics** — 留下來用的人是有 active coding activity 的 engineer, 不是 demographics, 對 enterprise adoption KPI 的 demographic-based segmentation 是 first counter-evidence;**(3) Adopters merged 24% more pull requests over 4-month window** — 用了 CLI coding agent 的 engineer 4 個月內 merge 24% more PRs。**但 paper 自己 acknowledge**:**「**we use merged pull requests as our proxy for output — acknowledging that a merged PR is not the same as the value it delivers**」** —— paper 直接說 24% 是 PR 數, 不是 productivity, 不是 value。
