### Codex #28058 加密 sub-agent 訊息後移除 human-readable audit trail，7/14 GitHub issue 登上 HN front-page

[Codex Issue #28058 〈Regression: encrypted MultiAgentV2 messages remove readable task audit trail〉7/14](https://github.com/openai/codex/issues/28058) + [HN front-page 多 thread 累計 234 則高密度回覆](https://news.ycombinator.com/item?id=48905028) —— OpenAI 在 6/5 合併的 [PR #26210 〈Encrypt multi-agent v2 message payloads〉](https://github.com/openai/codex/pull/26210) 把 MultiAgentV2 的 `spawn_agent` / `send_message` / `followup_task` 訊息 payload 加密，存到 `InterAgentCommunication.encrypted_content`，但刻意把 `InterAgentCommunication.content` 留為空字串。Issue 原文指出三個具體 debug 場景因此被破壞：(a) 開發者檢查 parent rollout/history/trace 時看不到「`spawn_agent` 給 child agent 的 task 是什麼」；(b) 看不到「`send_message` 傳給 subagent 的 message」；(c) 在事後 review rollout 時無法解釋「為什麼會有這個 child thread」。

這是繼 [6/22 Codex 640 TB SSD feedback log 寫入 bug](https://news.ycombinator.com/item?id=48712000) 後，Codex 在「user-visible 透明度」上的第二個結構性回退——差別在 640 TB 是「指標數字錯誤」(metric 層)，這次是「**本地 audit trace 結構性消失**」(data layer)。Issue reporter 明確指出，這不是要 revert 加密（隱私 hardening 是合理的），而是要求**保留一份 non-encrypted 的 audit 欄位**供 user 與 maintainer 檢查，類似「encryption at delivery, plaintext at audit」的雙欄位 pattern。

HN 討論中 [@braebo](https://news.ycombinator.com/item?id=48905028) 直接指出「Sol 用 subagent 很差，常常做 dumb decision」；[@radicality](https://news.ycombinator.com/item?id=48905028) 反向佐證 Codex 早期的 encrypted compaction 體驗「明顯比 Claude 好」是促使他從 Claude 跳槽的關鍵；[@ignatremizov](https://news.ycombinator.com/item?id=48905028) 補充「`multi_agent_v2` 還在 Under Development 標籤下，OpenAI 內部明說不要針對它開 issue，但他們把 Sol/Terra 在 v2 下 globally deploy 出去了」——這構成「**internally-marked-as-experimental 的 feature 透過 default model globally deploy 給所有付費用戶**」的具體 supply chain 風險。

對開發者的意義：當 Codex MultiAgentV2 的 parent rollout 看不到 child 的 task 內容，**所有依賴 subagent 結果做人工 review 的 team 都進入「trust the model, not the trace」的工作模式**——這對企業 SaaS 場景（agent 出問題時的 compliance audit）是直接威脅。對 OpenAI 而言，這個 issue 觸及「**encrypted privacy 與 human audit 該用什麼 abstraction 平衡**」的設計問題，是 [6/22 640 TB issue](/daily/2026-06-22)、[5/22 Patrick McCanna Extended Thinking exposé](https://news.ycombinator.com/item?id=48649673) 後，**「Codex 在 subagent 路徑上的 transparency debt 連續第三次累積」**——OpenAI 必須在 0.145.x release cycle 內回應這個 issue，否則 Codex 對企業用戶的「audit-ready」marketing 將徹底破產。

對 OpenAI 內部而言，**「internally experimental + globally default deploy」這個 supply chain pattern**——`multi_agent_v2` 在 OpenAI 內部仍標記為「Under Development / 不接受 issue」，但透過 Sol/Terra globally deploy——是 [2026 H2 frontier vendor 對 enterprise SaaS 風險管理](/daily/2026-07-16) 的具體 reference case。

### Samsung Health app 威脅「若 opt out AI training 就 delete 你的健康資料」

[neow.in 7/13 報導](https://neow.in/cWsyMTV3) + [HN 7/13 front-page 持續討論](https://news.ycombinator.com/item?id=48897991) —— Samsung Health 在最近的 app 更新中加入一段「**若用戶 opt out AI training，將會刪除所有 health data**」的措辭。具體的 UX 設計是：當用戶在 settings 內關閉「allow Samsung to use my health data for AI training」時，app 會跳出警告說明「this will result in permanent deletion of your data」，並要求用戶確認刪除。

這是 2026 H2「**consent-as-conditional-destruction**」這個新 anti-pattern 的具體 reference case。它的結構是把「**用戶對自己資料的處置權**」與「**廠商對模型訓練資料的需求**」做硬綁定——你不同意，就失去所有資料的所有權。對 EU/UK/加州等已有較強個資法的市場，這直接踩 GDPR Article 7 (consent 必須 freely given)、CCPA/CPRA 的 right to delete 與 opt-out 對稱性。在 2025 年 Adobe 與 Scale AI 都曾被監管機關就「必須同意才能繼續使用核心服務」開罰，但 Samsung 這次更極端——不是「不能用服務」，是「**刪掉你過去所有累積的資料**」。

HN 討論的共識：這是 consumer AI 商業模式走到「**AI 訓練是免費增值商業模型的核心資產來源**」的具體 reflection——Samsung 一年免費、訂閱制、可穿戴硬體三條 revenue stream 之間，AI training opt-in 的資料量是決定「Samsung Health premium 訂閱能否有獨特 AI feature」的核心變數。當用戶 opt out，**模型沒有足夠在地化資料訓練 on-device health AI**——這是商業邏輯，但被包裝成「刪除你的資料」時，**是對「user 對自己資料的所有權」這個核心原則的結構性違反**。

對開發者的意義：所有在做「**你的資料是否用於 AI 訓練**」這個 toggle 的 product 都要重新審視——這個 toggle 必須是「**opt out 仍然保留所有資料**」，不能是「**opt out = 刪除**」。對 enterprise vendor 採購而言，這是「**consent architecture audit**」進入 2026 H2 procurement checklist 的具體 reference——任何 consumer AI 服務的「**AI opt-out 觸發資料刪除**」設計現在都應該是 auto-fail。

### 澳洲 7/1 起 NSW / SA / SEQ 強制三小時免費日間電力，AI 能源競爭直接進入「**peak solar giveaway to households**」時代

[lenergy.com.au 7/14 報導](https://lenergy.com.au/free-daytime-electricity-is-coming-heres-how-it-actually-works/) + [HN 7/14 240+ 則 front-page 討論](https://news.ycombinator.com/item?id=48902320) —— 澳洲政府 7/1 開始實施「**Solar Sharer Offer**」計畫，要求 NSW、South Australia、Southeast Queensland 三州的能源零售商每天中午 11am-2pm 或 noon-3pm（依地區日照調整）提供 3 小時免費電力給 opt-in 用戶，**不需要屋頂太陽能板、不需要自有房屋**——只要有 smart meter（多數澳洲家庭已有）。計畫設計是將中午屋頂太陽能產生的「批發市場負價格」pass-through 給家戶。

這不是單純的能源補貼——**它是 AI 資料中心能源競爭直接導致的政策回應**。當 2025-2026 H1 Meta、Google、Microsoft 在澳洲 / Singapore / Indonesia 簽 5-15 年長約購太陽能 + battery 容量，**peak solar 的批發價格在 11am-2pm 被 hyperscaler 鎖定**，導致居民電價分攤結構改變。Solar Sharer Offer 把 midday 太陽能「**在 hyperscaler 買走之前**」的 3 小時**直接 give back 給家庭**——這是 2025-11 公告時只有 2 小時，2026-05 修法改為 3 小時的原因。

對開發者與企業的意義：這是 2026 H2「**AI 能源競爭的社會成本回流機制**」第一個 G20 等級的 policy reference case。當美 / 英 / 韓 / 日 / 印也在 2026 H2 進入類似的「AI 訓練資料中心 vs 居民能源成本」debate，**澳洲 Solar Sharer Offer 是這些國家設計 policy 時會被引用的具體 prototype**——尤其是「**3 小時」這個 magic number 直接映射到 hyperscaler 白天 peak solar 鎖定的 window，是「**AI 訓練負載對電網貢獻**」與「**居民電價結構**」的具體度量**。對 frontier AI lab 而言，**這種政策回應的擴散速度會直接影響 2027 年的 hyperscaler capex 在哪些國家落地**。

### 「如何讓 Claude 別再說 load-bearing」7/14 一夜爆紅：用 `MessageDisplay` hook 把「seam」改成「whatchamacallit」

[jola.dev 7/14 〈How to stop Claude from saying load-bearing〉](https://jola.dev/posts/how-to-stop-claude-from-saying-load-bearing) + [GitHub Issue anthropics/claude-code#53454](https://github.com/anthropics/claude-code/issues/53454) + [HN 7/14 380+ 則 front-page 討論](https://news.ycombinator.com/item?id=48905248) —— 開發者 jola.dev 寫了一個 [Claude Code `MessageDisplay` hook](https://docs.claude.com/en/docs/claude-code/hooks) script，把 Claude 輸出中的 "seam" 替換成 "whatchamacallit"、"you're absolutely right" 替換成 "I'm a complete clown"、"honest take" 替換成 "spicy doodad"、"load-bearing" 替換成 "cooked"。把 script 放到 `~/.claude/hooks/wordswap.sh` 並在 `~/.claude/settings.json` 註冊，新 session 啟動時自動載入。

這篇文章**意外地觸及 2026 H2 frontier coding agent 的具體 user-pain point**：當 Claude Sonnet 5 / Opus 4.8 / Fable 在大量 training data 中學到「seam / load-bearing / honest take / you're absolutely right」這類辭彙時，它在 software architecture 描述中**過度使用這些 phrase**——直接降低了對 developer 來說的溝通清晰度。jola.dev 的解法不是「**讓模型少說這些詞**」(那是 fine-tune / system prompt 層)，而是「**在 client 端做 string replacement**」——這個解法之所以爆紅，是因為它揭示了**「模型 vocabulary drift」+「client-side hook abstraction」的產品形態可能性**。

對開發者與 Anthropic 的意義：這篇文章與 [6/19 Anthropic 對 Fable/Mythos US gov 禁用指令的公開 dispute](/daily/2026-06-19) 的設計哲學不同——那是 model-level capability 限制，這是 user-level output 過濾。**`MessageDisplay` hook 抽象層的存在本身** 讓 user-level vocabulary control 變成 first-class extension point，這是 Anthropic 在 Claude Code 2.1.x 系列把「**agent configurability**」推到「**output filter 層**」的具體 reference case。對企業 IT 而言，這代表**「frontier model 的 vocabulary 在組織內可統一 custom 的」**是 2026 H2 的一個 product line——例如「在公司 Claude Code settings 中把 jargon 替換成 domain-specific 詞彙」或「**把 vendor-specific 詞換成中性詞**」都是可行 use case。**Anthropic 若把 `MessageDisplay` hook 從 hidden feature 升級為 first-class extension API，會是 Claude Code 在 enterprise 推廣的 next unlock**。

### OpenAI 7/14〈How to manage AI investments in the agentic era〉 提出「useful work per dollar」框架，正式把 enterprise AI 採購 metric 從 token price 拉開

[OpenAI 7/14 〈How to manage AI investments in the agentic era〉](https://openai.com/index/managing-ai-investments-in-agentic-era/) —— OpenAI 發布 enterprise AI 採購的 5 條指南：(1) 提升 usage 與 spend 的能見度（透過 [ChatGPT Enterprise 新的 usage analytics 與 spend controls](https://openai.com/index/chatgpt-enterprise-spend-controls/)）；(2) 用「**outcome ROI**」評估 model efficiency——不是比 token price，而是**比「達到 acceptable result 的 total cost」**；(3) 在 advanced workflow scale up 之前先做 governance；(4) 把 AI 投資當 portfolio 管理（broad access + function-specific + strategic bets）；(5) 為什麼現在就要 start 內部 AI practice。

**這份文件的結構性意義是 OpenAI 第一次正式把 enterprise AI 採購的「headline metric」從「**per-million-token price**」轉到「**cost per accepted outcome**」**。具體佐證是 OpenAI 引用 [GPT-5.6 vs GPT-5.4 的 cost-per-outcome 比較](https://openai.com/index/gpt-5-6/)：「54% fewer output tokens and 57% less time per task」——這是 outcome-level 數字，不是 per-token 數字。

OpenAI 同步承認了 enterprise AI 在 2026 H2 的一個痛點：很多企業的 AI spend 在「成長」但 admin 看不到「這個 spend 對應的 business outcome 是什麼」。這也是 [5/22 Adweek 報導 OpenAI ad business 預測可能 miss 90%](https://www.adweek.com/media/openais-ad-business-is-on-pace-to-miss-its-own-forecast-by-90-analyst-s) 的 enterprise 層 read——**OpenAI 自己在「用 token price 當 headline metric」這條路上也撞到牆**。

對開發者與企業的意義：當 frontier vendor 集體把 metric 從 token price 轉到 outcome ROI，**企業內部的 AI 採購流程必須在 2026 H2 重做**——具體的「**cost per accepted outcome**」表格需要把 (a) 失敗重試次數、(b) human review 時間、(c) 工具使用 cost、(d) 結果 quality gate 等多個維度整合。對 enterprise vendor 評估而言，這個 framework 應該是 2026 H2 procurement RFP 的核心 section。

### Bobby Tables 7/14〈The Agentic Loop: Three loops in a trench coat〉把 agent loop 拆成 inference / tool / agent 三層，agent 的「outer loop」概念首次被正式釐清

[Bobby Tables 7/14 〈The Agentic Loop: Three loops in a trench coat〉](https://www.bobbytables.io/p/the-agentic-loop-three-loops-in-a) + [HN 7/14 持續討論中](https://news.ycombinator.com/item?id=48907672) —— Bobby Tables 在這篇 blog post 中把「**agentic loop**」拆成三層架構：(1) **inference loop**（chat completion API call、tool usage 轉發、chat history persistence）；(2) **tool loop**（在 agent 框架內對 tool 呼叫做 retry、timeout、back-off、validation）；(3) **agent loop**（inference loop + tool loop + 對整體 task 的 state machine 編排）。他明確指出「**agent loop = inference loop + tool loop + state machine**」，並提供 pseudo-code 範例。

這篇文章**對 2026 H2 agent architecture discourse 的具體貢獻**是「**outer loop 是抽象層而非字面意義上的 loop**」——很多 vendor 與 framework 說「agent loop」其實混了三層，這是 first 個清晰分層的 reference text。它與 [6/23 Armin Ronacher〈The Coming Loop〉](https://lucumr.pocoo.org/2026/06/the-coming-loop/) + Boris Cherny「**My job is to write loops**」quote（[6/27 7/8 daily cross-ref](/daily/2026-07-08)）、[6/24 yfu〈The Control Plane Was the Point〉](https://lobste.rs/s/.../control-plane) 形成 2026 H2「**loops / harness / control plane**」三條 reference text 的 convergence。

對開發者的意義：當 [Claude Code 2.1.x](/daily/2026-07-15) 把 `MessageDisplay` hook 變成 first-class extension point、[Codex 0.144.x](/agents/2026-07-15) 把 MultiAgentV2 變成 default deploy mode、opencode v1.17.x 把 session snapshot 變成 first-class object——這些**都是 agent loop 第三層（state machine 編排）的具體 extension**。Bobby Tables 的三層架構給了這些 vendor 改動一個共同的 mental model。

## 一流學者與前沿研究

- **Bobby Tables** — [〈The Agentic Loop: Three loops in a trench coat〉7/14](https://www.bobbytables.io/p/the-agentic-loop-three-loops-in-a)
  - **背景：** Bobby Tables 是 distributed systems 與 AI infrastructure 領域的資深工程師（[Substack](https://www.bobbytables.io/)、[Twitter @bobby_tables](https://x.com/bobby_tables)），他的 writing 風格是把抽象的 agent architecture 概念透過 pseudo-code + diagram 拉到「**這個概念在 production code 裡是什麼樣子**」的層次。這篇是他 2026 H2 對「**agent loop**」這個被過度簡化的概念做的正式拆解。
  - **方法／論點：** Bobby 明確把 agent loop 拆成三層：(1) **inference loop**（chat completion API call、tool usage 轉發、chat history persistence）；(2) **tool loop**（retry、timeout、back-off、validation）；(3) **agent loop**（inference + tool + state machine 編排）。他用 pseudo-code 展示 inference loop 內每個 iteration 怎麼把 assistant message 與 tool calls append 到 chat history，並指出「**agent loop 不是 literal loop，是 state machine + loops 的 layered abstraction**」。
  - **關鍵結論：** 第一，「**outer loop 不是 literal loop**」——這是 first 個把 agent architecture 拉到「**state machine + nested loops**」的正式 mental model 的 reference text。第二，「**chat history persistence 是 inference loop 與 agent loop 的 boundary**」——當 chat history 從 process-local array 變成 Redis / database，agent loop 的 persistence boundary 改變，這對 [opencode v1.17.x session snapshot](/agents/2026-07-15) 與 [Claude Code 2.1.x `/rewind`](/daily/2026-07-15) 設計有直接 mapping。第三，「**streaming 改變 loop shape 但不改變 loop responsibilities**」——這是 vendor 討論 streaming behavior 時常見的混淆點。
  - **我的看法：** 對開發者而言，這篇是 2026 H2 agent architecture discourse 的「**finally someone put it in writing**」moment。它把 [6/23 Ronacher〈The Coming Loop〉](https://lucumr.pocoo.org/2026/06/the-coming-loop/)、[6/24 yfu autofz prequel](https://lobste.rs/s/.../autofz)、[7/12 Addy Osmani Agent Harness Engineering](https://addyosmani.com/blog/agent-harness-engineering/) 三個 reference 串成**「loops / control plane / harness」**三個可互換的 mental model。對企業評估 vendor 時，這個 mental model 是 **「agent loop 第一層的 inference loop 在 vendor 之間是 commodity，第二層的 tool loop 是 differentiator，第三層的 state machine + persistence 是 vendor 鎖定點」** 的具體 reference。

- **Han Tu, Martin Monperrus (KTH)** — [〈Latent Programming Horizons in Coding Agents〉arXiv 2607.05188 7/7 釋出，7/14 HN 持續討論](https://arxiv.org/abs/2607.05188)
  - **背景：** 這是 2026 H2 第一個把「**mechanistic interpretability for coding agents**」推到「**linear probe 能 decode coding agent 的未來 edit 結果**」的 reference paper。André Silva (KTH) + Han Tu + Martin Monperrus（KTH Royal Institute of Technology 軟體工程教授，**Sigstore / Dependabot 領域的 reference researcher**）透過 [logistic-regression probe on hidden states](https://arxiv.org/abs/2607.05188) 對 coding agent 的 residual stream 做線性解碼，發現**模型內部 representation 包含 about the evolving program 的結構性資訊**。
  - **方法／論點：** 第一個 finding：對 hidden state 做 logistic regression probe，**能 decode 當前 code 是否 parse、是否通過 test suite、是否 reduce failing tests、是否引入 regression**——AUC 達到 0.83 for correctness（跨 2 個 models + 2 個 benchmarks）。第二個 finding（更具結構性意義）：**這些 representation 領先 agent 的實際 edit**——probe trained to predict **未來 edit 結果**（在 edit 實際發生之前）的 performance above chance，**可達 ~25 steps in advance**。作者稱之為「**agent's latent programming horizon**」。Probes 跨 benchmarks 不用 retraining，external validity 強。
  - **關鍵結論：** 第一，「**coding agent 的 residual stream 對「program 狀態」有 linear encoding**」——這是 mechanistic interpretability 對 coding agent 的 first concrete empirical result。第二，「**agent 的內部 state 領先 agent 的實際 edit ~25 steps**」——這是 **「model 的 planning horizon 比 reactive behavior 大 1 個數量級」** 的量化。第三，「**probe 跨 benchmarks transfer**」——代表 latent programming horizon 不是 benchmark-specific，是 coding agent 結構的 general property。
  - **我的看法：** 對企業 vendor 評估 coding agent 時，這篇 paper 的「**latent programming horizon**」概念**是 2026 H2 interpretability-driven vendor selection 的具體 reference dimension**——當 vendor 開始自報「**我的 coding agent 的 latent programming horizon 是幾步**」，企業可以評估 agent 在 long-running tasks 上的可靠性。對 agent 安全研究而言，這個 probe 的存在代表 **「**agent 內部 state 可以被第三方 inspector 線性 decode**」**——這對 [6/22 Codex 640 TB audit trail](/daily/2026-06-22)、[7/14 Codex #28058 encrypted sub-agent messages](/daily/2026-07-16) 這類「**encryption vs auditability**」的設計爭論提供新的 scientific evidence：**如果 probe 能 decode，那 encryption 對 audit 防禦是 illusion**。
