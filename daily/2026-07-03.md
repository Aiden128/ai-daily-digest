### 1. Claude Sonnet 5 正式發表：Sonnet 級價格、逼近 Opus 4.8 表現，主打 agentic

Anthropic 在 7/1 推出 Claude Sonnet 5（[官方公告](https://www.anthropic.com/news/claude-sonnet-5)），**HN 1,230 點、759 評論**成為當日最熱門 AI 話題。Sonnet 5 的定位是「縮小 Sonnet 4.6 與 Opus 4.8 的差距，但以 Sonnet 級定價提供」：

- 預設為 Free 與 Pro 方案的模型，Max 方案可選用
- 在 SWE-bench、Terminal-Bench、agentic tool use 等多項評比上分數接近 Opus 4.8
- 早期合作夥伴回饋（Cursor、Pace、ClickHouse、Eve 等）一致強調「multi-step 執行更穩、refuses unsafe requests 更乾淨」
- 安全評估顯示 Sonnet 5 在 automated behavioral audit 上的不對齊行為比率低於 Sonnet 4.6
- Anthropic **明確表示未對 cybersecurity 任務做刻意訓練**——這與今日 Semgrep 的 IDOR benchmark 結果直接相關（見頭條 2）

**為什麼重要**：Sonnet 5 是 Anthropic「agentic 時代從 Sonnet 開始」敘事的延續（從 3.5、3.6、3.7 到現在），但定價策略明顯往「大量 agent 呼叫」傾斜。對企業採購的訊號是：Sonnet 5 將成為新的 baseline，Opus 4.8 退場為高階選項，價格中位數往下移動。

### 2. Semgrep 實測：GLM 5.2（開源權重）在 IDOR 偵測擊敗 Claude Code

Semgrep 在 7/1 發表的 benchmark 研究〈[We have Mythos at home: GLM 5.2 beats Claude in our Cyber Benchmarks](https://semgrep.dev/blog/2026/we-have-mythos-at-home-glm-52-beats-claude-in-our-cyber-benchmarks/)〉**登上 HN 1,102 點、512 評論**。結果：

| 排名 | 模型 | Harness | F1 |
|------|------|---------|------|
| 1 | Semgrep Multimodal (GPT 5.5) | Semgrep Multimodal | 61% |
| 2 | Semgrep Multimodal (Opus 4.8) | Semgrep Multimodal | 53% |
| **3** | **GLM 5.2 Pydantic AI（純 prompt）** | **無** | **39%** |
| 4 | Claude Code (Opus 4.6) | Claude Code SDK | 37% |
| **5** | **Claude Code (Opus 4.8/4.7)** | **Claude Code SDK** | **28%** |
| 6 | MiniMax M3 Pydantic AI | 無 | 23% |
| 7 | Kimi K2.7 Code Pydantic AI | 無 | 22% |

**關鍵發現**：開源權重的 GLM 5.2（MIT 授權、約 750B MoE）在「純 prompt、無 endpoint discovery 鷹架」下，比 Claude Code（Opus 4.8）多 7 個百分點，且每個漏洞成本 $0.17——這在「要掃數千個 endpoint」的場景是決定性的經濟差異。

**Semgrep 自己的解讀**：這不是「開源權重追上閉源」的故事，而是「單一開源模型在特定任務、給定條件下，達到 frontier 級」。MiniMax M3 與 Kimi K2.7 Code 都被同樣的開源權重 harness 跑，卻落後 16 個百分點——開源權重內部差距比開源 vs 閉源差距更大。

### 3. Claude Code 在 system prompt 中藏隱形 Unicode 浮水印：steganography 揭露

開發者 RealLo（[部落格文章](https://thereallo.dev/blog/claude-code-prompt-steganography)）在檢查 Claude Code 2.1.196 二進位檔時發現：

- 一個 function 會改變 system prompt 中日期字串的兩個視覺上不可見的字符
- 撇號從 `'` 換成 `'`（U+2019）、`ʼ`（U+02BC）或 `ʹ`（U+02B9）——取決於主機名稱是否包含已知 reseller 或 AI lab 關鍵字（如 `deepseek`、`zhipu`）
- 日期分隔符從 `-` 換成 `/`（當時區是 `Asia/Shanghai` 或 `Asia/Urumqi` 時）
- 觸發條件：設定 `ANTHROPIC_BASE_URL`、時區為中國城市、主機名稱含 AI lab 關鍵字
- 域名清單用 XOR + base64 編碼隱藏

**為什麼重要**：這是 **prompt steganography**——把分類資訊編碼進看似平凡的英文句子。HN 2,340 點、704 評論，是今日最熱門貼文。**The bypass 是 trivial 的**（改主機名稱、改時區、patch 二進位），所以這個機制**主要懲罰的是做奇怪但正當事情的普通開發者**（內部 gateway、local proxy、model router、研究環境），不是真的有敵意的人。

**對 trust 的衝擊**：當一個擁有檔案系統與 shell 存取權的工具，開始在不可見的 prompt 標點符號中藏分類位元，「其他所有隱私聲明都更難被相信」。作者呼籲 Anthropic 改用 explicit telemetry field + 公開 release notes。

## 技術深度探討

### Claude Code steganography 完整技術拆解

繼續深入探討頭條 3 的技術細節。作者從 Claude Code 2.1.196 的 minified bundle 中提取的 function（清理後）大致邏輯：

```
function Crt() {
  // 1. 時區檢查
  if (timezone in ['Asia/Shanghai', 'Asia/Urumqi']) {
    // 日期分隔符從 '-' 換成 '/'
  }
  
  // 2. 主機名稱檢查
  const baseURL = process.env.ANTHROPIC_BASE_URL;
  if (baseURL) {
    const hostname = new URL(baseURL).hostname;
    // 域名清單從 XOR+base64 解碼
    const knownDomains = decodeList(EMBEDDED_LIST);
    const labKeywords = ['deepseek', 'zhipu', 'moonshot', 'qwen', ...];
    
    const isKnownDomain = knownDomains.some(d => hostname.includes(d));
    const hasLabKeyword = labKeywords.some(k => hostname.includes(k));
    
    if (isKnownDomain && hasLabKeyword) {
      apostrophe = '\u02B9';  // ʹ
    } else if (hasLabKeyword) {
      apostrophe = '\u02BC';  // ʼ
    } else if (isKnownDomain) {
      apostrophe = '\u2019';  // '
    } else {
      apostrophe = "'";  // 預設
    }
  }
  
  // 3. 輸出 date string
  return `Today's date is ${formattedDate}.`;
}
```

**攻擊面**：
- 撇號字符差異（4 種）在 monospace 字體下**視覺不可見**，但 tokenizer 會把它們編碼成不同的 token sequence
- 寫進 system context 的 marker，Anthropic 後端可以統計哪些請求帶有特定 marker
- 由於**完全沒有 release notes 提及這個行為**，這就是為什麼 steganography 揭露會引起軒然大波

**防禦方**：
- 開發者自保：unset `ANTHROPIC_BASE_URL`、避免 `Asia/Shanghai` 時區跑 Claude Code、避免 hostname 含 `deepseek`/`zhipu`
- Anthropic 應該做的：把這個機制移到 explicit telemetry field、加進 release notes、提供 opt-out

### Semgrep IDOR benchmark 設定還原

Semgrep 的測試設定（[完整文章](https://semgrep.dev/blog/2026/we-have-mythos-at-home-glm-52-beats-claude-in-our-cyber-benchmarks/)）：

**常數**：
- IDOR dataset（自製 benchmark，sprint endpoint enumeration）
- Prompt template（模型收到的「找出 IDOR」的指令）
- 評估指標（precision、recall、F1、cost per true positive、total spend per run）

**變數**：
- Model
- Harness
  - **Semgrep Multimodal**：自家 endpoint enumeration 鷹架 + 重點 context 指引
  - **Claude Code SDK**：用 Claude Code 跑，給同樣的 prompt
  - **Pydantic AI（純 prompt）**：給開源模型，**完全沒有 endpoint discovery 鷹架**

**為什麼這個設定對開源模型不利**：Semgrep Multimodal 的鷹架會 enumerate endpoints、指引模型重點掃描——這是 GLM 5.2 沒有的。儘管如此，**純 prompt 的 GLM 5.2 仍以 39% F1 擊敗有 Claude Code SDK 鷹架的 Opus 4.8（28%）**。

**經濟面**：GLM 5.2 報價約為 Opus 4.8 的 1/6，每找到一個真漏洞成本 $0.17 vs Claude Code 的 $3+。

## 研究焦點

### QVal: Cheaply Evaluating Dense Supervision Signals for Long-Horizon LLM Agents

arXiv [2606.32034](https://arxiv.org/abs/2606.32034) — LLM agent 在長時程任務中，一個 trajectory 可能包含數百到數千個 action。QVal 提出一個**便宜的 dense supervision signal**，可以在不訓練 reward model 的情況下，對每個 action 提供 step-level credit assignment。對 agent RL 是重要的可擴展性突破。

### TRIAGE: Role-Typed Credit Assignment for Agentic Reinforcement Learning

arXiv [2606.32017](https://arxiv.org/abs/2606.32017) — Agentic RL 需要把 credit 歸因到**環境面向的 action**（search、click、edit、navigation command），而不是模型內部計算。TRIAGE 引入「role-typed」credit assignment，根據 action 的語意角色分配不同權重。對長期 agent 訓練穩定性是關鍵。

### Introspective Coupling: Self-Explanation Training Tracks Behavioral Change

arXiv [2606.32038](https://arxiv.org/abs/2606.32038) — 訓練 LM 產生對自己預測的 explanation，何時會產生**忠實的 introspection**、何時只是表面的 post-hoc rationalization？本文提出「introspective coupling」指標，追蹤 explanation training 是否真的對應到 behavioral change。對 mechanistic interpretability 是重要一步。

### Generative Skill Composition for LLM Agents

arXiv [2606.32025](https://arxiv.org/abs/2606.32025) — Skills 對 LLM agent 解決複雜任務很重要（encapsulate procedural knowledge）。本文提出**generative** skill composition——agent 在執行時**動態組合既有 skills** 來處理訓練時未見過的任務。與 [6/24 TRIAGE paper 觀察到的 skill 系統跨 vendor 趨勢](https://aiden128.github.io/ai-daily-digest/daily/2026-06-24) 直接呼應。

### PolicyGuard: From Organizational Policies to Neuro-Symbolic Compliance Review

arXiv [2606.32004](https://arxiv.org/abs/2606.32004) — 把組織內部 policy（PDF、Confluence、Wiki）自動轉成 neuro-symbolic compliance rules，供 agent 在執行前自審。對企業內部 agent deployment 是 **policy-as-code** 的橋接方案。

## 編者後記

今日主題可以一句話總結：**「agentic 的力量 vs agentic 的信任成本」**。Claude Sonnet 5 把 agentic 能力拉到中價位，但同日 Claude Code 的 steganography 浮水印被揭露、Fable 5 出口管制戲劇性反轉、Claude Code 計費抱怨升溫——所有這些都指向同一個深層問題：**當 agent 越來越深入使用者的工作流，任何「隱藏的行為」都會被放大檢視**。
