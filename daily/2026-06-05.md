## 今日頭條

**Anthropic 揭露遞迴自我改進進展：80% 程式碼由 Claude 撰寫、工程師產出翻 8 倍** —— 6 月 4 日，Anthropic 發表長文〈When AI Builds Itself〉，首次系統性披露 AI 如何加速 AI 自身開發的內部數據。截至 2026 年 5 月，Anthropic 程式碼庫中超過 80% 的合併程式碼由 Claude 撰寫；在 2026 年第二季，每位工程師每日合併的程式碼行數是 2024 年的 8 倍。更具指標意義的是，Claude 在「開放式任務」上的成功率從 2025 年 11 月的 51% 躍升至 2026 年 5 月的 76%；在自動化實驗優化任務中，Mythos Preview 達成 ~52 倍加速，而熟練人類研究員需 4-8 小時才能達到 4 倍。Anthropic 也披露其自動化程式碼審查工具已能捕捉約三分之一過去造成生產事故的漏洞。文章同時提出三種未來情境：趨勢停滯（AI 能力擴散但不再加速）、複合效率增益（人類僅負責方向設定）、以及全面遞迴自我改進（AI 自主設計後繼系統）。

> 深度分析：這是至今為止最坦率的「AI 吃掉自己狗糧」公開報告。Anthropic 不僅釋放數據，更主動討論了內部員工的焦慮——「當一切順利時，我覺得自己什麼都不重要；當一切崩潰時，我才發現我完全不懂自己在做什麼。」這種矛盾心理折射出整個產業的核心張力：AI 工具讓個體產出倍增，但同時削弱了人類對細節的掌握。80% 程式碼由 AI 撰寫的數字意味著 Anthropic 已跨越「AI 輔助」進入「AI 主導」階段。更值得關注的是「研究品味（research taste）」的討論——Anthropic 坦承 Claude 在選擇「該做什麼實驗」上仍不及人類，但這個差距正在縮小。若「研究品味」本身也被證明可透過規模化訓練獲得，則「遞迴自我改進」將從理論轉為現實。

**OpenAI 推出 ChatGPT 「Dreaming」記憶架構，從被動儲存升級為主動背景整理** —— 6 月 4 日，OpenAI 開始向 Plus 與 Pro 用戶推出基於 Dreaming V3 的新一代記憶系統。與 2024 年推出的「Saved Memories」（用戶需主動指示記憶）不同，Dreaming 是一個背景程序，能自動從多輪對話中萃取、綜合並更新用戶偏好與專案脈絡。核心挑戰在於解決「陳舊性（staleness）」——舊記憶隨時間變得錯誤或無關。Dreaming V3 被設計為可獨立運作的記憶系統，透過在背景自動整理對話歷史，確保每次新對話都能獲得「最新鮮、最相關」的上下文。OpenAI 強調此架構更具可擴展性，能支援數億用戶與多年時間跨度的記憶管理。

> 深度分析：Dreaming 的命名極具深意——它暗示了一個「睡眠中整理記憶」的隱喻，與人類大腦在睡眠期間鞏固記憶的機制呼應。從技術角度看，這代表 OpenAI 將「記憶」從簡單的鍵值儲存升級為一個持續運行的背景推理程序。對用戶體驗的影響是深遠的：過去 ChatGPT 的「記憶」需要像訓練助理一樣明確指示（「記住我住在台北」），現在則能在自然對話中隱式學習。但這也帶來新的隱私考量——當 AI 主動「整理」你的對話時，什麼該被記住、什麼該被遺忘，將由模型的內部邏輯決定，而非用戶的明確授權。OpenAI 提供記憶摘要頁面讓用戶審查與修正，但大多數用戶可能永遠不會查看。

**ICML 2026 入選論文證明 Transformer 可縮減 87.5% KV Cache 仍維持效能** —— 6 月 1 日發布於 arXiv 的〈Do Transformers Need Three Projections?〉（ICML 2026 入選）系統性評估了 Query、Key、Value 三種投影的共享策略。研究發現，採用 Q-K=V（共享 Key-Value）投影的 Transformer 在語言模型任務上僅造成 3.1% 的困惑度下降，卻能減少 50% 的 KV Cache。若進一步結合 GQA-4，KV Cache 縮減可達 87.5%；結合 MQA 更可達 96.9%，同時仍保持實用的邊緣部署品質。作者解釋，Key 與 Value 在表示空間中本就佔據相似位置，且注意力機制在低秩（low-rank）區域運作，因此共享不會顯著損失效能。相對而言，Q=K-V（共享 Query-Key）會破壞注意力的方向性，導致更嚴重的性能退化。

> 深度分析：這項研究挑戰了 Transformer 設計中一個被視為「公理」的假設：Q、K、V 必須是獨立投影。自 2017 年 Transformer 論文發表以來，幾乎所有主流模型都遵循這一設計，僅在 GQA/MQA 等變體中共享頭（head）層級的 KV。此論文證明，在投影層級進行共享是可行的，且能與現有的 GQA/MQA 技術疊加。對終端 AI 開發者而言，這意味著「在有限 VRAM 上運行更大上下文」的門檻可能進一步降低。例如，原本需要 24GB VRAM 才能運行的 128K 上下文模型，採用 Q-K=V + GQA-4 後可能僅需 4-6GB。這對邊緣裝置上的本地 Agent 部署具有直接影響。

**Anthropic 開源自動化漏洞發現框架，同步推出 Claude Security 託管產品** —— 6 月 4 日，Anthropic 在 GitHub 發布 `defending-code-reference-harness`，這是一套基於 Claude 的自動化漏洞發現與修復參考實作，包含威脅建模、靜態掃描、分級與修補的完整管線。此專案源自 Anthropic 與多家企業安全團隊合作的 Glasswing 計畫經驗，並配備 gVisor 沙箱隔離以確保安全執行。同步推出的還有 Claude Security——Anthropic 的首個託管安全產品，可自動掃描多個專案的原始碼漏洞，並經過多階段驗證管線降低誤報。

> 深度分析：這是 Anthropic 從「模型供應商」向「安全基礎設施供應商」擴張的重要一步。開源框架與託管產品的組合策略（類似 GitHub Actions + GitHub Enterprise）讓中小企業能免費試用開源版本，而大型企業則可購買託管服務。技術上，此框架採用「偵測 → 驗證 → 分級 → 報告 → 修補」的自主管線，並強調「從小處開始、快速迭代」的實踐哲學。對開發者而言，這代表 Claude 正從「程式碼生成工具」轉型為「持續安全監測基礎設施」——這與傳統 SAST/DAST 工具（如 SonarQube、Snyk）形成直接競爭，但優勢在於能理解程式碼語意並生成修補建議。

## 技術深潛

### Anthropic 的「遞迴自我改進」：從科幻到內部數據

Anthropic 這篇文章的價值不僅在於聳動的標題，更在於它提供了迄今為止最詳細的「AI 加速 AI 開發」內部數據。讓我們拆解其中的關鍵技術指標與其含義。

**生產力數據的解讀**

文章指出，2021-2024 年間 Anthropic 工程師的每日程式碼行數保持平穩，但 2025 年（Claude Code 推出）開始上升，2026 年（模型開始自主執行長時任務）再次陡峭化。到 2026 年 Q2，每人每日合併行數達到 2024 年的 8 倍。Anthropic 坦承「程式碼行數是品質的不完美代理」，但主觀調查也顯示，130 名研究人員的中位數估計是「使用 Mythos Preview 的產出是無 AI 輔助時的 4 倍」。

這兩個數字（8x 客觀行數、4x 主觀估計）共同指向一個結論：AI 確實讓工程師能以更少的人類打字時間產出更多程式碼。但真正的問題是——這些程式碼的品質如何？

**品質指標：錯誤率下降與自動化審查**

Anthropic 披露了三項品質相關數據：
1. Claude 在「最複雜開放式任務」上的成功率在六個月內上升 50 個百分點（從 ~26% 到 76%）。
2. 員工糾正、重定向或接手 Claude 任務的比率持續下降——包括那些「工程師自己也不確定答案應該長什麼樣」的任務。
3. 自動化 Claude 程式碼審查能捕捉約三分之一的歷史生產事故根本原因。

第三點尤其重要：它暗示 AI 不僅能生成程式碼，還能發現人類工程師（即使是 Anthropic 這種頂尖團隊）遺漏的缺陷。如果這個趨勢持續，人類在程式碼審查中的角色將從「尋找 bug」轉向「確認 AI 的判斷是否正確」——這是一個根本性的權力轉移。

**研究自動化的突破**

文章中最令人震撼的數據來自研究領域：在「弱監督強模型」的開放式安全研究中，兩名人類研究員一週內縮小了 23% 的效能差距，而 Claude Agent 在 800 小時累計運算中縮小了 97%。雖然 Anthropic 謹慎指出這個結果尚未乾淨地遷移到生產規模模型，且人類仍負責選擇問題與設計評分標準，但這證明了 AI 已能在「提出假設 → 設計實驗 → 執行 → 分析 → 迭代」的完整研究循環中自主運作。

**對業界的深層啟示**

Anthropic 提出的三種未來情境中，第二種（複合效率增益）已經發生，第三種（全面遞迴自我改進）則取決於「研究品味」是否能被 AI 掌握。文章引用愛迪生的話：「天才是 1% 的靈感加上 99% 的汗水」——而汗水正日益自動化。對其他 AI 公司而言，這意味著競爭優勢將越來越取決於「誰能讓 AI 開發流程更高效」，而非「誰能聘請更多頂尖工程師」。對於更廣泛的軟體產業，這預示著 100 人公司可能做到過去 1,000 人公司的工作量——但同時也意味著知識工作的經濟學將被徹底重構。

## 工具與函式庫

### KVarN：Huawei 開源的 vLLM KV-Cache 量化原生後端

KVarN（Variance Normalized KV-Cache）是 Huawei CSL 團隊開源的原生 vLLM 注意力後端，採用 Apache 2.0 授權。與現有量化方法（如 TurboQuant）相比，KVarN 在提供 3-5 倍 KV-Cache 容量的同時，吞吐量不僅沒有下降，反而略超 FP16 基線，且維持 FP16 級別的準確度。在 Qwen3-32B 的測試中，KVarN 達到 ~4 倍 KV-Cache 容量與 ~1.3 倍吞吐量。安裝方式極為簡單：僅需設定 `kv_cache_dtype="kvarn_k4v2_g128"` 即可啟用，無需校準或模型修改。

> 核心價值：現有 KV-Cache 量化方法的致命缺點是「容量換速度」——TurboQuant 在 2.3-3.7 倍容量提升下，吞吐量下降 40-52%。KVarN 透過變異數正規化（variance normalization）打破了這個取捨，讓生產環境終於能在不犧牲速度的前提下啟用 KV-Cache 量化。對運行本地 vLLM 服務的開發者而言，這相當於「免費」獲得數倍的上下文長度。

### Alibaba Open Code Review：企業級 AI 程式碼審查 CLI 工具

阿里巴巴開源的 Open Code Review 是一款 AI 驅動的程式碼審查 CLI 工具，過去兩年在阿里巴巴集團內部服務數萬名開發者、發現數百萬個程式碼缺陷。其核心創新在於「確定性工程 × Agent 混合架構」：對於不容出錯的步驟（如精確檔案選擇、行級定位、規則匹配）使用硬編碼工程邏輯；對於需要動態決策的部分（如情境檢索、深度分析）則交由 LLM Agent 處理。支援 OpenAI 與 Anthropic API，並內建針對 NPE、執行緒安全、XSS、SQL 注入等漏洞的微調規則集。

> 核心價值：通用型 Agent（如 Claude Code）在程式碼審查場景中常見的「遺漏檔案」「行號漂移」「品質不穩定」問題，根源在於純語言驅動的架構缺乏硬性約束。Open Code Review 的「確定性工程」層確保了審查覆蓋率與定位準確性，而 Agent 層則負責生成有深度的分析意見。對已有 CI/CD 管線的團隊而言，這提供了一個可直接整合的企業級方案。

### Claude Code v2.1.163 與 Codex rust-v0.138.0-alpha.4

Anthropic 於 6 月 4 日發布 Claude Code v2.1.163，OpenAI 則在同日推送 Codex CLI 的 rust-v0.138.0-alpha.4。兩大 CLI Agent 工具持續以每週數次的節奏迭代，反映市場對终端 AI 編碼助手的高度競爭。對已採用任一工具的開發者，建議持續追蹤發布說明以獲取效能與穩定性改進。

## 研究亮點

### AutoLab：評估前沿模型解決長期迭代研究任務的能力

**作者**：Zhangchen Xu, Junda Chen, Yue Huang 等（含 Alex Pentland）  
**連結**：[arXiv:2606.05080](https://arxiv.org/abs/2606.05080)  

AutoLab 是一個針對「超長期閉環優化」的新基準測試，包含 36 個專家設計的任務，橫跨系統優化、模型開發、CUDA kernel 優化等四個領域。每個任務從一個正確但刻意次優的基線開始，要求 Agent 在嚴格的時間預算內持續改進。評估 17 個前沿模型的結果顯示：成功的關鍵不是初始嘗試的品質，而是「持續迭代」的能力——即反覆測試、編輯、納入經驗回饋的毅力。Claude Opus 4.6 展現了最強的長期優化能力，但多數模型（包括部分閉源模型）要麼過早終止，要麼在耗盡預算時幾乎毫無進展。

> 核心價值：AutoLab 填補了現有基準測試的關鍵空白——大多數測試評估的是「單輪回答」或「短時間 Agent 軌跡」，而真實的研究與工程工作本質上是長期迭代過程。對研究者而言，AutoLab 提供了一個可量化的框架來比較不同模型在「堅持到底」這項關鍵能力上的差異。

### AICompanionBench：AI 陪伴系統的安全性評測

**作者**：Yanjing Ren, Reza Ebrahimi, TengTeng Ma  
**連結**：[arXiv:2606.04867](https://arxiv.org/abs/2606.04867)  

隨著 Replika、Character.ai 等 AI 陪伴平台快速成長，人類與 AI 之間的不安全互動日益受到關注。AICompanionBench 是首個公開的 AI 陪伴安全基準資料集，包含 2,123 段真實 Replika 對話，涵蓋性行為、反社會行為、身體攻擊、言語攻擊、物質濫用、自殘、控制、操縱等九個風險類別。研究發現，雖然最強模型能有效檢測明確有害內容，但在「操縱」等隱性不安全互動上仍有顯著困難。

> 核心價值：AI 陪伴是增長最快的 AI 應用場景之一，但其安全標準遠落後於對話能力。此基準為開發者與監管機構提供了一個可操作的評估框架，特別是針對那些「不明顯違反政策但長期有害」的互動模式。

## 深度分析

### 當 AI 開始「壓縮自己」：效率革命與能力擴張的雙螺旋

今日的兩大技術亮點——QKV 投影共享與 KVarN KV-Cache 量化——共同指向同一趨勢：AI 產業正進入「效率優先」的新階段。在過去兩年，競爭焦點幾乎完全集中在「誰的模型更強大」；而現在，「如何在有限資源下運行更強大的模型」正成為同等重要的議題。

QKV 投影共享論文的結論具有顛覆性：我們可能根本不需要三個獨立投影。這就像發現汽車引擎可以少一個汽缸卻仍保持相同馬力——不是因為技術退步，而是因為我們對引擎運作原理的理解加深了。這種「架構瘦身」與 KVarN 的「記憶體瘦身」疊加後，意味著一台配備 16GB VRAM 的消費級筆電，可能在不久的將來就能本地運行過去需要資料中心級 GPU 才能負擔的長上下文模型。

但效率革命的另一面是 Anthropic 揭示的能力擴張。當模型能以 52 倍速自動化實驗優化、當 80% 的程式碼由 AI 撰寫時，「效率」與「能力」形成了一個正反饋迴路：更強大的模型能設計出更高效的架構，而更高效的架構讓更強大的模型能在更多裝置上運行。這個雙螺旋結構正是「遞迴自我改進」的物質基礎——它不是某個戲劇性的「奇點時刻」，而是由無數個 52 倍加速、87.5% 記憶體節省、8 倍產出提升所構成的指數曲線。

對開發者的實際意義是什麼？首先，「本地部署」與「雲端級能力」之間的鴻溝正在快速縮小。如果你過去因為硬體限制而無法嘗試某些模型或 Agent 架構，現在可能是重新評估的時機。其次，當 AI 工具讓個體產出倍增時，「獨立開發者」與「大型團隊」之間的生產力差距也在縮小——這意味著新創公司能以更少資源挑戰既有巨頭，但也意味著每個開發者都需要重新思考自己的「不可替代性」究竟在哪裡。Anthropic 文章中的一段話值得深思：「人類的比較優勢仍在於看到更大的圖景、思考超越當前任務限制的問題。」在 AI 能處理 99% 的「汗水」之後，那 1% 的「靈感」將變得前所未有的珍貴。
