### 1.3 Entire.io〈How version control will evolve for the agent boom〉— Session log 與 code 一起 version control,從「**agent 改 code**」走向「**agent 改 code + agent 改自己的 prompt + agent session 是 first-class artifact**」的具體 new reference

[Entire 7/9 blog post](https://entire.io/blog/how-version-control-will-evolve-for-the-agent-boom) + [HN thread 7/9](https://news.ycombinator.com/item?id=48844709)—— Entire.io 提出具體 hypothesis:**「**Session logs are now the most important artifact in software development, and should be stored alongside the code itself in the repository**」**。具體三層:(a) **過去 Git 儲存「**lines of code + commit messages**」**,agent world 的關鍵資產是「**agent sessions with prompts + tool calls + checkpoints + decisions**」**;(b) **把 session log commit 到 repo 提供 semantic memory layer**——**agent stop repeating mistakes**、**increase accuracy**、**decrease token spend**、**humans can more easily understand and verify what was built and why**;(c) **「**version control 對 agent 必須 capture 的是「**why**」而不只是「**what**」**」的具體 new design principle**。

> **架構性解讀**:這個 essay 的**結構性意義是「**version control 對 agent 從『**改 code 的記錄**』走向『**改 code + 改 prompt + 改 session**』的具體 vendor reference**」**。具體三層:
> 1. **「**Session log 是 first-class artifact,跟 code 一樣 commit**」的具體 new pattern**:過去 Git commit 是 code state diff,Entire 提議 commit 也包含 **agent session log(prompts + tool calls + decisions)**,讓 **(a) agent 之間可以 reference 過去 session、(b) humans can audit 為什麼 code 是這樣寫的、(c) 跨 session 的 semantic memory 變成 versioned object**——**「**session-as-versioned-object 跟 code-as-versioned-object 對等**」是 [6/24-6/27 opencode v1.17.11 session snapshot](https://aiden128.github.io/ai-daily-digest/agents/2026-07-04) + [Claude Code v2.1.191 /rewind](https://docs.claude.com/en/docs/claude-code/changelog) + [Copilot CLI v1.0.66 /chronicle](https://github.com/github/copilot-cli) 從 runtime 走向「**storage layer 應 version control session**」的具體 second step**
> 2. **「**『**why**』 capture 對 code review 的具體 new requirement**」**:Entire 提的 semantic memory layer 解決的核心問題是 —**過去 code review 看到 diff 但看不到「**為什麼是這個 diff**」**,有 session log 之後 reviewer 可以 trace 完整 decision tree——**「**code review 從 diff review 升級為 session review**」是 2026 H2 enterprise code review workflow 的具體 new direction**
> 3. **「**Version control 對 agent ecosystem 的具體 new vendor 機會**」**:Entire.io 推這個 hypothesis 對 GitHub / GitLab / Bitbucket 是「**platform 必須原生 support session-as-versioned-object**」的具體 pressure——也是 [Entire 自己作為 vendor](https://entire.io) 的 product 機會——**「**version control vendor 對 agent 必須有 first-class session storage**」的具體 new 2026 H2 requirement**

> **為什麼這個 essay 是 today's top 3 headline**:Entire.io 的 essay 是 2026 H2 **第一個明確把「**session log 應 commit 到 repo**」變成可執行 product hypothesis 的 vendor reference**——對 developer tooling 是「**code review / refactor / debugging 工具必須支援 session log import**」的具體 new baseline。**對 developer tooling vendor**:**「**session log commit + diff 跨 session + versioned semantic memory**」 是 2026 H2 coding agent infrastructure 必須。

### 1.8 arXiv 2607.07695〈Institutional Red-Teaming: Deployment Rules, Not Just Models, Causally Shape Multi-Agent AI Safety〉— Multi-agent safety 從「**model red-team**」走向「**deployment rules red-team**」的具體 new methodology

[arXiv 2607.07695〈Institutional Red-Teaming〉7/8 by IABench-CA team](https://arxiv.org/abs/2607.07695v1)—— arXiv 7/8 paper 提出 **institutional red-teaming 是新的 multi-agent AI safety evaluation methodology**:**「**Hold the agents, objectives, and task state fixed, vary only one rule, and attribute the resulting change in collective behavior to that rule**」**。具體 implement 在 **IABench-CA**:consequence-allocation benchmark 跨 **228 contexts、5 canonical rules、7 model populations、33,924 games** + normative cooperative reference + auto-labelled reasoning traces。三個 findings:(a) **Deployment rules causally alter collective safety**——僅改 consequence rule 就移動 mean fatality by **22 to 58 percentage points** within every population;(b) **沒有 safe default**——safest rule、least-safe rule、incidence effect direction 都 across populations 不一樣,**但 regressive identity-targeting 在任何 context / population 都不是 decisively safest,在 30-87% of games eliminates least-resourced agent,對所有 7 populations 都 selection-unsafe**;(c) **Identity salience 是 mechanism**——one-shot anonymization 在最 exploitation-prone population(gpt-5.1) 顯示,**僅 naming the loss bearer in the rule text 就驅動 targeted elimination 從 22% 升到 81% at identical payoffs**;在 repeated play 之下 anonymization 只 delays targeting,agents re-infer 隱藏 rule from observed eliminations。

> **架構性解讀**:這篇 paper 的**結構性意義是「**multi-agent AI safety 從『**red-team model**』走向『**red-team deployment rules**』**」的具體 new methodology reference**。具體三層:
> 1. **「**『**rule causation**』 對 multi-agent safety 評估的具體 new paradigm**」**:過去 multi-agent safety 假設 「**模型 + training**」 是 safety 的 root cause,這篇 paper 論證 —**僅改 deployment rule(不動 model) 就可移動 22-58pp 的 fatality**——**「**deployment rules causally alter collective safety**」是 [6/22-6/23 cross-vendor agent runtime safety wave](https://aiden128.github.io/ai-daily-digest/agents/2026-06-26) + [Anthropic 7/6〈How we contain Claude〉](https://aiden128.github.io/ai-daily-digest/daily/2026-07-10) 對「**multi-agent safety evaluation must include rules, not just models**」的具體 academic 化
> 2. **「**『**no safe default**』 + 『**identity salience 機制**』 對 enterprise IT 採購 agent 的具體 new framework**」**:這篇 paper 指出 **任何 single rule 都不是 across-context safe** + **identity salience (在 rule text 中 naming the loss bearer) 是 targeted elimination 的 mechanism**——**「**enterprise IT 對 multi-agent system 必須考慮 rule layer 而非只 model layer**」+「**rule text 內 identity naming 對 safety 有具體 impact**」的具體 new 2026 H2 framework
> 3. **「**『**safety-case workflow with certified rule region Φ(c,P)**』 對企業 IT 採購 multi-agent 系統 的具體 new reference**」**:paper 將 methodology 包裝成 **safety-case workflow**:**certifies a provisional rule region Φ(c,P) per deployment context and population,with explicit residual risks and monitoring obligations**——**「**multi-agent system 採購必須 reference safety-case workflow with explicit residual risks**」的具體 new 2026 H2 enterprise IT reference**

> **為什麼這個 paper 是 today's top 8 headline**:這篇 paper 是 2026 H2 **first academic 對 「**institutional red-teaming」 的 33,924-game 大規模 benchmark 化**——對 enterprise IT 是「**multi-agent system 採購必須 reference IABench-CA-style benchmark + safety-case workflow**」的具體 new 2026 H2 reference。**對企業 IT**:**任何 multi-agent system(尤其 enterprise 內部) 的安全評估 必須 include rule layer + identity salience + IABench-CA-style benchmark**。
