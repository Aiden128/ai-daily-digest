## 今日頭條

1. **OpenAI 內部模型獨立證明離散幾何學中長達八十年的 Erdős 單位距離猜想不成立**（2026-05-20）
   這是人工智慧首次在無人類數學家直接主導的情況下，獨立解決一個核心數學領域的知名開放問題。該問題由 Paul Erdős 於 1946 年提出：在平面上放置 n 個點，最多可以有多少對點之間的距離恰好為 1？長久以來，數學界普遍認為「方形網格」構造已經接近最優解，但 OpenAI 的通用推理模型找到了一個無限的範例家族，給出了多項式級別的改進（polynomial improvement），徹底推翻了這個核心猜想。證明已經由外部數學家群組（包括 Fields 獎得主 Tim Gowers、組合學權威 Noga Alon 等）驗證通過。Gowers 在伴隨論文中稱此結果為「AI 數學的里程碑」，而數論學家 Arul Shankar 更直言：「這證明了當前的 AI 模型不僅僅是人類數學家的助手，它們能夠產生原創的、精巧的想法，並將其貫徹到底。」值得注意的是，這並非一個專為數學設計的系統，而是一個通用推理模型在 Erdős 問題集合上的廣泛測試中自主發現的。

2. **Anthropic 與 SpaceX 簽訂每月 12.5 億美元的算力租賃協議，並擴展至 Colossus 2 的 GB200 叢集**（2026-05-20）
   根據 SpaceX 向 SEC 提交的 S-1 招股書，Anthropic 已同意每月支付 12.5 億美元，租用 SpaceX COLOSSUS 與 COLOSSUS II 的運算容量，合約期至 2029 年 5 月。同一天，Anthropic 聯合創辦人 Tom Brown 在 X 上確認，Anthropic 將在整個六月持續擴充 Colossus 2 上的 GB200 容量。這筆交易的規模令人震撼：每年 150 億美元，幾乎相當於 Anthropic 目前的年度營收預估。對整個 AI 產業而言，這標誌著「算力即地緣政治籌碼」的時代正式來臨——不是誰的模型更聰明，而是誰能保證在未來三年內取得穩定、巨量的 GPU 供應。SpaceX 的 Colossus 叢集（由 xAI 的 Grok 5 訓練需求驅動而建）現在成了 Anthropic 的「第二機房」，這種「競爭對手共享基礎設施」的現象也反映了晶圓廠產能才是真正的稀缺資源。

3. **DeepSeek 發布 V4 預覽版，開源 1M 上下文模型並將長上下文定為官方服務標配**（2026-04-24，近期獲得廣泛關注）
   DeepSeek 發布了全新系列的 DeepSeek-V4 預覽版，包含 Pro 與 Flash 兩個版本，最大上下文長度均達到 100 萬 token（1M）。V4-Pro 在數學、STEM、競賽型程式碼的評測中超越所有已公開評測的開源模型，達到世界頂級閉源模型的水準；在 Agentic Coding 評測中，V4-Pro 已達到當前開源模型的最佳水準，內部評測甚至認為使用體驗優於 Claude Sonnet 4.5，接近 Opus 4.6 非思考模式。技術上，V4 採用了全新的注意力機制，在 token 維度進行壓縮，結合 DSA（DeepSeek Sparse Attention）稀疏注意力，實現了全球領先的長上下文能力，同時顯著降低計算與顯存需求。DeepSeek 更宣布，從此刻起，1M 上下文將成為所有官方服務的標配。對開發者而言，這意味著「長上下文」從高階功能變成了基礎設施——你可以一次性餵給模型一整本技術手冊、數百頁程式碼庫，或長時間的對話歷史，而不需要複雜的 RAG 管道。

4. **Google I/O 2026 百項發布：Gemini Omni、Gemini 3.5、Gemini Spark 與 Antigravity 2.0 構築「Agent 優先」生態系**（2026-05-20）
   Google 在 I/O 2026 一口氣宣布了超過 100 項更新，核心主軸從「模型發布」轉向「Agent 基礎設施」。除了已於昨日發布的 Gemini 3.5 Flash 之外，這次 I/O 還揭曉了 Gemini Omni（原生多模態模型）、Gemini Spark（被定位為「你的個人 AI Agent」，原生連接 Gmail、Calendar、Drive、Docs、YouTube 等 Google 服務）、以及 Google Antigravity 2.0（桌面應用、CLI agent 工具與開發框架）。Simon Willison 注意到一個有趣的細節：Gemini Spark 的 FAQ 透露它運行在 Gemini 3.5 Flash 與一個名為「Antigravity」的模型之上。Google 同時推出了 Managed Agents in the Gemini API，讓開發者能夠建構具有長期記憶與多工具調用能力的代理。這顯示 Google 的戰略已經明確：不再單純比拼模型基準分數，而是利用其無與倫比的消費產品生態系，讓 Gemini 無處不在。

## 一流學者與前沿研究

- **Anthropic** — [2028: Two scenarios for global AI leadership](https://www.anthropic.com/research/2028-ai-leadership)（2026-05-14）
  - **背景：** Anthropic 發表了一份政策研究報告，闡述其對美中 AI 競爭的看法。報告認為，民主國家必須在 AI 發展與部署上領先，因為 AI 很快將強大到足以被威權政府用來前所未有地壓迫公民，甚至改變國家間的力量平衡。
  - **方法／論點：** 報告的核心論點是「運算（compute）」是開發前沿 AI 最重要的原料，而美國目前透過出口管制維持領先。但中國實驗室之所以能緊追在後，主要依賴三個因素：世界級人才、利用出口管制漏洞，以及大規模的蒸餾攻擊（distillation attacks）——即非法提取美國模型的創新來模仿其能力。報告提出兩個 2028 年的情境：情境一是美國成功鞏固運算優勢，民主國家設定 AI 規則；情境二是美國未採取行動，中國利用漏洞趕上甚至超越，由威權政權塑造 AI 規範。
  - **關鍵結論：** Anthropic 認為，如果美國及其盟友現在就加強運算出口管制、阻斷蒸餾攻擊，並加速民主國家的 AI 採用，有可能在 2028 年前鎖定 12-24 個月的前沿能力領先優勢。這個時間窗口不會永遠敞開。
  - **我的看法：** 這份報告是 Anthropic 從「技術公司」向「地緣政治行為者」轉變的明確信號。與 OpenAI 的軟性遊說不同，Anthropic 直接將自身定位為「民主國家 AI 聯盟」的技術支柱。對開發者而言，更值得關注的是「蒸餾攻擊」被提升到國家安全層級——這可能意味著未來 API 服務將有更嚴格的反蒸餾機制（如延遲回應、動態水印、行為指紋），影響所有透過 API 進行研究或模型訓練的開發者。

- **Simon Willison** — [SpaceX S-1 and How fast is 10 tokens per second really?](https://simonwillison.net/2026/May/20/spacex-s1/)（2026-05-20）
  - **背景：** Willison 持續追蹤 SpaceX 的 S-1 文件與 AI 產業的實用工具。他在同日分享了兩個觀察：Anthropic 與 SpaceX 的巨型算力交易，以及一個模擬 LLM token 輸出速度的互動網頁工具。
  - **方法／論點：** 在 SpaceX S-1 的財務揭露中，Willison 高亮了一段關鍵文字：Anthropic 同意每月支付 12.5 億美元使用 COLOSSUS 與 COLOSSUS II 的運算容量。這筆交易的規模讓 Willison 將其標記為產業重大信號。同時，他推薦了 Mike Veerman 製作的 HTML 工具 [tokenspeed](https://mikeveerman.github.io/tokenspeed/)，讓使用者從 5 token/秒到 800 token/秒直觀感受 LLM 輸出的速度差異。
  - **關鍵結論：** Willison 認為，Anthropic 的算力支出揭示了前沿 AI 實驗室的真實成本結構——模型能力背後是天文數字的資本支出與運營費用。而 token 速度視覺化工具則解決了一個開發者常見的認知偏差：我們經常在 benchmark 中看到「30 tokens/second」，但很少真正理解這對使用者體驗意味著什麼。
  - **我的看法：** Willison 的價值在於他總能從財務文件與使用者體驗兩個極端同時切入。Anthropic 每月 12.5 億美元的算力租賃，相當於每天 4,100 萬美元——這讓「訓練一次 frontier 模型要花多少錢」的討論顯得蒼白，因為真正的成本不是訓練，而是「持續 inference 與不斷的後訓練迭代」。而 token 速度工具看似 trivial，卻是產品設計中缺失的一環：當 agentic 工作流動輒輸出數萬 token 時，10 tokens/秒與 100 tokens/秒的差距就是「使用者是否會關掉分頁」的關鍵。

## 企業前沿動態

- **Cursor**（2026-05-18）：閱讀 [*Introducing Composer 2.5*](https://cursor.com/blog/composer-2-5) 全文後，重點如下：
  - Cursor 發布了 Composer 2.5，官方定位為「在長期 agentic 任務上的智能與行為有顯著提升」。這是繼 4 月發布 Cursor 3（統一的 agent 工作空間）與 3 月的 Composer 2 之後的又一次快速迭代，顯示 Cursor 正在以每週級別的速度改進其 agent 引擎。
  - 技術細節上，Composer 2.5 專注於「長期 horizon agentic tasks」——即需要多步規劃、跨檔案編輯、以及與外部工具（如終端機、瀏覽器、Linter）持續互動的任務。這與 Cursor 3 月以來的產品路線一致：從「程式碼補全」走向「自主完成整個功能開發」。
  - 對業界的影響是：Cursor 正在定義「AI 原生 IDE」的標準。當 GitHub Copilot 還在強調「程式碼建議」時，Cursor 已經在讓 agent 自主執行 `git commit`、`npm test`、甚至修復 CI 錯誤。這種「從助手到同事」的轉變，正在重塑軟體開發團隊的協作模式——人類開發者越來越像「專案經理 + 程式碼審查者」，而實際的打字工作交給了 agent。

- **GitHub**（2026-05-20）：根據 [BleepingComputer 報導](https://www.bleepingcomputer.com/news/security/github-confirms-breach-of-3-800-repos-via-malicious-vscode-extension/)，GitHub 確認有 3,800 個儲存庫透過惡意的 VS Code 擴充功能遭到入侵：
  - 攻擊者將惡意程式碼植入多個熱門的 VS Code 擴充功能（包括「dracula-theme-official」等主題與工具擴充），這些擴充功能在被安裝後會竊取開發者的 GitHub 認證 token，並利用這些 token 對儲存庫進行未授權的修改、植入後門。
  - GitHub 已經確認此次事件並撤銷了所有受影響的 token，但 3,800 個儲存庫的規模顯示了「開發者工具供應鏈」作為攻擊向量的嚴重性。這不是傳統的 npm 供應鏈攻擊，而是直接針對開發者本地環境的 IDE 擴充功能。
  - 對開發者的啟示是：我們長期以來對 VS Code 擴充功能的安全性過於信任。每一個安裝的擴充功能都擁有讀取檔案系統、執行指令、甚至存取環境變數的權限，但我們很少審查它們的原始碼或更新歷史。在 AI coding agent 日益依賴 IDE 外掛生態系的今天，這次事件是一個嚴厲的警告：「便利」與「安全」之間的界線需要被重新劃定。

## Hacker News 熱門討論

- **"An OpenAI model has disproved a central conjecture in discrete geometry"**（[HN 連結](https://news.ycombinator.com/item?id=48212493)，686 points / 490 comments）
  - **背景：** 這則 OpenAI 模型獨立解決 Erdős 單位距離問題的消息迅速登上 HN 榜首，數學家、AI 研究員與軟體工程師齊聚評論區，討論這個結果的真實意義與 AI 在數學中的角色。
  - **高品質回覆精選：**
    1) **trostaft**（數學博士後）表示這是「相當令人興奮的」成果。他指出，伴隨論文的評註文件相當易讀，證明本身「雖然受到文獻中結果的啟發，但調整是非平凡的」。他同時提出一個重要批評：模型輸出的思維鏈中缺乏對先前數學成果的「歸屬」（attribution），這在數學領域既是社會信用也是知識建構的基礎。他呼籲 LLM 開發者必須讓模型輸出包含完整的文獻引用。
    2) **isotypic**（47 分鐘前的評論，被大量 upvote）強調這不是「機器證明」而是「通用推理模型」的成果——區別在於它不是一個專為數學設計的系統，而是一個廣泛的推理模型在測試 Erdős 問題集合時偶然發現的。這意味著該模型的推理能力具有通用性，而不局限於特定領域。
    3) **trostaft** 進一步指出，雖然他對 AI 取代創意工作者感到「厭惡」，但對科學家而言，這些工具解決了「複雜度爆炸的認知屏障」——由於近期相關進展數量過大，人類越來越難以在腦中維持完整的知識地圖。LLM 在這裡的角色不是取代數學家，而是幫助他們「容納」更多的相關進展。
  - **共識與分歧：** 共識是這確實是一個里程碑——首次有 AI 獨立解決了一個重要數學領域的核心開放問題，且證明經過了人類數學家的嚴格驗證。分歧在於「這是否代表 AI 即將取代數學家」：一派認為這只是「高級模式識別」，另一派（包括 Tim Gowers 和 Noga Alon）則認為模型展現了「原創的、精巧的想法」。更深層的分歧在於「歸屬權」與「可解釋性」——當 AI 產生一個證明時，它是否應該像人類數學家一樣引用先前工作？如果模型無法有意識地進行學術歸屬，那麼「AI 數學家」的社會規範該如何建立？

- **"GitHub confirms breach of 3,800 repos via malicious VSCode extension"**（[HN 連結](https://news.ycombinator.com/item?id=48207660)，501 points / 172 comments）
  - **背景：** GitHub 確認 3,800 個儲存庫因惡意 VS Code 擴充功能而遭入侵，引發對開發者工具供應鏈安全的廣泛討論。
  - **高品質回覆精選：**
    1) **psadauskas** 以諷刺口吻指出：「如果 VS Code 背後的公司、NPM 背後的公司與 GitHub 背後的公司能夠聚在一起想出解決方案就好了。」（這三家公司都是 Microsoft 的子公司或部門。）這條評論獲得了大量 upvote，反映了社群對 Microsoft 內部協調不力的普遍不滿。
    2) **lacker** 回應說這「完美地證明了『Microsoft 組織圖』漫畫的真相」，並貼上 bonkersworld.net 的組織圖對照，暗示 Microsoft 內部各事業群之間的溝通壁壘導致安全漏洞無法被系統性解決。
    3) 多位評論者討論了 VS Code 擴充功能的權限模型。共識是：VS Code 擴充功能預設擁有過高的權限，而安裝流程沒有足夠的風險提示。與手機 App 的權限管理相比，IDE 擴充功能的安全模型明顯落後了一個時代。
  - **共識與分歧：** 共識是這次攻擊凸顯了「開發者工具供應鏈」作為攻擊向量的嚴重性，且 Microsoft 作為 VS Code、NPM 與 GitHub 的擁有者，理應有能力建立更強大的跨產品安全防禦。分歧在於解決方案：一派主張「更嚴格的擴充功能審查與沙盒化」，另一派則認為根本問題是「開發者過度依賴第三方擴充功能」，應該回到最小化安裝的原則。

## 重要工具與框架更新

1. **DeepSeek-V4 預覽版：1M 上下文成為標配，API 與開源權重同步上線**（2026-04-24，近期更新）
   DeepSeek-V4 預覽版提供 Pro 與 Flash 兩個版本，均支援 1M（一百萬 token）上下文長度，這是 DeepSeek 首次將長上下文能力全面普及到所有官方服務。技術上，V4 採用了一種全新的注意力機制，在 token 維度進行壓縮，結合 DSA（DeepSeek Sparse Attention）稀疏注意力，不僅實現了長上下文能力，還大幅降低了計算與顯存需求。

   對開發者而言，API 的遷移非常簡單：只需將 model 參數改為 `deepseek-v4-pro` 或 `deepseek-v4-flash`，base_url 不變。兩個版本均支援「非思考模式」與「思考模式」，後者支援 `reasoning_effort` 參數（high/max）。舊有的 `deepseek-chat` 與 `deepseek-reasoner` 將在三個月後（2026-07-24）停止服務。V4-Pro 的內部評測顯示，在 Agentic Coding 場景中優於 Claude Sonnet 4.5，接近 Opus 4.6 非思考模式。隨著雲端 API 價格持續上漲，DeepSeek 以開源權重 + 極具競爭力的 API 定價提供 1M 上下文，對需要處理長文件、大型程式碼庫或長期對話記憶的應用來說，是一個極具吸引力的替代方案。

## 深度觀點（今日）

今天四條主線——OpenAI 解決 Erdős 猜想、Anthropic 簽下每年 150 億美元的算力租約、DeepSeek 開源 1M 上下文模型、Google I/O 全面轉向 Agent 基礎設施——共同指向一個正在成形的產業格局：AI 的「發現階段」正在結束，「建設階段」正在開始。

OpenAI 模型獨立解決數學問題，是一個比我們此刻能理解的還要深遠的信號。這不是「AlphaGo 打敗棋王」那種封閉規則下的勝利，而是開放領域、原創思維的勝利。Noga Alon 指出，這個證明「以優雅而巧妙的方式，將代數數論中相當精緻的工具應用於一個初等的幾何問題」。換句話說，AI 展現的不是「記住了很多數學然後拼湊出答案」，而是「從一個人類未曾想到的角度切入問題」。這種跨領域的聯想能力，正是創造力的核心定義。然而，HN 上的數學博士後 trostaft 提出了一個銳利的批評：模型的思維鏈缺乏學術歸屬。這不只是一個禮節問題——數學作為一個知識體系，其進步依賴於「誰提出了什麼」的精確記錄。如果 AI 無法有意識地引用前人工作，那麼它產生的知識將如何被整合進人類的知識網絡？這可能是「AI 數學」下一個需要解決的基礎設施問題。

Anthropic 與 SpaceX 的 150 億美元算力協議，則揭示了這場競賽的地下結構。當我們在討論「哪個模型更聰明」時，真正的決定性戰場是「誰能拿到足夠的 GB200」。Tom Brown 公開感謝 Elon Musk 幫 Anthropic 的 Claude「找到好家園」，這種「競爭對手共享基礎設施」的現象非常反直覺，但也非常真實——晶圓廠產能是硬上限，而 xAI、Anthropic、OpenAI 都受同一個上限約束。SpaceX 的 S-1 文件更透露，xAI 的 Grok 5 正在 COLOSSUS II 上訓練，而 Anthropic 每月支付的 12.5 億美元中，部分就是租用同一個叢集的容量。這創造了一個奇特的地緣政治經濟學：AI 實驗室之間的競爭，在某個層面上被「誰能從 NVIDIA 與台積電拿到更多晶片」統一了。而當 Anthropic 願意每年支付 150 億美元只為了「算力租賃」時，我們必須重新評估 frontier AI 的單位經濟學——這不是一個能用「寫得更好提示就能降低成本」的業務，而是一個純粹的資本密集型重工業。

與此同時，DeepSeek 的 V4 預覽版像一面鏡子，照出了這個產業的另一種可能性。當 Anthropic 每年燒 150 億美元租 GPU 時，DeepSeek 用架構創新（DSA 稀疏注意力、token 維度壓縮）讓 1M 上下文在開源模型上成為現實，而且以極具競爭力的價格提供 API。這不是說 DeepSeek 的模型比 Anthropic 或 OpenAI 的更強——V4-Pro 自己也承認與 Opus 4.6 思考模式仍有差距——而是說，在「用聰明的工程降低對硬體的依賴」這條路上，DeepSeek 是目前走得最遠的團隊。對開發者而言，這提供了一個現實的選擇：如果你需要最極致的推理能力，付費使用 frontier 模型；如果你需要處理長文件、大型程式碼庫或構建 agentic 工作流，DeepSeek-V4 的 1M 上下文已經足夠強大，而且成本可能只有 frontier 模型的幾分之一。

最後，Google I/O 的百項發布看似喧囂，實則透露了一個清晰的戰略收斂：Google 不再試圖在「最強單一模型」的競賽中擊敗 OpenAI，而是利用其無與倫比的產品生態系（Gmail、Calendar、Drive、YouTube、Maps、Android）讓 Gemini 成為「無所不在的底層作業系統」。Gemini Spark 作為「個人 AI Agent」的願景，本質上是把 Google 過去二十年累積的用戶數據與產品鎖定，轉化為 AI 時代的護城河。當 OpenAI 和 Anthropic 還在賣 API 時，Google 在賣「AI 原生生活」。這場競爭的終局可能不是「誰的模型在 MMLU 上高兩分」，而是「誰的 agent 能幫你排定下週的會議、回覆重要的電子郵件、並在 YouTube 上找到你真正想看的影片」——然後讓你永遠不想離開這個生態系。

綜合來看，2026 年 5 月的 AI 產業已經分裂為三條平行賽道：第一條是「遞迴式自我改進」的技術軍備競賽（OpenAI 的數學突破、Anthropic 的算力軍備）；第二條是「成本效率與開放性」的民主化運動（DeepSeek 的長上下文開源、Forge 的本地 guardrails）；第三條是「生態系鎖定」的平台戰爭（Google 的 Agent 基礎設施）。這三條賽道不會相互取代，而是會在未來三年內持續交織，最終形成一個分層的產業結構：極少數的 frontier 實驗室生產最強大的模型，大量的開源與本地化解決方案服務中間層，而平台巨頭則把 AI 嵌入每一個消費者接觸的介面。對開發者來說，這意味著「選擇生態系」比「選擇模型」變得更加重要——因為模型的能力正在快速商品化，而整合深度與成本結構才是決定產品成敗的關鍵。
