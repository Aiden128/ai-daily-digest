### 1.1 Claude Code 自 v2.1.181 起已改用 Rust 重寫的 Bun 執行環境,Simon Willison 7/19 透過 `strings` 指令實測確認百萬用戶端都在跑「Bun v1.4.0」與 563 個 `.rs` 檔

[HN 7/19 thread](https://news.ycombinator.com/item?id=48966569) + [Simon Willison 7/19 〈Claude Code uses Bun written in Rust now〉](https://simonwillison.net/2026/Jul/19/claude-code-in-bun-in-rust/) + [Bun 官方 blog 〈Rewriting Bun in Rust〉(Jarred Sumner)](https://bun.com/blog/bun-in-rust)。Simon Willison 7/19 凌晨發表的 link blog 是這個故事的核心:他引用 Bun 創辦人 Jarred Sumner 的官方聲明,**Claude Code v2.1.181(6/17 釋出)起已改用 Rust 重寫的 Bun 執行環境**,Linux 啟動速度提升 10% 但用戶幾乎沒感覺 — 然後 Simon 用兩條指令親自驗證:(1) `strings ~/.local/bin/claude | grep -m1 'Bun v1'` 在他機器上輸出 `Bun v1.4.0 (macOS arm64)`,而 Bun GitHub 上最新 tagged release 是 5/12 的 v1.3.14 — 證明 Claude Code 內嵌的是 v1.4.0 的 canary 預覽版;(2) `strings ~/.local/bin/claude | grep -Eo 'src/[[:alnum:]_./-]+\\.rs'` 列出 563 個 `.rs` 檔名,以 `src/runtime/bake/dev_server/mod.rs`、`src/runtime/bake/production.rs`、`src/bundler/bundle_v2.rs` 開頭,直接證明 Rust port 已經在 production 跑。

具體內容(從 [Simon Willison 7/19 post](https://simonwillison.net/2026/Jul/19/claude-code-in-bun-in-rust/) + [Bun 官方 blog](https://bun.com/blog/bun-in-rust) 完整):**Bun 為什麼要用 Rust 重寫** — Jarred 4 月啟動 Rust port,目標是把 JavaScriptCore 引擎換成 JavaScriptKit + 全部 runtime 改寫,主要驅動力是 4× 啟動速度、減少 Zig 編譯時間(對 contributor 友善)、更安全的 FFI(避免 Zig 對 undefined behavior 的依賴),並為將來的 Bun macOS app / Windows / Linux 跨平台鋪路。**Claude Code 的具體效益** — 啟動快 10%,這對 `claude --print` 短任務的 shell wrapper 用戶特別明顯;記憶體使用更穩定,垃圾回收暫停更短。**HN 討論重點**:(a) 仍有人質疑「**為什麼 TUI 要跑 terminal React + JavaScript**」(HN ID weakfish),引發 「**Anthropic 應該用 native 重寫 CC**」 與 「**它 work + 營收巨大 = 工程上不必重寫**」 的兩派辯論;(b) 多則 top comment 引用 [Anthropic 7/16 〈How Anthropic runs large-scale code migrations with Claude Code〉](https://claude.com/blog/ai-code-migration) 與 [Bun in Rust 7/14 Andrew Kelley "My thoughts on the Bun in Rust rewrite"](https://news.ycombinator.com/item?id=48955960) 連結,指出 **Anthropic 內部已在用 Claude Code 做 Zig-to-Rust / Python-to-TypeScript 的程式遷移實驗**,把 Bun 自己當作第一個 real-world case study。

對開發者的意義:這是 [Anthropic 6/24 Claude Code v2.1.187 skill marketplace](/daily/2026-07-16) + [Claude Code 6/27 v2.1.191 /rewind](/daily/2026-07-15) 之後,**第一個 production-grade 大規模 coding agent runtime migration 公開案例**。對企業 IT 採購:「**Anthropic 不只用 Claude Code 幫別人遷移程式,Claude Code 自己就是用 Claude Code 遷移出來的**」 是 2026 H2 frontier vendor 「**eat your own cooking**」 的具體 state;對 [Charles Azam 7/18 Fable 5 vs GPT-5.6 Sol NP-Hard test](/daily/2026-07-20) 的「**raw task quality**」 加上 「**runtime performance 也是 agent 競爭力一環**」 的 7/19 雙軸 reference。**Hacker News 高分 thread + 大量回覆 + Simon Willison 親自實測** 確認這是 7/19 最大的「**frontier vendor 公開技術細節**」 story。

對 [YK Dojo 7/18 〈Setting up your spare Mac for Claude Code to control〉](/daily/2026-07-20) 的 「**spare Mac 作為 always-on Claude Code runtime**」 路線互補:**Bun Rust port 讓 Claude Code 在 Linux server / Mac mini / CI runner 上啟動更快、memory 更穩**,對企業 IT 「**Claude Code always-on runner on dedicated Mac mini or Linux server**」 的 7/19 new baseline。**對 [Karpathy 2026-02 〈microgpt〉](http://karpathy.github.io/2026/02/12/microgpt/) + [Sebastian Raschka 7/18 〈Controlling Reasoning Effort in LLMs〉](/daily/2026-07-20) 的 「**frontier model + runtime stack 雙軸推進**」**,7/19 Bun in Rust 是 「**runtime 端 first concrete signal**」 對企業 IT 採購 2026 H2 的 「**per-task cost 不只看 model tokens,還看 runtime overhead**」 維度是 new 監控 dimension。

### 1.2 OpenAI Codex 在 7/18 rust-v0.144.6 release 把 GPT-5.6 Sol / Terra / Luna 的 context window 從 372k 縮到 272k,HN 高分 thread 引爆「**這是 cost optimization 還是 quality regression?**」 辯論

Resolve the exact targets with read-only checks when necessary. Do not use $HOME, ~, /, a workspace root, or another broad directory as the target of a recursive or destructive command**」 — 直接對應 [Thibault Sottiaux 7/15 公開的 Codex accidentally deleted home directory bug](https://twitter.com/thsottiaux/status/2077630111499882637),這是 safety fix 跟 context reduction 同一個 release 出現的 7/18 雙重 state。

對開發者的意義:這是 [OpenAI 7/9 GPT-5.6 Sol launch](https://openai.com/index/gpt-5-6/) + [Codex 7/15 #28058 subagent prompt encryption](/daily/2026-07-16) 之後,**第一個 cross-vendor 「**context window 是 product feature 不是 spec**」** 的具體 case。對企業 IT 採購:「**Codex 272k vs Claude Code 1M context 是 frontier model subscription 採購的 7/19 new baseline**」 — [HN ID 48968718](https://news.ycombinator.com/item?id=48965850) 直接寫 「**1M should be table stakes for frontier models at this point for programming**」;但 [HN ID 48971151](https://news.ycombinator.com/item?id=48965850) 反向觀點 「**I force my context size down to 280k on purpose as in my experience your best work is done within the 30-250k range**」,所以 「**1M 是 marketing, 300k 是 sweet spot**」 也是合理 framing。**quadratic attention cost 計算** ([HN ID 48968816](https://news.ycombinator.com/item?id=48965850)) 顯示 372k cost 87% > 272k,意味 **Codex 7/18 的 reduction 是 OpenAI 對 cost-vs-quality 的具體權衡**;對 [Microsoft 7/13 24% PR study](/daily/2026-07-20) 的 「**24% PRs ≠ 24% productivity**」 互補:**Codex 7/18 context reduction 是 vendor 對 「**internal cost optimization 對外 silently 改 user-facing context**」** 的 7/19 first concrete case,對企業 IT 「**vendor 是否能 silent 改 model spec**」 是 2026 H2 subscription 採購 due diligence 的 new 維度。

對 [Charles Azam 7/18 Fable 5 vs GPT-5.6 Sol NP-Hard test](/daily/2026-07-20) 的 「**Fable 5 raw intelligence lead**」 + [7/19 Codex PR #33972 7/18 context reduction] + [Codex 7/18 system prompt 加 destructive action check] 構成 「**OpenAI 7/18 Codex 兩難 trade-off**」 的 7/18-7/19 三方 reference:**raw intelligence 上 Fable 5 仍 lead,但 OpenAI 7/18 透過 「**context reduction + safety prompt 強化**」 把 GPT-5.6 Sol 拉到 「**narrower but safer**」 的 sweet spot**;對企業 IT 「**frontier vendor 在 7/18 同時改 context + safety 是 vendor 對 「**compute cost + production safety**」 雙重 trade-off**」 是 7/19 new baseline。

### 1.5 Anthropic 7/19 Engineering 發表 〈How we contain Claude across products〉 6 個月內 2 個未公開 vulnerability 揭露,「**claude.ai 客製 proxy 是最大單點失敗**」 公開 first concrete case

[Anthropic Engineering 7/19 〈How we contain Claude across products〉](https://www.anthropic.com/engineering/how-we-contain-claude) (HTTP date header: Sun, 19 Jul 2026 20:05:33 GMT) + [Claude Code auto mode reference](https://www.anthropic.com/engineering/claude-code-auto-mode) + [Anthropic Mythos preview security advisory](https://red.anthropic.com/2026/mythos-preview/) + [Anthropic 7/14 Claude Code v2.1.208 release notes](https://github.com/anthropics/claude-code/releases/tag/v2.1.208)。Anthropic 工程團隊 7/19 發表的 〈How we contain Claude across products〉 是 2026 H2 第一份 **production-grade 跨三個 agent 產品 (claude.ai / Claude Code / Claude Cowork) 的安全圍欄 (containment) 公開技術細節**,核心訊息是 「**cap blast radius 不是 supervise 行為,是 supervise 能做什麼**」。

具體內容(從 [Anthropic 7/19 Engineering post](https://www.anthropic.com/engineering/how-we-contain-claude) 完整):**兩種圍欄策略** — (1) **「**supervise via human-in-the-loop**」** — Claude Code 原本用 「**ask permission at each turn**」,但 telemetry 顯示 **用戶 approve 93% 的 permission prompts**,「**approval fatigue**」 是真實的問題;(2) **「**contain via environment**」** — sandboxes / VMs / egress controls,Anthropic 工程師花最多 effort 在這層。**三個產品三個 containment 架構** — (a) **claude.ai**:gVisor container,ephemeral filesystem,per-session isolation,「**blast radius minimal but ceiling 也 minimal**」;(b) **Claude Code**:OS-level sandbox (macOS Seatbelt / Linux bubblewrap),「**reads 允許, writes 在 workspace 內允許, network 預設 deny**」,sandbox 開啟後 permission prompts **降低 84%**;[open-sourced sandbox runtime](https://github.com/anthropic-experimental/sandbox-runtime) 讓 audit 可行;(c) **Claude Cowork**:full VM(Apple Virtualization framework on macOS, HCS on Windows),credentials 留在 host keychain **永遠不進 guest**,agent 「**as an ordinary Linux user, no awareness of being sandboxed**」 — 6 個 isolation mechanisms 中 2 個由 guest kernel 外部 enforce,即使 agent 在 VM 內取得 root 也無法 escape。**未公開 vulnerability 揭露** — (1) 「**Everything before the trust dialog**」 — 2025-2026 收到 3 個 responsible disclosure 報告,攻擊者透過 `.claude/settings.json` 在 「**Do you trust this folder?**」 prompt 出現前讓 project hook 自動執行,fix 是 「**defer parsing until after trust**」;(2) 「**User as injection vector**」 — 2026-02 內部 red-team 25 次重試 **24 次成功 exfiltrate `~/.aws/credentials`** 透過 phishing 讓 user 貼一段 「**routine task**」 prompt,只能靠 environment 層的 egress control 擋,model 層完全失效;**Claude Mythos Preview (2026-04) 因 blast radius 過大不釋出** 是 7/19 公開的 first concrete case。
