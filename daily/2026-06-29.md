### 1.2 DeepSeek 開源 DSpark / DeepSpec：speculative decoding 全棧代碼與 6,000 個 prompt 的訓練資料

- **來源**：[DSpark paper (PDF)](https://github.com/deepseek-ai/DeepSpec/blob/main/DSpark_paper.pdf) / [DeepSpec GitHub](https://github.com/deepseek-ai/DeepSpec) / [HN 682pt](https://news.ycombinator.com/item?id=48696585)

- **深度分析**：HN 討論串中 [DeepSeek continues to not only push the boundaries but also publish these incredible papers explaining how they achieved their gains - something the American labs no longer do unfortunately](https://news.ycombinator.com/item?id=48696585) 點出了一個結構性問題：美國前沿實驗室在 2026 H1 已基本停止發表 frontier inference 細節（OpenAI gpt-oss 細節寥寥、Anthropic 未公開 Claude 訓練配方），但 DeepSeek、Qwen、Kimi 持續以 paper + code + data 的「三件套」形式公開。另一條重要評論：[Qwen 3.6 shipped with working MTP first, and had working MTP in llama.cpp first](https://news.ycombinator.com/item?id=48699605) 指出 DSpark 並非首創——Qwen 3.6 已有 working MTP inference path，且 MTP head 與主模型在同一檔案內、避免 inference engine「焊進」MTP 模組的麻煩。對中國開源生態而言，DeepSpec + Qwen 3.6 共同把 speculative decoding 從「前沿實驗室玩具」變成 llama.cpp / vLLM production-grade 模組。

## 2. Technical Deep Dive

### 2.1 arXiv 2606.27288：Co-Failure Ceiling — 67 個 frontier model 的多模型組合上限

- **論文**：[arXiv 2606.27288](https://arxiv.org/abs/2606.27288) "When Does Combining Language Models Help? A Co-Failure Ceiling on Routing, Voting, and Mixture-of-Agents Across 67 Frontier Models"（6/25 提交）
- **核心發現**：multi-model LLM systems（routing、voting、cascades、fusion、mixture-of-agents）的 gain 被一個 field 很少報導的量 cap 住：對任何「output is one of the member models' answers」的政策，accuracy 最多等於 1 − β，其中 β 是「所有模型在同一 query 上同時答錯」的比率。傳統診斷（平均 pairwise error correlation ρ）無法辨識 β——相同 marginals 與 pairwise correlation 的 error laws 可能有完全不同的 all-wrong 比率。
- **empirical 數字**：在 67 個來自 21 個 provider 的模型上，tetrachoric-calibrated single-factor model **仍然低估**了 all-wrong tail：在開放式數學題上，觀察 β = 0.052、full 67-model Gaussian copula 預測 β = 0.023（**2.5 倍低估**，90% CI 1.7 to 3.4）。在 execution-graded code 上 β = 0.079。意思是即使最佳 multi-model router，理論 gain ceiling 比 pairwise correlation 暗示的要低 2-3 倍。
- **為何重要**：這個 paper 直接質疑了 2026 H1 多模型 ensemble SaaS（如 Marten、Not Diamond、Unify、Composite、BrainTrust）的 marketing。Notion 6/25 採用 Cursor SDK 的 [How Notion used the Cursor SDK](https://cursor.com/blog/notion) 案例（per [6/28 prior digest](daily/2026-06-28)）、GPT-5.6 Sol launch 提到的 Mixture-of-Agents、Anthropic 6/24 mythos 提到的 Project Glasswing——這些「multi-model ensemble 自動選 model」的 framework 都受 β ceiling 限制。對企業架構師：**multi-model routing 的合理投資報酬率上限 ≈ 1 − β_max_in_your_query_distribution**；如果 query distribution 包含高難度 STEM（β 高）就只能期待 5-10% gain，遠小於 vendor marketing 暗示的 20-40%。
- **與本週其他 paper 的搭配**：arXiv 2606.27369 [Reinforcement Learning without Ground-Truth Solutions can Improve LLMs](https://arxiv.org/abs/2606.27369) 指出 RLVR（verifiable rewards RL）不需要 ground-truth answers 也能改進 LLM——這是 Anthropic Mythos launch 提到的 "model is judged by its own verifiable outputs" 路線的理論基礎。arXiv 2606.27287 [Prompt Injection in Automated Résumé Screening with LLMs: Single and Multi-Injection Settings](https://arxiv.org/abs/2606.27287) 從 security 角度證明 LLM 履歷篩選的 multi-injection 攻擊在 production 環境中依然有效（攻擊者可達 60%+ bypass rate）——呼應 1.5 HackMyClaw 的結論：簡單 anti-injection rules 對 opportunistic 攻擊有效，但對有預算的攻擊者無效。

### 2.2 Simon Willison《AI and Liability》+ 6/25 德國 Google AI Overviews 判決：AI 是部署者的代理人

- **來源**：[Simon Willison link blog 6/25](https://simonwillison.net/2026/Jun/25/ai-and-liability) 引用 [Bruce Schneier](https://www.schneier.com/blog/archives/2026/06/ai-and-liability.html) / 原始判決 [the-decoder.com](https://the-decoder.com/landmark-german-ruling-declares-googles-ai-overviews-are-googles-own-words-and-makes-it-liable-for-false-answers/)
- **核心論點**：德國法院近期判決 Google 須為其 AI Overviews 中的錯誤陳述負責——理由是 AI agents 是部署者（deployer）的代理人，應被視同雇員。Schneier 引申：「若公司雇人寫 summary，公司需為 summary 錯誤負責；若允許公司以『AI 比較便宜且免除僱主錯誤責任』為藉口規避責任，會引發企業失序（disastrous incentives for corporate misbehavior）」。
- **對企業採購的衝擊**：這是歐洲法律體系首次明確把 LLM-as-agent 的法律責任歸於 deployer（而非 model provider）。在 US 法律體系，Section 230 仍把 LLM output 視為 third-party content；但歐洲的 product liability directive 2024/2853 已把 AI 系統納入嚴格責任（strict liability）。對在歐營運的 SaaS 企業：採購 LLM API 時，合約中的 indemnity clause 必須涵蓋 deployer-liability；Anthropic、OpenAI 的 standard TOS 並未對 factual-error 損失負責，deployer 需自購 cyber-liability insurance。
- **與 1.4 Mythos 出口禁令的搭配**：Mythos 5 的 GTM 策略核心是「US 國內 trusted cyber-defenders」，其法律框架假設 deployer（US 公司）對 model 行為負責。德國判決把這個假設推進到「deployer even liable for factual errors」——這會讓任何用 LLM 做 customer-facing summary 的公司（搜尋引擎、電商 review summarization、news aggregator）在歐洲暴露於更高的 product-liability 風險。預期 2026 H2 會看到第一批「AI 產品責任險」產品（如 Munich Re、Allianz 已開始接洽 Anthropic/OpenAI 的 enterprise customer）。

### 3.1 workweave/router：production-grade model router，< 50ms 路由，40-70% 成本降幅

- **來源**：[GitHub workweave/router](https://github.com/workweave/router) / [HN Show HN 196pt 6/26](https://news.ycombinator.com/item?id=48688700)
- **核心**：把 model 路由抽成 endpoint-level middleware——把 OpenAI / Anthropic / Google / DeepSeek / Mistral 統一介面，下游代碼零改動，router 根據 prompt 內容自動選最便宜的能完成任務的 model。官方 claim 40-70% 成本降幅，per-prompt 路由延遲 < 50ms。
- **為何重要**：呼應 [6/28 prior digest](daily/2026-06-28) 提到的 2.1「Co-Failure Ceiling」與 1.4「Coding agent provider abstraction」主題。對企業 IT：workweave/router 是 [Notion × Cursor SDK](https://cursor.com/blog/notion)、[OMC v4.15.0 antigravity](https://github.com/Yeachan-Heo/oh-my-claudecode) 之外的第三種「harness layer 標準化」實作。HN 評論 [Smart model routing directly in Claude, Codex and Cursor](https://news.ycombinator.com/item?id=48688700) 指出 workweave 已在 Claude Code / Codex / Cursor 內建整合。對 freelance agent developer：router 是「2 行 config」就能把 Claude Opus 4.8 / Sonnet / Haiku 加上 GPT-5.6 / Gemini Flash / DeepSeek 的混合部署拼起來——預期 2026 H2 會看到 5-10 個類似 workweave 的開源 fork。

- **來源**：[GitHub deepseek-ai/DeepSpec](https://github.com/deepseek-ai/DeepSpec)

## 4. Research Spotlight

### 4.1 arXiv 2606.27288：Co-Failure Ceiling（已在 §2.1 詳述）

- 跨 67 frontier models 的多模型系統理論上限。對 routing / voting / mixture-of-agents 廠商：gain ceiling 1 − β，β 是 all-wrong rate，pairwise correlation 嚴重低估（2.5 倍低估於開放式數學題）。open-ended math β=0.052, execution-graded code β=0.079。
- 與本週主題的 link：Notion × Cursor SDK（多模型 ensemble）與 Mythos 5（多 model 不同 safeguard 切換）都受這個 ceiling 限制。

### 4.2 arXiv 2606.27330：Empowering GUI Agents via Autonomous Experience Exploration and Hindsight Experience

- **論文**：[arXiv 2606.27330](https://arxiv.org/abs/2606.27330)
- **核心**：multimodal web agent 透過 autonomous experience exploration 自動產生 training trajectories，再用 hindsight relabeling 把失敗 trajectories 轉成 successful demonstrations。有效 task planning 是在 GUI 環境（瀏覽器、桌面 app）中操作 agent 的關鍵瓶頸。
- **為何重要**：本週 OMC v4.15.0 antigravity 6/23 加入 antigravity gemini drop-in（per [6/28 prior digest](daily/2026-06-28)）、Copilot CLI v1.0.65 6/24 推出 `copilot skill` subcommand 與 Claude Code 6/24-6/27 `/rewind` + session snapshot（1.6）——這個 paper 從 RL 角度提供「GUI agent 自主探索」理論依據。對企業 IT：GUI agent 是 RPA 2.0 的核心（取代 legacy UiPath / Automation Anywhere），2606.27330 的 hindsight relabeling 讓企業用少量 seed demonstrations 就能 bootstrap 出 production GUI agent。

### 4.3 arXiv 2606.27326：Hallucination in World Models is Predictable and Preventable

- **論文**：[arXiv 2606.27326](https://arxiv.org/abs/2606.27326)
- **核心**：modern generative world models（render realistic action-controllable futures）經常 hallucinate，這些 hallucination **可預測**（有 structured pattern）且 **可預防**（specific interventions during training 即可降低）。
- **為何重要**：對 video diffusion（如 Sora 2 / Veo 3）與 robotics sim2real（NVIDIA Isaac / Cosmos）是直接影響：world model hallucination 會讓 robot 學到錯誤的物理規律。配合 [6/28 prior digest](daily/2026-06-28) 的 NVIDIA Halos Robotics safety 與 Project Fetch Phase Two Opus 18.9× 加速，2026 H2 的 robotics foundation model 競賽核心是「world model that doesn't hallucinate」。
