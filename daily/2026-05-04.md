## arXiv 研究精選 (May 1, 2026)

### AI 系統與推理

**When LLMs Stop Following Steps: A Diagnostic Study of Procedural Execution in Language Models**  
*Sailesh Panda, Pritam Kadasi, Abhishek Upperwal, Mayank Singh*  
[arXiv:2605.00817](http://arxiv.org/abs/2605.00817v1)

這項研究揭示了一個被廣泛忽視的關鍵問題：LLM 在推理基準測試中取得的高分，並不代表它真的忠實執行了使用者指定的步驟。研究者建立了一個診斷性基準測試，讓模型執行簡單的算術程式（如加減乘除），但通過增加程式長度和變數依賴性來控制難度。結果發現，在 14 個模型、55 組資料上，首次回答準確率從 5 步程式的 61% 急力下降至 95 步程式的 20%。更令人擔憂的是，模型的失敗模式包括：遺漏答案、提早結束、初始錯誤後自我修正、執行不完整的追蹤路徑，以及幻覺化額外步驟。這些發現意味著現有基準測試可能高估了模型的實際執行能力，終端答案正確並不能反映模型是否真正按照指示執行每個步驟。對於開發依賴 LLM 執行複雜工作流的應用來說，這是一個重要警訊——我們需要新的評估框架來測量步驟履行率，而不只是最終答案的正確性。

**RunAgent: Interpreting Natural-Language Plans with Constraint-Guided Execution**  
*Arunabh Srivastava, Mohammad A. Khojastepour, Srimat Chakradhar*  
[arXiv:2605.00798](http://arxiv.org/abs/2605.00798v1)

目前 LLM 在執行結構化工作流時仍然不可靠，這是因為自然語言的表達性雖然強大，但缺乏程式設計的確定性。RunAgent 提出了一個多智能體計劃執行平台，核心創新在於將自然語言計劃轉換為具有明確控制構造（如 IF、GOTO、FORALL）的智能體語言。不僅如此，系統還能根據任務描述自主推導出每個步驟的約束條件，並在執行時動態選擇使用 LLM 推理、工具調用或代碼執行（如 Python）。當發現錯誤時，系統還內建了錯誤修正機制。為了控制上下文長度，RunAgent 會過濾執行歷史，只保留與當前步驟相關的資訊。在 Natural-plan 和 SciBench 資料集上的評測顯示，RunAgent 的表現優於基線 LLM 和最先進的 PlanGEN 方法。這項研究展示了如何在保留自然語言便利性的同時，給予 LLM 程式化的執行保證。

**Characterizing the Expressivity of Local Attention in Transformers**  
*Jiaoda Li, Ryan Cotterell*  
[arXiv:2605.00768](http://arxiv.org/abs/2605.00768v1)

Transformer 的全域注意力機制雖然強大，但計算成本是二次方的。局部注意力（local attention）將每個 token 的注意範圍限制在固定窗口內，降低到線性成本，但一個長期以來的謊團是：為什麼局部注意力不僅更快，有時甚至提升了模型品質？這篇論文從認知器表達能力（recognizer expressivity）的角度提供了正式諑明。作者證明，固定精度的全域注意力 Transformer 對應於含有單一過去操作符的線性時序邏輯片段；加入局部注意力後，等於引入了第二個時序操作符，嚴格擴展了可識別的正規語言類別。更重要的是，全域與局部注意力在表達能力上是互補的：兩者不是包含關係，而是各自捕捉了不同類型的語言規律，結合後能夠形成最豐富的片段。實驗在形式語言識別和自然語言建模上都證實了混合全域-局部 Transformer 優於純全域版本。這提供了理論基礎，說明為什麼在實際應用中（如 Longformer、BigBird），局部注意力不只是效率優化，更是能力增強。

### 視覺語言模型

**Persistent Visual Memory: Sustaining Perception for Deep Generation in LVLMs**  
*Siyuan Huang, Xiaoye Qu, Yafu Li, Tong Zhu*  
[arXiv:2605.00814](http://arxiv.org/abs/2605.00814v1)

自迴歸大型視覺語言模型（LVLM）在多模態任務上表現出色，但存在一個根本性的結構問題：「視覺信號稀釋」（Visual Signal Dilution）。當模型生成文字時，文字歷史會不斷累積，這使得注意力的「分配函數」擴大，導致視覺注意力與生成序列長度成反比衰減。簡單說，諈得越多，看圖片越不清楚。為了解決這個問題，論文提出了 Persistent Visual Memory（PVM），一個輕量級的可學習模塊。PVM 作為並行分支插入到 LVLM 的前飯式網路（FFN）旁，建立一個與距離無關的記憶取回路徑，直接提供視覺嵌入向量給注意力機制，從結構上緩解了深度生成中的信號抑制。在 Qwen3-VL 的 4B 和 8B 模型上的實驗顯示，PVM 在只增加極少參數的情況下，顯著提升了需要持續視覺感知的複雜推理任務的準確率。深入分析更發現，PVM 不僅能抵抗長度導致的信號衰減，還能加速內部預測的收斂。這對於需要長序列生成的多模態應用（如長文檔描述、影片理解）具有重要意義。

**Make Your LVLM KV Cache More Lightweight**  
*Xihao Chen, Yangyang Guo, Roger Zimmermann*  
[arXiv:2605.00789](http://arxiv.org/abs/2605.00789v1)

KV Cache 已經是現代大型語言模型推理的標配組件，但直接套用到 LVLM 時引發了嚴重的 GPU 記憶體開銷問題——因為視覺 token 的數量往往遠遠超過文字 token。為此，論文提出了 LightKV，一種利用視覺 token 嵌入之間冗餘性來減少 KV Cache 大小的方法。與僅在視覺空間進行壓縮的先前方法不同，LightKV 的核心創新在於「交叉模態訊息傳遞」：通過文字提示來引導視覺 token 之間的訊息聚合，在 prefill 階段逐步壓縮視覺 token。這種「提示感知」的壓縮策略讓系統能夠根據具體查詢保留相關的視覺資訊，而不是統一地壓縮所有視覺內容。在 8 個開源 LVLM 和 8 個公共基準測試（MME、SeedBench 等）上的評測顯示，LightKV 只需保留 55% 的原始視覺 token，就能（a）將視覺 KV Cache 大小減半；（b）減少達 40% 的計算量；（c）不僅保持了通用性能，還顯著優於現有基準方法。這對於部署 LVLM 到資源受限的環境（如邊緣設備、實時應用）非常重要。

### AI for Science & Engineering

**HyCOP: Hybrid Composition Operators for Interpretable Learning of PDEs**  
*Jinpai Zhao, Nishant Panda, Yen Ting Lin, Eirik Valseth*  
[arXiv:2605.00820](http://arxiv.org/abs/2605.00820v1)

偏微分方程（PDE）是描述物理現象的核心數學工具，從流體力學到材料科學都離不開它。傳統方法通常學習一個單一的神經運算子來映射 PDE 解，但這種「單體式」方法在分布外（OOD）場景表現不佳。HyCOP 提出了一個模組化框架，核心思想是不學習單一映射，而是學習一個「程式政策」——根據狀態統計和區域特徵，決定使用哪些簡單模組（對流、擴散、學習閉合項、邊界處理）以及使用多久。這些模組可以是傳統數值求解器，也可以是學習組件，形成混合代理模型，且可以在任意查詢時間點直接評估，無需自迴歸推理。在多個 PDE 基準測試上，HyCOP 不僅提供了可解釋的解算程式（如「先擴散、再對流」這類清晰的步驟序列），更在 OOD 場景中比單一神經運算子提升了一個量級。此外，由於模組化設計，只需更新字典（如換個邊界條件、增加殘差項）就能實現知識轉移。理論分析更提供了誤差分解，將組合誤差與模組誤差分離，同時作為過程級診斷工具。這對於需要可解釋性的科學計算應用具有重大價值。

**Can Coding Agents Reproduce Findings in Computational Materials Science?**  
*Ziyang Huang, Yi Cao, Ali K. Shargh, Jing Luo*  
[arXiv:2605.00803](http://arxiv.org/abs/2605.00803v1)

LLM 編碼智能體在軟體工程基準測試（如 SWE-bench）上已經取得了令人印象深刻的成績，但一個關鍵問題仍未解答：這些能力能否轉移到計算科學工作流？科學工作流不只需要編碼能力，還需要理解複雜的領域專業知識、操作專門工具鏈，並能夠在科學聲稱的上下文中解釋結果。為了回答這個問題，研究者開發了 AutoMat 基準測試，評估 LLM 智能體在計算材料科學領域復現論文結論的能力。AutoMat 包含三個互相關聯的挑戰：（1）從論文文字中恢復不完整的計算程式；（2）操作專門的材料科學工具鏈；（3）判斷實驗結果是否支持論文聲稱。研究者與材料科學領域專家合作，從真實論文中篩選了一批聲稱來測試智能體。結果顯示，目前最好的設定也只達到 54.1% 的成功率。錯誤分析發現，智能體在必須從論文文字中重建工作流時表現最差，主要失敗原因包括：程式不完整、方法偏離（如用錯誤的模擬參數）、執行脆弱性（如環境配置問題）。這項研究提醒我們，不能簡單地將軟體工程的成功套用到科學計算領域，需要為科學工作流設計專門的智能體框架。

**GeoContra: From Fluent GIS Code to Verifiable Spatial Analysis with Geography-Grounded Repair**  
*Yinhao Xiao, Rongbo Xiao, Yihan Zhang*  
[arXiv:2605.00782](http://arxiv.org/abs/2605.00782v1)

地理資訊系統（GIS）空間分析需要保持座標語義、拓撲關係、單位一致性和地理合理性，但目前基於 LLM 的 GIS 系統雖然能生成流暢的程式碼，卻很少在大規模上強制執行這些地理規則。GeoContra 是一個針對 LLM 生成的 Python GIS 工作流的驗證與修復框架。其核心思想是將每個任務表示為一個「可執行的地理空間契約」，包含自然語言問題、資料結構、坐標參考系統元資料、預期輸出、空間謂詞、拓撲關係、必需操作，以及禁止的捷徑。生成的程式需經歷静態規則檢查、執行時驗證和語意驗證三個階段，發現的違規會被送入一個有界修復迴圈。在 7,079 個真實地理空間任務（覆蓋波士頓地區 15 個區域、9 類任務、11 個開源模型，每個 600 次執行）上的評測顯示，GeoContra 將閉源模型的空間正確率從 47.6% 提升至 77.5%（DeepSeek-V4）和 57.7% 至 81.5%（Kimi-K2.5）。對於 11 個開源模型，平均正確率提升了 26.6%。GeoContra 能夠捕捉負值行旅時間、CRS/欄位結構違規、遺漏的空間謂詞、以及脆弱的輸出類型轉換等問題——這些都是可以執行但地理空間上無效的程式。這項研究展示了如何將「流暢的代碼生成」轉變為「可驗證的空間分析」。

### 應用與安全

**Generating Statistical Charts with Validation-Driven LLM Workflows**  
*Pavlin G. Poličar, Andraž Pevcin, Blaž Zupan*  
[arXiv:2605.00800](http://arxiv.org/abs/2605.00800v1)

從表格資料生成統計圖表看似簡單，但對 LLM 來說卻是一個持續的挑戰。許多錯誤只有在圖表渲染後才會顯現（如軸標簡裁、類別重疊、比例失真），無法從原始資料或代碼中直接偵測。更困難的是，現有的圖表資料集很少提供完整對齊的成果物（可執行代碼、資料集上下文、問答對）。為此，論文提出了一個結構化的 LLM 工作流程，將圖表生成分解為七個步驟：資料集篩選、圖表提案、代碼合成、渲染、驗證驅動的改進、描述生成、以及問答對生成。通過將渲染輸出納入驗證環節，工作流能夠偵測和修正視覺化特定的失敗模式，如可讀性不足或語意不匹配。該工作流將圖表生成視為一個可檢查的過程，而不是一次性的提示到代碼任務。應用於 UCI 資料集後，該流程產生了 1,500 張圖表（來自 74 個資料集，覆蓋 24 種圖表類型）和 30,003 組問答對。評測 16 個多模態 LLM 發現，圖表語法問題已經接近飽和，但數值擷取、比較和推理任務仍然更具挑戰性。這證明該工作流不僅能產生高品質圖表，還能作為診斷性工具研究多模態推理能力。

**When RAG Chatbots Expose Their Backend: An Anonymized Case Study of Privacy and Security Risks in Patient-Facing Medical AI**  
*Alfredo Madrid-García, Miguel Rujas*  
[arXiv:2605.00796](http://arxiv.org/abs/2605.00796v1)

面向患者的醫療 RAG 聊天機器人正在普及，但它們的安全性和隱私保護卻未得到充分關注。這篇論文報告了一個匿名化、非破壞性的安全評估案例。研究者採用雙階段策略：首先使用 Claude Opus 4.6 進行探索性提示測試和結構化的漏洞假設；然後通過 Chrome 開發者工具手動驗證候選發現。結果令人震驚：一個關鍵漏洞是敏感的系統和 RAG 配置資訊竟然通過客戶端-伺服器通訊暴露，而不是僅限於伺服器端。具體來說，普通的瀏覽器檢查就能獲取：系統提示詞、模型和嵌入配置、检索參數、後端端點、API 綶要、資料文件和塊元資料、知識庫內容，以及最近的 1,000 則患者-機器人對話。更糟糕的是，該部署與其隱私聲明相矛盾——包含健康相關查詢的完整對話記錄竟然可以在未經身份驗證的情況下被取回。研究的結論是：嚴重的隱私和安全失敗可以用標準瀏覽器工具發現，無需專業技能或身份驗證；獨立審查應該是部署前的必要條件。此外，研究也提醒我們，商用 LLM 加速了審計過程，但這些協助審計的能力同樣可以被對手利用。

**ML-Bench&Guard: Policy-Grounded Multilingual Safety Benchmark and Guardrail for Large Language Models**  
*Yunhan Zhao, Zhaorun Chen, Xingjun Ma, et al.*  
[arXiv:2605.00689](http://arxiv.org/abs/2605.00689v1)

隨著 LLM 越來越廣泛地部署在跨語言環境中，確保多元文化背景下的安全性成為一個關鍵挑戰。現有的多語言安全基準測試主要依賴泛化的風險分類學（如偏見、歧視、暴力）和機器翻譯，這樣的方法有兩個局限：一是無法對應各地實際的法規和文化差異（比如歐盟的 GDPR、中國的個人資訊保護法）；二是守門人模型被限制在預定義的類別中，無法處理未預見的風險。ML-Bench&Guard 提出了一個基於「政策」的新方法：不再使用固定的風險類別，而是讓守門人模型直接學習與具體政策文件對齊。基準測試包含多個國家/地區的法規和文化實践，評估模型在真實政策框架下的表現。實驗結果顯示，基於政策的方法能夠捕捉到傳統方法遺漏的文化特定風險，且守門人模型能夠隨著政策更新而動態調整，而不是被固定在過時的分類中。這對於需要同時服務多個市場的全球性 AI 產品具有重要意義。

**Themis: Training Robust Multilingual Code Reward Models for Flexible Multi-Criteria Scoring**  
*Indraneil Paul, Goran Glavaš, Iryna Gurevych*  
[arXiv:2605.00754](http://arxiv.org/abs/2605.00754v1)

獎勵模型（Reward Models, RMs）已經成為語言模型後訓練的標配組件，用於政策對齊和測試時擴展。然而，獎勵模型在代碼生成領域的應用相對缺乏研究，現有工作大多只依賴執行反饋（能不能跑）。這種單一標準的獎勵模型限制了後訓練的目標——只能優化功能正確性，而無法考慮代碼風格、可讀性、效率、安全性等多維度。Themis 項目旨在解決這個問題。首先，作者建立了 Themis-CodeRewardBench，一個跨越五個偏好維度（功能正確性、可讀性、效率、安全性、維護性）和八種程式語言的評估基準測試，並測試了 50+ 個獎勵模型。結果發現，現有模型除了功能正確性外在其他維度上表現不佳。為此，作者開發了 Themis-CodePreference，目前最大的開源代碼偏好資料集（超過 35 萬組偏好對），並訓練了 Themis-RM 系列獎勵模型（600M 到 32B 參數）。實驗顯示多標準訓練能夠提升模型在所有維度上的可靠性，且跨語言轉移表現良好。這對於想要用獎勵模型改善代碼品質的團隊來說是一個重要資源。

**Learning How and What to Memorize: Cognition-Inspired Two-Stage Optimization for Evolving Memory**  
*Derong Xu, Shuochen Liu, Pengfei Luo, Pengyue Jia*  
[arXiv:2605.00702](http://arxiv.org/abs/2605.00702v1)

LLM 智能體要實現持續的個性化服務，必須能夠追蹤使用者在長期互動中演變的偏好。然而，受限的上下文窗口阻礙了這稫能力。現有記憶系統主要依賴静態的手工規則（如「提取關鍵信息、定期匯總」），這種方法難以適應個別使用者的動態需求。雖然有研究嘗試用強化學習（RL）來學習記憶更新，但稀疏的結果獎勵提供的監督信號太弱，導致長期優化不穩定。這篇論文受認知神經科學啟發，提出了 MemCoE 框架。記憶結構理論認為，人類大腦的前額葉負責組織和規劃記憶，而海馬回負責快速記錄和回取。MemCoE 模擬這種分工，採用雙階段優化：第一階段「記憶指南誨導」通過對比反饋（視為文字梯度）來優化一個全局記憶組織原則；第二階段「指南對齊的記憶政策優化」使用誘導出的指南來定義結構化的過程獎勵，並執行多輪次的強化學習來學習一個遵循指南的記憶演變政策。在三個個性化記憶基準測試（涵蓋顯性/隱性偏好、不同模型大小和噪聲水平）上的評測顯示，MemCoE 一致性地優於強基線，且具有良好的魯棒性、轉移性和效率。這提供了一個更加動態和智能的記憶管理方法，而不是依賴静態的手工規則。

## AI Coding 趨勢

### Karpathy：「Software 3.0」與 Agentic 拐點
Andrej Karpathy 發布 Sequoia Ascent 2026 爐邊談話摘要 (May 1)，提出多項核心觀點，反映了他對 AI 編碼未來的深層思考：
- **2025 年 12 月是 agentic 拐點**：Karpathy 認為 coding agent 產生的程式碼區塊變得更大、更連貫、更可靠，程式設計師的角色正從「寫程式」轉為「編排 agent」。這不是說程式設計師會消失，而是工作方式的根本轉變——由直接撰寫代碼轉為設計任務、審查 agent 產出、組織多個 agent 協作。
- **Software 3.0**：Karpathy 提出一個新的軟體語境框架。Software 1.0 是人類編寫的硬編碼；Software 2.0 是神經網路用資料訓練出的歐姆犯；Software 3.0 則是上下文視窗成為新的「程式」——LLM 透過提示、工具、範例、記憶與指令來執行運算。這意味著程式的轟動性（volatility）變得更高，因為同樣的任務可能因為提示詞的微小變化而產生不同結果。
- **可驗證性 (Verifiability)**：Karpathy 強調，AI 進步最快的領域都具備自動回饋機制（測試通過/失敗、基準可量測）。編碼是可驗證性最強的領域之一（編譯器告訴你對錯），這也是為什麼 coding agent 的體驗遠優於一般聊天機器人的根本原因。
- **Jagged Intelligence**：能力突增的粗略公式為 `可驗證性 × 訓練注意力 × 資料覆蓋率 × 經濟價值`。這提供了一個理論框架來理解為什麼某些任務（如象棋、數學競賽）AI 進展迅速，而其他任務（如開放式創作、情感陪伴）則較緩慢。

## 深度分析：AI Agent 執行可靠性的挑戰與突破

本週最重要的議題是 AI Agent 的執行可靠性。從 arXiv 上的多篇論文來看，這個領域已經形成了明確的共識：LLM 在將自然語言轉換為確定性行動時仍然面臨困難。

**「程式化執行」的幻覺**  《When LLMs Stop Following Steps》的研究用診斷性的方式揭示了一個令人不安的現實：即使是最先進的模型，在 95 步的簡單算術程式中，首次回答的正確率也只有 20%。更誇張的是，模型的失敗模式包括遺漏答案、提早結束、在初始錯誤後自我修正（但修正得不對）、執行不完整的追蹤路徑，以及幻覺化額外步驟。這意味著什麼？意味著我們目前使用的基準測試（以終端答案正確性為唯一指標）可能高估了模型的實際能力。當我們依賴 LLM 執行金融交易、醫療診斷、工業控制等關鍵任務時，「答案對了但步驟錯了」可能比「答案錯了」更危險——因為前者更難被發現。

**結構化約束 vs. 自然語言彈性**  
RunAgent 的研究揭示了核心問題：人類執行計畫時是目標導向的，每個步驟都有明確的成功標準；但 LLM 在執行結構化工作流時，往往會「偷懒」或「偏離軌道」。研究者提出的解決方案是在自然語言計劃中嵌入結構化約束——這不是讓 LLM 變成程式，而是在彈性與紀律之間尋找平衡。這個思路與 Anthropic 推出的 Claude Opus 4.7 不謀而合：Opus 4.7 的重點之一就是在長時間執行任務中保持一致性。同樣地，OpenAI 的 Symphony 也是同一方向的產物：它不試圖讓單一智能體做所有事，而是讓多個專門化智能體通過明確的協議協作，每個智能體負責一個小而精確的任務。

**從「能做什麼」到「能可靠地做什麼」**  
這些發展並非孤立的技術進步，而是反映了產業對 AI 實用性的普遍焦慮。徟復興興的投資和企業採購之後，市場正在從「能做什麼」轉向「能可靠地做什麼」。對於開發者來說，這意味著現在是開始建立可重複、可測試、可靠的 AI 工作流的最佳時機。這也是為什麼 GeoContra、RunAgent、驗證驅動的圖表生成等研究同時出現的原因——產業正在從「生成流暢的輸出」轉向「生成可驗證的結果」。

**對開發者的啟示**  
結合 Karpathy 的「可驗證性」理論和這些實證研究，我們可以得出一個實際的行動框架：
1. 為 AI 任務設計明確的驗證機制（測試、基準測試、人類審查）
2. 將複雜任務分解為小而可驗證的子任務
3. 不要盲目信任終端答案的正確性，而是檢查執行路徑
4. 使用多 agent 協作而非單一巨型 agent 處理所有事務

這些原則不僅適用於學術研究，也是實際建置 AI 應用時應該遵循的最佳實踐。
