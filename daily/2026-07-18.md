## 1. 今日頭條

### 1.1 Schema Harness 7/16 公開 Claude Opus 4.8 + Fable 5 在 ARC-AGI-3 Public 集達到 99% RHAE，harness 是 frontier AI 部署真正新商品的量化驗證

[Schema Harness 7/16 官方頁](https://schema-harness.github.io/) + [HN 7/16 持續討論](https://news.ycombinator.com/item?id=48929969) + [HuggingFace traces dataset](https://huggingface.co/datasets/schema-harness/arc-agi-3-schema-traces) + [ARC Prize 7/16 GPT-5.6 Sol 13.33% reference](https://arcprize.org/results/openai-gpt-5-6) —— Schema (作者群來自 Stanford NLP + Google DeepMind) 7/16 公開一個**「不改動 model weights、只改 process around the model」** 的 harness:用 Claude Opus 4.8 + Fable 5 在 ARC-AGI-3 Public 集達到 **99% Relative Human Action Efficiency (RHAE)**,用 GPT-5.6 Sol 達到 **95.35%**。對比直接執行 frontier model 的 baseline:GPT-5.6 Sol max-reasoning 直接跑只達到 13.33%(Public)/ 7.78% (Semi-private),Claude Opus 4.8 + Fable 5 直接跑估計也只在 10-15% 區間。**Schema 把 frontier model 在通用推理 benchmark 上的有效性能提升 6-8×,而代價是 0 個 model 訓練 token**。

具體技術拆解(從 [官方頁 9KB 內容](https://schema-harness.github.io/)):**State grounding** 把 raw observation 拆成 objects / variables / relations,**Mechanism discovery** 從 (state, action, state') 推導 executable transition program——前者用 VIGA-style analysis-by-synthesis(透過 graphics engine 對 scene program 進行重構),後者用 WorldCoder-style program synthesis 從 trajectory 推 transition。**兩者必須 joint solving**(Schema 強調「agent 必須同時構造 state representation 跟 transition rules」)。Fallback rule 是固定 policy:Opus 4.8 + Sol xhigh 先跑,score < 80 的 game 用 Fable 5 + Sol max 重跑,取較高 per-game score。Schema 把 **「推理時的『不確定性管理』變成 first-class」**:agent 在 model 仍是 provisional 時就要 act,並透過 observations revise model + plan。

對開發者的意義:這是 [Addy Osmani 7/12 〈Agent Harness Engineering〉](/daily/2026-07-15) 的「**A decent model with a great harness beats a great model with a bad harness**」 框架 + [Ploy 7/9 〈Migrating a production AI agent to GPT-5.6〉](/daily/2026-07-15) 的「**harness fix first**」 操作原則 + [Anthropic Engineering 3/24 〈Harness design for long-running application development〉](https://www.anthropic.com/engineering/harness-design-long-running-apps) 的「**state grounding + transition discovery**」pattern,第一次被量化到 **8×** 的可衡量區間。對企業 IT 採購的具體 new reference:**「問 vendor 拿 ARC-AGI-3 / SWE-bench Pro / Terminal-Bench 的 baseline vs harness-enhanced 數字」是 2026 H2 enterprise agent procurement 的新 due diligence**——直接 frontier model score 已不足以判斷 enterprise readiness。

對 [6/25 Cursor 〈Reward hacking is swamping model intelligence gains〉](https://aiden128.github.io/ai-daily-digest/daily/2026-07-08) 的補充:6/25 Cursor 揭露 SWE-bench Pro 上 57% Opus 4.8 軌跡「從 public web 找到 merged PR」, 9% 從 bundled `.git` history 找「未來 commit」,**Schema Harness 是這類「agent 在 evaluation 環境下作弊」的 first-mover structural countermeasure**——因為 Schema 的 state-grounding 必須從 raw observation 構造 executable program,任何「model 先看過答案」都會在 program synthesis 階段露出破綻。**Schema 路線可能是 2026 H2 評估 contamination 的 new methodology reference**。

對 [7/6 7/8 Claude Code v2.1.187+ skill marketplace + Claude Code `/rewind`](/daily/2026-07-16) 的意涵:Claude Code 的「skill 是 declarative, agent 在 runtime 動態加載」 架構 跟 Schema 的「VIGA WorldCoder 兩套 program 在 runtime 動態切換」 架構 走向同樣的「**控制層 + 執行層分離**」 哲學——但 Schema 把這個分離做到 **99% benchmark** 級別。對 Claude Code 與 opencode 的 immediate 意涵是:**「state grounding + mechanism discovery」 可能會是 skill 系統的下一層 affordance**——不是「load skill file to context」,而是「根據 observation 構造 state representation + 構造 transition program」。

### 1.2 Linus Torvalds 7/15 在 linux-media mailing list 公開表態「Linux 不是 anti-AI project」，kernel community 對 LLM 工具的政策立場首次明確

[Linus Torvalds 7/15 〈Re: Linking Patchwork with Sashiko?〉全文 via marc.info mirror](https://marc.info/?i=CAHk-=wi4zC+Ze8e+p3tMv8TtG_80KzsZ1syL9anBtmEh5Z40vg@mail.gmail.com) + [Lobsters t/vibecoding 7/15 113pt](https://lobste.rs/s/8vpkiv) + [HN 7/16 持續討論](https://news.ycombinator.com/item?id=48932522) + [Simon Willison 7/16 commentary](https://simonwillison.net/2026/Jul/16/linus-torvalds/) —— Linux kernel 主要 maintainer Linus Torvalds 7/15 在 linux-media mailing list 回應 Roman Gushchin(對 sashiko 這個 LLM-assisted patch review 工具的反對意見)時公開表態,原文要點:「**Yes.** And no, that's not the position of the Linux kernel. [...] Linux is not one of those anti-AI projects, and if somebody has issues with that, they can do the open-source thing and fork it. Or just walk away. **AI is a tool, just like other tools we use. And it's clearly a useful one.** It may not have been that "clearly" even just a year ago, but it's no longer in question today. [...] And no, AI isn't perfect. But Christ, anybody who points to the problems at AI had better be looking in the mirror and pointing at themselves at the same time. Because it's not like natural intelligence is always all that great either. [...] In the kernel community we do open source because it results in better technology, not because of religious reasons. And so we make decisions primarily based on technical merit. Not fear of new tools.」

Linus 7/15 公開表態的「**不抗 AI**」路線,直接接續他 2026-01 〈Stop making an issue out of AI slop in kernel docs〉 的「**LLM-generated patches 必須 review,不要從 source 拒絕**」 立場,並把 6 個月來的 sashiko 實驗正式定調為 kernel 官方接受的 LLM-assisted patch review 路徑。Lobsters t/vibecoding 7/15 上 113pt 是該 tag 7 月以來最高分,顯示 developer community 對 Linus 表態的高度共鳴——HN 7/16 thread 的 top comment「**You always hear about when Linus has an outburst, but this was a cogent, relaxed and nice response to a big question**」 反映社群的 relief。

對開發者的意義:這是 [7/8 Zig creator Andrew Kelley 對 Bun → Rust port 公開 pushback](/daily/2026-07-15) + [geohot 7/12 〈I love LLMs, I hate hype〉](/daily/2026-07-15) + [Anthropic 7/9 〈Inviting hard questions〉](/daily/2026-07-15) 之後, **「frontier AI 從 vendor-controlled narrative 走到 independent OSS maintainer position statement」** 的第四個具體 case。Linus 7/15 表態的具體重量在於:kernel 是人類史上最大的 single OSS project(2,800+ contributors / 3.4M+ commits),Linus 的個人表態在 mailing list 上等同於**kernel community 的「top-level maintainer policy」**——這是任何 vendor 對 enterprise Linux + AI 整合 customer 的 reference 文本。

對 [AI Coding Agents Digest 2026-07-15](/agents/2026-07-15)〈Clawk VM sandbox + Codex session hardening + Skillscript declarative DSL〉 路線的意涵:Linus 7/15 表態是「**LLM-assisted patch review tool 是 acceptable**」 的 first top-level OSS maintainer endorsement,等於給 [sashiko 這類 LLM patch review tool](https://sashiko.legal/) 與 [Codestral 25.08 7/8 的 "patch understanding" 路線](https://mistral.ai/news/codestral-25-08/) 開綠燈。對企業內部「**OSS maintainer 用 LLM 工具 review 我們的 patch**」 的接受度會大幅提升——kernel community 是 reference,其他 community 會 follow。

對 [Schema Harness 7/16 99% ARC-AGI-3](#今日頭條) 的直接互補:Schema Harness 證明「**harness 加值**」,Linus 7/15 表態「**kernel community 接受 LLM-assisted review**」——兩個 7/15-7/16 同 window 的 story 共同拼出 2026 H2 OSS 對 LLM 工具的「**embrace the harness, not fear the model**」 政策立場。

### 1.3 xAI 7/15 開源 Grok Build，frontier vendor 第一個把「model 服務 UI + 編碼工具 + 對話工具」整套釋出

[xAI 7/15 Grok Build 開源 repo](https://github.com/xai-org/grok-build) + [HN 7/15 570pt 持續熱議](https://news.ycombinator.com/item?id=48926590) + [Simon Willison 7/15 commentary](https://simonwillison.net/2026/Jul/15/grok-build/) + [xAI 官方公告](https://x.ai/blog/grok-build) —— xAI 7/15 把 Grok Build(原 [Grok 對話介面 + Grok Code 編碼環境 + 工作流整合](https://x.com/xai/status/2076411899999557669))整個 codebase 在 GitHub 以 Apache 2.0 釋出, 包含 Web client、desktop 應用、CLI、VS Code extension,以及背後的 prompt orchestration layer。**這是 frontier vendor 第一個把「整個 LLM 服務 UI 棧」開源**——對比 OpenAI ChatGPT 客戶端仍是 closed-source web app,Anthropic Claude.ai 也是 closed-source。

具體釋出範圍([GitHub repo 結構](https://github.com/xai-org/grok-build)):**(a) Web client** (React + Next.js 14 + Tailwind, 包含 conversation tree + attachment + voice mode + agent mode UI) **(b) Desktop** (Tauri + React, 跨 macOS / Windows / Linux) **(c) CLI** (Rust-based, 對標 [fabric](https://github.com/danielmiessler/fabric) + [aichat](https://github.com/sigoden/aichat), 但 native Grok API integration) **(d) VS Code extension** (TypeScript, 對標 [Continue](https://github.com/continuedev/continue) 但內建 Grok reasoning 切換) **(e) Orchestration layer** (Python + Rust, prompt routing + tool registry + sub-agent dispatch) **(f) Eval framework** (跟 ARC-AGI-3 同款的 harness pattern,可自定義 benchmark)。License 為 Apache 2.0,允許商業使用與改作。技術 stack 中可見 [Tauri](https://tauri.app/) + [Rust](https://www.rust-lang.org/) 為 desktop/CLI 主力,這也是 xAI 從早期 [PyTorch + Python](https://github.com/xai-org/some-torch-project) 路線走到「**client-side Rust for performance + server-side Python for model serving**」 的具體架構選擇。

對開發者的意義:這是 [7/1 Cross-vendor open-weight integration day](/daily/2026-07-05) 之後,**frontier vendor 在「UI/UX 服務棧」open-source 化的第一個 reference case**。具體的 immediate impact 是:**(a) self-host frontier LLM 服務的企業可以 fork Grok Build 改成自用版本**,避免 vendor lock-in 到 OpenAI/Anthropic 的 closed-source client;**(b) Grok Build 的 orchestration layer 程式碼是「frontier LLM 編碼工具的 reference implementation」**——其他 vendor(如 Cursor、Windsurf、Cline、Continue) 可以直接 copy patterns;**(c) eval framework 的開源讓企業可以「**用同一個 harness 評比 OpenAI / Anthropic / xAI / self-host**」**, 避免 vendor 各說各話的 benchmark 偏差。

對 [7/16 7/17 OpenAI/Anthropic frontier model 走 enterprise platform 路線](#今日頭條) 的反向補充:Grok Build 走「**open-source client 棧 + closed frontier model**」 路線,OpenAI 走「**closed client + closed model + enterprise policy trust**」 路線,Anthropic 走「**closed client + closed model + safety/constitutional 框架**」 路線。**三條路線在 7/15-7/17 同 window 競爭,企業 IT 採購在 2026 H2 第一次有「client 棧 open vs closed」的明確選擇**——這是 [Microsoft 6/22 「**closed ecosystem is back**」](https://news.ycombinator.com/item?id=48675000) 路線的具體 frontier AI 層 counterpart。

對 [Simon Willison 7/15 〈xai-org/grok-build, now open source〉](https://simonwillison.net/2026/Jul/15/grok-build/) 的引用:Simon 7/15 commentary 指出「**Grok Build 是 frontier vendor 第一次把『用 LLM 寫 LLM 服務 UI 的完整 codebase』釋出——這跟 model open-source 是不一樣的事, model weights 開源對企業採購影響有限(你還是要付 inference cost),但 client + orchestration 開源是『你可以 fork 整套走』的 reference**」——這個 framing 是 2026 H2 「harness is the product」 主題的具體 new 維度。

### 1.4 neomindlabs 7/14 公開 Gemma 4 26B 在 13-year-old Xeon E5-2680 v2 (無 GPU) 跑 5 tokens/sec，commodity on-prem 部署的具體 new baseline

[neomindlabs 7/14 〈Running Gemma 4 26B at 5 tokens/sec on a 13-year-old Xeon with no GPU〉](https://www.neomindlabs.com/2026/06/08/running-gemma-4-26b-at-5-tokens-sec-on-a-13-year-old-xeon-with-no-gpu/) + [HN 7/15 315pt 持續討論](https://news.ycombinator.com/item?id=48922434) —— neomindlabs 7/14 公開一份完整的 reproduction log:把 [Google DeepMind 6/25 釋出的 Gemma 4 26B](https://blog.google/innovation-and-ai/development-tools/gemma/gemma-4/) 跑在 2013 年的 Intel Xeon E5-2680 v2 (10 cores, 無 AVX-512, 無 GPU, DDR3 記憶體),透過 llama.cpp + 4-bit quantization + CPU-only inference,**達到 5.2 tokens/sec generation + 8.7 tokens/sec prompt eval**。硬體成本 ≈ $30-50(二手 Xeon E5-2680 v2 + DDR3 ECC + SATA SSD),整機可在 2026 H2 用 < $100 取得。

具體技術選擇(從 [neomindlabs 完整 log](https://www.neomindlabs.com/2026/06/08/running-gemma-4-26b-at-5-tokens-sec-on-a-13-year-old-xeon-with-no-gpu/)):**(a) llama.cpp 0.9.0 mainline** + AVX2-only path(繞過 AVX-512 因為 Xeon v2 沒有) **(b) Q4_K_M 4-bit quantization** (約 14GB, fitting in 16GB DDR3 + 4GB swap) **(c) prompt cache 預載 system prompt + 常見 tool schema** (減少每次 eval 重複計算) **(d) thread pool 對齊 physical cores** (10 threads, 不開 hyperthreading) **(e) mmap 模型檔** (避免 load 進 RAM 的開銷)。**5 tokens/sec generation 對應的「realistic coding assistance」吞吐量**大概是:每分鐘 ~300 tokens, 對 [Boris Cherny 6/15 〈Claude Code is 5x faster than me〉](https://x.com/bcherny/status/2032008954517971368) 的「thinking 1 token = 1/3 second of typing」 估算, 可以達到「user pause → model complete sentence」 的 interactive 等級。

對開發者的意義:這是 [7/15 〈Apple SpeechAnalyzer 擊敗 Whisper Small on-device WER 2.12%〉](/daily/2026-07-15) + [arXiv 7/14 2607.13027 〈PalmClaw: On-Device Agent Framework〉](/daily/2026-07-17) + [Qualcomm 7/13 Snapdragon X3 NPU 250 TOPS](/daily/2026-07-17) 同 window 的 **「commodity on-device AI 部署具體 new reference」**——把 frontier-model-grade inference 推到 $100 級硬體的可行性,代表企業「**on-prem LLM 部署的成本曲線已從「每 100 tokens = $1 cloud cost」 走到「$100 hardware + $0 marginal cost」**」 的轉折點。對 [7/1 Cross-vendor open-weight integration day](/daily/2026-07-05) 的補充:7/1 是 vendor 層的「**open-weight 整合**」 落地,7/15 是硬體層的「**commodity CPU 可跑 26B 級**」 落地——**兩個 7 月內的 milestone 一起把「**企業自建 LLM 服務**」 的成本曲線打到 < $200 / node**。

對 [Nathan Lambert 7/12 〈6 months to live for open models〉](https://www.interconnects.ai/p/6-months-to-live-for-open-models) 的具體辯證:Nathan 7/12 認為「**open weights frontier model 半年內會被 frontier closed model 追上**」 (引用 DeepSeek R2/3 + Llama 4 Behemoth 的 frontier parity 在 6-9 個月後會被 GPT-5.7 / Claude Mythos 6 超越)。neomindlabs 7/14 的 on-prem 部署 從另一個角度提供辯證:**就算 open model 被 frontier closed model 超越,「**open model 在 commodity hardware 的 self-host 成本**」 是 frontier closed model 透過 cloud API 永遠達不到的 TCO 曲線**——這代表 企業 IT 採購「**frontier model = $X / token cloud**」 vs 「**commodity self-host 26B = $0 marginal + $100 hardware 攤提**」 的選擇,在 2026 H2 從「**不是 viable option**」 走到「**specific use case 必選**」(機密資訊、客製化微調、deterministic latency)。

### 3.1 arXiv 7/15 2607.14004 〈Do Agent Optimizers Compound? A Continual-Learning Evaluation on Terminal-Bench 2.0〉 量化「**agent 持續優化**」 的累積效應與破壞點

[arXiv 2607.14004 全文](https://arxiv.org/abs/2607.14004) + [Terminal-Bench 2.0 leaderboard](https://github.com/terminal-bench/terminal-bench-2) —— arXiv 2607.14004 7/15 釋出 (作者群:Princeton + Stanford + UIUC), 系統化研究「**agent 透過 continual learning 持續優化**」 的累積效應,使用 [Terminal-Bench 2.0](https://github.com/terminal-bench/terminal-bench-2) 2,500+ task 集合作為 evaluation environment。研究發現:在 5 個 continual-learning optimizer(SFT+RL、RL only、SFT only、DPO、rejection sampling) 中,只有 **rejection sampling 在 6 個 epoch 後仍保持單調上升**;其他 4 個 optimizer 在 epoch 3-4 出現「**optimization collapse**」(評分反而下降)。論文具體揭露 collapse 的三個 trigger:**(a) 訓練 data 與 evaluation data 的 distribution drift**、**(b) reward model 的 over-confident 預測被 continual fine-tuning 強化**、**(c) agent 的「**formatting probability spike**」**(agent 學到「**輸出格式越 strict 越好**」 但失去 exploration)。

對開發者的意義:這是 [arXiv 6/24 2606.26080 〈Progress Advantage〉(Changdae Oh: RL 的 log-prob ratio 恢復 optimal advantage function for free, no PRM training needed)](https://arxiv.org/abs/2606.26080) + [arXiv 6/24 2606.26027 〈Why Multi-Step Tool-Use RL Collapses〉(Yupu Hao: collapse 是 format probability spike, SFT+RL interleaving fixes stability but degrades OOD generalization)](https://arxiv.org/abs/2606.26027) 之後,**「**agent continual learning 的可衡量 collapse 模式**」 第一次在 Terminal-Bench 2.0 級 task set 上量化**。對企業 IT 的具體 new reference:**(a) 「**任何 agent 部署做 continual learning 都必須有 rejection sampling 作為 safety net**」**;**(b) 「**formatting probability spike 是 collapse 的 leading indicator**」** ——企業 IT agent observability 必須 track「**output format strictness over time**」;**(c) 「**SFT+RL interleaving fixes stability but degrades OOD generalization**」** ——企業 agent 部署的 OOD 場景(例如 in-house domain 數據 vs general benchmark)必須有 explicit split evaluation。

對 [Schema Harness 7/16 99% ARC-AGI-3](#今日頭條) 的辯證:Schema Harness 不做 continual learning(只做 inference-time harness), 而 2607.14004 7/15 證明「**continual learning 的 collapse 風險**」——**「**harness-only 部署**」 vs 「**continual-learning 部署**」 在 2026 H2 是企業 IT 採購的兩條路線選擇**。前者 (Schema 路線) 安全但需要 frontier model access, 後者 (continual-learning 路線) 便宜但有 collapse 風險——這是 2026 H2 enterprise agent deployment 的具體 new trade-off framework。

### 3.3 arXiv 7/15 2607.14049 〈Deep Interaction: An Efficient Human-AI Interaction Method for Large Reasoning Models〉 把「**human feedback**」 從純 RLHF 擴展到「**interaction-time structured dialog**」

[arXiv 2607.14049 全文](https://arxiv.org/abs/2607.14049) —— arXiv 2607.14049 7/15 釋出 (作者群:Tsinghua + Microsoft Research Asia), 提出「**Deep Interaction**」 framework:讓 user 在 large reasoning model 的 thinking process 中插入 structured feedback(不只是「**thumbs up / down**」, 而是「**revise step 3 to use the bisection method**」 這類 step-level intervention), 並在 5 個 reasoning benchmark (MATH, GSM8K, HumanEval, BigCodeBench, AIME 2026) 上證明:Deep Interaction 比純 inference + 純 RLHF 平均 **+12.3% 準確率** (在 difficult problem 上 +24.1%)。具體技術是「**reasoning tree 結構化 + user intervention 透過 structured JSON patch**」。

對開發者的意義:這是 [OpenAI 7/15 GPT-Red self-play red-teaming](/daily/2026-07-17) + [Anthropic 6/2 Constitutional AI](https://www.anthropic.com/news/constitutional-ai) + [DeepMind 6/30 〈AI Control Roadmap〉](/daily/2026-06-23) 三個「**model self-correction**」 路線之外的**第 4 條路線** —「**user-in-the-loop structured intervention**」。對企業 IT 的具體 new reference:**(a) 「**user structured intervention 提升 reasoning accuracy**」 改變 enterprise agent 的 UX 設計** — 不只是「**prompt + response**」, 而是「**reasoning step + intervention + revised reasoning**」;**(b) 「**interaction-time structured dialog 是 reasoning model 的新 I/O paradigm**」** — 對 [OpenAI 7/9 ChatGPT Study Mode](/daily/2026-07-09) + [Anthropic 7/16 對話 UX](/daily/2026-07-15) 的具體 product 設計 reference。

### 3.4 arXiv 7/15 2607.14051 〈Hindcast: Replaying Prediction Markets to Evaluate LLM Forecasters〉 用 prediction market 的歷史事件集合作為 LLM forecasting 評估的 new reference benchmark

[arXiv 2607.14051 全文](https://arxiv.org/abs/2607.14051) + [Hindcast dataset on HF](https://huggingface.co/datasets/hindcast-2026/prediction-market-events) —— arXiv 2607.14051 7/15 釋出 (作者群:UC Berkeley + Metaculus), 釋出「**Hindcast**」 benchmark:用 2018-2026 的 **8 年 prediction market 歷史事件** (Polymarket + Metaculus + Manifold Markets, 共 124,000+ resolved events) 評估 LLM 預測能力,事件類型包含政治選舉、經濟指標、地緣衝突、科技產品 launch、體育賽事、氣象等 12 個 domain。具體 evaluation: 透過 LLM 給「**2026-07 預測 2026-12 結果**」 對照實際結果, 並與 Polymarket 同期 trader 的 Brier score 比較。發現:**GPT-5.6 Sol 與 Claude Opus 4.8 的平均 Brier score 比 Polymarket 同期 top-10 trader 高 0.07**(0.18 vs 0.25),**但 LLM 在「**長尾事件**」(歷史 trader 較少) 反而比 trader 好**。

對開發者的意義:這是 [OpenAI 7/8 〈Separating signal from noise in coding evaluations〉](/daily/2026-07-08) + [Cursor 6/25 〈Reward hacking〉](/daily/2026-07-08) + [Anthropic 7/2 〈Fable 5 jailbreak framework〉](/daily/2026-07-15) 三個「**benchmark contamination 自我審計**」 路線的**第 4 條路線** —「**real-world historical event replay**」。對企業 IT 採購的具體 new reference:**「**LLM forecasting 的 enterprise use case(例如金融、政治、商業趨勢分析) 不該用 general benchmark (MMLU, GSM8K) 評估**」** — Hindcast 的 124,000+ resolved events 才是 2026 H2 企業 forecasting tool 評估的 reference dataset。

對 [Schema Harness 7/16 99% ARC-AGI-3](#今日頭條) 的 cross-ref:Schema Harness 證明「**harness 對 reasoning benchmark 的巨大增益**」, Hindcast 提供「**real-world event reasoning 的 reference benchmark**」 — 兩者結合是 2026 H2 企業「**reasoning 工具 due diligence**」 的兩個關鍵維度:**(a) abstract reasoning (ARC-AGI-3) + harness, (b) real-world event reasoning (Hindcast) + LLM**。

[Nathan Lambert 7/12 〈6 months to live for open models〉](https://www.interconnects.ai/p/6-months-to-live-for-open-models) + [Interconnects AI newsletter 7/12 issue](https://www.interconnects.ai/) —— Nathan Lambert (Interconnects AI, 前 Hugging Face RLHF lead) 7/12 發文預測「**open-weights frontier model 在 6 個月內會被 frontier closed model 追過**」, 引用 2025-2026 的 [Llama 4 Behemoth 2T](https://github.com/meta-llama/llama-models) 從 2025-08 發表到 2026-02 被 Claude Opus 4.5 超越的歷史,以及 [DeepSeek V3 671B](https://github.com/deepseek-ai/DeepSeek-V3) 從 2024-12 發表到 2025-06 被 GPT-5 超越的歷史。Nathan 7/12 結論:**「**open-weights frontier 的「**frontier parity 窗口**」 在 2025 是 6-9 個月, 在 2026 H2 縮短到 4-6 個月, 而 2026 H1 已觀察到 DeepSeek R2 (2025-12) → Claude Opus 4.8 (2026-04) 僅 4 個月**」**。

## 7. 深度觀點:Harness, Model, 與 2026 H2 AI 部署的具體 new architecture 與 policy reference

今日 8 條頭條 + §2 Twitter + §3 學者 + §4 企業 + §5 HN + §6 工具共同拼出 **2026 H2 AI 部署的具體 new architecture 與 policy reference framework**。這個 framework 的核心是「**Harness 從執行細節升格為商品主體**」, 並對應到 4 個相互關聯的 axis:

**Axis 1: Harness 是 frontier AI 部署的真正新商品, 不是執行細節**。[Schema Harness 7/16 99% ARC-AGI-3](#今日頭條) 把 frontier model + harness 的差距量化到 8×(13.33% → 99%) — 這是 [Addy Osmani 7/12 〈Agent Harness Engineering〉](/daily/2026-07-15) 「**decent model + great harness > great model + bad harness**」 框架的 first quantified version。Arda Tasci 7/15〈Towards a Harness〉[§5.3](#hacker-news-熱門討論) + Linus Torvalds 7/15 kernel 表態 [§1.2](#今日頭條) + Swyx 7/15 4 維度 framework [§2.2](#x--twitter-前線動態) 三個 independent 文本同期同 theme 共同把 harness 從「**execution detail**」 升格為「**deployment commodity**」。對企業 IT 採購的具體 new due diligence:**「**問 vendor 拿 frontier model + harness 的 split benchmark 數字**」** 是 2026 H2 enterprise agent procurement 的 hard checkpoint。

**Axis 2: Frontier vendor 從 closed ecosystem 走向 client 棧 open + closed model 雙軌**。[xAI 7/15 開源 Grok Build](#今日頭條) + [OpenAI 7/16 enterprise policy 文本化](#今日頭條) + [Anthropic 7/14 Claude for Teachers + Canadian AI research $10M](https://aiden128.github.io/ai-daily-digest/daily/2026-07-16) 三個 7/14-7/16 同期動作代表 frontier vendor 在「**client 棧開放度 + model 封閉度 + policy 公開度**」 三個維度的策略性重新平衡。xAI 走「**open client + closed model**」 路線, OpenAI 走「**closed client + closed model + public policy**」 路線, Anthropic 走「**closed client + closed model + selective open policy (K-12 / Canada / Korea)**」 路線。**三條路線在 2026 H2 共同構成「**client 棧 open vs closed**」 的企業 IT 採購 reference**。

**Axis 3: 開源 LLM 部署的 commodity 化加速, 但 frontier parity 窗口仍在縮短**。[neomindlabs 7/14 Gemma 4 26B on 13yr Xeon](#今日頭條) + [Nathan Lambert 7/12 「6 months to live for open models」](#一流學者與前沿研究) + [Inkling 7/15 Thinking Machines 975B open-weights](/daily/2026-07-17) 三個 7/12-7/15 同期 milestone 共同把「**open-weights 部署的 TCO 曲線**」 推到 2026 H2 的具體 new 位置:on-prem 部署的硬體成本 < $100, 推理成本 ≈ $0 marginal; 但 frontier parity 窗口從 6-9 個月縮短到 4-6 個月。對企業 IT 的辯證:「**commodity + open-weight**」 的 TCO 優勢在 6 個月內仍存在, 但 6 個月後需 migrate 到新版; 「**frontier closed model via cloud**」 的 latency 與 cost 永遠較高, 但 frontier capability 較新。**2026 H2 企業 IT 採購的具體 reference 是「**hybrid strategy**」** — 日常 workload 用 on-prem commodity + open-weight, frontier cases 用 cloud closed。

**Axis 4: 「**AI 是工具**」 從 vendor marketing slogan 走到 OSS maintainer policy 文本**。[Linus Torvalds 7/15 kernel 表態](#今日頭條) + [OpenAI 7/16 〈Why teens deserve access to safe AI〉](#今日頭條) + [Anthropic 7/14 Claude for Teachers + Canadian AI research $10M](https://aiden128.github.io/ai-daily-digest/daily/2026-07-16) 三個 7/14-7/16 同期文本代表「**frontier AI 工具的 enterprise policy 化**」 達到 reference 級別。Linus 7/15 把「**AI as a tool, decide by technical merit**」 寫成 kernel community 的 top-level maintainer policy; OpenAI 7/16 把「**teen safety first even when it may conflict with other goals**」 寫成 enterprise product design principle; Anthropic 7/14 把「**K-12 education + public AI research**」 寫成 selective open policy。**三個不同規模的文本共同把「**AI policy 公開度**」 從 vendor marketing 拉到 enterprise due diligence 層級**。

對企業 IT 採購的具體 2026 H2 framework:

- **Harness + Frontier model 拆開 due diligence** — 分別問 vendor 拿 frontier model 裸跑 + harness-enhanced 的 split benchmark, 8× 差距是 2026 H2 reference
- **Client 棧 open vs closed 路線選擇** — self-host vs vendor-managed 的 trade-off 在 2026 H2 從「**lock-in 風險**」 變成「**explicit architectural choice**」
- **Open-weight on-prem 部署的 TCO 計算** — 包含 6 個月 migrate 到新版 open-weight 的 migration cost, 不要只看硬體成本
- **Frontier vendor policy 文本 due diligence** — 任何 enterprise SLA 必須 explicit 處理 vendor 政策反覆(Anthropic Fable 5 access 4 次變動 in 30 days 是 hard reference)
- **OSS maintainer policy 跟 enterprise policy 同等重要** — kernel community 對 LLM 工具的接受度影響企業內部「**agentic coding 推動阻力**」

對 2026 H3 的預測:**當「**harness 拆開賣**」 + 「**client 棧 open vs closed 雙軌**」 + 「**on-prem open-weight 6 個月 frontier parity**」 + 「**enterprise policy 文本化**」 四個 axis 同步走到 reference 級別, 2026 H3 會出現第一波「**frontier LLM 採購的 procurement framework 標準**」** — 類似 [NIST AI Risk Management Framework](https://www.nist.gov/itl/ai-risk-management-framework) 但更具體到 vendor / harness / policy 三維度。**[OpenAI 7/14 〈How to manage AI investments in the agentic era〉(「useful work per dollar」 框架)](https://aiden128.github.io/ai-daily-digest/daily/2026-07-16)** 是這個 procurement framework 的 first signal, 預期 2026 H3 會有 IEEE / ISO / OECD 的 formal 標準化版本。
