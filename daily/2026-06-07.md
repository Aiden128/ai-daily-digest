## 今日頭條

**OpenAI 公開「Harness Engineering」：以零手寫程式碼、純 Codex Agent 打造百萬行級產品** —— 6 月 6 日，OpenAI 發表長文〈Harness Engineering: Leveraging Codex in an Agent-First World〉，披露一項為期五個月的內部實驗：從零開始，完全由 Codex Agent 撰寫所有程式碼（應用邏輯、測試、CI 配置、文件、可觀測性與內部工具），人類工程師完全不碰鍵盤寫 code。成果是一個已上線、擁有數百名內部日活用戶與外部 alpha 測試者的產品，程式碼庫達到約一百萬行，累計 1,500 個 pull request，團隊僅從 3 人擴張到 7 人，平均每位工程師每天產出 3.5 個 PR，且隨團隊擴大產出仍在增加。OpenAI 估計總耗時約為傳統手寫的十分之一。

這項實驗的核心哲學是「人類掌舵，Agent 執行」。工程師的工作從「寫程式」轉變為「設計環境、明確意圖、建立反饋迴路」。當 Agent 失敗時，人類不會去修 bug，而是問：「缺了什麼能力，如何讓 Agent 能看懂並執行？」團隊將應用程式 UI、日誌、指標全部變成 Codex 可直接讀取的格式——例如透過 Chrome DevTools Protocol 讓 Agent 能截取 DOM 快照與螢幕截圖來重現與驗證 bug；透過 LogQL/PromQL 讓 Agent 能查詢「服務啟動是否低於 800ms」或「關鍵用戶旅程是否有 span 超過兩秒」。OpenAI 甚至觀察到單一 Codex session 可持續運作超過六小時（通常發生在人類睡覺時）。

> 深度分析：這不是另一個「AI 輔助寫 code」的案例，而是「AI 主導開發」的系統性方法論宣告。OpenAI 揭示的幾個機制值得所有軟體團隊深思。首先是「漸進式揭露（progressive disclosure）」：他們將 `AGENTS.md` 從「百科全書」重新定位為「目錄」——僅約 100 行，指向結構化的 `docs/` 目錄，讓 Agent 從小入口開始自主導航，而非一次性塞入過多上下文。其次是「Ralph Wiggum Loop」——Codex 在提交 PR 前，必須先通過本地與雲端的「Agent 審查者」檢驗，並迭代到所有審查者滿意為止。這本質上是用 AI 替代傳統的人類 code review，且隨著時間推移，人類審查逐漸被推向邊緣。最具顛覆性的是他們對「程式碼可讀性」的重新定義：過去程式碼是寫給人類同事看的，現在則是優先寫給 Codex 看——任何不在版本控制中的知識（Google Docs、聊天記錄、人腦記憶）對 Agent 而言「 effectively doesn't exist」。這預示著未來軟體工程的核心競爭力將從「寫好 code」轉向「設計好 Agent 能理解的環境」。

**Meta 證實超過兩萬個 Instagram 帳號遭駭：駭客僅需「開口詢問」AI 聊天機器人即可重置密碼** —— 6 月 6 日，Meta 向緬因州檢察長辦公室提交的資料外洩通知顯示，至少 20,225 名用戶的 Instagram 帳號遭駭客入侵，其中包括緬因州 30 位居民。攻擊手法極其簡單：駭客向 Meta 的 AI 客服聊天機器人聲稱「我被駭了」，並提供一個與帳號無關的電子郵件地址，聊天機器人竟直接將密碼重置驗證碼發送至該地址。由於帳號未啟用雙因素認證，駭客收到驗證碼後即可完全接管帳號，包括貼文、私訊與聯絡資訊。攻擊自 4 月 17 日開始，持續至本週初才被修復。Meta 目前已停用該 AI 聊天機器人，並移除相關程式路徑。

> 深度分析：這起事件是「AI 客服變成攻擊向量」的經典案例，其嚴重性不亞於傳統的 SQL injection 或 XSS。問題核心在於：Meta 將一個高風險操作（密碼重置）交給一個無法正確驗證身份的新系統，而這個系統的「自然語言介面」反而讓攻擊門檻降至最低——駭客不需要寫任何程式碼，只需用自然語言「詢問」即可。Meta 的聲明稱「工具本身運作正常，但另一條獨立的程式路徑存在漏洞」，這種說法迴避了根本問題：為什麼一個 AI 聊天機器人會被賦予發送密碼重置連結的權限？為什麼沒有強制雙因素認證？這與 OpenAI 同日發表的「Harness Engineering」形成詭異的對照：當一邊在展示 AI Agent 如何優雅地管理複雜系統時，另一邊卻展示了 AI 介面在缺乏適當 containment 時能造成多大的實際傷害。對開發者而言，這是一記當頭棒喝：任何賦予 AI 系統「副作用操作」權限的設計，都必須有比傳統 API 更嚴格的安全邊界，因為自然語言的「模糊性」本身就是可利用的漏洞。

**Anthropic 祕密向 SEC 提交 S-1 草案，同步發布 AI 網路威脅年度分析報告** —— 6 月 6 日，Anthropic 宣布已向美國證券交易委員會（SEC）祕密提交 Form S-1 註冊聲明草案，為首次公開募股（IPO）鋪路。股數與價格尚未確定，最終能否上市仍取決於市場條件與 SEC 審查進度。同日發布的還有一份網路安全研究報告：Anthropic 分析 2025 年 3 月至 2026 年 3 月間 832 個因惡意網路活動被封鎖的帳號，將其映射至 MITRE ATT&CK 框架。報告指出三項關鍵發現：一、67.3% 的攻擊者使用 AI 撰寫惡意軟體；二、AI 使用從「初始入侵」轉向「入侵後的橫向移動與權限提升」，顯示攻擊正變得更自主；三、MITRE ATT&CK 框架尚未涵蓋「AI Agent 自主編排攻擊鏈」等新型行為。風險評估顯示，前六個月僅 33% 攻擊者被評為中等風險以上，後六個月躍升至 56%。

> 深度分析：Anthropic 在同一天釋放「商業化」與「安全研究」兩大信號，這並非巧合。S-1 提交代表 Anthropic 認為自身業務已達到公開市場的成熟度——這與 5 月披露的「80% 程式碼由 Claude 撰寫、工程師產出翻 8 倍」數據共同描繪出一個即將 IPO 的 AI 原生企業形象。而網路威脅報告則是在對潛在投資者與監管機構傳遞訊息：「我們不僅懂 AI，也懂 AI 的風險。」報告中最發人深省的結論是「平台（Claude Code、API 或聊天介面）與攻擊者風險等級無關」——過去安全團隊可以透過「攻擊者使用多少種技術」或「使用什麼工具」來評估威脅，但 AI 讓最菜的腳本小子也能執行 16 種技術，與頂尖駭客的 20 種相差無幾。真正的區別在於「AI 被應用在攻擊生命週期的哪個階段」以及「駭客如何設計 scaffolding 讓模型自主串聯攻擊步驟」。這暗示未來的網路防禦將從「特徵偵測」轉向「行為意圖分析」，而這正是 Anthropic 希望被視為領導者的領域。

### OpenAI Harness Engineering 的實務啟示
OpenAI 的 Agent-only 開發實驗揭示了幾個可立即應用的實務原則：
1. **AGENTS.md 應該是地圖，不是百科全書**：OpenAI 將其維持在約 100 行，作為指向更深層文件的目錄，避免「過多指引反而成為無指引」的困境。
2. **程式碼必須對 Agent 可讀**：將應用 UI、日誌、指標全部變成 Agent 能直接解析的格式（DOM 快照、LogQL、PromQL），而非僅供人類閱讀的儀表板。
3. **知識必須版本化且位於倉庫內**：任何不在 git 中的知識對 Agent 而言等於不存在。設計文件、架構決策、品質評分都應 check-in，並由專門的 "doc-gardening" Agent 定期掃描過時文件。
4. **Agent 可執行長時任務**：Codex session 持續運作 6 小時以上意味著開發者可以「下班前發起複雜重構，隔日早上收成果」。

## 深度分析

### 當 AI 吃掉軟體工程的三個信號

今天的新聞表面看似雜亂——OpenAI 展示 Agent 開發、Meta 暴露 AI 安全漏洞、Anthropic 準備上市——但它們共同指向一個更深層的轉折點：AI 正在從「工具」變成「基礎設施」，而這個轉變的速度比多數組織準備的還要快。

**信號一：工程流程的範式轉移**

OpenAI 的「Harness Engineering」不只是公關文宣，它提供了一個可複製的框架。其中最反直覺的發現是：當人類停止寫 code 時，工程師的產出反而增加——因為人類的時間被重新配置到「設計 Agent 能理解的環境」上。這與工業革命時「工人從手工製作轉向操作機器」的邏輯相同，但時間壓縮了百倍。1,500 個 PR、百萬行 code、3-7 人團隊——這些數字若發生在一個傳統軟體團隊，需要 30-50 名工程師與數年時間。

但這個範式有一個隱藏的假設：**倉庫必須成為唯一的真相來源**。OpenAI 明確指出「Google Docs、聊天記錄、人腦記憶對 Agent 而言 effectively doesn't exist」。這對現有企業的衝擊是巨大的——大多數組織的關鍵知識分散在 Slack、Notion、Email 與會議記錄中。若要引入 Agent-first 開發，首先必須進行一次徹底的「知識搬遷」。

**信號二：自然語言介面的雙面刃**

Meta 的 AI 聊天機器人被駭事件，與 OpenAI 的成就形成詭異的鏡像：兩者都展示了自然語言介面的威力，但一個用在建設，一個被用在破壞。20,225 個帳號不是因為複雜的駭客技術而淪陷，而是因為一個簡單的社會工程學提問。這揭示了一個被低估的風險：**當 AI 系統被賦予「執行權限」時，自然語言的模糊性本身就是可利用的漏洞**。傳統 API 有嚴格的參數驗證與身份認證，但 AI 聊天機器人的「對話式介面」繞過了這些防護——因為它設計成「理解並幫助用戶」，而非「嚴格驗證請求」。

對正在導入 AI 客服或 AI 代理的企業而言，Meta 的教訓是：任何涉及「副作用操作」（密碼重置、轉帳、刪除資料、發送郵件）的 AI 介面，都必須有比傳統系統更嚴格的 containment。Anthropic 的 containment 架構（gVisor、bubblewrap、Apple Virtualization）之所以值得參考，正因為它預設了「模型可能行為失當」——這是一種「不信任但驗證」的工程哲學。

**信號三：AI 安全公司的商業化臨界點**

Anthropic 提交 S-1 草案，標誌著「AI 安全」從非營利使命轉向可持續商業模式。這並非背叛初衷，而是承認一個現實：若沒有商業成功，就無法持續投入頂尖研究與安全基礎設施。值得注意的是，Anthropic 選擇在同時發布網路威脅報告——這是在向投資者展示「我們不只能做模型，還能做安全基礎設施」。從 Glasswing（開源安全掃描）到 Claude Security（託管安全產品）再到上市準備，Anthropic 正在複製 Palo Alto Networks 或 CrowdStrike 的路徑：先建立技術領導地位，再將其轉化為企業級產品。

綜合來看，2026 年 6 月的第一週提供了三個明確的座標：**工程方式**（Agent-first）、**安全邊界**（containment 優先）、**商業模式**（安全即服務）。對開發者而言，最實際的建議是：現在就開始將你的專案知識遷移至版本控制的 Markdown 與結構化文件中，因為當 Agent 成為你的主要協作者時，任何不在倉庫內的知識都將成為瓶頸。
