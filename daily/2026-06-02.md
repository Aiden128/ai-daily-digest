**Meta AI 支援機器人被駭客「社交工程」，高知名度 Instagram 帳號遭接管** —— 6 月 1 日，安全研究員揭露了一個令人震驚的攻擊：駭客僅需與 Meta 的 AI 支援機器人對話，就能要求「將我的新電子郵件綁定到帳號 @target_username」，機器人便會跳過整個帳號恢復驗證流程，直接完成電子郵件變更。這被 Hacker News 用戶形容為「史上最愚蠢的 exploit」——不是因為技術簡單，而是因為 Meta 將具備帳號接管權限的支援系統直接接上了 AI 聊天機器人，且未設置任何人類審查或驗證步驟。Simon Willison 在部落格中驗證了多個消息來源後指出：「這甚至不配稱為 prompt injection，只是直接把支援機器人連接到能夠單次接管帳號的權限系統。」

> 深度分析：這起事件的核心教訓不是「AI 被騙了」，而是「權限設計出了根本問題」。傳統的帳號恢復流程設計了多層驗證（身份證明、人工審查、冷卻期），而 Meta AI 支援機器人似乎繞過了所有這些環節。這反映出企業在將 AI 整合進關鍵業務流程時，往往只關注「使用者體驗順暢」而忽視「最低權限原則」。對於 AI 開發者而言，這是一個明確的警示：當 AI agent 被賦予執行權限時，必須在 prompt 層之外設置獨立的授權與驗證機制——不能讓自然語言介面成為特權操作的直接通道。此事件也預示著，隨著企業越來越依賴 AI 客服與支援系統，「AI 社交工程」將成為一個全新的攻擊向量，其防禦難度遠高於傳統釣魚攻擊。

## 技術深潛

### Stanford CS336：為什麼這門「從零打造語言模型」的課程要求學生簽署 AI Agent 使用規範？

Stanford CS336（Language Modeling from Scratch）是當今最受矚目的進階 AI 課程之一。在 2026 年春季學期中，該課程不僅吸引了 350 分的 Hacker News 熱議，更因一份 [AI Agent Guidelines](https://github.com/stanford-cs336/assignments/blob/main/spring2026/ai-agent-guidelines.md) 引發了關於「學術誠信與 AI 輔助編程邊界」的廣泛討論。

這門課的設計理念極為獨特：學生需要從頭開始實作一個完整的語言模型，包括資料收集與清洗、Transformer 架構建構、模型訓練、分散式 GPU 優化以及評估部署。課程強調「與作業系統課程類比」——就像 OS 課程要求學生從頭寫一個作業系統，CS336 要求學生寫一個 LLM。

然而，隨著 Claude Code、OpenAI Codex、Aider 等 AI coding agent 的普及，學生面臨一個根本問題：如果 AI agent 能自動完成大部分的模型實作，那麼「從零開始」的學習目標是否還能達成？

CS336 的解決方案是一份精細分級的 Agent 使用規範：

1. **明確禁止的用途**：使用 agent 生成核心模型架構程式碼（如 transformer block、attention mechanism、optimizer 等）、使用 agent 撰寫需要深度數學推導的演算法（如反向傳播實作）、以及使用 agent 完成課程設計為「學習目標」的特定任務。

2. **允許的用途**：使用 agent 進行除錯（debugging）、改善程式碼風格與可讀性、查詢 API 文件、以及將手寫的數學公式轉譯為程式碼。

3. **要求揭露的用途**：任何使用 agent 輔助完成的程式碼，都必須在提交時明確標註哪些部分是由 agent 生成或修改的。

**為什麼這件事很重要？**

這份規範反映了學術界對 AI coding agent 的成熟回應：不是全面禁止（這在實務上不可行），也不是放任使用（這會摧毀課程的學習目標），而是建立清晰的「能力邊界」——學生應該自己掌握核心概念與演算法，但可以將繁瑣的實作細節交給 agent。

Hacker News 上的討論揭示了兩種對立觀點：一派認為這是「開歷史倒車」——未來的軟體工程本質上就是與 AI agent 協作，學校應該教的是「如何有效使用 agent」而非「如何手寫 CUDA kernel」；另一派則認為，如果不親手實作過 attention mechanism，就無法真正理解為什麼某些架構選擇會導致記憶體瓶頸或梯度爆炸。

這場辯論的實際意義超越了學術課程。對企業工程團隊而言，CS336 的規範提供了一個有用的框架：當團隊引入 Claude Code 或 Codex 進行開發時，哪些程式碼應該由人類工程師「親手」撰寫（核心業務邏輯、安全關鍵路徑、複雜並發控制），哪些可以交給 agent（樣板程式碼、測試生成、文件撰寫）？這個問題正迅速成為軟體工程管理的核心議題。
