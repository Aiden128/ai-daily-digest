# AI Agents Digest - 2026-05-29

## 今日頭條

### Claude Code v2.1.154 發布：動態工作流程與背景 Agent Shell 重塑終端開發流程

Anthropic 在長假週末前推出 Claude Code v2.1.154，這是近兩週最重要的終端更新。核心亮點是「動態工作流程」（dynamic workflows）正式上線，用戶只需輸入 `/workflows`，Claude 即會即時撰寫協調腳本，並啟動數十到數百個背景 agent 協同處理跨越多檔案、多模組的大型任務。Boris Cherny 在 X 上說，這是他們「幾個月前就建置好的功能，已經慢慢成為 Anthropic 內部開發的核心流程」。

技術實現上，這套系統採用了從「單一 agent 輪詢」到「分幣式任務排程」的架構：Claude 會先分析任務範圍，自動切割工作單元，然後透過背景 session 啟動子 agent，最後匯總結果。這意味著終端開發者不再需要手動啟動多個 tmux pane 或 zellij tab 來跟蹤各個子任務。v2.1.154 同時將「精簡系統提示」設為所有模型的預設（除 Haiku、Sonnet 及 Opus 4.7 以前版本外），直接減少每次輪詢的 token 消耗，對長期使用者的成本控制意義重大。新版還讓背景 agent 支持 `! <command>` 快速執行 shell 指令，用戶可以 `claude --bg --exec '<command>'` 被動啟動，完成後自動切換，這讓終端環境的多工作流协調變得更像傳統的 Unix job control。

### OpenAI Codex CLI v0.135.0 終端體驗大幅提升：Vim 模式、SQLite 記憶體與 Zellij 相容性修復

OpenAI 同步發布 Codex CLI v0.135.0，此版本雖然沒有重大模型更新，但對終端用戶的使用體驗做了大量細節改善。最吸引人的是 Vim 模式新增了「文字物件」（text object）編輯能力，以及可配置的中斷輮次快速鍵，這讓長期在終端使用 Codex 的 Vim 用戶終於能用一套統一的指令在 TUI 與編輯器之間切換，不再需要接受“不完整的 Vim 實現”。

技術底層方面，記憶體（memory）運行時狀態從純文字檔案遷移到專用 SQLite 資料庫，這不僅提升了資料一致性與交易安全性，也為未來更複雜的持久化上下文管理奠定基礎。此外，之前在 tmux 與 iTerm 控制模式下 `Ctrl-C` 失靈的問題已被修正，Zellij 中原始輸出會覆蓋 TUI composer 的 bug 也已解決。這些看似小修復，對於把 Codex 作為日常終端開發工具的用戶而言，是決定「能不能長期留在終端」的關鍵。新增的 `codex doctor` 指令則能一次性診斷環境、Git、終端、app-server 與線程庫存狀態，減少了排錯時的猜測工作。

### Claude Code v2.1.156 修補版發布：协助 Opus 4.8 穩定上線

緊接在 v2.1.154 之後，Anthropic 推出 v2.1.156 修補版，專門修復 Opus 4.8 在特定情境下因 thinking blocks 被修改而導致 API 400 錯誤的問題。這個追速修補顯示 Anthropic 在前沿模型與終端工具之間的協調週期已經非常紧密——模型更新後的 24 小時內就有配套工具修補。對依賴 Opus 4.8 處理高負荷任務的終端用戶來說，建議盡快升級到 v2.1.156 以上版本，避免在背景 agent 執行長任務時遇到中斷。

## 核心工具更新

- **Claude Code v2.1.154** (2026-05-28) — [GitHub Releases](https://github.com/anthropics/claude-code/releases/tag/v2.1.154)
  - **更新內容：** 除了動態工作流程與精簡提示預設化外，這版還調整了 `/simplify` 指令，從「完整代碼審查」改為「清理專用審查」，只做重構、簡化、效率提升與抽象層級調整，不做 bug hunting。`/effort` 滑桿的標籤從「Speed/Intelligence」改為「Faster/Smarter」，更直觀。
  - **技術細節：** `claude agents` 呼叫新增 `! <command>` 背景 shell 執行功能，以及 `claude --bg --exec '<command>'` 呼叫方式。背景 session 分類器也修復了在排定的 `/command` 觸發時可能遺失用戶目標的 bug，並解決了背景 agent 繞過 worktree 隔離守衛、寫入共用 checkout 的安全漏洞。
  - **終端實際影響：** 終端用戶現在可以讓 Claude 同時處理數十個檔案，不用自己管理多個 tmux/zellij pane。`/simplify` 變成輕量級重構，適合日常保持代碼健康。
  - **模型建議：** Opus 4.8 已成為預設高努力模式，建議在複雜終端任務上使用 `/effort xhigh`。Fast mode 價格降為標準費率的 2 倍，速度提升 2.5 倍，對需要快速反饋的交互式編輯更具價值。

- **OpenAI Codex CLI v0.135.0** (2026-05-28) — [GitHub Releases](https://github.com/openai/codex/releases/tag/rust-v0.135.0)
  - **更新內容：** 新增 `codex doctor` 診斷指令、Vim 文字物件編輯、命名權限配置檔、打包 zsh helper，以及 TUI markdown 表格與多行清單的排版改善。
  - **技術細節：** 記憶體狀態遷移至 SQLite，提升了交易安全性。`​--listen` HTTP 服務器的 body 累積從 O(n²) 修復為正常複雜度，解決了大請求導致的阻塞。老版 tmux/iTerm 控制模式下的 `Ctrl-C` 失靈問題已修正。
  - **終端實際影響：** Vim 用戶終於能在 Codex TUI 中使用 `diw`、`ci)` 等文字物件指令。`codex doctor` 讓排錯變得像診所一樣系統化。Zellij 用戶不會再看到 TUI 被終端輸出覆蓋。
  - **模型建議：** 本版為純粹工具更新，模型本身未變，但建議配合 GPT-5.x 系列模型使用。

- **Claude Code v2.1.156** (2026-05-29) — [GitHub Releases](https://github.com/anthropics/claude-code/releases/tag/v2.1.156)
  - **更新內容：** 修復了使用 Opus 4.8 時，thinking blocks 被修改導致 API 400 錯誤的問題。

- **fzf v0.73.1** (2026-05-25) — [GitHub Releases](https://github.com/junegunn/fzf/releases/tag/v0.73.1)
  - **更新內容：** 修復了兩個稀見但嚴重的 bug：當 `$FZF_CURRENT_ITEM` 包含 NUL byte 時，`exec(2)` 會拒絕該環境變數，導致預覽和其他子命令失敗；以及 `--listen` HTTP body 累積是 O(n²) 的問題，單一個 390KB 請求就能阻塞單線程服務器約 8 秒。
  - **終端實際影響：** fzf 常被整合進終端 agent 的代碼庫探索與文件選擇 workflow 中（例如透過 pipe 傳遞檔案列表讓 fzf 篩選）。NUL byte 修復确保了當檔案名包含稀有字元時不會整個 workflow 異常中斷。HTTP body 的 O(n²) 修復則讓使用 fzf 作為遠端搜索引擎前端的佈局更穩定。

## 技巧與優化

- **背景 agent 的 Shell 快速執行技巧：** Claude Code v2.1.154 新增的 `! <command>` 是終端用戶不容錯過的功能。之前要在背景執行 shell 命令，需要先 `claude --bg` 啟動一個獨立 session，然後手動切換。現在只需在任何對話中輸入 `! make test`，系統就會自動啟動背景 agent 執行，完成後回傳結果，不影響當前工作。對於習慣在 Vim 或 Emacs 中不斷切換終端執行測試的開發者，這簡化了 workflow。

- **Codex TUI 的 Vim 文字物件編輯：** 在 Codex v0.135.0 中，Vim 模式不再是「半成品」。現在支持 `diw`（刪除單字）、`ci)`（變更括號內文字）、`dap`（刪除整個段落）等標準文字物件指令。建議終端 Vim 用戶在 `~/.codex/config` 中確認 `vim_mode = true`，並熟悉新增的中斷輮次快速鍵配置，這樣在 TUI 中修改代碼時就能保持手指記憶一致。

## 深度觀點：終端 Agent 正從「單一工具」進化為「分布式協調平台」

今日的所有動態都指向一個共同趨勢：終端 coding agent 不再滿足於「幫你寫一個函式」或「修一個 bug」，它們正在進化為能夠協調數十到數百個實體的「分布式任務平台」。Claude Code 的動態工作流程是最明顯的例證：以前開發者需要自己在 tmux 中切割工作、手動分配任務，現在 Claude 自己就是任務排程器。同時，背景 agent 的壯大（`! <command>` 和 `claude --bg --exec`）讓終端的多工作流管理變得更像 Unix job control 而不是 GUI 的模擬。

另一個值得注意的趨勢是「終端先」（terminal-first）的設計理念。Codex 在本版中修復了諸多舊版終端模擬器（tmux、iTerm、Zellij）的兼容性問題，並為 Vim 用戶完善文字物件支援。這說明 OpenAI 將 Codex 視為「終端原生應用」而非「雲端 IDE 的附屬品」。當終端工具的穩定性、反應速度和可編程性都達到甚高水準時，開發者會發現他們不需要離開命令列就能完成絕大部分工作——這就是為什麼 fzf、lazygit 這類終端原生工具的每一個穩定性修復都值得關注。
