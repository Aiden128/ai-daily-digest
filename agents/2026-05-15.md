# AI Agents Digest - 2026-05-15

## 今日頭條

- **Claude Code v2.1.142 發布：引入「/review」指令，AI 驅動的代碼審查進入終端**（May 15）— [GitHub Releases](https://github.com/anthropics/claude-code/releases/tag/v2.1.142)
  - Claude Code 最新版本新增了 `/review` 指令，允許 Agent 對當前 git diff 進行結構化審查。與傳統的靜態分析工具不同，Claude 的審查不僅檢查語法和風格，還會分析「設計意圖」——例如，它會指出「這個變更似乎違反了項目中的 Repository 模式慣例，建議將數據訪問邏輯移到 DAO 層」。
  - 技術上，`/review` 利用了 Claude 4 的長上下文能力（500K tokens），可以一次性分析包含數百個文件變更的大型 PR。審查報告分為三個嚴重等級：「阻擋」（必須修復的安全或正確性問題）、「警告」（可能導致維護困難的設計問題）、「建議」（可選的優化或風格調整）。每個問題都附帶具體的代碼引用和修復建議。
  - 對於團隊中缺乏資深工程師審查資源的小型公司，這是一個革命性功能。它相當於為每個 PR 自動配備了一個「24/7 在線的 Staff Engineer」。當然，AI 審查不能替代人類的最終把關，但它可以顯著減少「明顯問題漏到生產環境」的情況。

- **Windsurf 推出「Cascade」：多 Agent 並行編輯的 IDE**（May 14）— [Windsurf Blog](https://codeium.com/blog/cascade)
  - Windsurf（由 Codeium 開發的 AI IDE）發布了 Cascade 功能，允許同時運行多個 Agent 並行處理不同任務。例如，你可以啟動一個 Agent 重構前端組件，同時讓另一個 Agent 優化後端 API，兩者獨立運行但共享一個「衝突檢測層」——當兩個 Agent 試圖修改同一個文件時，系統會自動暫停其中一個並通知你決策。
  - Cascade 的技術創新在於「Agent 隔離」：每個 Agent 運行在自己的「虛擬工作區」中，擁有獨立的文件系統視圖。只有在用戶確認「合併」後，Agent 的修改才會寫入真實文件系統。這種設計允許「實驗性編輯」——你可以讓三個 Agent 嘗試三種不同的重構方案，然後選擇最好的一個。

## 工具與框架

- **codex-v0.2 發布：支持本地模型與自定義 system prompt**（May 15）— [npm](https://www.npmjs.com/package/@openai/codex/v/0.2.0)
  - OpenAI 的 Codex CLI 在開源後迅速迭代到 v0.2，新增了 `--model` 參數支持任意 OpenAI-compatible endpoint（包括 Ollama、vLLM、TGI 等本地推理服務），以及 `--system-prompt` 參數允許用戶覆蓋默認的 Agent 行為指令。這對於希望在企業內網部署 Codex 的用戶至關重要。

- **Roo Code v1.15：基於 VS Code 的開源 Claude Code 替代方案**（May 15）— [GitHub](https://github.com/RooVetGit/Roo-Code/releases/tag/v1.15.0)
  - Roo Code 是一個 VS Code 插件，旨在複製 Claude Code 的核心體驗但完全開源。v1.15 新增了「Plan/Act」雙模式：Plan 模式下 Agent 只生成修改計劃但不執行，Act 模式下則執行計劃。這種分離讓開發者可以在「放手」之前先審查 Agent 的意圖。

## 深度觀點

今日 Agent 生態的兩個重磅更新——Claude Code 的 `/review` 和 Windsurf 的 Cascade——分別代表了 AI 在軟體開發中的兩個新角色：「審查者」和「並行工作者」。

`/review` 的意義在於，AI 開始進入軟體工程的「質量閘門」環節。過去，AI 主要負責「生產」（寫代碼），而人類負責「審查」（代碼審查、測試、部署）。這種分工有一個隱含的假設：AI 生成的代碼需要人類檢查。但當 AI 也可以擔任審查者時，這個分工開始模糊。未來的 workflow 可能是「AI 寫、AI 審、人類抽樣」——人類不再需要逐行審查每個 PR，而是審查 AI 審查報告的質量。

Cascade 的意義則在於，AI 開始從「單線程」轉向「多線程」。人類開發者已經習慣了多任務並行（一邊寫前端一邊想後端），但過去的 AI Agent 因為架構限制只能順序執行。Cascade 的「虛擬工作區」設計讓多個 Agent 可以真正並行工作，這相當於為開發者提供了「AI 線程池」——你可以同時啟動 5 個 Agent 處理 5 個不同文件，效率提升不是線性的，而是指數性的。

這兩個趨勢的結合，預示著一個「AI 原生軟體工程」時代的到來：在這個時代中，AI 不僅僅是輔助工具，而是開發團隊中的平等成員——它們可以寫代碼、審代碼、並行工作，而人類的角色逐漸轉向「架構師」和「質量仲裁者」。
