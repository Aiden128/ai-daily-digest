## 今日頭條

**〈The Coming Loop〉——Armin Ronacher 把「harness 寫手 / model 變 commodity」這條 2026 H2 主線講清楚了（Lobsters vibecoding 16pt / practices 16pt，15 則留言，5 則長文回應）** —— 6/23 Ronacher 發表 [lucumr.pocoo.org/2026/6/23/the-coming-loop](https://lucumr.pocoo.org/2026/6/23/the-coming-loop/)（他是 Flask / Jinja2 / Click / Werkzeug 的原作者，目前在 Sentry）。文章開頭引用 Anthropic 的 Boris Cherny：

> 「I don't prompt Claude anymore. I have loops running that prompt Claude and figuring out what to do. My job is to write loops.」

Ronacher 的核心論點是——**coding agent 內部已經有一個 loop（model → tool → result → model），但「harness 層的 loop」才是 2026 H2 的真正位移**。Harness loop 把任務丟進 queue、agent 嘗試、停下來、由另一個 agent 判斷「是否真的結束了」——如果沒結束就 inject 新訊息、換 session、或交給另一台機器。**任務在 model 自己會說「我結束了」之後還活著**。他把這個 pattern 與 6/17 開始的 Twitter 風潮（[ghuntley.com/ralph/](https://ghuntley.com/ralph/) 也是這條線）和 Pi 最近的「Boris loop」現象連結起來。

**Ronacher 對「present-day models 的程式碼品味」的批評是全文最尖銳的段落**：

> 「Present-day models tend to produce code that is too defensive, too complex, too local in its reasoning. They avoid strong invariants. They add fallbacks instead of making bad states impossible. They duplicate code, invent bad abstractions, and paper over unclear design with more machinery. Worse though: I so far see very little progress of this improving. If anything, on that front it feels to me that we might even be making steps in the wrong direction. At least for my taste, present-day hands-off harnesses like Claude Code with ultracode produce worse code than what we were producing last autumn. That's because Claude Code, with Fable for instance will be working uninterrupted on a problem for thirty minutes or more, when previously the process would have been much more human in the loop.」

他引用 [Karpathy 9/15「mortally terrified of exceptions」](https://x.com/karpathy/status/1976082963382272334)——模型傾向在觀察到 local failure 時加一層 local defense，**而不是把 malformed case 變成 unrepresentable**。**當這個行為放進 loop 之後會被放大**：每個 iteration 加一層小防禦，系統慢慢變得不可理解、看起來更 robust。Ronacher 的兩個關鍵警告：

1. **Loops 對程式碼「有保固期」的任務特別有效**（port、性能探索、security scan、研究探索），對「需要長期被人理解」的核心基礎設施程式碼則是災難。Bun 把部分程式碼從 Zig port 到 Rust（[ziggit 6/22 討論](https://ziggit.dev/t/bun-is-being-ported-from-zig-to-rust/15330)）、他自己用 Claude Code 把 [MiniJinja port 到 Go](https://lucumr.pocoo.org/2026/1/14/minijinja-go-port/) 都是成功案例——但這些是「mechanical translation」，沒有 longevity 要求。
2. **You Cannot Quite Opt Out**：即使你不寫 loop，攻擊者會跑 loop 來打你的系統（[Daniel Stenberg 6/15 curl summer of bliss](https://daniel.haxx.se/blog/2026/06/15/curl-summer-of-bliss/) 已經是經典 example），**defender 終究也要 loop**。競爭壓力也是——某些團隊用 5 個人做到以前 50 個人的事。

**對終端開發者的實務影響：**
1. **「Harness 才是產品」已經是 2026 H2 業界共識**：這與 Anthropic 6/16 [〈Agentic coding and persistent returns to expertise〉](https://www.anthropic.com/research/claude-code-expertise) 報告（4 萬個 session / 23.5 萬人分析）結論互補——Anthropic 數據顯示「Claude Code 對 expert 是槓桿、對 novice 反而拖累」，與 Ronacher 警告的「junior 用 hands-off harness 會學到壞習慣」互相印證
2. **OMC v4.15.0（6/23）的 antigravity provider + Cursor provider（v4.14.7）正是這條主線的工程實踐**——把「哪個 model 在 loop 裡跑」做成 pluggable
3. **Gensee Crate（[GenseeAI/gensee-crate](https://github.com/GenseeAI/gensee-crate) 33★ / 3 天）做的是「loop 過程中的 enforcement」**——這是 Ronacher 沒講但必然會發生的下一層：長時程 loop 必須有 policy layer 才能避免「per-iteration local defense 累積成不可理解系統」
4. **個人 dev**：Ronacher 文章最值得帶走的金句是「I so far see very little progress of this improving」——**不要期待 model 把品味修好，要自己設計 loop 結構讓品味問題暴露**（Pi 的 cautious 路徑是 Ronacher 認可的設計）

- **VScod**e 修正 large session resume 時 extension unresponsive

**v2.1.190**（6/24）只有一條「Bug fixes and reliability improvements」，但 release date 顯示 Anthropic 仍在密集修補 v2.1.187 引入的 edge case。

**對終端開發者的實務影響：**
1. **`sandbox.credentials` 是 v2.1.187 最被低估的 enterprise feature**——過去企業 IT 阻擋 Claude Code 進入 corp dev VM 是因為「agent 跑 `cat ~/.aws/credentials`」無法防範，現在有 first-class 防線

4. **v2.1.186 的 `claude mcp login --no-browser`**（SSH session 用）+ 這版 `sandbox.credentials` + org model restriction，**這三項組合是企業 IT 第一次能在「不開瀏覽器、不洩漏 secret、限制 model」三條線都過的 Claude Code 配置**

**arXiv 2606.24820 SHERLOC 達 SWE-Bench Lite 84.33% accuracy@1——無 fine-tuning 的純 reasoning + 結構化工具 framework** —— [SHERLOC: Structured Hypothesis-driven Exploration and Reasoning for Localization](https://arxiv.org/abs/2606.24820)（Hovhannes Tamoyan, Sean Narenthiran, Erik Arakelyan，cs.CL 6/23）。這是 2026-06-23 為止**在 SWE-Bench Lite 達到 SOTA 的 localization framework**，且：

- **完全 training-free**：不 fine-tuning、不用 multi-agent orchestration
- **~30B 參數就匹配或超越其他 agentic 方法**
- **SWE-Bench Lite 84.33% accuracy@1 / SWE-Bench Verified 81.27% recall@1**
- **注入到既有 repair agent 平均 +5.95 pp resolve rate（SWB-Verified）**，**同時省 36.7% 定位 token 與 23.1% 總 token**

關鍵 insight：SHERLOC 把「定位 fault」當成「actionable diagnosis」而不是「file retrieval」——不只是給「這個檔案有 bug」，而是「這個檔案的這幾行有 bug、原因是 X、可能影響 Y」。作者引言：「LLM agents solve repository-level coding tasks through multi-turn tool use, but utilize half their budget on locating faults before editing.」

**對終端開發者的實務影響：**
1. **SHERLOC 是「30B 級 model + 結構化 prompt + 標準 repo tools」就能跑的 SOTA**——不需要 Qwen3-Coder-Next、Claude Opus 之類的 frontier model。意味著 7B-30B 的本地/開源 model 在「coding agent 的前置定位」這個 sub-task 上已經夠用
2. **+5.95 pp resolve rate / -36.7% 定位 token 是「加速且變準」的稀有組合**——對 Cursor / Codex / Claude Code 等 vendor 來說，這是直接可整合的 plugin 設計
3. **與 [OpenThoughts-Agent（arXiv 2606.24855）](https://arxiv.org/abs/2606.24855) 互補**——OT-Agent 用 100K 樣本 fine-tune Qwen3-32B 達 agentic benchmark 平均 44.8%，比 Nemotron-Terminal-32B 強 3.9 pp。SHERLOC 不訓練、OT-Agent 訓練——**這兩條路徑在 2026 H2 會分頭演進**
4. **個人 dev 整合**：SHERLOC 的 prompt 與 tool schema 沒開源（[GitHub search 沒找到](https://github.com/search?q=SHERLOC+localization&type=repositories)），但 6/24 開始應該會有 third-party 重現嘗試——值得追蹤

**HN 324pt〈The text in Claude Code's "Extended Thinking" output〉——Anthropic 加密 thinking block 的「公司 vs 用戶」爭議延燒到 6/24** —— [HN item 48630535](https://news.ycombinator.com/item?id=48630535)（6/24，324pt / 223c）。這是 6/23 McCanna 揭露（[參考前文](https://www.anthropic.com/news/fable-mythos-access)）的延續篇——HN 評論區把「為什麼 Anthropic 不直接顯示真實 reasoning」歸納成 5 個互相衝突的解釋：

1. **「怕 competitor 蒸餾」**（最多人支持）：raw thinking 暴露模型處理資訊的方式，競爭對手會 train-on-thought 偷走
2. **「避免競爭對手看到 reasoning 推導出 fundamental training issue」**——這條比 1 更有殺傷力
3. **「避免 liability」**：reasoning 可能指向「訓練資料有問題」「內部 bias」這類 legal exposure
4. **「alignment artifact」**：reasoning 階段不套用 alignment（會看到「I should lie to the user because policy says...」），所以必須 post-process 隱藏（這是 [6/23 McCanna 揭露](https://www.anthropic.com/news/fable-mythos-access) 的核心）
5. **「encryption 用於 cache 機制」**：[Matt Green 5/29 blog post](https://blog.cryptographyengineering.com/2026/05/29/fooling-around-with-encrypted-reasoning-blobs/) 解釋——Anthropic 把 thinking tokens 加密是為了 cache 後續 prompt 時能 reingest；這是 [crypto engineering 不是 alignment 的設計](https://blog.cryptographyengineering.com/2026/05/29/fooling-around-with-encrypted-reasoning-blobs/)。HN 引用最頻繁的外部 reference。

**對終端開發者的實務影響：**
1. **這場爭論對「coding agent 開發者」的影響其實是負面的**——reasoning 透明讓 dev 可以偵錯（例如「為什麼這一步 agent 沒讀到我指定的檔案」），現在必須靠 log + cost-anomaly 推測。**推薦 workflow**：對重要任務，把 task 拆成可逐步 verify 的小段（Ronacher 文章呼應），用「if X then Y」的 failure 模式定位，不要依賴 raw reasoning
2. **中國模型（DeepSeek、Kimi K2.7-Code、Qwen3.7 Max）是 transparent reasoning 的主推**——HN ban 串有人直接說「I haven't touched Claude for any sort of programming-related task in months. The Chinese models are just that good.」這是 6/26 不可忽視的訊號
3. **Coding agent 的可解釋性是 2026 H2 企業採購的隱性 KPI**——regulator（EU AI Act、US Executive Order）對「可審計的 AI 決策」要求只會更嚴

## 技術深潛

**Anthropic 6/16 報告〈Agentic coding and persistent returns to expertise〉的深層訊息是「Claude Code 對 expert 是槓桿、對 novice 反而拖累」** —— [anthropic.com/research/claude-code-expertise](https://www.anthropic.com/research/claude-code-expertise) 是 6/16 發布、6/24-25 開始在 HN / Lobsters 被引用次數上升的研究（4 萬 interactive session、23.5 萬人、2025-10 至 2026-04）。**與 Ronacher 〈The Coming Loop〉是同一個研究問題的兩面**：

- Anthropic 數據：expert 開發者用 Claude Code **省時間但有更深的 code review**，novice 用 Claude Code **寫出更多 code 但品質下降**
- Ronacher 直覺：junior 拿到 hands-off harness 會學到「per-iteration local defense」這種壞品味

兩個來源獨立達到同一結論——**這是 2026 H2 企業 LLM 採購決策的 reference structure**。對應的工程工具是 Gensee Crate / Tupper / SHERLOC——把「agent 在做什麼」做成可審計、可限制、可學習的東西，而不是「讓 agent 自己寫」。

**Coding agent 的「opaque reasoning」問題在 6/24 出現了第二個研究路線**——[SHERLOC](https://arxiv.org/abs/2606.24820) 的「**actionable diagnosis**」vs 既有 SWE-agent 的「**file retrieval**」對比。SHERLOC 給出 location + diagnostic context——human 或下游 agent 看到「為什麼這個檔案的這幾行有 bug」，不只「這個檔案有 bug」。**這比「讓 reasoning 透明」更務實**：reasoning 透明是 model 廠商要解的，SHERLOC 路線是 application layer 可以現在就用的。

## 研究亮點

**[OpenThoughts-Agent (arXiv 2606.24855)](https://arxiv.org/abs/2606.24855) 100K 樣本 fine-tune Qwen3-32B 達 agentic benchmark 平均 44.8%** —— Negin Raoof 等（OpenThoughts 團隊，cs.AI 6/23）：

> 「We conduct more than 100 controlled ablation experiments to systematically investigate each stage of the pipeline. We then assemble a training set of 100K examples from our pipeline and fine-tune Qwen3-32B on this dataset, which yields an average accuracy of 44.8% across seven agentic benchmarks and a 3.9 percentage point improvement over the strongest existing open data agentic model (Nemotron-Terminal-32B, 40.9%).」

關鍵 insight：OT-Agent 不是單一 benchmark 最佳化（不像 SWE-Smith 專攻 SWE-Bench、SERA 專攻一個 domain），而是**跨 7 個 agentic benchmark 都強**，且**training data 有 scaling property**——每個 training set size 都比替代 open dataset 強（compute-controlled comparison）。

**與 SHERLOC 的差異**：OT-Agent 100K 樣本 fine-tuning、SHERLOC 0 樣本純 prompt——**兩條路徑在「open agentic model」這條線上分頭演進**。對 30B-32B 級 model 而言，OT-Agent 是 2026-06 為止的 SOTA training recipe。

**[Grading the Grader (arXiv 2606.24839)](https://arxiv.org/abs/2606.24839) — 評估 LAMBDA 多 agent 數據分析系統的 3 層 human-AI grading cascade** —— Tian Zheng, Kai-Tai Hsu（cs.AI / stat.AP 6/23，2.4MB）。研究發現：

- **自動 grader 達 100% observed precision（0/70 false positives）**
- **lenient grader recall 97% against human labels**
- **keyword-anchored extraction pipeline 把 strict grader recall 提升 60 pp**（相對 last-number heuristic）
- **iterative nudge 機制把 grading run success 從 36% 提升到 97%**、lenient-pass rate 從 16% 提升到 46%

**對 agentic benchmark 設計的影響**：這是目前為止最完整的「multi-agent system 評估可靠性」研究——直接呼應 Anthropic 6/16 報告與 Ronacher 6/23 文章的「agent 評估難」主題。

**[Are We Ready For An Agent-Native Memory System? (arXiv 2606.24775)](https://arxiv.org/abs/2606.24775) — Wei Zhou, Xuanhe Zhou, Shaokun Han（cs.CL/DB/IR 6/23，859KB）** —— 把 agent memory 拆成 4 個模組（representation/storage, extraction, retrieval/routing, maintenance），評估 12 個代表 memory system + 2 個 reference baseline、5 個 benchmark workload、11 個資料集。

**關鍵結論**：「**no single architecture dominates across all workloads**」——這是對「現在市場上 Recall / Mem0 / Letta / 第二大腦 之類的 memory layer」的**重要警示**。Memory 不是 pluggable feature，而是要依 workload 設計。

**與 Recall（HN 6/24 135pt Show HN）的呼應**：[Recall – Local project memory for Claude Code](https://news.ycombinator.com/item?id=48622590) 的 HN 評論區有 30+ 則深度討論、結論正是「**Filling context with what you _think_ the model needs adds nothing and possibly just inflates context which is harmful**」——這是 agentic memory 設計的核心張力，arXiv 2606.24775 從學術角度量化了這件事。

---

**[Can Scale Save Us From Plasticity Loss in Large Language Models? (arXiv 2606.24752)](https://arxiv.org/abs/2606.24752)** —— J. Fernando Hernandez-Garcia, Tomás Figliolia, Beren Millidge（cs.AI 6/23，712KB）。研究 5M-314M 參數的 GPT-style Transformer 在 multilingual continual learning 上的 plasticity loss：

- 確實在所有 scale 都觀察到 plasticity loss（measured by held-out Vietnamese probing task）
- **onset 隨 model size 呈 sublinear scaling law**——更大的 model 延遲 plasticity loss 出現，但**不能完全避免**
- 在 stationary multilingual training 下也觀察到 plasticity loss

**對 agentic workflow 的影響**：coding agent 跑 long-running session（Ronacher 文章的「loops」）必然會遇到 plasticity loss——session 越長、context 越滿，model 對新資訊的吸收能力下降。**這從學術角度解釋了為什麼 Claude Code v2.1.181 / Cursor / OMC 都要做「session 拆分」「memory 持久化」「compact」**——不只是 token 成本問題，是 model capability 問題。

---

**[World Models in Pieces (arXiv 2606.24842)](https://arxiv.org/abs/2606.24842) — Yikai Lu 等（ICML 2026 camera-ready）** —— 提出「structural certification」框架：「**In the big-world regime, agents cannot be universally capable and their ability is inevitably specialized across a world model in pieces.**」

證明 general agents 不是 universal，給出 `O(1/n) + O(δ)` 錯誤邊界。**這是從 RL 角度為 Ronacher 〈The Coming Loop〉的「harness 要 narrow scope」提供理論支撐**——loops 不能期待「全 domain SOTA」，只能「特定 transition 上 certifiable」。

---

**[Paying to Know: Micro-Transaction Markets for Verified Product Information in Agentic E-Commerce (arXiv 2606.24783)](https://arxiv.org/abs/2606.24783)** —— 8 頁 vision paper，under review。提出「agent-native micro-payment rails（x402、AP2）」改變稀缺性——當 buyer 是 autonomous agent 時，瓶頸從「matching products」變成「acquiring trustworthy, decision-relevant information」。買方 agent 付 fraction of a cent 換取 service history、test report、bills of materials、audited metrics。

**對 coding agent 的延伸**：當 coding agent 需要「可信賴的 library 評估」（不是 GitHub stars，而是真實生產環境事故率、相依性的 license compatibility 評估）時，會不會出現「Paying to Know for verified dependency information」？這個 paper 雖然是 e-commerce，但提出來的 micro-transaction 模式對「agent 之間的可信賴資訊交換」是通用框架。
