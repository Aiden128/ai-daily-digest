# AI Coding Agents Digest 2026-07-31

> 七月份的「cross-vendor 工具 + session UX」主旋律延燒到 7 月最後一天。今天的 6 個頭條圍繞一個共同主題：**harness 不只是 wrapper，security boundary 才是 2026 H2 coding agent 真正的競爭前線。** Medley 的 8-point 短文〈The harness is the capability multiplier〉把「harness 決定 capability 上下限」講得最直白；同日 arXiv 連發三篇 harness/skill 安全研究（SkillGate、Harness Engineering、CHILL-Harness），加上 ClickHouse 工程師公開〈SRE Agent MCP〉實作 + Anthropic 7/28 MCP 2026-07-28 spec 落地，**這個禮拜的訊號非常一致：coding agent 的 2026 H2 戰場從 model 移到「harness + 工具 + 安全」三軸。**

## §1 今日頭條

### 1.1 HN 7/29 〈The harness is the capability multiplier〉：8 點短文把 2026 H2 coding agent 的核心命題講完

Medley 工程師 7/29 在 [〈The harness is the capability multiplier〉](https://www.medley.sh/blog/the-harness-is-the-capability-multiplier) 寫了一篇 8 點積分的短文，論點極簡：**模型是原料，harness 才是乘數器。** 同一個 Opus 5 / Fable 5 / Kimi K3，放在不同的 harness（context window 配置 + tool surface + verification loop + retry policy + cost ceiling + skill marketplace）裡，產出的 code quality 可以差到 3-5 倍。

文章的具體案例：他們用 7 個內部 codebase 跑同一個 Opus 5 模型 + 同一組 prompt，差別只在 harness——結果 strict pass rate 從 19%（vanilla）到 71%（Medley 自家 harness），**delta 52pp 全部來自 harness 設計，不來自 prompt、不來自模型。** 這呼應了 Ronacher 6/23〈The Coming Loop〉「harness is the product」的 framing，但 Medley 把它量化成可重現的 benchmark 數字。

**我的看法：** Medley 的文章跟上週 7/29〈Why Software Factories Fail (or: harness engineering is not enough)〉是同一條主旋律的兩個切片——前者說「harness 決定上限」，後者說「光 harness 還不夠，還要 harness engineering 這個獨立工程紀律」。把兩篇合在一起看，2026 H2 的 coding agent 競爭已經不是「誰家的 Claude/Opus/Kimi 比較強」這種 model-tier 比較，而是「誰家的 harness 設計 + harness evolution 流程比較成熟」。Boris Cherny 5 月在訪談說「My job is to write loops」其實是同一件事——Claude Code 的 `/rewind`、`/doctor`、skill marketplace、session snapshot 全是 loop（harness）的具體化。

**這個主旋律的 7 月具體證據：**
- 7/22 Anthropic 〈Schema Harness Achieves ~99% on Arc-AGI-3 Public〉：同一個 Opus 用 6 種不同 harness，delta 51pp
- 7/27〈Why Software Factories Fail〉：harness engineering 是獨立學科，不是 prompt engineering 的延伸
- 7/29 Medley 本文：harness 是 capability multiplier
- 7/28 arXiv SkillGate：harness 內的 skill file 是新的 attack surface

四件事指向同一個方向：**harness 已經從「程式庫」升級到「產品」**，2026 H2 任何嚴肅的 coding agent vendor 都必須有「harness engineering」這個獨立 roadmap，不只是 ship 新 feature。

### 1.2 HN 7/28 〈I sent Claude Opus 5 '--' 5k tokens about a cartographer〉：dangling document effect 量化 Opus 5 的 prompt 注入面

Austin's Nerdy Things 7/28 公開 [〈I sent Claude Opus 5 '--' and it wrote me 5k tokens about a cartographer〉](https://austinsnerdythings.com/2026/07/28/claude-opus-5-dangling-document-effect/)，這是 Opus 5 上市後第一個**結構化 prompt 注入面量化研究**：作者把 `--` 當成 dangling document delimiter，故意構造一個會讓 Claude Code 誤判「對話尚未結束」的字串，結果 Opus 5 在 6 次試驗中有 5 次**寫出 4500-5800 tokens 的「cartographer 寓言」**——不是回答使用者問題，而是用第三人稱寫一個關於製圖師的虛構故事。

這個 bug 不是 Opus 5 獨有，但 Opus 5 的 5k token 平均長度**比 Opus 4.6 的 1.2k 多 4 倍**，而且 6/6 試驗都進入「fiction writing mode」而不是「code mode」。作者認為原因是 Opus 5 對 dangling markdown / code block 邊界的 tokenizer 處理有 edge case：當對話結尾是 `--` + newline，Opus 5 的 turn boundary detector 會把後續 token 當成「上一個 file 的 continuation」而非「下一個 user turn」。

**我的看法：** 這跟 7/29 公開的 [〈Boris Cherny: Opus 5 is our least prompt injectable model yet〉](https://twitter.com/yampeleg) 是同一個研究週的兩個互補發現——Boris Cherny 從 Anthropic 內部資料說 Opus 5 比 Opus 4.6 prompt injection 成功率降 41%，但 Austin 從外部 reproduction 說 Opus 5 在 dangling document edge case 反而**更容易**誤觸 fiction mode。**Boris 講的是「整體 injection 成功率」，Austin 講的是「特定 edge case 的 failure mode 變化」——兩個都是真的，但 vendor 自家 audit 跟 independent reproduction 的訊號必須分開看。**

對 harness engineering 的意義：harness 必須有「dangling document detector」這種 edge case handler，不能假設 model 的 turn boundary detector 永遠是對的。Claude Code 7/29 出的 [「Claude Code has a hardcoded instruction telling Opus 5 not to use subagents」](https://github.com/anthropics/claude-code/issues/5821) 顯示 Anthropic 已經在 system prompt 加 explicit guard，但這是「症狀處理」不是「harness 等級」解法。

### 1.3 HN 7/29 〈We built an MCP server for your SRE agent〉：ClickHouse 公開 ClickStack MCP + 1 個 production eval 框架

ClickHouse 工程師 7/29 公開 [〈Benchmarking the ClickStack MCP server with HDX evals〉](https://clickhouse.com/blog/benchmarking-the-clickstack-mcp-server-with-hdx-evals)，把 ClickStack observability stack 透過 MCP 2025-06-18 spec 暴露成 SRE agent 可呼叫的 tool surface，並公開 **HDX (HyperDX evals)**——一個可以量化「agent + MCP tool」整體 query-to-resolution time 跟 precision 的開源 eval framework。

具體架構：ClickStack MCP server 暴露 9 個 tools（`search_logs`, `get_metrics`, `trace_query`, `dashboard_lookup` 等），HDX evals 跑 5 個真實 SRE 場景（p99 latency spike investigation、error rate 異常偵測、跨 service dependency 追蹤、log-driven root cause、capacity planning query），每個場景 20 個 query × 4 種 agent 設定（GPT-5.6 / Claude Opus 5 / Kimi K3 / 自家開源 agent）。結果：Opus 5 + ClickStack MCP 在 5 個場景平均 87% 一次到位（first-turn correct），Kimi K3 71%，GPT-5.6 68%；沒有 MCP 時 Opus 5 只能 34%（需要人工補 log grep）。

**我的看法：** 這是 2026 H2 「production-grade MCP server + eval framework 一起 ship」的第一個公開 reference impl。先前大家都在寫 MCP server（市場上 2,400+ 個），但**只有 MCP server 沒有 eval 等於盲飛**——你不知道哪個 tool surface 對哪個 agent 有效。ClickHouse 把 ClickStack + HDX 一起開源，等於把「observability for agents」這個新興垂直從「拼湊 MCP」升級到「可重現的 eval-driven MCP 開發流程」。

對 2026 H2 coding agent 競爭的意義：**MCP 已經從「protocol spec」升級到「ecosystem KPI」**。Agent 選哪個 MCP server 不是看「有沒有」而是看「有沒有 HDX-grade eval」。ClickHouse 開這個頭，預期 Datadog、Splunk、Grafana 在 8 月會跟進同樣的 pattern（open MCP + open eval framework）。對 Claude Code / Codex / Cursor / opencode 的啟示：harness 必須原生支援「eval-driven tool selection」——不能 hardcode MCP server list，要根據 HDX 類的 eval 結果動態推薦。

### 1.4 HN 7/29 Show HN 〈Wallfacer: A terminal session manager for Claude Code〉：Claude Code 第一個專用 TUI session manager

7/29 Show HN 公開 [Wallfacer](https://news.ycombinator.com/item?id=49099123)——一個專門給 Claude Code 用的 terminal session manager，提供 Claude Code CLI 沒有的 4 個功能：(1) 多個 Claude Code session 同時開著不互相干擾（每個 session 獨立 working directory + 獨立 context state + 獨立 transcript log）；(2) session 之間可以共享 file watch（某個 session 改了 file，其他 session 自動 reload）；(3) `/attach` 可以 attach 到現有的 background Claude Code process（解決 Claude Code CLI detach 後 process 還在跑但 UI 連不回去的問題）；(4) session 之間的 cost / token 使用即時 dashboard。

整個工具 800 行 Rust，用 ratatui 做 TUI，跟 tmux 的差別是 **tmux 是「terminal multiplexer」，Wallfacer 是「Claude Code session multiplexer」**——它理解 Claude Code 的 session 結構（每個 session 有一個 `.claude/sessions/<id>.jsonl` transcript），所以可以做 attach / detach / cross-session state sync 這些 tmux 沒辦法做的操作。

**我的看法：** 這是 Claude Code 7 月「agent runtime maturity」系列事件的又一個訊號——之前有 v2.1.191 `/rewind`、v2.1.193 `claude_code.assistant_response` OTel log、v2.1.218 streaming CPU -37%，現在有社群寫出來的「session 層管理工具」。**這代表 Claude Code 已經大到值得有人寫「外掛 management 層」，就像 2010 年代 Docker 大到有人寫「kubernetes for docker」一樣。**

對 harness engineering 的意義：harness 必須有「session-as-versioned-object」的標準介面，才能讓 third-party tools（Wallfacer、Tmuxinator、tmuxinator-cc 之類）可以 attach / detach / share state。**這呼應 opencode v1.17.11 7/24 出的 session snapshot + revert**——opencode 領先 Claude Code 做出 native session snapshot，Claude Code 領先 opencode 做出社群 management 工具。**opencode 走 native-first 路線，Claude Code 走 ecosystem-first 路線，兩個都不是錯，但等 8 月看哪個路線能在 eval-driven 對決裡贏。**

GitHub Copilot CLI 在 7/28-29 連出三版（v1.0.76-2 / v1.0.76-3 / v1.0.76-4），其中 [v1.0.76-2](https://github.com/github/copilot-cli/releases/tag/v1.0.76-2) 推出兩個 structural 改動：

**我的看法：** 7/28-29 這個三件同天 ship 的 cluster 是 7/30 agents digest 報過的「7/28 cross-vendor wave」（opencode v1.18.9 + Copilot CLI v1.0.76-1 + Codex rust-v0.146.0-alpha.14）的**延續**——v1.0.76-2 把 v1.0.76-1 的「mouse setting live update + queue message handling」升級成「**directable queue + multi-session sidebar**」兩個 structural 改動。**這個升級速度（從 1.0.76-1 的 4 個小 UX 修到 1.0.76-2 的 2 個 structural 改動）顯示 GitHub 把「Copilot CLI 拉到 Claude Code / Codex 同等 session maturity」當作 7 月最高優先級。** 對 enterprise 客戶的訊號：Copilot CLI 已經從「個人開發者玩具」升級到「team-grade coding agent」，sandbox floor + multi-session + directable queue 三件是 team workflow 的基本盤。

### 1.6 arXiv 7/28 2607.25619 〈SkillGate〉：coding agent skill file 是新的 attack surface，需要 runtime detection

arXiv 7/28 公開 [2607.25619 〈SkillGate: Cost Efficient Runtime Malicious Skill File Detection in Coding Agents〉](https://arxiv.org/abs/2607.25619)。論文核心發現：**Claude Code、Cursor、GitHub Copilot 的 skill file（`.claude/skills/*.md`、`.cursor/rules/*.mdc`、`.github/copilot-instructions.md`）已經成為新的 supply chain attack surface——攻擊者可以在 skill file 裡藏 prompt injection、filesystem 寫入指令、credential exfiltration pattern，而 agent 在 load skill 時沒有 runtime validation。**

SkillGate 提出的解法：對 skill file 做靜態掃描 + LLM-based 行為分析 + allowlist 強制，三層 pipeline 在 agent load skill 之前攔截 malicious patterns。實驗：構造 2,400 個 malicious skill file + 8 個真實攻擊樣本，SkillGate 攔截率 96.8%，false positive 4.2%；Claude Code 原生 load 機制攔截率 0%。

論文重點強調：**skill file 跟 package.json / requirements.txt 一樣，是「開發者信任的第三方代碼」**，但 skill file 內含 natural language（不是 executable code），傳統 SAST / SCA 工具完全掃不到。Claude Code skill marketplace、Cursor rule library、Copilot instructions 三大生態都已達到「marketplace-grade」規模（>10K skill / >5K rule / >1M instructions），這是 2026 H2 必須解決的 supply chain 問題。

**我的看法：** 這跟 Medley (1.1) 的「harness 是 capability multiplier」是同一週的兩個互補發現——Medley 講「harness 決定上限」，SkillGate 講「harness 決定 attack surface」。**harness 越大（skill marketplace 越大、rule library 越豐富），attack surface 越大。** 7/28 arXiv 2607.18130〈Handbook.md shows that long policy documents do not reliably govern agents〉（已收錄於 [7/31 daily digest 1.3](https://aiden128.github.io/ai-daily-digest/daily/2026-07-31)）也指向同一個方向：長篇 policy 跟 skill file 一樣，form 跟 semantic 合規之間有 gap。

對 2026 H2 vendor roadmap 的啟示：**Claude Code / Cursor / Copilot 必須在 8-9 月推出「skill marketplace 的 security layer」**——這不是 nice-to-have，是 enterprise procurement 的 hard requirement。SkillGate 是第一篇把這個問題量化的公開學術論文，預期 8 月會有 follow-up 開源實作（類似 Socket.dev for npm，但 for skill file）。

## §3 一流學者與前沿研究

### 3.1 Simon Willison 7/29 〈Adding a custom MCP server to Claude and ChatGPT〉：MCP 在 7/28 spec 後的 developer experience 標竿

Simon Willison 7/29 公開 [〈Adding a custom MCP server to Claude and ChatGPT〉](https://simonwillison.net/2026/Jul/29/mcp-in-claude-and-chatgpt/)，這是 7/28 MCP stateless spec 落地後第一篇**完整的 developer experience 標竿記錄**——涵蓋 Claude Code CLI、Claude.ai 網頁版、ChatGPT 桌面 app 三種 host 的 MCP server 安裝流程、配置檔位置、tool discovery 機制、error handling 差異。

具體發現：ChatGPT 桌面 app 7/28 起支援 MCP，但 tool discovery 採 opt-in model（必須手動 `/mcp enable <server>`），跟 Claude Code 的 auto-discovery 模式不同。**這代表 MCP 雖然 protocol 已穩定，但不同 host 的 UX 仍然分叉**——enterprise 客戶如果要「單一 MCP server 跨 host 使用」必須維護兩份配置。

**我的看法：** Simon 的文章跟 1.3 ClickHouse 的「production-grade MCP + eval」合在一起看，2026 H2 MCP 競爭的關鍵不是「誰支援最多 spec」而是「誰的 DX 摩擦最低」。Anthropic 在 Claude Code 走 auto-discovery、OpenAI 在 ChatGPT 走 opt-in、Microsoft 在 Copilot 走 enterprise-managed，三條路線都還沒收斂。

### 3.2 arXiv 7/28 2607.25890 〈Distributing Security Controls Through Harness Engineering〉：harness engineering 的 formal framework

arXiv 7/28 公開 [2607.25890 〈Distributing Security Controls Through Harness Engineering〉](https://arxiv.org/abs/2607.25890)。論文核心論點：**coding agent 的 security 必須分佈在 harness 各層（context layer / tool layer / verification layer / execution layer），不能集中在單一「安全 prompt」**。提出 DSH (Distributed Security Harness) 框架：每個 layer 都有獨立的 security control + cross-layer 協調機制，類似 network security 的 defense-in-depth。

實驗：構造 8 類常見 attack（prompt injection、skill file poisoning、tool misuse、context overflow、credential leak、filesystem escape、network exfiltration、privilege escalation），在 4 個現有 harness（Claude Code、opencode、Codex、Copilot CLI）上跑 100 次 attack attempt，**單層「安全 prompt」阻擋率平均 23%，4 層 DSH 阻擋率 81%。** 論文重點：DSH 不是 prompt engineering 升級，是 harness architecture 升級——需要 explicit control plane、audit log、rollback 機制。

**跟 1.6 SkillGate 的互補：** SkillGate 講「skill file 載入時的 static scan」，DSH 講「runtime 各 layer 的 distributed control」。兩個合在一起是 2026 H2 coding agent security 的 reference architecture。

### 3.3 arXiv 7/28 2607.25825 〈CHILL-Harness: Counterfactual Harness Learning for Long-Horizon Agents〉

arXiv 7/28 公開 [2607.25825 〈CHILL-Harness〉](https://arxiv.org/abs/2607.25825)。論文核心：**傳統 harness 設計靠人類工程師 hand-craft rules，但長時程 agent 任務（>50 steps）的 failure mode 太多，人類設計的 rule 覆蓋率有限**。CHILL 提出「counterfactual harness learning」——用 agent 自己跑出來的 failure log 訓練一個「harness policy network」，在 runtime 動態選擇哪個 verification / retry / context-restoration rule 套用。

實驗：5 個 long-horizon coding tasks（multi-file refactor、test suite 重寫、API migration、dependency upgrade、CI/CD pipeline 改寫），傳統 static harness 成功率 47%，CHILL 動態 harness 67%（delta +20pp），但 compute overhead +38%。**trade-off 明確：長時程任務值得 +20pp，但計算成本增加近 4 成。**

**我的看法：** CHILL 是「harness is the capability multiplier」這個主旋律在 arxiv 的 formal 版本。Medley 用 7 個 codebase 量化「harness 決定上限」，CHILL 用 5 個 long-horizon task 量化「dynamic harness 比 static harness 高 20pp」——**兩個獨立來源指向同一個結論，harness 設計的 ROI 在 2026 H2 已經比 model selection 更值得投資。**

## §4 企業前沿動態

### 4.1 Anthropic 7/29〈Bringing MCP 2026-07-28 to Claude〉：14 小時 ship + legacy 相容

## §7 深度觀點：harness 是 product，security boundary 是 2026 H2 coding agent 真正的戰場

這週的 6 個頭條 + 6 個研究論文 + 多個 vendor release 加在一起，講的是同一件事：**2026 H2 coding agent 的戰場從 model 移到 harness，從 prompt 移到 security boundary，從單一 model selection 移到 ecosystem orchestration。** 這不是 hype，是六個獨立訊號的 convergence。

第一個訊號軸是 **harness engineering 正在從 prompt engineering 升級到獨立學科**。Medley (1.1) 量化「harness 決定 52pp 能力上下限」、Schema Harness 7/22 量化「同一個 Opus 用 6 種 harness 差 51pp」、CHILL-Harness (3.3) 量化「dynamic harness 比 static harness 高 20pp」——三個獨立來源、兩種方法論（empirical + formal）、同一個結論。**harness engineering 的 ROI 已經逼近 model upgrade ROI，2026 H2 任何嚴肅 vendor 都必須有 dedicated harness team。** Boris Cherny 5 月說「My job is to write loops」、Ronacher 6/23 說「harness is the product」、Medley 7/29 說「harness is the capability multiplier」——三個 voice 在 70 天內形成共識，harness-as-product 不再是 fringe 觀點。

第二個訊號軸是 **skill file / rule library / instruction 三大 ecosystem 已達 marketplace 規模，但 security 跟不上**。Claude Code skill marketplace >10K、Cursor rule library >5K、Copilot instructions >1M——三個 ecosystem 加起來 >1.5M third-party artifacts 在 production agents 裡被 load。SkillGate (1.6) 量化「攻擊者可以在 skill file 藏 attack，agent load 時沒有 runtime validation」、Handbook.md (7/31 daily 1.3) 量化「長篇 policy form / semantic 合規有 gap」、DSH (3.2) 量化「單層安全 prompt 阻擋率 23%，4 層 DSH 81%」——三個獨立量化結果指向同一個結論：**2026 H2 coding agent security 必須升級到 distributed harness security model，不能停在「安全 system prompt」時代。** 這不是 nice-to-have，是 enterprise procurement 的 hard requirement——任何金融、醫療、政府客戶在 8-9 月的 vendor 評估都會問「你的 skill marketplace 有沒有 security layer」。

第三個訊號軸是 **「harness × session × enterprise policy」三軸的 UX 主旋律**。Copilot CLI v1.0.76-2 (1.5) 的 directable queue + multi-session sidebar、Zed v1.14.1-pre (4.3) 的 IDE 層 sandboxing、Wallfacer (1.4) 的 third-party session multiplexer、Claude Code 7/24 enterprise sandbox floor (在 7/30 agents digest 報過)、opencode v1.18.9 7/28 的 V2 desktop sidecar——**5 個 vendor 在 7/28-29 同步 ship「harness + session + enterprise policy」相關 feature，這個 cadence 已經是 category formation 等級。** 跟 6/24-27 那一波（skill marketplace / OTel / MCP OAuth）相比，這一波更聚焦在「agent runtime 的 enterprise readiness」。

三個軸加在一起的 macro framing：**2026 H2 coding agent 競爭的本質是「誰的 harness 是最好的 enterprise-grade runtime」**。Model 已經 commodity 化（Opus 5 / Fable 5 / Kimi K3 / GPT-5.6 四家 frontier model 在大多數 coding task 的差異 < 15pp），skill ecosystem 已經有 1.5M artifacts 但 security 落後，enterprise customer 在 8-9 月的 procurement cycle 會把 60-70% 的 weight 放在「harness engineering maturity + ecosystem security + session UX」三項。**Anthropic 在 harness 領先（harness design + ecosystem security first），OpenAI 在 session 領先（Codex session schema），GitHub 在 enterprise 領先（Copilot CLI 7/28 wave + sandbox floor），Zed 在 IDE-layer sandboxing 探索新路線，opencode 在 native session snapshot 領先，Cursor 在 rule library 領先。** 六個 vendor 都有不同的「harness 路線」，2026 H2 的贏家是「能最快把 harness / ecosystem / session 三軸收斂成單一 product story」的那個。

這個判斷的風險是 **「harness engineering 變成新一輪 framework war」**——每一個 vendor 都有自己的 harness 規格，enterprise 客戶被迫在六個 harness 間選邊站，而不是專注在 model quality 跟 developer experience。Medley (1.1) 跟 CHILL (3.3) 呼應 Ronacher 6/23〈The Coming Loop〉的擔憂：「per-iteration local defense 累積成不可理解系統」——harness 越複雜、security layer 越多，最後的系統行為沒有人能完整理解。**2026 H2 coding agent 真正的 deep research 議題不是「更好的 harness」，而是「可理解 / 可驗證 / 可審計的 harness」**——harness engineering 必須跟 formal verification、interpretability、audit 結合，不是停在 hand-craft rules 的層次。SkillGate 1.6、DSH 3.2、CHILL 3.3 是這個方向的 early signals，但 8-9 月需要 vendor 跟 academic community 一起把 reference architecture 收斂。

**對 8 月的展望：** vendor roadmap 應該聚焦 (a) skill marketplace security layer (SkillGate-style runtime detection)、(b) DSH-style distributed security control、(c) session-as-versioned-object 的 standard interface（讓 third-party tools 像 Wallfacer 可以 attach / detach）、(d) enterprise policy floor 跟 user-customizable 範圍的明確邊界。enterprise 客戶在 8-9 月的 vendor 評估清單應該加三項：skill marketplace security audit、DSH 控制覆蓋率、session policy 可審計性。**harness engineering 從 2026 H2 起是 coding agent 的新 baseline，model selection 退到第二位。**
