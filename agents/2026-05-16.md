# AI Agents Digest - 2026-05-16

## 今日頭條

- **Cursor 發布「Cursor Agent Protocol (CAP)」：開放式 Agent 通信標準**（May 16）— [Cursor Blog](https://cursor.com/blog/cap)
  - Cursor 宣布開放其內部 Agent 通信協議 CAP，允許第三方工具與 Cursor 的 Agent 生態無縫集成。CAP 定義了一套標準的消息格式和 RPC 接口，涵蓋了「任務委託」（一個 Agent 如何將子任務交給另一個 Agent）、「狀態同步」（多個 Agent 如何共享進度信息）、以及「衝突仲裁」（當多個 Agent 修改同一資源時的解決機制）。
  - 這意味著，你可以編寫一個自定義的 MCP server，讓它不僅能被 Cursor 調用，還能主動向 Cursor 的 Agent 發送任務請求。例如，一個監控 MCP server 可以檢測到測試失敗，然後通過 CAP 向 Cursor Agent 發送「修復這個測試」的任務，而無需人類介入。
  - 對於工具開發者來說，CAP 是一個機會——它提供了一個「成為 Cursor 生態一部分」的標準路徑。對於企業用戶來說，CAP 意味著可以將內部工具（如自定義的 CI/CD 系統、內部知識庫）與 Cursor Agent 深度集成，構建真正端到端的自動化 workflow。

- **Replit Agent v3 發布：從「自然語言到部署」的完整 Pipeline**（May 15）— [Replit Blog](https://blog.replit.com/agent-v3)
  - Replit 的 Agent v3 現在可以完成「從想法到 URL」的完整閉環：你描述一個應用（如「一個可以分享食譜的社交網站，支持圖片上傳和標籤搜索」），Agent 會自動生成數據庫 schema、後端 API、前端組件、測試、並部署到 Replit 的雲端，最後給你一個可訪問的 URL。
  - 技術上，v3 引入了「部署驗證」階段——在 Agent 認為「完成」後，系統會自動運行一系列端到端測試（如「用戶能否註冊？能否上傳圖片？搜索是否返回正確結果？」），如果任何測試失敗，Agent 會回退到開發階段修復問題。這種「自驗證」機制顯著提高了「vibe coding」項目的可靠性。

## 工具與框架

- **Tabby v0.28：自托管 AI 代碼補全的新標準**（May 16）— [Tabby ML](https://tabby.tabbyml.com/blog/2026/05/16/tabby-0-28)
  - Tabby 是一個開源的自托管代碼補全引擎。v0.28 新增了「repository-level context」——補全時不僅考慮當前文件，還會分析整個代碼庫的結構和依賴關係，生成更符合項目慣例的補全建議。對於擔心代碼外泄的企業，Tabby 提供了一個「完全私有」的 GitHub Copilot 替代方案。

## 深度觀點

Cursor 開放 CAP 協議是一個戰略性舉措。過去，AI Agent 的生態是「封閉花園」——每個工具都有自己的擴展機制（Claude Code 有 hooks，Cursor 有 MCP，Copilot 有 extensions）。CAP 試圖成為「Agent 間的 HTTP」——一個通用的、開放的通信標準。

如果 CAP 成功，它將解決當前 Agent 生態中最惱人的問題之一：「工具孤島」。當你使用 Claude Code 時，你無法直接調用 Cursor 的某個功能；當你使用 Copilot 時，你無法利用 Aider 的某個特性。CAP 的願景是：無論前端是什麼工具，後端的 Agent 都可以無縫協作。

當然，標準之戰從來都不容易。OpenAI 有自己的 function calling 格式，Anthropic 有 MCP，現在 Cursor 有 CAP。最終的贏家可能是某個「更通用的標準」（如 MCP 的擴展版本），或者市場會分裂為多個互不兼容的陣營。對開發者來說，當前的最佳策略是「觀望但準備」——不要過早押注某一個標準，但要確保自己的工具支持至少一個開放協議。
