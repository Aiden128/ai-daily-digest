## 今日頭條

1. **Claude Code v2.1.153 發布：MCP 修復、記憶體優化與終端整合強化**（2026-05-28）
   這是 Claude Code 本週的穩定版更新，雖然沒有「重大功能」標籤，但對終端用戶的實際影響相當深遠。首先，狀態列指令（status line commands）現在會收到 `COLUMNS` 和 `LINES` 環境變數，這讓自訂腳本能正確偵測終端寬度並調整輸出——對於習慣在 Claude Code 內執行自訂工具的 tmux/終端用戶來說，這解決了長期以來輸出被截斷的問題。其次，`claude agents` 的自動補全現在會同時建議原生斜線指令與 bundled skills，而不只是 project skills，這讓多 agent 協作時的 dispatch 流程更流暢。修復方面，一個在 v2.1.147 引入的 MCP SSE stream 重連迴圈 bug 被修正，同時解決了 resume session 時因為過多儲存 sessions 導致的多 GB 記憶體暴增問題。最值得注意的是 `--strict-mcp-config` 的行為調整：現在不再會把 agent 定義中的 inline `mcpServers` 剝離，而是對被阻擋的 subagent MCP servers 顯示可見警告——這讓企業環境中的 MCP 權限管理變得更可預測。

2. **OpenAI Codex 將於 6 月 2 日終止 GPT-5.2 / GPT-5.3-Codex，GPT-5.5 成為唯一預設模型**（2026-05-27）
   Codex 團隊成員 Tibo 在 X 上宣布這項變更，稱此舉是為了「簡化運算艦隊管理」。免費方案用戶的未來建構與工作將全面轉向 GPT-5.5，而付費方案則保留更高階模型選項。Tibo 同時透露，GPT-5.2 目前在 Codex 生產環境的使用率已不到 1%，被認為「相當過時」。這個時間點耐人尋味：GPT-5.2 去年 12 月才發布，半年後就被視為 legacy——這顯示出 frontier 模型的淘汰週期正在急劇縮短。對終端用戶來說，最大的實際影響是 prompt 行為可能會改變，因為 GPT-5.5 的 instruction-following 風格與 5.2 有顯著差異。建議在 6 月 2 日前測試現有 workflow 的相容性。

3. **lazygit v0.62.0 發布「按鍵綁定大改版」，終端 Git workflow 進入新世代**（2026-05-26）
   lazygit 這次更新的核心是可自訂按鍵綁定系統的全面翻新。新版支援更豐富的按鍵組合（如 `ctrl-alt-shift-x`），並引入更直覺的語法（`<ctrl+a>` 取代舊的 `<c-a>`，但舊語法仍相容）。最引發討論的是 breaking change：Mac 上提交 commit 的預設按鍵從 `alt-enter` 改為 `command-enter`，Linux/Windows 則改為 `ctrl-enter`。作者 Jesse Duffield 坦承這並非所有終端都支援，因此提供了回退設定。對與 Claude Code / Codex 協作的開發者來說，lazygit 是終端內最常用的 Git UI 之一，這次改版讓「在 agent session 中快速瀏覽 branch 差異、cherry-pick、rebase」的體驗更接近現代 IDE 的流暢度。

4. **Claude Code 安全指導插件正式上線，從市場安裝即可啟用**（2026-05-27）
   Anthropic 在 X 上宣布推出 Security Guidance plugin，這是第一個由官方維護的 Claude Code 安全外掛。它能在撰寫程式碼時主動識別潛在漏洞並建議修復。這個插件的意義不只在於功能本身，而在於它確立了 Claude Code plugin marketplace 的「官方認證」模式——和 VS Code 的 Microsoft 官方 extension 類似。對終端用戶來說，這意味著可以在純 CLI 環境中獲得接近 IDE 安全掃描的能力，而不需要跳出 terminal 去跑 SonarQube 或 CodeQL。

## 核心工具更新

- **Claude Code v2.1.153**（2026-05-28）— [Release](https://github.com/anthropics/claude-code/releases/tag/v2.1.153)
  - **更新內容：** 本次是 bugfix 與體驗優化為主的穩定版。重點包括：
    - `skipLfs` 選項加入 `github`/`git` plugin marketplace sources，clone 時可跳過 Git LFS 下載
    - npm global install 無法 auto-update 時顯示一次性通知；`/doctor` 列出修復方案
    - Status line commands 接收 `COLUMNS`/`LINES` 環境變數
    - `claude agents` 自動補全納入 native slash commands 與 bundled skills
    - macOS background agents 在 Privacy & Security 中顯示為「Claude Code」並保留跨版本權限
    - 修復 MCP SSE stream reconnect-looping（v2.1.147 regression）
    - 修復 resume session 時的 excessive memory usage（多 GB）
    - 修復 Windows PowerShell installer 假報「Installation complete!」
  - **終端實際影響：** `COLUMNS`/`LINES` 是本次對終端用戶最有感的改進——它讓自訂 status line 腳本能正確偵測 pane 尺寸。MCP fixes 則讓在企業環境中使用 `--strict-mcp-config` 的用戶不再遇到 subagent 權限被靜默剝離的問題。記憶體修復對長期開機、大量 sessions 的用戶尤其重要。

- **Codex CLI rust-v0.135.0-alpha.2**（2026-05-27）— [Release](https://github.com/openai/codex/releases/tag/rust-v0.135.0-alpha.2)
  - **更新內容：** Rust rewrite 分支的 alpha 預發布。目前 release notes 較為簡略，但這個版本號的頻繁更新顯示 Codex CLI 的 Rust 重寫正在積極推進中。
  - **終端實際影響：** Rust rewrite 的目標是顯著降低啟動延遲與記憶體佔用。目前仍建議終端用戶使用穩定版（Node.js 版本），但 Rust 分支值得持續關注——一旦正式發布，Codex 的啟動速度可能接近原生 CLI 工具等級。

## 技巧與優化

- **讓 Claude Code status line 腳本正確適應 pane 尺寸**
  v2.1.153 開始，status line commands 會收到 `COLUMNS` 和 `LINES`。你可以在自訂腳本中這樣使用：
  ```bash
  # ~/.claude/status-line.sh
  width=${COLUMNS:-80}
  printf "%-${width}s\n" "$(git branch --show-current 2>/dev/null)"
  ```
  這讓你在 tmux split 中的 Claude Code 也能正確顯示滿寬 status line，不會被截斷或溢出。

- **測試 Codex GPT-5.5 相容性**
  在 6 月 2 日前，建議用 `codex --model gpt-5.5` 跑一遍你的關鍵 workflow（例如 "refactor this module" 或 "write tests for these functions"）。觀察 5.5 是否會比 5.2 更積極地執行未請求的探索指令，並相應調整你的 prompt 中的 guardrails。

## 深度觀點

今日的終端 agent 生態呈現出兩條並行的主線：**穩定性的堆疊**與**淘汰週期的加速**。

Claude Code v2.1.153 是前者的代表。這個版本沒有震撼性的新功能，但修復了 MCP SSE reconnect-looping、記憶體暴增、Windows installer 假成功等「日常摩擦點」。對終端用戶來說，這些 bug 的影響遠比一個新 slash command 更深——因為 terminal 是開發者每天停留 6-8 小時的環境，任何需要重啟 session 或手動清理記憶體的問題都會累積成巨大的時間成本。`COLUMNS`/`LINES` 的支援看似微小，但它代表 Anthropic 開始把「終端原生體驗」當成 first-class concern，而非把 CLI 視為 Web UI 的降級版。

另一方面，OpenAI Codex 的 GPT-5.2 退役則是後者的縮影。一個去年 12 月才發布的模型，半年後使用率就跌到 1% 以下——這不是因為 5.2 變差了，而是因為 5.5 的提升幅度大到讓用戶自然遷移。對終端用戶來說，這意味著「學會一個模型特性就能用一年」的時代已經結束。Tibo 說「回想起來進展相當瘋狂」，但對每天依賴這些工具的開發者來說，這種瘋狂更像是一種持續的適應壓力：你的 prompt 技巧、workflow 設計、甚至 muscle memory（比如記住某個模型特別擅長處理 regex）都在以月為單位過期。

lazygit 的 keybinding revamp 則從另一個角度提供了啟發。在 GUI IDE 瘋狂整合 AI 功能的同時，終端工具也在進化——只是進化的方向不是「加入 AI」，而是「讓終端本身更好用」。 richer keybindings、更好的終端相容性、更直覺的語法，這些改進讓 terminal 作為 agent 的「宿主環境」變得更強大。當 Claude Code 和 Codex 在 terminal 中執行時，它們依賴的是 fzf、lazygit、tmux、yazi 這些工具構成的生態系。這個生態系的健壯程度，直接決定了 agent 能發揮多少潛力。

最後，Anthropic 關於「agent 權限應隨能力演進」的聲明值得深思。目前 Claude Code 的權限模型是靜態的：你在啟動時設定 allow/deny list，之後 agent 的能力成長不會自動反映到權限邊界上。Cherny 暗示的「動態沙盒化」可能是下一個重大架構變革——如果 agent 發現自己能夠理解某個新框架，系統就自動開放相應的檔案存取權；反之，如果 agent 在嘗試執行危險操作，沙盒就自動收緊。這種「自適應權限」對終端環境尤其重要，因為 terminal 是離系統核心最近的地方，一個過度授權的 agent 造成的破壞遠比在瀏覽器中嚴重。
