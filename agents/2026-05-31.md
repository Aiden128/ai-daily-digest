# AI Agents Digest - 2026-05-31

## 今日頭條

### Claude Code v2.1.158 發布：Auto Mode 正式登陸 Bedrock、Vertex 與 Foundry

Anthropic 於 5 月 30 日發布 **Claude Code v2.1.158**，其中最具戰略意義的更新是 **Auto Mode 支援擴展至 Amazon Bedrock、Google Vertex AI 與 Azure AI Foundry**，且適用於 Opus 4.7 與 4.8 模型。此前 Auto Mode 僅限於 Anthropic 官方 API 用戶，這次更新意味著企業用戶與雲端託管環境的開發者也能體驗「無需人工確認即可連續執行工具呼叫」的全自動 agent 體驗。

技術實現上，使用者需設定環境變數 `CLAUDE_CODE_ENABLE_AUTO_MODE=1` 來啟用。Auto Mode 的核心價值在於將「人機協作」轉為「人機協作 with 可選介入」——Claude 會在需要時主動詢問，但對於低風險的檔案讀取、測試執行、git 操作等可以自主完成。對於 Bedrock 與 Vertex 的支援尤其重要，因為許多企業的資安政策禁止直接使用 Anthropic API，而雲端市場通路是合規的唯一入口。

這次更新延續了 Anthropic 近期「平台化」策略：從單一 CLI 工具轉向可嵌入不同雲端環境與企業工作流的 agent 基礎設施。對於終端用戶而言，這意味著無論你的組織使用哪種 AI 供應商合約，Claude Code 都能提供一致的 agentic 編程體驗。

### Herdr：專為 AI 編程 Agent 打造的終端多工器，一週內飆升至 3,200+ Stars

本週 Hacker News 與 GitHub 上最受矚目的 TUI 新創工具是 **Herdr**（`ogulcancelik/herdr`）——一款「活在終端裡的 agent 多工器」（agent multiplexer）。截至發稿已達 **3,215 stars**，儴然成為 AI 原生終端工具的現象級專案。

Herdr 的核心概念是：如果 tmux 是為人類設計的終端多工器，那麼 Herdr 就是為 AI agent 設計的。它提供 workspace、tab、pane 三層組織結構，支援滑鼠原生操作（點擊、拖曳、分割），並且「每個 agent 一目瞭然」：blocked、working、done 等狀態直接在介面中呈現。最重要的是，agent 執行的是它自己的終端，而非某個 GUI 應用程式對終端的「詮釋」。

技術架構上，Herdr 採用背景 session server 模式：在專案目錄執行 `herdr` 即可啟動或 attach 到現有 session。快捷鍵沿用 tmux 慣例（`ctrl+b` 前綴），並擴充了 agent 專用指令如建立 workspace、切換 agent pane 等。它支援 detach/reattach，agent 在背景持續運行。目前支持 Claude Code、Codex CLI、Aider 等主流工具。

**對終端生態的影響：** Herdr 的出現標誌著終端工具設計範式的轉移——從「人類操作多個 shell」到「人類監督多個自主 agent」。這與傳統 tmux/zellij 的定位截然不同。值得觀察的是，Herdr 是否會與 zellij 的 plugin 系統或 tmux 的現有生態整合，抑或走向完全獨立的協議。

### Forge：本機 LLM 工具呼叫的「防彈背心」，讓 8B 模型從個位數飆升至 84%

**Forge**（`antoinezambelli/forge`）是一款專注於「提升自架 LLM 工具呼叫可靠性」的 Python 框架，近日在 GitHub 獲得 **1,927 stars**。其最引人注目的數據是：**Forge 能將 8B 本機模型在 26 場景評測中的成功率從個位數提升至 84%**，甚至連 Claude Sonnet 4.6 也能從 85% 推升至 98%。

Forge 不是 agent 編排器，而是「agent 迴圈內的可靠性層」。它提供三種使用方式：
1. **Proxy Server**——開箱即用的 OpenAI / Anthropic API 相容代理，座落在客戶端與本機模型伺服器之間。Claude Code、Aider、opencode、Continue 等工具只要將端點指向 Forge，就能透明地獲得 guardrails 保護。
2. **WorkflowRunner**——完整的結構化 agent 迴圈管理，包含系統提示詞、工具執行、上下文壓縮與 guardrails。
3. **Guardrails 中介層**——可嵌入自訂編排迴圈的組合式中介件，負責驗證回應、搶救格式錯誤的工具呼叫、強制執行必要步驟。

技術上，Forge 的 guardrails 包含「救援解析」（rescue parsing，當模型輸出不符合 JSON schema 時自動修復）、「重試提示」（retry nudges，以結構化方式要求模型修正）以及「回應驗證」。它也支援 `required_steps`、`prerequisites` 與 `terminal_tool` 等可選約束，讓開發者在需要時施加流程控制。

**對終端用戶的影響：** Forge 打破了「本機模型不適合 agent 工作」的迷思。對於擔心 API 費用或資料外洩的開發者，Forge 讓 Ollama、llama.cpp、vLLM 等本機後端真正具備生產力。Proxy 模式尤其巧妙——無需重寫現有工具鏈，只需改變 API 端點即可。

## 核心工具更新

- **OpenAI Codex CLI v0.135.0** (2026-05-28) — 本次更新聚焦「開發者體驗與操作效率」：
  - `codex doctor` 現在提供更豐富的環境、Git、終端、app-server 與執行緒庫存診斷，大幅簡化支援案例的資訊收集。
  - TUI 的 `/status` 指令現在會顯示遠端連線細節與伺服器版本（當透過遠端傳輸連接時）。
  - **Vim 模式獲得重大強化**：新增文字物件編輯（text-object editing）、改善的字詞/行尾行為，以及可設定的中斷回合綁定鍵。
  - `/permissions` 現在支援「具名權限設定檔」（named permission profiles），允許團隊預先定義一組權限模板並快速切換。
  - 打包版 Codex 能在支援的 macOS 與 Linux 目標上自動發現並使用捆綁的 patch zsh helper。
  - Python SDK 公開了友善的 `Sandbox` 預設集，簡化 thread 與 turn API 的使用。
  - 安裝腳本 `install.sh` / `install.ps1` 支援 `CODEX_NON_INTERACTIVE=1` 的非互動安裝模式，對 CI/CD 與容器建構更友善。

- **Claude Code Proxy** (`raine/claude-code-proxy`，124 stars) — 一個讓 Claude Code 透過 ChatGPT Plus/Pro 或 Kimi Code 訂閱運作的本地代理。對於同時持有 OpenAI 或月之暗面帳號、但想繼續使用 Claude Code 介面的開發者，這是極具吸引力的橋接方案。支援 Homebrew 安裝與預建二進位檔，本週獲得 **124 stars**。

- **Dragoman** (`asakin/dragoman`，4 stars) — 讓 Claude Code 的 sub-agent 系統能夠呼叫非 Anthropic 模型（Ollama、Perplexity、OpenAI、Gemini）的小型 CLI。概念類似「模型路由器」：Claude 判斷問題類型後，Dragoman 自動轉發給最適合的後端（例如搜尋題給 Perplexity、本機推理給 Ollama）。目前處於 alpha 階段，**4 stars**。

## 研究亮點

### Statewright：以「狀態機護欄」馴服 AI Agent 的失控工具呼叫

**Statewright**（`statewright/statewright`，**372 stars**）提出了一個與 Forge 互補但方向不同的解決方案：不是提升模型本身的工具呼叫準確度，而是**限制模型在特定階段能呼叫的工具集合**。其核心理念是「Agents are suggestions, states are laws」——給予模型 40+ 工具與開放式問題時，它會重複讀取同一個檔案五次、在審查階段呼叫編輯工具、在測試通過前部署。Statewright 用狀態機將這些行為硬性禁止。

運作方式：開發者定義工作流程狀態（例如 Planning → Implementation → Testing → Deploy），每個狀態僅開放特定工具。處於 Planning 狀態時，編輯工具會被拒絕並提示「如需編輯請先 transition 至 Implementation」。狀態機支援迴圈與重試（與 DAG 不同），這更符合 agentic 工作的實際需求。

Statewright 提供視覺化工作流程編輯器，並以 Claude Code 外掛形式分發（`/plugin marketplace add statewright/statewright`）。值得注意的是，文件明確指出「低於 13GB 的模型能產生工具呼叫但無法保留足夠檔案內容以進行準確編輯」，這揭示了本地 agent 部署的硬體門檻。

**技術評估：** Statewright 與 Forge 分別從「流程約束」與「呼叫修復」兩個維度提升 agent 可靠性。兩者結合使用——Forge 修復格式錯誤的工具呼叫，Statewright 確保呼叫發生在正確的語境——可能是目前自架 agent 最務實的可靠性策略。

## 快速咬文

- **PlanBridge** (`contextbridge/planbridge`，23 stars) — 讓你像 review 程式碼一樣 review AI agent 的執行計畫。它攔截 Claude Code 與 Codex CLI 的 plan，讓你在任何一行加上精確回饋，agent 在寫下第一行程式碼前就會調整。完全本地運行，計畫內容不會外傳。
- **Cordon** (`marras0914/cordon`) — MCP 工具呼叫的安全閘道，強制實施 HITL（Human-in-the-Loop）審批。對於「想部署 AI agent 但不敢給資料庫鑰匙」的企業，Cordon 試圖彌補 MCP 本身缺乏安全模型的缺口。
- **InsForge** (`InsForge/InsForge`，10,780 stars) — 號稱「AI 編程 agent 的開源 Heroku」，提供資料庫、認證、儲存、運算、託管與 AI 閘道的一站式後端平台，讓 coding agent 能端到端地交付全端應用。
- **amux** (`mixpeek/amux`，208 stars) — 開源的 Claude Code 控制平面，透過 tmux 在背景並行執行數十個 agent session，並提供網頁儀表板、kanban 看板與 agent-to-agent 協調功能。單檔案、零外部依賴、自癒式 watchdog。
- **kmux** (`kkd927/kmux`，4 stars) — macOS 原生的 AI agent 工作區，讓 Claude Code、Codex CLI 與 Gemini CLI 並排運行，整合用量監控、即時恢復與 worktree-safe 分支管理。
- **Séance** (`no1msd/seance`，50 stars) — GTK4 捲動式終端多工器，專門追蹤 AI coding agent 的輸出流，讓你可以「通靈」觀察多個 background agent 的即時狀態。
- **xAI Grok Build** — 根據開發者社群觀察，xAI 已正式推出 Grok Build，進軍終端 AI 編程代理市場。具備互動式 TUI、Plan Mode、Headless 模式與 Skills/Plugins 系統，直接與 Claude Code、Codex CLI 競爭。
- **Hacker News 熱議：**〈Anyone else went through the AI-editor carousel back to the terminal?〉——多位開發者分享從 Cursor、Windsurf 等 GUI 編輯器「迴歸」終端代理的經驗，主張「TUI 的簡潔性與可組合性勝過華麗的 IDE 包裝」。

## 編者註（Editor's Note）

本文稿經由 **realcoder-panel** （Claude Code Opus 4.7）快速 fact-check，以下是重要修正與補充：

1. **Forge 數據必須加上基準線說明**：文中「8B 模型從個位數飆升至 84%」與「Sonnet 4.6 從 85%推至 98%」是指在 Forge 自身的 26-場景評測套件中，「未使用 guardrails 的原始提示」對比「啟用 guardrails 、重試、格式校正」之後的結果。這並非「模型能力提升」，而是「框架對提示工程的增益」。引用時應注明基準線條件，避免誤導讀者。

2. **Claude Code v2.1.158 Auto Mode 擴展**：官方 release notes 指出「Auto mode is now available on Bedrock, Vertex, and Foundry for Opus 4.7 and Opus 4.8」，但實際啟用仍需 `CLAUDE_CODE_ENABLE_AUTO_MODE=1`，且各後端的支援程度可能微有差異。建議使用者在各自家雲平台實測確認。

3. **xAI Grok Build 發布狀態待確認**：「正式進軍」是強斷言。目前社群資訊顯示 Grok Build 已推出，但其是否為 GA、還是 preview/邀請制、TUI 是否已實裝等細節尚未明確。文中已使用「根據開發者社群觀察」作為來源修飾，但讀者應將此項視為「待確認」。

4. **GitHub Stars 即時漂移**：文中 Herdr 3,215、Forge 1,927、Statewright 372 等數據為 2026-05-31 10:00 CST 前後抓取的即時值，實際數字每小時漂移。引用時建議標註抓取時間。

5. **Herdr 「支援」用詞收緊**：Herdr 對 Claude Code、Codex CLI、Aider 的支援，更準確的說法是「能在其 pane 內執行」（即「可承載 / compatible」），而非「原生整合」。已在正文修正為「目前支持...等主流工具」，但讀者應理解為「終端內執行」而非 API 層接觸。

6. **Claude Code Proxy 風險提示**：「用 ChatGPT 訂閱運行 Claude Code」屬於繞過官方計費機制的灰色用法，可能觸及 OpenAI 服務條款。Digest 中已保留中性描述，但編者註應提醒讀者：**此類代理工具存在服務條款風險，生產環境使用前請評估合規性。**

7. **HN 「迴歸終端」為意見討論**：該文為「Ask HN」討論貼，屬於開發者個人經驗與觀點，非經驗證的客觀趨勢。文中已使用「熱議」一詞，但編者註應強調其「意見性」。
