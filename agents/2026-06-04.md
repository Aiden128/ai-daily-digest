# AI Agents Digest - 2026-06-04

## 今日頭條

**OpenAI Codex CLI v0.137.0 穩定版發布：F13-F24 按鍵綁定、企業雲端配置 Bundle 與多代理 v2 架構** —— 6 月 4 日，OpenAI 發布 Codex CLI 的穩定版本 v0.137.0（由 rust 分支構建），距離上個 alpha 版本僅一天，顯示其發布節奏正加速。本次更新對終端開發者最重要的改進包括：(1) **TUI 控制增強**：搜尋選單現在支援貼上操作，狀態列新增「僅顯示推理」的緊湊模式，且完整支援 F13-F24 功能鍵綁定——對使用程式化鍵盤或終端多工環境的高階用戶而言，這消除了過去功能鍵無法映射的限制；(2) **企業與教育管理流程**：管理員現在可以檢視月度信用額度上限，並推送雲端託管的配置 bundle 至 EDU 工作空間，這對需要在數百台學生機器上統一部署 Codex 設定的大學 IT 部門至關重要；(3) **遠端控制 RPC 擴充**：app-server v2 現在允許遠端控制客戶端發起配對、列出或撤銷控制授權，這意味著「一個雲端 Codex 進程服務多個本地 TUI 客戶端」的架構已從實驗走向可用；(4) **多代理 v2**：每個執行緒（thread）現在獨立保留執行時選擇，並為衍生代理提供更乾淨的後續追蹤與預設後設資料。

> 對終端開發者的實務影響：如果你使用 Codex 的 app-server 模式在遠端伺服器上執行長時間任務，v0.137.0 的遠端控制 RPC 讓你終於可以「從筆電 A 發起配對，從筆電 B 撤銷授權」，而無需直接 SSH 進伺服器操作。企業配置 bundle 的推出也標誌著 Codex CLI 正從「個人駭客工具」轉型為「可集中管理的開發基礎設施」。建議所有 app-server 用戶盡快升級以獲取穩定性修復——本次修復了 macOS 啟動、Windows SQLite 啟動、執行緒恢復與沙箱設定更新等多項平台可靠性問題。

**Claude Code v2.1.162 發布：`claude agents --json` 新增 `waitingFor`、搜尋工具修復與大量背景 Session 穩定性改進** —— 6 月 3 日，Anthropic 推出 v2.1.162，這是繼前日 v2.1.160/161 後的連續第三個版本，顯示其正處於高頻迭代週期。核心變更包括：(1) **`claude agents --json` 新增 `waitingFor` 欄位**，現在可以精確看到一個等待中的 session 被什麼阻擋（例如權限提示），這對同時管理數個背景代理的開發者而言是關鍵的可觀測性提升；(2) **`--tools` 顯式列出 Grep/Glob** 時，現在會在原生構建（內嵌搜尋）上提供專用的搜尋工具，過去這些名稱會被靜默忽略；(3) **遠端控制改為持續性頁尾膠囊**（persistent footer pill）並附帶 session 連結，取代過去的啟動訊息，減少視覺干擾；(4) **大量背景 session 修復**：修正了寬終端上 `claude agents` 狀態文字被截斷至 60-120 欄的問題、長 session 名稱在 40 欄截斷的問題、背景服務重啟後首次 attach 彈回列表的問題、Ctrl+V 貼上圖片無反應的問題、背景化時對話靜默遺失的問題、以及跨 session 訊息傳送失敗後遺失的問題。此外，MCP 伺服器子秒級（<1000ms）timeout 配置過去會被錯誤地進位為 1 秒並中止所有工具呼叫，現在已修正為忽略不合理的子秒值並回退至預設值。

> 對終端開發者的實務影響：如果你曾因 `claude agents` 畫面在寬螢幕上顯示殘缺、或背景 session 過夜後對話遺失而困擾，v2.1.162 幾乎一次性修復了所有已知的背景 session UI 與狀態同步問題。這對將 Claude Code 作為「常駐背景工作管家」的用戶是重大更新，建議立即升級。

**Show HN: Mnemo —— 本機優先的 AI 記憶層，Rust + SQLite + petgraph 實現持久知識圖譜** (Jun 3, 25 pts) —— [GitHub](https://github.com/zaydmulani09/mnemo)  
Mnemo 是一個以 Rust 撰寫的側車（sidecar）服務，為任何 LLM（Ollama、OpenAI、Anthropic 或任何 OpenAI 相容後端）提供「跨對話持久記憶」。其核心機制是：當你 POST 一段對話文字至 `/ingest`，Mnemo 會呼叫配置的 LLM 提取命名實體（人、工具、地點、概念）與它們之間的關係，將結果寫入 SQLite 並更新記憶體中的 petgraph 知識圖譜。當你需要上下文時，POST `/retrieve` 會觸發六階段檢索管道：全文區塊搜尋 → 實體名稱搜尋 → 圖譜擴展（BFS）→ 關係過濾 → 評分排序 → 組裝 `context_prompt` 字串，整個過程在 50 毫秒內完成。

> 對終端開發者的實務影響：與雲端記憶服務（如 Komi-learn、Jolli）不同，Mnemo 是「零雲端依賴」的單一靜態二進位檔，特別適合對隱私敏感或希望在本地完全掌控資料的開發者。如果你經常發現「上個 session 教過 Claude Code 的專案慣例，今天又要重新解釋一遍」，Mnemo 提供了一個不需要向量資料庫的輕量級替代方案——只需將 `context_prompt` 注入系統提示詞即可。它同時提供 Rust crate、Python SDK 與 Docker Compose 部署方式。

**LLM 滲透測試實戰：研究者花費 1,500 美元比較各大模型破解漏洞 App 的能力** (37 pts on HN) —— [kasra.blog](https://kasra.blog/blog/i-spent-1500-seeing-if-llms-could-hack-my-app/)  
安全研究者 Kasra 建構了一個故意留下漏洞的 React Native / FastAPI 書評 App，目標是利用內嵌的 `google-services.json` 直接存取 Firebase Firestore。他讓 GPT-5.5、DeepSeek V4 Pro、Claude Sonnet 4.6、Claude Opus 4.8 等模型各嘗試 10 次，每次上限 10 美元、兩小時。結果：**GPT-5.5 以 7/10 的破解率居冠**，平均每次破解成本僅 9.46 美元；**DeepSeek V4 Pro 3/10**，但單次成本僅 0.62 美元，性價比最高；**Claude Sonnet 4.6 與 Opus 4.8 各 2/10**，有趣的是 Opus 多次「差一點成功」，卻因安全護欄（late refusals）在關鍵時刻終止 session。所有 Gemini 模型與 MiniMax M2.7 均未成功（0/10）。

> 對終端開發者的實務影響：這個實驗揭示了兩個重要信號。第一，**GPT-5.5 在「自主探索 + 工具使用」的攻防場景中展現了顯著優勢**，幾乎每次都能正確識別 Firebase 作為攻擊面，而非浪費時間在已加固的 API 上。第二，**Claude 的安全護欄在滲透測試等「合法惡意」場景中成為雙面刃**——雖然阻止了濫用，但也中斷了授權安全研究。對使用 AI 代理進行自動化安全稽核的團隊，這意味著可能需要為代理設定明確的「紅隊模式」豁免規則，或選擇在不同階段切換不同模型（例如用 Claude 規劃、用 GPT-5.5 執行攻擊嘗試）。

## 技術深度剖析

### Codex v0.137.0：從「個人 CLI 工具」到「企業級代理基礎設施」的轉捩點

Codex CLI 的 v0.137.0 穩定版雖然版本號遞增不大，但其功能組合明確指向兩個戰略方向：**終端體驗的專業化**與**企業部署的可管理性**。

**TUI 專業化：不再只是「能用的介面」**

支援 F13-F24 功能鍵看似小眾，但它解鎖了一個特定使用場景：開發者將 Codex 嵌入 tmux 或 Zellij 等多工環境，並希望用功能鍵快速切換代理狀態、觸發巨集或呼叫自訂快捷指令。搜尋選單支援貼上操作則解決了「在大量技能列表中快速定位」的痛點——過去需要手動輸入關鍵字過濾，現在可以直接貼上完整的技能名稱或路徑。緊湊推理狀態模式則讓小螢幕（如遠端 SSH 終端或平板上的終端模擬器）能更好地展示代理的思考過程，而不被進度條與狀態圖示佔據過多空間。

**企業配置 Bundle：「基礎設施即程式碼」進入 AI 代理領域**

v0.137.0 允許管理員透過雲端推送配置 bundle，這相當於將 Codex 的設定（模型選擇、權限規則、技能安裝列表、MITM 代理憑證等）納入版本控制與自動化部署流程。對於擁有數百台開發機器或數千名學生的組織，這消除了「每台機器手動設定」的痛苦。結合同版本中「環境身份識別的權限請求」與「受管 MITM 代理匯出可讀 CA bundle 至子命令」的改進，Codex 正在建立一套完整的「代理執行環境治理」框架——這是單人開發者不需要、但企業安全團隊迫切要求的基礎設施。

**多代理 v2 與外掛 JSON 輸出**

多代理 v2 讓每個執行緒獨立保留執行時選擇，並為衍生代理提供更乾淨的後設資料預設值。這解決了 v1 中「子代理繼承父代理的錯誤模型或過期上下文」的問題。同時，`codex plugin list --json` 的機器可讀輸出讓 CI/CD 管道可以自動驗證技能安裝狀態，將代理配置納入自動化測試範圍。

## 核心工具更新

- **fzf v0.73.1** (May 25) — [GitHub](https://github.com/junegunn/fzf/releases/tag/v0.73.1)
  - 修復兩個對 AI 編碼 workflow 有潛在影響的問題：(1) 當 `$FZF_CURRENT_ITEM` 包含 NUL 位元組時，`exec(2)` 會拒絕該環境變數，導致預覽與其他子命令中斷——這在處理二進位檔案名或 AI 生成內容時可能發生；(2) `--listen` 模式的 HTTP body 累積存在 O(n^2) 複雜度，單一約 390KB 的請求就能阻塞單執行緒伺服器達 8 秒。對於將 fzf 作為 AI 代理「互動式檔案選擇器」或「API 端點」的開發者，這兩個修復顯著提升了穩定性。
  - 終端實務影響：如果你在使用 fzf 的 `--listen` 模式與自訂代理整合（例如透過 fzf 的 HTTP API 觸發代理動作），強烈建議升級至 v0.73.1。

- **lazygit v0.62.1** (May 28) — [GitHub](https://github.com/jesseduffield/lazygit/releases/tag/v0.62.1)
  - 修復 v0.62.0 引入的崩潰回歸。對於在 Claude Code 或 Codex session 中頻繁使用 lazygit 進行互動式 rebase、stash 管理與分支切換的開發者，這個修補版本避免了在關鍵操作中途程式崩潰導致倉庫狀態不一致的風險。

## 研究與生態亮點

- **Datasette Agent 的 WASM 沙盒實驗** (Simon Willison, Jun 2) — [Simon Willison](https://simonwillison.net/2026/Jun/2/datasette-agent/)
  - Simon Willison 正在為其 Datasette Agent 建立安全的 Python 程式碼執行環境，採用 MicroPython 的 WASM 構建並透過 wasmtime 執行。他報告「GPT-5.5 目前為止未能突破沙盒」。這個實驗的意義在於：當 AI 代理需要「生成並執行程式碼」時，傳統的容器沙箱（如 gVisor）雖然強大，但啟動成本較高；WASM 提供了一個輕量級、低延遲的替代方案，特別適合需要頻繁執行小段 Python（如資料查詢、格式轉換）的代理 workflow。
  - 對終端開發者的啟示：如果你正在為自訂代理設計「安全執行用戶提供的程式碼」功能，可以考慮 WASM + wasmtime 作為容器沙箱的補充方案，尤其在延遲敏感的互動場景中。
