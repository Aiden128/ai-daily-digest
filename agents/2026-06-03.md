# AI Agents Digest - 2026-06-03

> 今日重點：OpenAI Codex CLI 發布 v0.137.0-alpha.4，強化 app-server 遠端控制能力；Anthropic 連續推出 Claude Code v2.1.160/161，大幅加強代理安全性與背景 session 穩定性；終端 AI 編碼代理的周邊生態持續爆發——Paseo、Revdiff、Clor、Nezha 等專案從不同角度解決「多代理管理」「差異審查」「背景自動化」「持久記憶」等痛點。

## 今日頭條

**OpenAI Codex CLI rust-v0.137.0-alpha.4 發布：遠端控制 RPC 與擴展輸入貢獻者機制** —— 6 月 3 日，OpenAI 發布 Codex CLI 的最新 alpha 版本 v0.137.0-alpha.4。雖然 release notes 極為簡短，但從 commit 紀錄可看出兩個關鍵方向：(1) **app-server 遠端控制客戶端管理 RPCs** (#25785) —— 這代表 Codex 的 app-server 模式正從「單一 session 遠端監控」進化為「多客戶端協調管理」，為未來的分布式代理編排奠定基礎；(2) **extension turn-input contributors** (#25959) —— 允許外掛在對話輪次中貢獻輸入，意味著第三方工具可以更深層地介入 Codex 的思考流程。此外，EDU 教育帳號現在可以獲取雲端配置 bundle (#25963)。

> 對終端開發者的實務影響：如果你已在生產環境使用 Codex 的 app-server 模式（例如透過遠端伺服器運行 Codex 並從本地 TUI 連線），這個 alpha 版本的 RPC 增強可能讓你能同時管理多個 Codex session——類似 Claude Code 的 `claude agents` 功能。但 alpha 版本不建議用於關鍵任務，建議在沙箱環境測試後再評估升級。

**Claude Code v2.1.160/161 連續發布：代理安全性強化、並行工具呼叫獨立化、背景 session 穩定性大幅提升** —— Anthropic 在 6 月 2 日連續發布兩個版本。v2.1.160 聚焦安全性：(1) 寫入 shell 啟動檔（`.zshenv`、`.bash_login` 等）與建構工具配置（`.npmrc`、`.bazelrc`、`.pre-commit-config.yaml` 等）前會先提示確認，防止代理意外植入持久化命令；(2) `grep` 單檔搜尋後可直接編輯，不再需要額外的 Read 步驟；(3) 修復背景 session 過夜後重新連線時遺失對話、重跑原始提示的問題；(4) Windows 背景 session 的鍵盤與 Esc 無響應問題。v2.1.161 則強化可觀測性與協作：`OTEL_RESOURCE_ATTRIBUTES` 現在會成為指標資料點的標籤，方便團隊按維度切分使用量；並行工具呼叫時，單一 Bash 命令失敗不再取消同批次其他呼叫——每個工具獨立返回結果。

> 對終端開發者的實務影響：v2.1.160 的安全性改進是「代理安全」領域的重要里程碑。過去開發者擔心 Claude Code 可能在不知情的情況下修改 shell 啟動檔或安裝惡意依賴，現在這些高風險操作都有明確的確認提示。對於團隊使用，v2.1.161 的 OpenTelemetry 標籤讓管理者能按團隊或專案追蹤 API 使用量與成本。建議所有 Claude Code 使用者立即升級。

**Show HN: Paseo —— 一個介面統管 Claude Code、Codex、Copilot、OpenCode 與 Pi** (Jun 2, 22 pts) —— [GitHub](https://github.com/getpaseo/paseo)  
Paseo 是一款自架式（self-hosted）多提供商代理管理介面，讓開發者能從手機、桌面或 CLI 同時運行多個 AI 編碼代理。核心賣點是「代理在你的機器上運行，使用你的開發環境、你的配置、你的技能」，而非將程式碼上傳到雲端 IDE。目前支援 Claude Code、Codex、Copilot、OpenCode 與 Pi。

> 對終端開發者的實務影響：如果你同時使用多個代理工具（例如用 Claude Code 處理複雜重構、用 Codex 快速原型、用 Copilot 自動補全），Paseo 提供了一個統一的切換介面，無需記住每個工具的啟動指令。但需注意，「統一介面」可能犧牲各工具的原生功能深度——建議先評估是否習慣在單一介面中操作不同個性的代理。

**Show HN: Revdiff —— 專為 AI 編碼 session 設計的 TUI 差異審查工具** (Jun 2, 17 pts) —— [GitHub](https://github.com/umputun/revdiff)  
Revdiff 是一個終端差異審查工具，專為「不離開 AI 編碼 session 就能審查變更」而設計。它支援行內註釋（inline annotations）、結構化輸出到 stdout（可 pipe 給代理或腳本）、word-diff、Jujutsu 與 Mercurial 支援、blame gutter、Vim 風格搜尋，以及 Markdown TOC 導航。最關鍵的設計哲學是「剛剛好的 UI」——足以導航差異、標註特定行、將結果返回給呼叫進程，不多不少。

> 對終端開發者的實務影響：在 Claude Code 或 Codex session 中審查大型 PR 或重構結果時，開發者常需要在代理 TUI 與 git diff 之間切換。Revdiff 可以作為中間層，讓代理直接呼叫 `revdiff` 並將你的行內註釋讀回，形成「代理生成變更 → 人類標註問題 → 代理根據註釋修正」的閉環。對於習慣終端工作流的團隊，這可能取代部分 GUI code review 工具。

## 技術深度剖析

### Claude Code v2.1.160：「代理安全」從邊緣議題變為核心功能

Claude Code v2.1.160 看似只是常規修補版本，但其安全性改動反映了 Anthropic 對「代理權限失控」這一根本問題的嚴肅回應。過去數月，社群不斷討論 AI 編碼代理的潛在風險：一個被 social engineering 的 prompt 可能誘使代理修改 `.bashrc` 植入後門，或透過 `.npmrc` 替換 registry 為惡意伺服器。v2.1.160 的改進直接針對這些攻擊向量：

**高風險檔案寫入確認**
當 Claude Code 嘗試寫入 shell 啟動檔（`.zshenv`、`.zlogin`、`.bash_login`）或版本控制/建構工具配置（`.npmrc`、`.yarnrc*`、`bunfig.toml`、`.bazelrc`、`.pre-commit-config.yaml`、`.devcontainer/` 等）時，現在會彈出明確的確認提示。這意味著代理無法在背景中「安靜地」持久化惡意行為——即使 prompt 注入成功，仍需要用戶的最終授權。

**AcceptEdits 模式的額外防護**
在 `acceptEdits` 模式下（代理自動接受所有編輯建議），寫入上述建構工具配置檔前同樣會提示。這對於使用「全自動模式」的開發者尤其重要——它確保「自動化」不會逾越「安全」的界線。

**讀取-編輯一致性優化**
過去 Claude Code 要求「先讀取檔案才能編輯」，這導致一個繁瑣的流程：即使 `grep` 已經顯示了檔案內容，仍需發出額外的 Read 請求。v2.1.160 讓單檔 `grep`/`egrep`/`fgrep` 命令直接滿足 read-before-edit 檢查，減少了一輪 API 呼叫，也讓「搜尋後立即編輯」的直覺更符合人類開發者的習慣。

**背景 Session 穩定性**
v2.1.160 修復了多個背景 session 的致命 bug：已完成 session 從 `claude agents` 恢復時遺失歷史並重跑原始提示；背景 session 過夜後重新連線遺失對話；`claude --bg` 在機器負載高時偶發「socket missing」；Windows 上背景 session 的目錄無法刪除直到 daemon 退出。這些修復對於將 Claude Code 作為「長時間運行任務管家」的開發者至關重要。

### Codex v0.137.0-alpha.4：app-server 的「多客戶端管理」意味著什麼？

Codex CLI 的 app-server 模式允許開發者在遠端伺服器上啟動一個長時間運行的 Codex 進程，然後從本地 TUI 連線控制。v0.137.0-alpha.4 新增的「remote control client management RPCs」暗示 OpenAI 正在將這個架構擴展為「一個 app-server 服務多個客戶端」。

這可能意味著：
1. **團隊共享代理**：一個在雲端伺服器上運行的 Codex app-server 可以同時接受多個團隊成員的連線，每個人看到自己的 TUI，但代理操作同一個程式碼庫。
2. **代理編排**：未來可能允許一個「主控」Codex session 協調多個「從屬」app-server session，形成類似 Claude Code Dynamic Workflows 的分布式任務處理能力。
3. **擴展輸入貢獻者**：第三方工具（如 MCP server）可以在對話輪次中注入額外上下文，讓代理能綜合多個資訊源做出決策。

目前這仍是 alpha 功能，不建議用於生產環境，但方向明確：Codex CLI 正從「單人單機工具」演進為「可分布式部署的代理基礎設施」。

## 核心工具更新

- **Nezha** (Show HN, Jun 2) — [GitHub](https://github.com/hanshuaikang/nezha)
  - 定位為「Agent-First IDE For Vibe Coding」，支援同時運行 Claude Code 與 Codex 並跨專案切換。整合原生 Git、即時終端、session 自動發現、輕量級程式碼編輯器，安裝包僅 7MB。對於覺得傳統 IDE 過於臃腫、但單純終端又缺乏專案結構可視化的開發者，Nezha 提供了一個中間方案。
  - 終端實務影響：Nezha 的「session 自動發現」功能可以掃描機器上正在運行的 Claude Code 或 Codex session 並提供統一入口，這對於習慣同時開多個終端分頁的開發者可能減少 context switching 負擔。

- **Promptloop** (Show HN, Jun 2) — [GitHub](https://github.com/Bella3202019/promptloop)
  - 終端內的提示詞評估（prompt eval）互動代理。支援建立測試案例、執行評估、生成報告、核准提示差異，所有資料保存在專案內的 `.evals/` 目錄。內建延遲、JSON schema 驗證、fuzzy match、LLM judge 等指標。
  - 終端實務影響：如果你正在為團隊調校 Claude Code 或 Codex 的系統提示詞（system prompt），Promptloop 提供了一個可重複的評估框架——修改提示詞後運行相同測試案例，量化比較前後差異，避免「感覺變好了」的主觀偏差。

- **Terse** (Show HN, Jun 2) — [GitHub](https://github.com/TerseAI/Terse)
  - TypeScript 優先的 AI 工作流程建構平台，專為「編碼代理時代」設計。從工作空間生成型別安全的 SDK，部署混合「確定性工具呼叫」與「代理循環」的無伺服器工作流程。提供 Claude Code 外掛（skill）。
  - 終端實務影響：Terse 的核心價值在於將「代理的即興行為」封裝成「可版本控制、可重複執行的工作流程」。對於需要將 AI 編碼代理整合進 CI/CD 或自動化管道的團隊，這種「程式碼優先」的方法比純對話式介面更易維護。

## 研究與生態亮點

- **Project Brain —— Claude Code 的持久化導航記憶** (Show HN, Jun 2) — [GitHub](https://github.com/OoneBreath/claude-code-project-brain)
  - 不是資料庫、不是伺服器、不是另一個 AI 包裝器——而是一套約定加外掛：在專案中建立 `.project-brain/` 資料夾，裡面是純 Markdown 檔案，描述專案的架構、決策、已知陷阱與歷史。Claude Code 透過索引只載入需要的細節，避免每個 session 都重新解釋整個專案。
  - 技術意義：這代表了「代理記憶」的一種輕量級實現——不依賴向量資料庫或雲端服務，而是利用檔案系統與結構化 Markdown。對於擔心隱私或成本的開發者，這種「本機優先」的方案比 Komi-learn 或 Jolli 等雲端記憶工具更具吸引力。

- **Recall —— 跨工具 AI 對話歷史搜尋引擎** (Show HN, Jun 2) — [GitHub](https://github.com/pratikgajjar/recall)
  - 唯讀索引 Cursor、Claude Code、Codex 與 pi 的本機對話儲存，建立 SQLite 搜尋索引，讓開發者能從終端用 `recall "import cycle"` 找到過去的相關討論。不複製、不修改原始資料。
  - 技術意義：不同代理工具各自儲存對話歷史，導致「上週在 Cursor 裡解決的問題，今天在 Claude Code 裡又問了一遍」的浪費。Recall 提供統一的 grep 介面，並且設計了 pi 擴充功能讓代理可以直接呼叫 `recall_search` 查找過往上下文。

## 快速資訊

- **Clor** (Show HN, Jun 2) — [網站](https://clor.com/) — 讓編碼代理建立「claws」（背景代理），按排程自動執行任務。例如：每天早上檢查依賴項的新 CVE、監控競品定價頁變化、自動整理收件匣收據。Clor 提供 MCP 伺服器、網頁搜尋/截圖、電子郵件、跨模型路由等工具集。核心概念是「代理能做一次的事，claw 就能在背景持續做」。

- **Jolli** (Show HN, Jun 2) — [網站](https://www.jolli.ai) — 為 Claude Code、Codex、Gemini CLI 和 OpenCode 設計的連接知識平台。在提交時自動擷取 AI 編碼上下文，建立結構化的本機知識庫，並可同步至雲端。強調「無需註冊即可下載使用」。

- **KanVibe** (Show HN, Jun 2) — [GitHub](https://github.com/rookedsysc/kanvibe) — 自動透過 hooks 追蹤 AI 代理狀態的看板。當 Claude Code 或 Codex 開始/完成任務時，看板自動更新卡片狀態。對於需要視覺化管理多個代理任務的團隊，這是一個輕量級補充。
