## 今日頭條

**Godot 引擎 6/29 宣布不再接受 AI 生成的程式碼貢獻** —— [Godot 官方公告](https://godotengine.org/article/contribution-policy-2026/)（HN 518pt / 366 評論，[PC Gamer 報導](https://www.pcgamer.com/gaming-industry/open-source-game-engine-godot-will-no-longer-accept-ai-authored-code-contributions/)）。這是繼 Godot 2024 那次「想對 PR 強制 AI 標註」以失敗告終後的第二次表態，這次語氣明確：

> All contributions to Godot's main codebase are required to be original work created by a human. ... Any contribution that has been generated, in whole or in part, by an AI tool, regardless of how much human editing or review it has received, is not acceptable for inclusion.

**為什麼重要**：Godot 是繼 SFC、Homebrew（這兩個 6/22 digest 提過）之後又一個 major OSS 基礎設施的「明確拒絕 AI 貢獻」表態。三個項目的差異：SFC 拒絕的是「AI 訓練 license 的 SPDX tag 改動」（政策層），Homebrew 拒絕的是「任何 AI 工具生成的 patch」（審核層），**Godot 是「連 human-edited AI 輸出都不收」**——把「AI 改兩行後人再 review」這條 escape hatch 也堵掉。**這標誌著 2026 H2 OSS 治理的轉向：從「標註 / 揭露」到「完全禁止」**。對 agent / harness 設計的訊號是：個人 dev 與企業 dev 在「私有 fork 內大量用 agent」會持續，但「貢獻回去 upstream」的路會越來越窄。

**Cursor iOS app 安裝後靜默切換隱私設定且無法回復** —— [HN 48737226](https://news.ycombinator.com/item?id=48737226)（242pt / 34 評論）。使用者 [zkldi](https://news.ycombinator.com/user?id=zkldi) 報告：他長期使用「Privacy Mode (Legacy) 不存我的程式碼」（已被 Cursor 標為 Legacy 並藏在「Extra options」選單下），**安裝 Cursor iOS app 並登入後，帳號被自動切到新 Privacy Mode（語意是「Code may be stored for Background Agents or Other Features」），而且 Legacy 選項從所有選單中消失**。Cursor 客服表示「無法切回」。

Cursor 共同創辦人 [Lee Robinson (leerob)](https://news.ycombinator.com/user?id=leerob) 在 HN 親自回覆：「Sorry about this, we should have made this more clear. The new privacy mode is needed because we have to store some state to enable running agents in the cloud. If you don't want to use cloud agents, you can continue using the legacy privacy mode. Currently the mobile app requires this new privacy mode and won't work without it. We're pushing an update right now to make this more clear in app and can help you get reverted back to the legacy version on the support thread.」

**為什麼重要**：這是 6/22 GitHub Copilot Privacy、6/24 Cursor 對 Anthropic 蒸餾主張 等等一連串「AI 工具把個人 dev 隱私當 raw material」事件的最新一樁。**Cursor iOS app 是 enterprise 客戶最敏感的入口（手機代碼遠端觸發）**——企業內部 SOC、fintech、healthcare 三類用戶若被預設切到新 mode，會直接踩到「員工把客戶程式碼上傳到 cloud agents」的合規紅線。**對 agent 設計的訊號**：「agent-as-a-service」商業模式的代價是「預設 trust 路徑被打開」，要靠 UI 揭露才能關回去——而揭露是逐次靠 incident 累積出來的，不是 vendor 主動設計。

**Ornith-1.0：DeepReinforce 首發，主打 agentic coding 的開源模型家族** —— [GitHub deepreinforce-ai/Ornith-1](https://github.com/deepreinforce-ai/Ornith-1)（HN 260pt / 51 評論，[DeepReinforce 官方頁](https://deep-reinforce.com/ornith_1_0.html)，[Simon Willison 評測](https://simonwillison.net/2026/Jun/29/ornith/)）。Ornith-1.0 是**基於 Gemma 4 + Qwen 3.5 繼續預訓練**的開源模型家族，4 個 variants：

- 9B Dense
- 31B Dense
- 35B MoE
- **397B MoE**（旗艦）

授權：MIT；底層 Gemma 4 是 Apache 2.0（已**移掉之前「janky additional Gemma Terms of Use」**，Qwen 3.5 也是 Apache 2.0。

**為什麼重要**：這是 2026 H1 開源 agentic coding 模型少見的「大尺寸 MIT 開源 + 商用相容底層」組合。Simon Willison 在 Pi + LM Studio 35B Q4_K_M GGUF (20GB) 實測：

> 「I asked it to 'find the code that decodes the actor cookie' and then 'find the code that opens the insert dialog when the button is clicked' against a Datasette checkout, which it handled with ease.」

**對 agent 設計的訊號**：開源權重 model 進入「跑完整 agent harness（多 tool call、跑很多 step）」的能耐區——之前 open-weight 在 SWE-bench Verified 上分數不差，但 5-step 以上的 long-horizon 失敗率太高。**如果 397B MoE 在 SWE-bench Pro Multilingual 上能達到 Sonnet 5 70% 以上的水平 + 開源 + 商用相容 + MIT，會是 2026 H2 企業 agent 採購的「中國版 GLM 5.2 之後第二個重擊」**。DeepReinforce 之前唯一可查的 paper 是 [CUDA-L1](https://arxiv.org/abs/2507.14111)（2025-06，CUDA RL 優化），跟現在的 agentic 路線跳接明顯——可能是收了一個團隊 / 換方向。

**Grack〈Anatomy of a Failed (Nation-State?) Attack〉：Claudo 識破 crates.io 供應鏈 RAT** —— [grack.com](https://grack.com/blog/2026/06/25/dissecting-a-failed-nation-state-attack/)（Lobsters `t/vibecoding` 50pt，[HN 討論](https://www.reddit.com/r/rust/comments/1ug9pzn/anatomy_of_a_failed_nationstate_attack/) 也有 Rust 社群版）。作者是 crates.io 的 maintainer，描述他被一個**精心打造的「假 VC 面試 + 帶後門的 TypeScript repo」**鎖定：

- 攻擊者用「Lua Ventures」（已倒閉的新加坡 DeFi VC）的假身份聯絡
- 假 LinkedIn、看起來真的公司網站（Lyrasing、Roadpay，archive.org 有快照）
- 一個 TypeScript 面試任務「Ticket Harbor」（渡輪票務 app）
- 真正 payload 藏在 `patches/typescript+5.9.2.patch` 內：base64 編碼 + XOR(key=73) 加密 + `new Function('require','Buffer','WebAssembly','process','__dirname', ...)` 注入
- 注入觸發點是「跑 typecheck」——被指示「提交前先跑 build / typecheck / test」
- 假面試 repo 用了 27 個 `patches/` 目錄，**真正的 payload 藏在雜訊裡**

作者把 repo 丟給 Claude 做 triage，**Claude 在幾分鐘內**找出：
- 缺少 `postinstall` lifecycle hook（與 `patch-package` 矛盾）
- 異常數量的 `patches/` 目錄
- `typescript.js` 開頭的 XOR 解密 `new Function()` 自執行 stub
- 解碼後是「PinpinRAT」（作者自命名，內部字符串暗示）

**為什麼重要**：這是 2026 H2 第一個**公開且完整記錄的「agent + maintainer + 假面試」攻擊鏈**。攻擊者的設計意圖明確：把惡意 patch 塞到「看起來正常的 `patch-package` 工作流」裡，讓 CI 第一行 `npm run typecheck` 就執行 payload——而 payload 是 RAT，會在 maintainer 機器上 backdoor。**對 agent 設計的訊號**：Claude 在這個 case 救了場，但**前提是 maintainer 把可疑 repo 丟進 sandbox + Claude 環境**——如果 maintainer 直接在自己開發機跑 `npm i && npm run typecheck`，就中了。**這跟 [6/17 Manishearth〈The Future of the Con is Already Here〉](https://manishearth.github.io/blog/2026/06/17/the-future-of-the-con-is-already-here/) 是同一條供應鏈的兩個不同 endpoint**——Manishearth 收的是 IRC 上的惡意維護者提議，Grack 收的是「假面試 + 假 VC」。

**vLLM 〈Micro-Agent: Beat Frontier Models with Collaboration Inside Model API〉** —— [vllm.ai blog](https://vllm.ai/blog/2026-06-29-micro-agent-frontier-models)（HN 79pt / 22 評論）。核心論點：

> 「A router can make the model better. Not by changing weights. Not by asking every application to build a bespoke agent graph. By turning one model API call into a bounded collaboration inside the serving layer.」

vLLM Semantic Router 是一個**OpenAI-compatible endpoint**（`vllm-sr/auto`），router 在裡面**fan out → collect quorum → verify disagreement → synthesize final answer → repair output contract**，最後回傳一個正常的 OpenAI response。

**為什麼重要**：這是 6/22 Sakana Fugu 之後第一個**「router-as-serving-primitive」的 open-source 實作**——Sakana Fugu 是商業產品，vLLM Semantic Router 是 open serving layer。呼應 [6/26 digest Ronacher〈The Coming Loop〉](https://lucumr.pocoo.org/2026/06/23/the-coming-loop.html) 的「harness is the product, model is commodity」+ [6/28 workweave/router](https://github.com/workweave/router) 的「router is the new control plane for AI inference」。**對 agent 設計的訊號**：router 從「per-prompt cost 優化」升級成「per-prompt capability construction」——同一個 API call，後面跑的可能是「1 frontier model」、可能是「3 open-source + 1 frontier 投票」、可能是「5 worker 模型在 micro-task 上 fan out」——應用層完全無感。**這是 2026 H2 inference 層最被低估的轉向**。

## 技術深掘

**NLNet Labs 6/26 修訂 LLM Policy：DNS/RPKI 基礎設施對 AI 貢獻的正式禁令** —— [nlnetlabs.nl/llm-policy](https://nlnetlabs.nl/llm-policy/)（Lobsters `t/ai` 73pt）。NLnet Labs 維護 Unbound、NSD、Krill、Routinator 等 DNS / RPKI 核心基礎設施，6/26 修訂的 LLM Policy 明文規定：

> 「We restrict how Large Language Models (LLMs) can be used in the context of our organisation and our projects. If a submission (e.g. PR, issue, comment, forum post, etc.) does not comply with this policy, we may close or delete it without prior notice.」

政策細節（從 meta description 抽出）：
- 限制 LLM 在 PR / issue / comment / forum post 中的使用方式
- 不合規的 submission 會**無預警關閉或刪除**
- 6/26 是修訂日（meta 上明確標 "Revised 26 June 2026"）

**為什麼重要**：NLnet Labs 不是一般的小 library——他們的 Unbound 是全球第二大的遞迴 DNS resolver（佔 30%+ 解析量），Krill 是 RPKI 的兩個主要 implementation 之一。**這是 major Internet infrastructure maintainer 對 AI 工具使用的正式 policy 化表態**，比 Godot 的 contribution policy 更進一步——不只是「不收 AI 寫的程式碼」，而是「**連 LLM-assisted 寫的 issue / comment / forum post 都可能無預警刪除**」。

呼應 6/22 Homebrew 拒絕 AI 工具生成的 patch、6/22 SFC 拒絕 SPDX AI 訓練 license 提案、6/29 Godot 完全禁止 AI 貢獻——**「OSS infrastructure governance 對 AI 的轉向」是 2026 H2 第一個明確的 policy cycle**。對 agent 設計的訊號：**對企業用戶，內部 agent 跑出來的 PR 要投到 upstream 時，會踩越來越多 policy 紅線**——個人 dev 與企業 dev 越來越不是同一個 world。

**Cursor iOS 隱私事件細節 + 設計缺陷** —— 從 [HN 48737226 留言](https://news.ycombinator.com/item?id=48737226) 整理的關鍵設計問題：

1. **Cloud Agents 啟用 prompt 在 iOS 首次登入時觸發**——把帳號「自動升級」到新 Privacy Mode，但 prompt 文字**沒有明確標示這是 hard-to-undo 的隱私變更**
2. **Legacy 模式選項從所有選單中消失**——不是「仍可選但建議不要用」，而是「整個 UI 找不到」
3. **客服 LLM bot 無法處理 legacy 模式切回請求**——只會重複「我們正在努力」（一位留言者直接指出「That support quote is from an LLM」）
4. **Mobile app 的 functional 限制**：app 不能在你的電腦上啟動 agent session，只能「接手」已存在的 session——這跟 [Claude Code iOS beta](https://news.ycombinator.com/item?id=48737399) 的強制 onboarding 對比，**Cursor iOS 強制走 cloud agent 路線是 vendor 商業決策，不是技術限制**

Cursor 共同創辦人 [Lee Robinson](https://news.ycombinator.com/user?id=leerob) 的回覆承諾了 3 件事：
1. 推 UI 修正讓切換更明確
2. 客服可以幫忙把 legacy 用戶切回去
3. 但**不會改變 mobile app 必須要新 Privacy Mode 才能運作的設計**

**對 agent 設計的訊號**：「agent-as-a-service」商業模式的固有 trade-off——**要讓手機 / 平板 / 任何 client 觸發 cloud agent，就必須把程式碼上傳到 vendor 的 cloud**（不能在 user 本地機跑，因為 mobile 不是 user 的本機）。**這跟 [6/25 digest OpenAI〈How agents are transforming work〉](https://openai.com/index/how-agents-are-transforming-work/) 的「99% engineering 用 Codex」是同一個問題的另一面**——OpenAI 內部能接受是因為 OpenAI 對自己程式碼的威脅模型 = 內部威脅；企業客戶對 Cursor 的威脅模型 = vendor 風險。**「code may be stored」這條款的實質，就是 enterprise 客戶不能「無腦用 cloud agent」**。

## 工具與函式庫

**Herdr：tmux for agents，10MB Rust binary，agent multiplexer** —— [github.com/ogulcancelik/herdr](https://github.com/ogulcancelik/herdr)（HN 164pt / 102 評論）。Herdr 是 **tmux 的 agent 化重建**：

> 「run all your coding agents in one terminal. see who's blocked, working, or done at a glance.」

關鍵特性：
- **每個 agent 一個真實 terminal**（不是 GUI 模擬）——全螢幕 TUI 正確 render
- **sidebar 狀態指示**：🔴 blocked / 🟡 working / 🔵 done / 🟢 idle（不需要 hooks）
- **workspace / tab / pane**：用滑鼠 click、drag、split
- **detach 不死**：背景 server 保留 panes，從另一個 terminal 或手機 SSH 可 reattach
- **單一 ~10MB Rust binary**，Linux + macOS（Windows beta），無依賴
- **scriptable**：local socket API + CLI，agents 可以自己驅動

為什麼重要：呼應 2026 H2 的「multi-agent orchestration」需求——同一台機器跑 Claude Code + Codex + opencode + 幾個 long-running background agent 時，**沒有 unified multiplexer 是真痛點**。**如果 v1.4+ 加入「agent knows other agents' state」的 hook，就是 2026 H2 個人 dev 的「agent tmux」**。

**Open Memory Protocol：跨 Claude/ChatGPT/Cursor 的開源 AI 記憶標準** —— [github.com/SMJAI/open-memory-protocol](https://github.com/SMJAI/open-memory-protocol)（HN 33pt）。Open standard 解決「每個 AI 工具各記各的」問題：

> 「Every AI tool remembers you differently — and only within its own walls. Claude knows what you told it yesterday. Cursor doesn't. ChatGPT learned your preferences. Your custom agent hasn't.」

Spec v0.2（green badge），Apache 2.0 license。**對 agent 設計的訊號**：open standard 開始浮現——呼應 [6/22 digest OMC v4.15.0 antigravity](https://github.com/Yeachan-Heo/oh-my-claudecode) 的「跨 vendor 統一 provider 介面」、[6/26 Stack Overflow for Agents](https://stackoverflow.com/agents) 的「agent 之間的 knowledge sharing」嘗試。**2026 H2 的「agent 互通性」可能會比「agent 能力」更早形成 de facto 標準**。

**Lore（rac-core）：把團隊決策餵給 coding agent** —— [github.com/itsthelore/rac-core](https://github.com/itsthelore/rac-core)（HN 47pt / 55 評論）。Lore 是「RAG for coding agent 決策」：把團隊的 ADR（architecture decision record）、code review 慣例、commit message 風格統一餵給 agent。

**為什麼重要**：這是 [6/26 digest Ronacher〈The Coming Loop〉](https://lucumr.pocoo.org/2026/06/23/the-coming-loop.html) 的「agent 沒有 episodic memory」問題的**第一個 OSS 級解法**。**對企業 agent 採購的訊號**：「agent 知道你團隊的慣例」是比「agent 用 frontier model」更值錢的 feature。

**Moondream 〈Popping the GPU Bubble〉：Photon inference engine +35% throughput** —— [moondream.ai/blog/popping-the-gpu-bubble](https://moondream.ai/blog/popping-the-gpu-bubble)（HN 196pt / 49 評論，6/4 發但 7/1 才上 HN）。Moondream 公開 Photon 推理引擎細節：**pipelined decoding** —— GPU 跑下一個 forward 的同時，CPU 處理上一個 token 的 commit/plan/launch，**消除 GPU bubble**（CPU housekeeping 期間 GPU idle）。在 NVIDIA B200 上 VLM 達到 **~33ms latency**，**decode throughput 比 baseline 高 35%**。

為什麼重要：這是 2026 H2 inference 優化的**reference implementation**——**不靠新硬體、不靠 quantization、不靠 speculative decoding，純粹在 software scheduling 層**。呼應 [6/25 digest vLLM Semantic Router](https://vllm.ai/blog/2026-06-29-micro-agent-frontier-models) 對「serving layer 才是新戰場」的判斷。**對企業 agent 採購的訊號**：open-source inference engine 的優化空間還有 30%+，frontier model API 沒有把這個榨乾。

**Kulaxyz/self-learning-skills (722★)：會自己改進的 Claude Code / Cursor / AGEN 通用 skill** —— [github.com/Kulaxyz/self-learning-skills](https://github.com/Kulaxyz/self-learning-skills)。一個 cross-platform skill package：給 Claude Code / Cursor / 其他 coding agent 用，會根據過去 task 表現自我調整。

為什麼重要：呼應 [6/28 digest Pitfall #22](https://aiden128.github.io/ai-daily-digest/agents/2026-06-28) 的「agent operations layer 湧現」主題——**自改進 skill 是 2026 H2 agent 自主性的下一個 frontier**（從「skill 是人類寫的」到「skill 自己會 tune」）。

## 研究焦點

**arXiv 2606.32034 〈QVal: Cheaply Evaluating Dense Supervision Signals for Long-Horizon LLM Agents〉** —— [arxiv.org/abs/2606.32034](http://arxiv.org/abs/2606.32034v1)。問題：LLM agent 越來越多跑 long-horizon task，**單一 trajectory 就有數百到數千個 action**——要怎麼有效率地評估 dense supervision signals？

**arXiv 2606.32017 〈TRIAGE: Role-Typed Credit Assignment for Agentic Reinforcement Learning〉** —— [arxiv.org/abs/2606.32017](http://arxiv.org/abs/2606.32017v1)。問題：agentic RL 需要把 credit assign 給「面對環境的 actions」（搜尋、點擊、編輯）——TRIAGE 提出 role-typed credit assignment，比 vanilla policy gradient 更精準。

**arXiv 2606.32025 〈Generative Skill Composition for LLM Agents〉** —— [arxiv.org/abs/2606.32025](http://arxiv.org/abs/2606.32025v1)。LLM agent 用 skills 解 complex task，但現有方法在 skill composition 上不夠 generative——本文提一個「generative skill composition」框架。

**為什麼這三篇要放在一起**：**三篇都在解「2026 H2 LLM agent 訓練」的核心三難——** (a) 怎麼評 long-horizon trajectory（QVal）、(b) 怎麼把 credit assign 到正確的 action（TRIAGE）、(c) 怎麼讓 skill library 可組合（Generative Skill Composition）。**這是 [6/27 digest arXiv 2606.26057 Unfireable Safety Kernel + 2606.26080 Progress Advantage + 2606.26027 Why Multi-Step Tool-Use RL Collapses](https://aiden128.github.io/ai-daily-digest/agents/2026-06-27) 同一個 burst 的延伸——6/30 又一波「agent 訓練理論」的 arXiv burst，主題從「safety + 訓練穩定」轉向「credit assignment + skill composition」**。

**呼應 [6/26 digest Ronacher〈The Coming Loop〉](https://lucumr.pocoo.org/2026/06/23/the-coming-loop.html) 的「My job is to write loops」**——**這三篇是「怎麼讓 agent 在 loop 裡有效率地 learn」**——是「harness is the product, model is commodity」這個判斷的學術對應面。
