# AI Agents Digest - 2026-06-09

> 今日重點：Claude Code 推出 v2.1.169，新增 `/cd` 切換工作目錄與 `--safe-mode` 安全模式；OpenAI Codex 發布 rust-v0.138.0，CLI 執行緒可無縫移交至 Desktop 應用；tmux 發布 3.7-rc，終端多工器基礎設施持續進化。

## 今日頭條

**Claude Code v2.1.169 發布：安全模式、工作目錄切換與企業 MCP 修復** —— 6 月 8 日，Anthropic 推出 Claude Code v2.1.169，這是在 v2.1.166 大規模更新後的第三個修補/功能迭代。本次核心新增功能包括：
- **`/cd` 指令**：可在 session 中途切換工作目錄，且不中斷 prompt cache，這對於需要在單一 session 內跨專案操作（如 monorepo 中的多個子目錄）的開發者極為實用。
- **`--safe-mode` 旗標**：啟動時禁用所有客製化內容（`CLAUDE.md`、外掛、skills、hooks、MCP servers），專供故障排除使用。當遇到「某個外掛導致行為異常」的難解問題時，這是首個官方提供的隔離機制。
- **`disableBundledSkills` 設定**：可隱藏內建 skills、workflows 與 slash commands，讓模型專注於專案自訂內容，減少 noise。
- **企業 MCP 政策修復**：修正 `allowedMcpServers`/`deniedMcpServers` 在重連、IDE-typed configs、`--mcp-config` 首次 session 載入前未被強制執行的問題，對使用企業版並受合規約束的團隊至關重要。
- **Windows 與 macOS 效能修復**：解決 macOS 用戶以 claude.ai 憑證登入時每回合開頭的 30-50ms UI 停頓；修復 Windows 上 `claude -p` 因 slash-command/skill 掃描導致的緩慢/假死（v2.1.161 回歸問題）。

> 對終端開發者的實務影響：`/cd` 與 `--safe-mode` 分別解決了「session 內跨目錄操作」與「外掛衝突除錯」兩個長期痛點。企業 MCP 政策的修復意味著大型組織可以更安全地導入 Claude Code，不必擔心合規設定在重連時被繞過。

**OpenAI Codex rust-v0.138.0 發布：CLI-to-Desktop 移交與插件結構化輸出** —— 6 月 8 日，OpenAI 發布 Codex CLI Rust 重寫版的 v0.138.0。核心更新包括：
- **`/app` 移交**：CLI 執行緒現在可無縫移交至 macOS 與原生 Windows 上的 Codex Desktop 應用，Windows 工作區啟動也可直接進入 Desktop 而無需手動確認。
- **本地圖片附件**：圖片與獨立圖片生成現在會向模型暴露儲存檔案路徑，使後續編輯與檔案引用更可靠。
- **推理深度選擇彈性化**：TUI 新增 `Alt` 按鍵的後備快捷鍵（針對部分終端模擬器），且模型定義的 effort level 現在按模型宣告的順序流動。
- **插件自動化結構化輸出**：add/remove 與 marketplace 指令支援 `--json`，plugin list JSON 包含 marketplace 來源，plugin detail 暴露 default prompts、remote MCP servers 與 unavailable app templates。
- **Goal workflow 修復**：多行貼上在 `/goal edit` 不再提前提交；idle auto-turns 不會再進入 Plan mode；goal 在 terminal turn 失敗後不再自動繼續。

> 對終端開發者的實務影響：CLI-to-Desktop 移交消除了「在終端開始工作、發現需要 GUI 功能時必須重新輸入上下文」的摩擦。插件 `--json` 輸出則為自動化 pipeline（如 CI 中批量安裝/更新 Codex 插件）提供了程式化介面。

**tmux 發布 3.7-rc：終端多工器基礎設施進入新版本** —— 6 月 8 日，tmux 推出 3.7 預發行版。對於以終端為工作環境的代理使用者，tmux 是 session 持久化、分屏協作與遠端開發的核心基礎設施。3.7-rc 的發布意味著新版即將到來，建議終端重度使用者在測試環境試用以確保與新版終端模擬器的相容性。完整變更請參閱 [CHANGES 文件](https://raw.githubusercontent.com/tmux/tmux/3.7-rc/CHANGES)。

> 對終端開發者的實務影響：當你使用 Claude Code 或 Codex 在 tmux session 中進行長時間任務時，任何 tmux 的行為改變都可能影響代理的輸出解析或分屏布局。早期採用 rc 版可避免在正式版發布後才發現與工作流程衝突。

## 技術深度剖析

### 從提示工程到迴路工程：Addy Osmani 的五大原語解讀

Osmani 在《Loop Engineering》中提出，過去兩年與編碼代理的互動模式是「你打字 → 代理回應 → 你再打字」的回合制。這個模式正在過時。新的模式是「你設計一個系統，讓它自動驅動代理完成工作」。這個系統需要五個基本元件加上一個外部記憶體。

**原語一：Automations（自動化觸發）**

這是讓「迴路」成為迴路而非單次執行的關鍵。Codex app 提供 Automations 頁面，可設定專案、提示、執行頻率與環境，執行結果落入 Triage inbox。Claude Code 則透過 `/loop`（定時重複）、cron task、hooks（生命週期觸發 shell 指令）或 GitHub Actions 達到同樣目的。兩者都允許自動化呼叫 skill（`$skill-name`），避免在排程中貼上巨型提示牆。

對終端開發者的啟示：如果你每天早上都要讓 Claude Code 檢查昨天的 CI 失敗、開 issues、寫 commit summary，這應該是一個 automation，而非你手動輸入的 `/goal`。

**原語二：Worktrees（平行隔離）**

兩個代理同時寫入同一個檔案系統會產生衝突，這與兩個工程師搶修同一行 code 沒有區別。Codex 內建 worktree 支援，每個 thread 獨立分支。Claude Code 則透過 `git worktree`、 `--worktree` 旗標與 `isolation: worktree` 設定達成。這消除了平行代理的機械碰撞，但 Osmani 提醒：「你的審查頻寬仍是上限」——worktree 解決了檔案衝突，沒有解決「誰來審查這麼多並行成果」的問題。

**原語三：Skills（專案知識固化）**

Skill 是讓代理停止像金魚一樣每次 session 都從零學習專案的方法。兩者使用相同的 `SKILL.md` 格式，Codex 以 `$name` 或 `/skills` 呼叫，Claude Code 以同樣機制載入。Osmani 強調這與他的「意圖債務（Intent Debt）」概念直接相關：skill 就是寫在外部的意圖，避免代理每次都用「自信的猜測」填補空白。

**原語四：Plugins / Connectors（工具串接）**

基於 MCP 的 connectors 讓代理能讀取 issue tracker、查詢資料庫、發送 Slack 訊息。Codex 與 Claude Code 都支援 MCP，所以為一方寫的 connector 通常可直接用於另一方。Plugins 則將 connectors 與 skills 打包，讓團隊成員一鍵安裝完整設定。這是「代理從『告訴你該怎麼做』進化到『直接幫你開 PR、連結 ticket、CI 通過後自動通知頻道』」的關鍵。

**原語五：Sub-agents（分工與驗證）**

「寫 code 的模型」不應該同時「檢查 code 的模型」——它對自己的作業太寬容。Codex 允許以 TOML 定義 `.codex/agents/`，每個子代理可指定不同模型與 reasoning effort（如 security reviewer 用強模型 + high effort，explorer 用輕量模型）。Claude Code 則以 `.claude/agents/` 與 agent teams 實現同樣結構。常見分工：一個探索、一個實作、一個驗證。

**第六項：State / Memory（狀態持久化）**

模型在 session 之間會遺忘一切，所以「已嘗試什麼、通過什麼、還剩什麼」必須寫在磁碟上——Markdown 文件、Linear board、或任何外部儲存。這聽起來太簡單而不重要，但它是所有長期執行代理的命脈。

**Osmani 的警告：迴路不會替你完成一切**

文章結尾提出三個迴路無法解決、反而會加劇的問題：
1. **驗證仍是你的責任**：無人值守的迴路也在無人值守地犯錯。子代理的檢查是「claim 而非 proof」。
2. **理解能力會腐化**：迴路越順，你讀到的 code 越少，「程式碼存在」與「你理解它」之間的 gap 越大——這就是 comprehension debt。
3. **認知投降的誘惑**：當迴路自動運行時，最容易停止思考、接受代理給出的任何結果。Osmani 稱之為 cognitive surrender。

> 「設計迴路。但請像一個打算繼續當工程師的人那樣設計，而不只是按下『開始』的人。」

## 工具與函式庫

- **Canary：Claude Code 的 QA 測試框架** ([wizenheimer/canary](https://github.com/wizenheimer/canary)) — 來自 HN Ask HN 討論的亮點專案。Canary 讀取 code diff、識別受影響的 UI 流程，並在真實瀏覽器中執行測試。每次執行後產生螢幕錄影、console logs、network HARs 與 Playwright traces，讓你精確檢視代理做了什麼。對於使用 Claude Code 產生前端程式碼的開發者，這填補了「代理改了 20 個檔案，但我不知道哪個 UI 壞了」的驗證缺口。

- **llm-consortium** — HN 討論中出現的多模型平行推理工具（尚未找到獨立 GitHub 連結，以概念形式報導）。核心機制：平行查詢多個模型，循環迭代直到達成 confidence threshold，再整合為最終回應。更進階的版本支援「嵌套式 consortium」——每個成員本身可以是另一個 consortium，甚至 judge/arbiter 也可由 consortium 擔任。這為「單一模型偏見」問題提供了一個極具創意的工程解法，但需注意 token 成本會隨平行數量線性增長。

## 研究焦點

本日經查證，arXiv 無來自頂尖作者（LeCun、Karpathy、DeepSeek、Anthropic、OpenAI、DeepMind 等）且與終端代理直接相關的新論文。以下改以 HN 社群洞察替代：

- **HN 社群洞察：終端代理的「個人工具化」浪潮** —— 在「Ask HN: What are tools you have made for yourself since the advent of AI?」（150 點）討論中，多個高品質回覆揭示終端開發者正在為代理 workflow 打造專屬工具：
  - **自然語言 zsh 自動完成**：一位開發者建立本地 ollama 驅動的 zsh macro，輸入「git rename annotated branch」後按 `ctrl-g` 即可展開為實際指令，並以 `ctrl-r` 進行自然語言歷史搜尋。
  - **Whisper 終端語音輸入**：另一位開發者建立本地 Whisper 語音轉錄工具，專為 Claude Code 終端優化，比 Apple 內建聽寫更準確地識別技術詞彙（如 "git"），且不受 active window/cursor 問題干擾。
  - **專案管理終端**：可一鍵啟動資料庫、app server 與 Claude Code 於不同 tab，並在偵測到 `http://localhost:4000` 時自動開啟瀏覽器於正確 URL。

> 這些工具的共同特徵是「極度個人化」——不是為大眾設計的產品，而是為自己的終端 workflow 量身打造的腳本。這暗示著終端代理生態的下一波創新可能不是來自大型產品，而是來自開發者將自己的「摩擦點」自動化的無數小工具。

## 快速資訊

- **「Life is too short for a slow terminal」**（[mijndertstuij.nl](https://mijndertstuij.nl/posts/life-is-too-short-for-a-slow-terminal)，97 點 on HN）—— 一篇實務導向的 shell 效能優化指南。作者在 30ms 內啟動完全載入的互動式 zsh（含 completions、syntax highlighting、autosuggestions、fzf、direnv）。關鍵技巧：(1) 不使用 oh-my-zsh 等框架，僅手動 source 三個必要插件；(2) `compinit` 快取策略（每天只做一次完整安全檢查，其餘用 `-C` 跳過）；(3) lazy-loading（nvm、kubectl completions 在首次呼叫時才載入）。對於整天待在終端裡的代理使用者，這些微優化累積成巨大的時間節省。
