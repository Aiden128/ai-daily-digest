## 技術深度剖析

### Claude Code Dynamic Workflows：百人級 Agent 協作的終端實現

Claude Code v2.1.154 中的 Dynamic Workflows 是目前終端 AI 編碼代理領域最大膽的架構性變化之一。舊有的多 agent 協作模式大約分為兩類：第一類是用戶手動管理多個獨立 session（例如在 tmux 中開多個 pane、每個都跑 `claude`）；第二類是單一 session 中的子 agent 呼叫（如使用 `@` 呼叫其他工具）。Dynamic Workflows 則是第三類：在一個主 session 中，Claude 自動將大型任務分解為數十到數百個子任務，每個子任務都是一個獨立的背景 agent session，主 session 負責監控進度、處理依賴關係、合併結果。

**技術架構（依據 release notes 推斷）：**
- **任務分解層**：使用者提出一個高層目標（如「重構這個專案的測試架構」），Claude 先進行「計畫」階段，產生一個有向無瓏圍(DAG)的任務圖。
- **背景執行層**：每個節點被轉換為一個背景 agent session。這些 session 可能是本機的 `claude --bg` 運行，也可能是遠端的 `claude agents` session。
- **狀態監控層**：`/workflows` 命令提供一個 TUI 實時顯示所有運行中的 workflow 實例，包含進度、狀態、已完成的子任務等。
- **結果合併層**：當所有子任務完成後，主 agent 將各個部分結果匯集成最終產出（如統一的拉取請求、重構後的代碼庫）。

**與 Anthropic 提供的 `computer-use` 或其他框架的差異：**
Dynamic Workflows 並非單純的工作流程引擎，它是緊密整合在 Claude Code TUI 中的。這意味著使用者不需要離開終端環境就能監控和互動。相比之下，OpenAI 的 Codex CLI 也有 app-server 模式和 remote-control，但它們更偏向「遠端監控」而非「本地編排」。Anthropic 的方案是讓一個主 Claude 實例作為 conductor，其他實例作為 musicians，這是一個更接近「音樂指揮家模式」的設計。

**使用建議：**
目前 Dynamic Workflows 是一個很新的功能，建議從中等規模的任務開始嘗試（如「為這個專案所有模塊新增單元測試」），而非一上來就試圖讓它重構整個 monorepo。注意 workflow 實例會消耗大量 token，因為每個子 agent 都會獨立發出 API 請求。

### 終端 AI 編碼代理工具爆發：為什麼現在是終端的黃金時代？

過去一週出現的這波新工具不是偶然。它們的出現有三個深層原因：

**1. Claude Code 和 Codex CLI 已經「教會了用戶」如何與終端 AI 代理互動**
當 Claude Code 在 2024 年推出時，很多開發者對「在終端裡和 AI 對話」感到陌生。但經過兩年的教育，現在終端代理已經是許多開發者的主要工作方式。這意味著市場已經存在，不再需要「教育用戶」，而是「為已有用戶提供更好的工具」。

**2. 現有終端應用程式沒有為「多 agent 並行」優化**
傳統的 tmux、zellij、Ghostty 等終端多工具是為「人類開發者」設計的，目的是讓人類可以同時看到多個選單、多個日誌。但 AI agent 不需要「看」，它們需要的是「被管理」：自動分配資源、自動重啟崩潰的 session、自動匯集結果。cmux、agent-deck、herdr 等工具就是為了填補這個空白。

**3. Rust 和 Go 成為終端基礎設施的主流語言**
這波新工具中，jcode、herdr、cmux 的核心都是 Rust，DeepSeek-Reasonix 是 Go，agent-deck 也是 Go。這說明開發者希望終端工具能夠：(a) 在幾十毫秒內啟動，(b) 低 CPU/記憶體佔印，(c) 長時間穩定運行而不泄漏。這舊是 C 的領地，現在被 Rust 和 Go 分割。

**值得關注的具體工具：**
- **cmux** （JavaScript/Electron？待確認）：Ghostty 基礎 + 垂直分頁。當前 macOS 限定，但因為基於 Ghostty（一個快速成長的 GPU 終端），其渲染性能是重要優勢。
- **DeepSeek-Reasonix** （Go）：核心賦能是 prefix-cache 穩定性。這對於長時間運行的代理非常重要，因為當代理運行數小時後，如果每次輪次都需要重新傳送整個代碼庫上下文，API 成本會迅速上升。
- **superset** （TypeScript）：定位為「AI Agents 時代的編碼編輯器」。這個定位與 Cursor 或 Windsurf 不同，它不是「一個編輯器裡有 AI 功能」，而是「一個管理多個 AI 代理的編輯器」。這是一個重要的詞彙轉換：代理不是編輯器的附件，而是編輯器是代理的附件。

## 研究焦點

- **DeepClaude 登上 Hacker News 熱榜 (678 點)** (May 3) — [GitHub](https://github.com/aattaran/deepclaude) / [HN](https://news.ycombinator.com/item?id=48234567)
  - DeepClaude 是一個將 DeepSeek V4 Pro 的推理能力與 Claude Code 的 agent 迴路結合的開源專案。其核心想法是：DeepSeek 在系統性推理上表現優秀，但在工具使用和代碼生成上不如 Claude；因此讓 DeepSeek 負責思考，Claude 負責執行。
  - 技術實現上，DeepClaude 提供了一個透明的中間層，讓使用者可以選擇不同的「思考模型」和「執行模型」。這種「模型拼接」（model stitching）的趋勢正在越來越普遍：當沒有一個模型能在所有任務上達到最佳，開發者開始組合不同模型的長處來抵銶短處。
  - 對終端開發者的啟示：這個專案證明了一個重要的變化：AI 編碼代理不再是「選擇某個代理」，而是「組合多個代理和模型」。建議有興趣的開發者研究 DeepClaude 的架構，並考慮為自己的工作流增加類似的「思考/執行分離」層。

- **LazyAgent — 觀察所有 AI 編碼代理的 TUI** (Apr 15, HN 8 pts) — [GitHub](https://github.com/chojs23/lazyagent)
  - LazyAgent 是一個專為監控多個 AI 編碼代理而設計的終端 TUI。它可以同時顯示多個 Claude Code、Codex 或其他代理的運行狀態、token 消耗、執行時間等。
  - 雖然目前 star 數不高，但它代表了一個重要趨勒：當開發者同時執行多個代理時，他們需要一個「統一的儀表板」來監控所有任務。Claude Code 的 Agent View 提供了這個能力，但只限於 Claude 自己的 session。LazyAgent 則試圖跨平台地監控所有代理。
  - 對於使用多種代理的開發者，這類工具值得關注。如果你同時使用 Claude Code、Codex 和其他本地模型，一個統一的 TUI 儀表板可以大幅提升可觀測性。
