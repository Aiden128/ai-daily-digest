# Linux Kernel 深度解析 — Network Namespace 與 veth / bridge：從 `unshare(CLONE_NEWNET)` 到 `dev_queue_xmit` 的隔離虛擬網路、per-net 資料結構、`init_net` 與 `netns_list` 鏈表、`/proc/net` 綁定、veth pair 對接、bridge forward database 與 FDB 學習原始碼全徑

## 原理概述

`struct net` 是 Linux 為「網路隔離」設計的最頂層容器，每個 Network Namespace 都是一份完整的網路狀態副本 — 自己的 device list、socket hash table、route table、netfilter table、sysctl tree、procfs `/proc/net`。建立方式有兩條：`unshare(CLONE_NEWNET)` / `clone(CLONE_NEWNET)` 在現有行程內分裂出新 ns，或 `ip netns add nsX` 透過 `runc` / `iproute2` 把 `/proc/<pid>/ns/net` 綁到 mount namespace。`veth` 是成對出現的虛擬網卡，兩端在 host 上像普通 `net_device`，但寫入 `veth0` 的 skb 會直接走內部函式 `veth_xmit` 出現在對端 `veth1` 的 RX queue；當其中一端被移進 child netns，它就成了跨 namespace 的「軟管線」。Linux bridge (`/net/bridge/br.c`) 則把多個 device（含 veth、tap、實體 NIC、bond）黏成 L2 交換器，內部維護一個 forwarding database (FDB) — `net_bridge_fdb_entry` 的 hash table，用 MAC 學習 / aging 機制把 L2 流量做 flooding / forwarding / filtering 決策。

### 2. Netns Lifecycle

```c
// net/core/net_namespace.c
static struct kmem_cache *net_cachep;
static struct list_head  net_namespace_list;
static DEFINE_MUTEX(net_mutex);

struct net *copy_net_ns(unsigned long flags,
                        struct user_namespace *user_ns,
                        struct net *old_net)
{
    struct net *net;
    int rv;

    if (!(flags & CLONE_NEWNET))
        return get_net(old_net);

    rv = -ENOSPC;
    net = net_alloc();
    if (!net)
        goto out;

    refcount_set(&net->count, 1);
    refcount_set(&net->passive_count, 1);

    rv = setup_net(net, user_ns);
    if (rv == 0)
        rv = ucount_net_add(user_ns, net);
    if (rv < 0) {
        __put_net(net);
        goto out;
    }

    list_add_tail_rcu(&net->list, &net_namespace_list);
out:
    if (rv < 0)
        return ERR_PTR(rv);
    return net;
}
EXPORT_SYMBOL_GPL(copy_net_ns);

static int setup_net(struct net *net, struct user_namespace *user_ns)
{
    // 逐個 subsystem 呼叫 net_init()
    const struct pernet_operations *ops, *ops2;
    struct net_generic *ng;
    int error = 0;

    ng = net_alloc_generic();
    if (!ng)
        return -ENOMEM;
    rcu_assign_pointer(net->gen, ng);

    list_for_each_entry(ops, &pernet_list, list) {
        error = ops->init(net);
        if (error < 0)
            goto out_undo;
    }
    ...
}
```

每個 subsystem (IPv4 / IPv6 / bridge / netfilter / BPF / XFRM / unix / …) 都用 `register_pernet_subsys()` 註冊自己的 `init` / `exit` 回呼；`setup_net` 對 `pernet_list` 線性呼叫每個 init 函式，反序在 `net_free_net()` 跑 `exit`。

### 5. veth Driver 結構

```c
// drivers/net/veth.c
struct veth_rq_stats {
    u64           packets;
    u64           bytes;
    struct u64_stats_sync syncp;
};

struct veth_priv {
    struct net_device __rcu *peer;
    struct veth_rq_stats __percpu *rq_stats;
    unsigned int       head;
    bool               noisy;
    struct bpf_prog    *_xdp_prog;
    struct veth_xdp_stats __percpu *xdp_stats;
};

struct veth_stats_rx_bytes {
    struct u64_stats_sync syncp;
    u64           bytes;
};

// 核心 xmit：
static netdev_tx_t veth_xmit(struct sk_buff *skb, struct net_device *dev)
{
    struct veth_priv *rcv_priv, *priv = netdev_priv(dev);
    struct net_device *rcv = rcu_dereference(priv->peer);
    int rxq = skb_get_queue_mapping(skb);

    if (unlikely(!rcv))
        goto drop;

    // 跨 netns 流量需要 netns 隔離檢查
    skb = veth_xdp_rcv_one(skb, rcv, priv, rxq, veth_forward_skb, false);
    if (unlikely(!skb))
        return NETDEV_TX_OK;

    // 從 peer 的 rq 把 skb 送進 RX
    veth_forward_skb(priv, rcv, skb);
    return NETDEV_TX_OK;
}
```

veth 在 `veth_newlink()` 裡透過 `rtnl_newlink()` 註冊時會呼叫 `veth_newlink_peer()` 建立對端，並用 `rcu_assign_pointer()` 把 `peer` 互指。

## 源碼流程說明

### 流程 1：`unshare(CLONE_NEWNET)` 建立新 netns

```c
// kernel/fork.c / kernel/nsproxy.c
SYSCALL_DEFINE1(unshare, unsigned long, unshare_flags)
{
    ...
    if (unshare_flags & CLONE_NEWNET) {
        retval = unshare_nsproxy_namespaces(unshare_flags, &new_ns, ...);
        if (retval)
            goto bad_unshare_cleanup_nsproxy;
    }
    ...
}

int unshare_nsproxy_namespaces(unsigned long unshare_flags,
                               struct nsproxy **new_nsp,
                               struct cred *new_cred, struct fs_struct *new_fs)
{
    struct nsproxy *ns = current->nsproxy;
    struct nsproxy *new_ns;
    int err = 0;

    if (!(unshare_flags & (CLONE_NEWNS | CLONE_NEWUTS | CLONE_NEWIPC |
                           CLONE_NEWPID | CLONE_NEWNET |

        return 0;

    new_ns = create_new_namespaces(unshare_flags, current, new_cred, new_fs);
    if (IS_ERR(new_ns)) return PTR_ERR(new_ns);

    if (new_ns->net_ns)
        put_user_ns(new_ns->user_ns);     // net ns 跟 user ns 強綁
    *new_nsp = new_ns;
    return err;
}

static struct nsproxy *create_new_namespaces(unsigned long flags,
                       struct task_struct *tsk, struct fs_struct *new_fs)
{
    ...
    new_nsp->net_ns = copy_net_ns(flags, new_user_ns, tsk->nsproxy->net_ns);
    ...
}
```

走 `copy_net_ns` → `setup_net` → 每個 subsystem 跑 init → 鏈入 `net_namespace_list`。呼叫端從此之後 `current->nsproxy->net_ns` 指向新 ns，後續 `socket()` 會把 `skc_net` 設到這個新 net。

### 流程 2：`ip netns add` / `ip netns exec`

`iproute2` 工具實際是：

```bash
# ip netns add nsA 等同
unshare --net --mount /bin/sh -c "touch /run/netns/nsA; mount --bind /proc/self/ns/net /run/netns/nsA; sleep infinity &"
```

當程式 `open("/run/netns/nsA")` 拿到一個 file descriptor，後面 `setns(fd, CLONE_NEWNET)` 把它 attach 上來 — `setns` 內部把 `task->nsproxy->net_ns` 換成從 fd 解析出來的 `struct net`，並遞增 ref。

### 流程 3：建立 veth pair + 兩端分屬不同 netns

```bash
ip link add veth0 type veth peer name veth1
ip link set veth1 netns nsA
ip netns exec nsA ip link set veth1 up
ip addr add 10.0.0.1/24 dev veth0
ip netns exec nsA ip addr add 10.0.0.2/24 dev veth1
```

對應 kernel 流程 (`net/core/rtnetlink.c` → `drivers/net/veth.c`)：

1. `ip link add` → `rtnl_newlink()` → 解析 `IFLA_INFO_KIND = "veth"` 對應到 `veth_link_ops`，呼叫 `veth_newlink()`。
2. `veth_newlink()` 解析 `VETH_INFO_PEER` 拿到對端 netdev 屬性（包括 netns id 或 `IFLA_NET_NS_FD` 對應的 fd）。
3. `veth_newlink_peer()` 在目標 netns（若指定）建立對端 `veth1`，回填 `veth0->peer` 與 `veth1->peer` 的雙向指針。
4. `veth0` 註冊到 `init_net.dev_name_head` hash，`veth1` 註冊到 `nsA` 的同名 hash — 從此在 host `ip link show` 看不到 veth1。
5. `ip addr add` → `rtnl_newaddr()` → 在指定 netns 呼叫 `__inet_insert_ifa()`，把 `inet_ifaddr` 掛到 `dev->ip_ptr->ifa_list`。

### 流程 4：封包從 host 走到 veth1（跨 netns）

```c
// net/core/dev.c
int dev_queue_xmit(struct sk_buff *skb, struct net_device *sb_dev)
{
    struct net_device *dev = sb_dev;
    struct netdev_queue *txq;
    ...
    txq = netdev_pick_tx(dev, skb, sb_dev);
    q = rcu_dereference_bh(txq->qdisc);

    if (q->enqueue) {        // 有 qdisc
        rc = q->enqueue(skb, q, &to_free);
        qdisc_run(q, &budget);
    } else
        sch_direct_xmit(skb, q, ...);

    return rc;
}
```

`qdisc_run` 呼叫到 `veth_xmit()` (因為 veth 沒有自己的 qdisc，但仍是 netdev 之一，會經 dev_queue_xmit)：

```c
static netdev_tx_t veth_xmit(struct sk_buff *skb, struct net_device *dev)
{
    struct veth_priv *priv = netdev_priv(dev);
    struct net_device *rcv = rcu_dereference(priv->peer);
    int rxq = skb_get_queue_mapping(skb);
    struct veth_rq_stats *stats;

    if (unlikely(!rcv))
        goto drop;

    // veth 支援 XDP — 先給 peer 端的 XDP prog 機會
    skb = veth_xdp_rcv_one(skb, rcv, priv, rxq, veth_forward_skb, false);
    if (unlikely(!skb))
        return NETDEV_TX_OK;

    veth_forward_skb(priv, rcv, skb);
    return NETDEV_TX_OK;
}
```

`veth_forward_skb()` 把 skb 送進 peer 的 RX queue：

```c
static void veth_forward_skb(struct veth_priv *priv, struct net_device *rcv,
                             struct sk_buff *skb)
{
    ...
    skb->dev = rcv;
    skb->skb_iif = priv->dev->ifindex;
    dev_queue_xmit_nit(skb, rcv);
    netif_rx(skb);
}
```

`netif_rx()` → `netif_rx_internal()` → 把 skb enqueue 到 `get_cpu_var(softnet_data).input_pkt_queue` → softirq `NET_RX_SOFTIRQ` 觸發後 `net_rx_action()` 跑 `napi_poll()`，bridge slave 模式下會走到 `br_handle_frame_finish()`。

注意 — 跨 netns 時 `skb->dev` 換成對端後，後續的 `skb_dst_drop`、`ip_route_input_noref` 等都會以 `dev_net(rcv)` 為 lookup 域名（host 上 `init_net`，nsA 上 `nsA->`）。

### 流程 5：Bridge 收包 / FDB 學習

```c
// net/bridge/br_if.c
rx_handler_result_t br_handle_frame(struct sk_buff **pskb)
{
    struct net_bridge_port *p;
    struct sk_buff *skb = *pskb;
    const unsigned char *dest = eth_hdr(skb)->h_dest;
    ...
    if (!is_valid_ether_addr(dest))
        goto drop;

    p = br_port_get_rcu(skb->dev);
    ...
    if (p->state == BR_STATE_LEARNING) {
        br_fdb_insert(p, src, 0, false);  // 學習
        goto drop;
    }

    if (ether_addr_equal(p->br->dev->dev_addr, dest))
        skb->pkt_type = PACKET_HOST;

    if (p->flags & BR_VLAN_TUNNEL)
        br_handle_ingress_vlan_tunnel(skb, p, nbp_vlan_group_rcu(p));

    switch (p->state) {
    case BR_STATE_FORWARDING:
    case BR_STATE_LEARNING:
        if (!ether_addr_equal(src, dest))
            br_fdb_insert(p, src, 0, false);  // 學習 src MAC
        ...
    }

    if (p->br->stp_enabled == BR_NO_STP) goto forward;

    // STP blocking / listening / learning 處理
    ...
forward:
    switch (p->state) {
    case BR_STATE_FORWARDING:
        ...
        br_forward(p, skb);  // 走 FDB 找 dst port
        break;
    ...
    }
}
```

`br_fdb_insert()` 內部用 `rhashtable_lookup_insert_fast()` 插入 `net_bridge_fdb_entry`；同一個 src MAC 反覆出現會更新 `updated` 欄位；`br_fdb_cleanup()` 跑在 `gc_timer`（預設 5s）上，把 `jiffies - updated > ageing_time` 的 entry 刪掉。

`br_forward()` 流程：

```c
void br_forward(const struct net_bridge_port *to,
                struct sk_buff *skb, bool local_rcv)
{
    if (to && should_deliver(to, skb)) {
        if (__br_forward(to, skb, local_rcv))
            kfree_skb(skb);
    }
}
```

`__br_forward()` 把 skb clone 後送進 `to->dev` 的 RX queue；如果 FDB 找不到對應 port（unicast 未知），會走 `br_flood()` 把 frame 從所有 forwarding port 廣播出去（除了 in port）。

```c
    ...
    // 啟動 STP 計時器
    if (br->stp_enabled != BR_NO_STP)
        br_port_state_selection(p);

    netif_update_features(dev);

    return 0;
    ...
}
```

`netdev_rx_handler_register` 把 `br_handle_frame` 設為 `dev->rx_handler`，未來這個 slave dev 收到 frame 會先送到 bridge 處理。

### 流程 7：Bridge 自己發包 (L3 → L2)

```c
// net/bridge/br_device.c
static netdev_tx_t br_dev_xmit(struct sk_buff *skb, struct net_device *dev)
{
    struct net_bridge *br = netdev_priv(dev);
    const unsigned char *dest = eth_hdr(skb)->h_dest;

    if (!br->stp_enabled && !(dev->flags & IFF_PROMISC) && br_pass_frame_up(skb)) {
        return NETDEV_TX_OK;
    }
    // broadcast / multicast / unicast 處理
    if (is_broadcast_ether_addr(dest))
        br_flood(br, skb, BR_PKT_BROADCAST, false, true);
    else if (is_multicast_ether_addr(dest))
        br_multicast(br, skb, NULL, BR_PKT_MULTICAST);
    else if ((dst = br_fdb_find_rcu(br, dest, vid)) != NULL)
        br_forward(dst->dst, skb, false);
    else
        br_flood(br, skb, BR_PKT_UNICAST, false, true);
    return NETDEV_TX_OK;
}
```

### 流程 8：Netns exit / cleanup

```c
// net/core/net_namespace.c
static void cleanup_net(struct work_struct *work)
{
    struct net *net, *tmp;
    LIST_HEAD(net_kill_list);

    /* 從 exit_list 取出所有 is_active 的 net */
    list_for_each_entry_safe(net, tmp, &net_kill_list, exit_list) {
        list_del_init(&net->exit_list);
        rtnl_unlock();
        // 跑所有 subsys 的 exit 反序
        list_for_each_entry_reverse(ops, &pernet_list, list)
            if (ops->exit_batch)
                ops->exit_batch(&net_kill_list);
        rtnl_lock();
    }

    /* synchronize RCU，等所有 reader 離開 */
    synchronize_rcu();
}
```

`netns` 真正被 free 的條件是 `count` ref 與 `passive_count` 為 0 + RCU grace period 過完，否則某個在途的 socket / skb / route cache 仍會 deref 一個 `struct net *` 而 UAF。

## 設計原理與悲悸情境

### 1. 為什麼 `struct net` 是「per-subsystem opaque slot」而不是「每個 subsystem 直接塞欄位」？

因為 netns 子系統的數量隨時間成長（unified `struct net` 在 2.6.32 之前就存在，但 IPv6 / bridge / netfilter / BPF / XDP / SMC / MPTCP 陸續加掛）。每個 `register_pernet_subsys()` 透過 `pernet_operations->id` 在 `net_generic(net, id)` 拿到自己的 slot（offset 動態決定），新增 subsystem 不需要改 `struct net` 定義、不需要重新編譯其他子系統。壞處是 `net_generic()` 是 `rcu_dereference(net->gen)[id]`，hot path 多一次解參考 + RCU 讀，所以 4.9+ 開始把 hot subsystem（`netns_ipv4`, `netns_ipv6`, `netns_br`）直接 inline 到 `struct net` 固定 offset。

### 2. 為什麼 veth 要用 `rcu_dereference(peer)` 而非 `RCU_PROTECTED` lock？

veth 的 peer 會被外部 `rtnl_lock()` 改變 (`veth_newlink_peer` / `veth_dellink`)，但 XMIT 路徑在 softirq context 不能 sleep 拿 rtnl。所以 peer 的 `rcu_head` 在 dellink 時走 `kfree_rcu()`，讀端用 `rcu_dereference()` 拿到後就假設它不會消失；缺點是「peer 在 XMIT 中間被 close」會有一段空窗拿到 invalid pointer — 這靠 `veth_xmit` 開頭的 `if (unlikely(!rcv)) goto drop;` 補救。

### 3. 為什麼 bridge FDB 改用 `rhashtable` 而非 `hash table`？

5.4 之前 `net_bridge_fdb_entry` 用 `hlist_head[BR_HASH_SIZE]` 靜態 256 桶；FDB 在大型資料中心可能上百萬 entries，linear chain 會撞 chain，lookup 退化到 O(n)。改用 rhashtable 的 per-cpu locks + 動態 resize 後，FDB lookup 在 100k entries 量級穩定 50-100ns。

### 4. 為什麼 `br_fdb_insert` 在 learning 與 forwarding 兩種 state 都跑？

學習永遠是「記下 src MAC 對應 port」，forwarding 額外「查 dst MAC 對應 port」。如果只在 forwarding 學，第一個 frame 永遠是 miss flood；改成兩個 state 都學，第一個 frame flood，但從第二個 frame 開始就 hit。Linux 還會走「`BR_STATE_LEARNING` 不轉發」狀態過渡 15s（forward_delay）才進 forwarding — 避免 topology loop 把整個 layer 2 灌爆。

### 5. 為什麼 `skb->dev` 在 veth 跨 netns 時必須換成對端 device？

`skb->skb_iif`、`dev_net(skb->dev)`、`ip_route_input` lookup domain、`conntrack` zone 都依賴 `skb->dev` 找出它「從哪個 net 進來」。如果保留原本 dev，routing / conntrack / netfilter 會在錯誤 net 做 lookup，結果就是封包走 host route 出去，namespace 隔離完全失效 — 這也是早期 docker 0.x 有的一個「veth 沒換 dev 導致 NAT 不生效」bug。

### 6. 為什麼 netns exit 要走 `cleanup_net` 延遲 workqueue？

`struct net` 最後一個 `put_net()` 可能發生在 process context 也可能在 softirq context（skb free 時）。softirq 不能 sleep，但很多 subsys exit 需要 `synchronize_net()` / `flush_workqueue()` 等待子設備卸載。所以 `cleanup_net` 延後到 `cleanup_list` 上，再由 `cleanup_net` workqueue 跑 `synchronize_rcu()` + 反序 subsys exit + `free_net()`，確保完全 sleepable context。

### 7. 為什麼 `br_handle_frame` 要走 `RCU read-side critical section`？

因為 STP 計時器可能隨時刪 port (`nbp_delete`)，但 frame 已經在 RX 路徑持有 `skb->dev->rx_handler_data` 指向 `net_bridge_port`。RCU 確保 `br_handle_frame` 跑完前 `nbp_delete` 不會真的 free 該 port；`nbp_delete` 內部走 `kfree_rcu(p, rcu)`。違反這個 invariant 的 bug 通常表現為「刪除 veth 時偶發 kernel panic in br_handle_frame」。

### 8. 為什麼 veth 支援 XDP 卻要分 peer / dev 兩端獨立 XDP prog？

跨 netns 的 packet filtering 通常希望 host ns 與 child ns 各自有獨立 policy（例如 host 端做 DDoS mitigation，child 端做應用 L4 filter）。`veth` 在 XDP TX 路徑 `veth_xdp_rcv_one()` 內呼叫 peer 端的 `_xdp_prog`（透過 `bpf_prog_run_xdp()`），再決定 `bpf_redirect` / `XDP_DROP` / `XDP_PASS`；host 端 XDP prog 與 child 端 XDP prog 互不影響，這也讓 Cilium / Calico 能「per-ns」佈署不同 BPF prog。

### 9. 為什麼 bridge 不能在 unprivileged netns 內由 user 自建？

`br_add_if` 需要 `dev_set_promiscuity(dev, 1)`，而 promiscuous mode 屬於 `CAP_NET_ADMIN` 範疇（影響整個 host 的 MAC learning 表）。user namespace 內 `CAP_NET_ADMIN` 不會對應到 init userns 的 `CAP_NET_ADMIN`，所以 `unshare -Urn ip link add br0 type bridge` 在老 kernel 會 fail；5.x 起透過 user namespace 的 capability mapping 放寬了限制，但 rootless container 仍需要 `--sysctl net.ipv4.ip_forward=1` 等額外 patch。

### 10. 為什麼 netns reference 用 `passive_count` 與 `count` 兩條？

`count` 是 active ref，netns 不能被 free；`passive_count` 是「我也借了 ref 但不想擋 netns 釋放」。例如 netfilter 的 conntrack entry 屬於某個 netns，但 conntrack GC 跑時不希望整個 netns 為了一個 entry 不能退 — passive ref 跟著 netns 走，netns free 完才被一併清掉。`get_net()` 是 active ref，`get_net_track()` 才給 passive。

## 結語

Network Namespace 是 Linux 容器化、multi-tenant cloud、vpn wireguard / tailscale 等「虛擬網路」技術的地基 — Docker / Kubernetes / CRIO 全部依賴 `unshare(CLONE_NEWNET)` + veth pair + bridge 組合產生隔離的 L2/L3 環境。理解 `struct net` 的 per-subsystem init 機制、veth XMIT 跨 netns 時 `skb->dev` 的切換、bridge FDB 的 rhashtable 與 RCU free，是排查「為什麼 container 內網路不通 / 為什麼 macvlan 比 veth 快 / 為什麼 STP 沒起來」這類問題的根因。下一輪可以看 `macvlan / ipvlan`（driver-level 隔離）與 `tc` 內部 fq_codel / cake 演算法，或是 `wireguard` 怎麼把 netns 與 routing 綁在一起。
