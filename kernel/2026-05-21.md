## Linux Kernel 深度解析 — VFS 路徑查找與檔案開啟：從 openat 系統呼叫到 dentry cache 的原始碼旅程

### 原理概述

Virtual File System（VFS）是 Linux 核心為所有檔案系統提供的統一抽象層。當使用者空間呼叫 `openat()` 時，核心必須將一個路徑字串（如 `/etc/passwd`）轉換成具體的檔案描述子（file descriptor）。這個過程並非簡單的字串比對，而是一條經過高度最佳化的管線：從 RCU 無鎖路徑走訪（RCU-walk）到 dentry cache 的雜湊查找，再到 `struct file` 的初始化與檔案操作表的掛載。今日我們將沿著 `fs/open.c` 與 `fs/namei.c` 的原始碼，逐步拆解這條從系統呼叫到 inode 的完整路徑。

### 核心資料結構與函數（含路徑）

#### 1. `struct path` — 路徑的雙元組封裝
**檔案路徑**: `include/linux/path.h`（第 8 行起）

```c
struct path {
	struct vfsmount *mnt;
	struct dentry *dentry;
} __randomize_layout;
```

`struct path` 是 VFS 中最基礎的路徑表示單位。它只用兩個指標：一個指向掛載點（`vfsmount`），一個指向目錄項（`dentry`）。這樣的設計讓核心能以極低成本複製與傳遞路徑資訊。

#### 2. `struct dentry` — 目錄項快取節點
**檔案路徑**: `include/linux/dcache.h`（第 93 行起）

```c
struct dentry {
	/* RCU lookup touched fields */
	unsigned int d_flags;		/* protected by d_lock */
	seqcount_spinlock_t d_seq;	/* per dentry seqlock */
	struct hlist_bl_node d_hash;	/* lookup hash list */
	struct dentry *d_parent;	/* parent directory */
	union {
		struct qstr __d_name;		/* for use ONLY in fs/dcache.c */
		const struct qstr d_name;
	};
	struct inode *d_inode;		/* Where the name belongs to - NULL is negative */
	const struct dentry_operations *d_op;
	struct super_block *d_sb;	/* The root of the dentry tree */
	unsigned long d_time;		/* used by d_revalidate */
	void *d_fsdata;			/* fs-specific data */
	struct lockref d_lockref;	/* per-dentry lock and refcount */
	union {
		struct list_head d_lru;		/* LRU list */
		wait_queue_head_t *d_wait;	/* in-lookup ones only */
	};
	struct hlist_node d_sib;	/* child of parent list */
	struct hlist_head d_children;	/* our children */
	union {
		struct hlist_node d_alias;
		struct hlist_bl_node d_in_lookup_hash;
		struct rcu_head d_rcu;

```

`struct dentry` 是 VFS 的核心索引結構。它透過 `d_hash` 掛在全域雜湊表上，透過 `d_parent` 與 `d_children` 構成樹狀階層。`d_seq` 是每個 dentry 的 seqlock，用於 RCU-walk 路徑查找時偵測並發的重新命名（rename）操作。

`inode` 儲存檔案的真正中繼資料（權限、大小、時間戳等），而 `dentry` 儲存名稱與階層關係。兩者分離的設計讓核心得以實作硬連結（hard link）：多個 `dentry` 可以指向同一個 `inode`。

`struct file` 代表「已開啟的檔案」。每次 `open()` 成功，核心都會配置一個新的 `struct file`，即使多個行程開啟同一個檔案，它們也會擁有各自獨立的 `f_pos`（檔案偏移量）。

`nameidata` 是路徑查找的核心狀態載體。它攜帶當前走到哪一層（`path`）、最後一個路徑元件名稱（`last`）、符號連結巢套深度（`depth`）以及是否使用 RCU-walk（`flags & LOOKUP_RCU`）。

**檔案路徑**: `fs/internal.h`（第 187 行起）


這是 `openat` 系統呼叫將 `flags` 與 `mode` 轉換成核心內部表示後的結構，後續整條開啟路徑都依賴它。

### 源碼流程說明

#### 第一階段：系統呼叫與參數轉換

當使用者空間執行 `openat(fd, "foo/bar", O_RDONLY)` 時，流程從 `fs/open.c` 中的系統呼叫定義開始：

```c
SYSCALL_DEFINE4(openat, int, dfd, const char __user *, filename, int, flags,
		umode_t, mode)
{
	if (force_o_largefile())
		flags |= O_LARGEFILE;
	return do_sys_open(dfd, filename, flags, mode);
}
```

`do_sys_open()` 將參數封裝成 `struct open_how`，再交給 `do_sys_openat2()`：

```c
static int do_sys_openat2(int dfd, const char __user *filename,
			  struct open_how *how)
{
	struct open_flags op;
	int err = build_open_flags(how, &op);
	if (unlikely(err))
		return err;

	CLASS(filename, name)(filename);
	return FD_ADD(how->flags, do_file_open(dfd, name, &op));
}
```

`build_open_flags()` 負責解析 `O_CREAT`、`O_TRUNC`、`O_EXCL` 等旗標，填入 `struct open_flags`。`FD_ADD`（定義於 `include/linux/file.h`）是一個宏，它會先分配一個未使用的檔案描述子（fd），再將 `do_file_open()` 回傳的 `struct file*` 安裝到該 fd。

#### 第二階段：nameidata 初始化與 RCU-walk 嘗試

`do_file_open()` 位於 `fs/namei.c`：

```c
struct file *do_file_open(int dfd, struct filename *pathname,
		const struct open_flags *op)
{
	struct nameidata nd;
	int flags = op->lookup_flags;
	struct file *filp;

	if (IS_ERR(pathname))
		return ERR_CAST(pathname);
	set_nameidata(&nd, dfd, pathname, NULL);
	filp = path_openat(&nd, op, flags | LOOKUP_RCU);
	if (unlikely(filp == ERR_PTR(-ECHILD)))
		filp = path_openat(&nd, op, flags);
	if (unlikely(filp == ERR_PTR(-ESTALE)))
		filp = path_openat(&nd, op, flags | LOOKUP_REVAL);
	restore_nameidata();
	return filp;
}
```

這裡的關鍵設計是**三次嘗試**（triple retry）：
1. **第一次**：帶 `LOOKUP_RCU` 旗標，嘗試完全無鎖的 RCU-walk。
2. **第二次**：若 RCU-walk 因為 seqlock 失效或需要睡眠而回傳 `-ECHILD`，則退回到 reference-walk（常規模式）。
3. **第三次**：若遇到 stale dentry（`-ESTALE`），則強制重新驗證（`LOOKUP_REVAL`）。

這種設計讓快路徑（fast path）完全不需要拿任何鎖，只有慢路徑才會進入持有 `d_lock` 與 `rename_lock` 的代碼。

#### 第三階段：path_openat 的路徑走訪狀態機

```c
static struct file *path_openat(struct nameidata *nd,
			const struct open_flags *op, unsigned flags)
{
	struct file *file;
	int error;

	file = alloc_empty_file(op->open_flag, current_cred());
	if (IS_ERR(file))
		return file;

	if (unlikely(file->f_flags & __O_TMPFILE)) {
		error = do_tmpfile(nd, flags, op, file);
	} else if (unlikely(file->f_flags & O_PATH)) {
		error = do_o_path(nd, flags, file);
	} else {
		const char *s = path_init(nd, flags);
		while (!(error = link_path_walk(s, nd)) &&
		       (s = open_last_lookups(nd, file, op)) != NULL)
			;
		if (!error)
			error = do_open(nd, file, op);
		terminate_walk(nd);
	}
	...
}
```

對於一般檔案，`path_openat()` 會先呼叫 `path_init()` 設定起始根目錄（根據路徑是否絕對路徑，決定從 `current->fs->root` 或 `nd->dfd` 開始）。接著進入 `link_path_walk()` 的迴圈：

```c
static int link_path_walk(const char *name, struct nameidata *nd)
{
	...
	for(;;) {
		struct mnt_idmap *idmap;
		const char *link;
		unsigned long lastword;

		idmap = mnt_idmap(nd->path.mnt);
		err = may_lookup(idmap, nd);
		if (unlikely(err))
			return err;

		nd->last.name = name;
		name = hash_name(nd, name, &lastword);

		switch(lastword) {
		case LAST_WORD_IS_DOTDOT:
			nd->last_type = LAST_DOTDOT;
			nd->state |= ND_JUMPED;
			break;
		case LAST_WORD_IS_DOT:
			nd->last_type = LAST_DOT;
			break;
		default:
			nd->last_type = LAST_NORM;
			...
		}

		if (!*name)
			goto OK;
		...
		link = walk_component(nd, WALK_MORE);
	}
}
```

`hash_name()` 是高度最佳化的組合語言輔助函式，它能以每次一個 `unsigned long` 的方式解析路徑元件名稱並同時計算雜湊值。`walk_component()` 是每個路徑元件的處理核心：

```c
static __always_inline const char *walk_component(struct nameidata *nd, int flags)
{
	struct dentry *dentry;

	if (unlikely(nd->last_type != LAST_NORM)) {
		return handle_dots(nd, nd->last_type);
	}
	dentry = lookup_fast(nd);
	if (IS_ERR(dentry))
		return ERR_CAST(dentry);
	if (unlikely(!dentry)) {
		dentry = lookup_slow(&nd->last, nd->path.dentry, nd->flags);
		if (IS_ERR(dentry))
			return ERR_CAST(dentry);
	}
	return step_into(nd, flags, dentry);
}
```

#### 第四階段：dentry cache 的快慢查找

`lookup_fast()` 實現了 RCU-walk 與 reference-walk 的雙路徑邏輯：

```c
static struct dentry *lookup_fast(struct nameidata *nd)
{
	struct dentry *dentry, *parent = nd->path.dentry;
	int status = 1;

	if (nd->flags & LOOKUP_RCU) {
		dentry = __d_lookup_rcu(parent, &nd->last, &nd->next_seq);
		if (unlikely(!dentry)) {
			if (!try_to_unlazy(nd))
				return ERR_PTR(-ECHILD);
			return NULL;
		}
		if (read_seqcount_retry(&parent->d_seq, nd->seq))
			return ERR_PTR(-ECHILD);
		status = d_revalidate(nd->inode, &nd->last, dentry, nd->flags);
		if (likely(status > 0))
			return dentry;
		...
	} else {
		dentry = __d_lookup(parent, &nd->last);
		if (unlikely(!dentry))
			return NULL;
		status = d_revalidate(nd->inode, &nd->last, dentry, nd->flags);
	}
	...
}
```

`__d_lookup_rcu()`（位於 `fs/dcache.c`）在 RCU 讀端臨界區內掃描雜湊表：

```c
struct dentry *__d_lookup_rcu(const struct dentry *parent,
				const struct qstr *name,
				unsigned *seqp)
{
	u64 hashlen = name->hash_len;
	const unsigned char *str = name->name;
	struct hlist_bl_head *b = d_hash(hashlen);
	struct hlist_bl_node *node;
	struct dentry *dentry;

	hlist_bl_for_each_entry_rcu(dentry, node, b, d_hash) {
		unsigned seq;
		seq = raw_seqcount_begin(&dentry->d_seq);
		if (dentry->d_parent != parent)
			continue;
		if (dentry->d_name.hash_len != hashlen)
			continue;
		if (unlikely(dentry_cmp(dentry, str, hashlen_len(hashlen)) != 0))
			continue;
		if (unlikely(d_unhashed(dentry)))
			continue;
		*seqp = seq;
		return dentry;
	}
	return NULL;
}
```

這段代碼是 VFS 中最關鍵的熱路徑之一：它使用 `hlist_bl_for_each_entry_rcu()` 遍歷雜湊鏈表，比對 `d_parent`、`hash_len` 與名稱字串，全程**不拿任何 spinlock**。它只記錄下 `dentry->d_seq` 的原始值，交由上層 `lookup_fast()` 在適當時機驗證。

若 RCU-walk 失敗（例如遇到需要睡眠的檔案系統專屬 `d_revalidate`），`try_to_unlazy()` 會將 `nameidata` 從 RCU 模式切換為常規模式，隨後 `__d_lookup()` 會以 `spin_lock(&dentry->d_lock)` 保護比對過程，並遞增 `d_lockref.count`：

```c
struct dentry *__d_lookup(const struct dentry *parent, const struct qstr *name)
{
	unsigned int hash = name->hash;
	struct hlist_bl_head *b = d_hash(hash);
	struct hlist_bl_node *node;
	struct dentry *found = NULL;
	struct dentry *dentry;

	rcu_read_lock();
	hlist_bl_for_each_entry_rcu(dentry, node, b, d_hash) {
		if (dentry->d_name.hash != hash)
			continue;
		spin_lock(&dentry->d_lock);
		if (dentry->d_parent != parent)
			goto next;
		if (d_unhashed(dentry))
			goto next;
		if (!d_same_name(dentry, parent, name))
			goto next;
		dentry->d_lockref.count++;
		found = dentry;
		spin_unlock(&dentry->d_lock);
		break;
	next:
		spin_unlock(&dentry->d_lock);
	}
	rcu_read_unlock();
	return found;
}
```

#### 第五階段：從路徑到 struct file

路徑走訪完成後，`do_open()` 會進行最終的權限檢查，然後呼叫 `vfs_open()`：

```c
int vfs_open(const struct path *path, struct file *file)
{
	int ret;

	file->__f_path = *path;
	ret = do_dentry_open(file, NULL);
	if (!ret) {
		fsnotify_open(file);
	}
	return ret;
}
```

`do_dentry_open()`（`fs/open.c`）是真正將檔案系統操作表掛載到 `struct file` 的地方：

```c
static int do_dentry_open(struct file *f,
			  int (*open)(struct inode *, struct file *))
{
	static const struct file_operations empty_fops = {};
	struct inode *inode = f->f_path.dentry->d_inode;
	int error;

	path_get(&f->f_path);
	f->f_inode = inode;
	f->f_mapping = inode->i_mapping;
	...
	f->f_op = fops_get(inode->i_fop);
	if (WARN_ON(!f->f_op)) {
		error = -ENODEV;
		goto cleanup_all;
	}

	error = security_file_open(f);
	if (unlikely(error))
		goto cleanup_all;
	...
	if (!open)
		open = f->f_op->open;
	if (open) {
		error = open(inode, f);
		if (error)
			goto cleanup_all;
	}
	f->f_mode |= FMODE_OPENED;
	if ((f->f_mode & FMODE_READ) &&
	     likely(f->f_op->read || f->f_op->read_iter))
		f->f_mode |= FMODE_CAN_READ;
	if ((f->f_mode & FMODE_WRITE) &&
	     likely(f->f_op->write || f->f_op->write_iter))
		f->f_mode |= FMODE_CAN_WRITE;
	...
	return 0;
}
```

在這裡，核心透過 `fops_get(inode->i_fop)` 取得檔案系統註冊的操作表（例如 ext4 的 `ext4_file_operations`），並將其賦值給 `f->f_op`。如果該檔案系統提供了專屬的 `->open()` 方法（例如 ext4 會在這裡初始化 extent status cache），則會在此時被呼叫。最後 `FMODE_OPENED` 被設定，標誌這個 `struct file` 已完全就緒。

### 設計原理與悲劇情境

#### 1. dentry cache 的分離式設計：為什麼 inode 與 dentry 要分開？

傳統檔案系統（如 ext4）在磁碟上的資料結構與 VFS 的記憶體結構並非一一對應。磁碟上的目錄項儲存的是「名稱 → inode number」對應，而 inode 儲存的是檔案中繼資料。VFS 將兩者分離成 `dentry` 與 `inode`，讓核心可以：
- 快取負目錄項（negative dentry）：即使檔案不存在，核心也能快取「查過了，沒有」的結果，避免重複呼叫底層檔案系統的 `lookup()`。
- 支援硬連結：多個 `dentry`（不同路徑名稱）可以指向同一個 `inode`（透過 `d_alias` 鏈表）。
- 獨立回收：當記憶體不足時，核心可以只回收 `dentry`（名稱快取）而保留 `inode`（髒頁回寫仍需要它）。

#### 2. RCU-walk 的優雅與脆弱

RCU-walk 是現代 Linux VFS 的效能殺手鐧。它讓路徑查找在**不拿任何鎖、不遞增任何 refcount** 的情況下完成。但這條快路徑極其脆弱，以下任何一個條件都會迫使它退回常規模式：
- 目錄項的 `d_seq` seqlock 發生變化（表示有並發 rename）。
- 檔案系統的 `d_op->d_revalidate` 需要睡眠（如 NFS 需要向伺服器發送 GETATTR）。
- 遇到掛載點（mount point）需要切換 `vfsmount`。
- 符號連結（symlink）需要巢套解析。

在大量使用 NFS、FUSE 或容器掛載的環境中，RCU-walk 的退避率會顯著上升，導致 `__d_lookup()` 中的 `spin_lock` 爭搶加劇。

#### 3. `alloc_empty_file()` 與 fd 安裝的時序陷阱

`path_openat()` 一開始就呼叫 `alloc_empty_file()` 分配 `struct file`，但此時路徑尚未解析。如果路徑解析失敗（例如 `-ENOENT`），`path_openat()` 會走 `fput_close(file)` 釋放它。這個「先分配、後驗證」的設計看似浪費，實則是為了讓 `do_open()` 能將 `struct file` 傳遞給 `fsnotify`、`security_file_open()` 等子系統，這些子系統可能在開啟前就需要一個完整的 `file` 物件作為稽核標的。

#### 4. 負目錄項與安全風險

`dentry->d_inode == NULL` 表示這是一個負目錄項（negative dentry），用來快取「這個名稱不存在」的事實。然而，在特定的 timing attack 中，攻擊者可以操縱負目錄項的存活時間，影響核心對檔案存在與否的判斷。這也是為什麼 `d_invalidate()` 與 `d_drop()` 的呼叫點必須極其謹慎。

### 實際應用推薦

1. **觀測 dentry cache 命中率**：
   ```bash
   # 檢視全系統的 dentry 統計
   cat /proc/sys/fs/dentry-state
   # 輸出：nr_dentry nr_unused age_limit want_pages
   # nr_unused 接近 nr_dentry 表示快取充裕；若比例低，可能需要增加記憶體
   ```

2. **追蹤 VFS 路徑查找延遲**：
   ```bash
   # 使用 ftrace 追蹤 lookup_fast 與 lookup_slow 的呼叫比例
   echo 'probe:/tmp/namei.c:lookup_fast' > /sys/kernel/debug/tracing/uprobe_events
   echo 'probe:/tmp/namei.c:lookup_slow' >> /sys/kernel/debug/tracing/uprobe_events
   # 或更簡單地，使用 bpftrace：
   bpftrace -e 'kprobe:lookup_fast { @fast++; } kprobe:lookup_slow { @slow++; }'
   ```

3. **診斷 RCU-walk 退避**：
   ```bash
   # 透過 eBPF 統計 try_to_unlazy 的觸發次數
   bpftrace -e 'kprobe:try_to_unlazy { @unlazy[comm] = count(); }'
   # 若某個行程頻繁觸發 try_to_unlazy，可能是其工作目錄位於 FUSE/NFS 上
   ```

4. **清理 dentry / inode 快取（謹慎操作）**：
   ```bash
   # 強制回收未使用的 dentry 與 inode
   echo 2 > /proc/sys/vm/drop_caches
   # 注意：這不會回收仍被參照的 dentry，只會回收負目錄項與未使用 inode
   ```
