## Linux Kernel 深度解析 — VFS Inode 生命週期與 Page Cache 回寫：從 `alloc_inode` 到 `__writeback_single_inode` 的原始碼全徑

### 原理概述

Virtual File System（VFS）不僅是路徑查找的抽象層，更是檔案內容在記憶體中駐留與落盤的總指揮部。當使用者透過 `write()` 修改檔案內容時，真正的資料並非直接抵達磁碟，而是先進入與 `struct inode` 綁定的 `struct address_space` 所管理的 Page Cache；當髒頁累積到一定門檻，核心的 `bdi_writeback` 執行緒便會喚醒，透過 `__writeback_single_inode()` 將資料與中繼資料同步回檔案系統。本文將沿著 `inode_init_always()` 的初始化路徑、`__mark_inode_dirty()` 的髒狀態機，以及 `fs/fs-writeback.c` 中的回寫管線，逐行拆解這條從記憶體到區塊裝置的完整旅程。

> **版本說明**：本文原始碼行號與結構定義取自 Linux v6.13/v6.14 主線（torvalds/linux master）。`struct super_block` 定義參照 v6.13 穩定版；`struct inode`、`struct file` 與 `struct address_space` 來自 master 分支 `include/linux/fs.h`。

`struct inode` 是 VFS 與具體檔案系統之間的契約載體。`i_mapping` 指向統一管理該 inode 頁快取的 `address_space`；`i_data` 則是內嵌的 `address_space` 實體，大多數檔案系統讓 `i_mapping = &inode->i_data`。`i_state` 記錄 inode 的髒狀態（`I_DIRTY_SYNC`、`I_DIRTY_PAGES`、`I_DIRTY_TIME`），是回寫排程器的核心判斷依據。`i_lock` 保護 `i_state`、`dirtied_when` 與 `i_io_list` 的變更；而 `i_rwsem` 則提供高階的讀寫同步，例如 `ext4` 在寫入前會鎖住 `i_rwsem`。

### 源碼流程說明

#### 路徑一：Inode 的誕生 — `inode_init_always()` 與 `alloc_inode`

當檔案系統需要一個新的 inode（例如 `creat()` 或 `mkdir()`）時，底層檔案系會呼叫 `new_inode()`（`fs/inode.c`），其內部鏈為：

```
new_inode() -> alloc_inode() -> inode_init_always()
```

`inode_init_always()`（`fs/inode.c`，約第 436 行）是 VFS 層統一的初始化函式：

```c
int inode_init_always(struct super_block *sb, struct inode *inode)
{
    static const struct inode_operations empty_iops;
    static const struct file_operations empty_fops;
    struct address_space *const mapping = &inode->i_data;

    inode->i_sb = sb;
    inode->i_blkbits = sb->s_blocksize_bits;
    inode->i_mapping = mapping;
    /* ... */
    mapping->a_ops = &empty_aops;
    mapping->host = inode;
    mapping->flags = 0;
    mapping->i_pages = XARRAY_INIT(mapping->i_pages, GFP_NOFS);
    /* ... */
    INIT_LIST_HEAD(&inode->i_io_list);
    INIT_LIST_HEAD(&inode->i_lru);
    INIT_LIST_HEAD(&inode->i_sb_list);
    INIT_LIST_HEAD(&inode->i_wb_list);
    /* ... */
}
```

關鍵在於 `mapping->host = inode` 與 `inode->i_mapping = mapping` 的雙向掛載。從這一刻起，所有對此 inode 的頁快取操作都會透過 `i_mapping->i_pages` 這顆 XArray 進行索引。`i_io_list`、`i_wb_list` 與 `i_sb_list` 分別是髒 inode 佇列、回寫佇列與 super_block 全域鏈表的錨點。

#### 路徑二：標記髒亂 — `__mark_inode_dirty()` 的狀態機

當使用者寫入資料時，檔案系統的 `write_end` 會呼叫 `mark_inode_dirty()`，最終進入 `__mark_inode_dirty()`（`fs/fs-writeback.c`，第 2588 行）。這是 VFS 回寫體系最核心的狀態轉換點：

```c
void __mark_inode_dirty(struct inode *inode, int flags)
{
    struct super_block *sb = inode->i_sb;
    int dirtytime = 0;
    struct bdi_writeback *wb = NULL;

    if (flags & I_DIRTY_INODE) {
        /* 通知檔案系統更新日誌或 on-disk inode */
        if (sb->s_op->dirty_inode)
            sb->s_op->dirty_inode(inode, flags & (I_DIRTY_INODE | I_DIRTY_TIME));
        flags &= ~I_DIRTY_TIME;
    } else {
        dirtytime = flags & I_DIRTY_TIME;
    }

    smp_mb();   /* 與 __writeback_single_inode() 的 lockless 測試配對 */

    if ((inode_state_read_once(inode) & flags) == flags)
        return;

    spin_lock(&inode->i_lock);
    if ((inode_state_read(inode) & flags) != flags) {
        const int was_dirty = inode_state_read(inode) & I_DIRTY;
        inode_attach_wb(inode, NULL);
        inode_state_set(inode, flags);

        if (!was_dirty) {
            wb = locked_inode_to_wb_and_lock_list(inode);
            spin_lock(&inode->i_lock);
        }

        if (inode_state_read(inode) & I_SYNC_QUEUED)
            goto out_unlock;

        if (!S_ISBLK(inode->i_mode) && inode_unhashed(inode))
            goto out_unlock;
        if (inode_state_read(inode) & I_FREEING)
            goto out_unlock;

        if (!was_dirty) {
            struct list_head *dirty_list;
            bool wakeup_bdi = false;

            inode->dirtied_when = jiffies;
            if (dirtytime)
                inode->dirtied_time_when = jiffies;

            if (inode_state_read(inode) & I_DIRTY)
                dirty_list = &wb->b_dirty;
            else
                dirty_list = &wb->b_dirty_time;

            wakeup_bdi = inode_io_list_move_locked(inode, wb, dirty_list);
            if (wakeup_bdi && (wb->bdi->capabilities & BDI_CAP_WRITEBACK))
                wb_wakeup_delayed(wb);
            /* ... unlock and return ... */
        }
    }
out_unlock:
    /* ... */
}
```

這段程式碼體現了回寫系統的三個精妙設計：

1. **smp_mb() 屏障**：在設定 `I_DIRTY` 之前插入記憶體屏障，與 `__writeback_single_inode()` 開頭的 `WARN_ON(!(inode_state_read_once(inode) & I_SYNC))` 形成 lockless 握手，確保回寫執行緒不會在狀態位元完全生效前開始清掃。

2. **時間戳排序**：`dirtied_when = jiffies` 記錄首次變髒的時間。回寫執行緒在 `writeback_sb_inodes()` 中會依照 `dirtied_when` 由舊到新遍歷 `wb->b_dirty` 鏈表，這保證了先髒先寫（FIFO）的公平性，也讓 `sync()` 能根據時間判斷哪些 inode 必須立即處理。

3. **BDI 喚醒**：如果 `wakeup_bdi` 為真且 backing device 具備 `BDI_CAP_WRITEBACK`，則呼叫 `wb_wakeup_delayed(wb)`。這並非立即排程，而是透過工作佇列延遲喚醒 `bdi_writeback` 執行緒，讓短時間內累積的多次髒標記有機會合併，減少 CPU 中斷次數。

#### 路徑三：回寫執行 — `__writeback_single_inode()`

當 `bdi_writeback` 執行緒（由 `wb_thread_fn()` 驅動）從 `wb->b_dirty` 鏈表摘下一個 inode，它會設定 `I_SYNC` 旗標，然後呼叫 `__writeback_single_inode()`（`fs/fs-writeback.c`，第 1753 行）：

```c
__writeback_single_inode(struct inode *inode, struct writeback_control *wbc)
{
    struct address_space *mapping = inode->i_mapping;
    long nr_to_write = wbc->nr_to_write;
    unsigned dirty;
    int ret;

    WARN_ON(!(inode_state_read_once(inode) & I_SYNC));

    ret = do_writepages(mapping, wbc);

    /* WB_SYNC_ALL 且非 sync(2) 時，等待資料 I/O 完成 */
    if (wbc->sync_mode == WB_SYNC_ALL && !wbc->for_sync) {
        int err = filemap_fdatawait(mapping);
        if (ret == 0)
            ret = err;
    }

    /* lazy time 到期時，強制轉成 I_DIRTY_SYNC */
    if ((inode_state_read_once(inode) & I_DIRTY_TIME) &&
        (wbc->sync_mode == WB_SYNC_ALL ||
         time_after(jiffies, inode->dirtied_time_when +
                    dirtytime_expire_interval * HZ)))
        sync_lazytime(inode);

    spin_lock(&inode->i_lock);
    dirty = inode_state_read(inode) & I_DIRTY;
    inode_state_clear(inode, dirty);

    smp_mb();   /* 與 __mark_inode_dirty() 的 lockless 測試配對 */

    if (mapping_tagged(mapping, PAGECACHE_TAG_DIRTY))
        inode_state_set(inode, I_DIRTY_PAGES);
    else if (unlikely(inode_state_read(inode) & I_PINNING_NETFS_WB)) {
        /* netfs writeback pinning 處理 */
    }
    spin_unlock(&inode->i_lock);

    if (dirty & ~I_DIRTY_PAGES) {
        int err = write_inode(inode, wbc);
        if (ret == 0)
            ret = err;
    }
    return ret;
}
```

回寫分為兩個階段：**資料回寫**與**中繼資料回寫**。`do_writepages()` 呼叫檔案系統的 `a_ops->writepages()`，將髒頁透過 bio 下發到區塊層；隨後 `write_inode()`（由 `sb->s_op->write_inode` 實作）將 inode 的 metadata（大小、時間戳、區塊指標）寫入磁碟。為什麼要分兩次？因為許多檔案系統（如 ext4）使用日誌（journal），metadata 的寫入順序必須在資料落盤之後，否則崩潰後會出現「metadata 指向尚未寫入的舊資料區塊」的不一致狀態。

注意 `mapping_tagged(mapping, PAGECACHE_TAG_DIRTY)` 這一行：即使 `do_writepages()` 已經寫了一批頁，在 `smp_mb()` 之後若 XArray 仍然標記了 `PAGECACHE_TAG_DIRTY`，表示在回寫期間又有新的髒頁產生（所謂「redirty」），`I_DIRTY_PAGES` 會被重新設置，inode 將再次進入 `wb->b_dirty` 佇列，等待下一輪 flush。

### 設計原理與悲悸情境

#### 1. Page Cache 的雙面性：加速與遺失的權衡

Page Cache 的存在讓重複讀取與延遲寫入（write-back）變得極為高效，但代價是系統崩潰時尚未回寫的資料會全部遺失。核心為此設計了多層安全網：

- **pdflush / bdi_writeback 執行緒**：預設每 5 秒（`dirty_expire_centisecs`）或當髒頁超過一定比例（`dirty_ratio` / `dirty_background_ratio`）時自動喚醒。
- **sync() 與 fsync()**：提供強制落盤的顯式語意。`fsync()` 會將指定檔案的資料與中繼資料全部回寫，並等待 I/O 完成；其底層正是透過 `WB_SYNC_ALL` 模式的 `writeback_single_inode()` 實現。

#### 2. 回寫的競爭與活鎖（livelock）

`__mark_inode_dirty()` 與 `__writeback_single_inode()` 之間存在精巧的競爭窗口。想像以下時序：

- **CPU 0**：`__writeback_single_inode()` 呼叫 `do_writepages()`，正在構建 bio。
- **CPU 1**：使用者寫入新資料，觸發 `__mark_inode_dirty()`。

如果沒有 `smp_mb()` 與 `I_SYNC` 旗標的保護，`__mark_inode_dirty()` 可能在回寫執行緒尚未完成時就將 inode 移回 `b_dirty`，導致同一個 inode 被並發回寫兩次，破壞 `nr_to_write` 的計數，甚至讓檔案系統日誌產生不一致的順序。`I_SYNC` 旗標的作用正是在回寫期間「鎖住」inode，讓後來的 `__mark_inode_dirty()` 看到 `I_SYNC_QUEUED` 後放棄重新排隊，改為僅更新狀態位元。

#### 3. Inode 記憶體壓力與 `iput()` 的陷阱

當 `struct file` 被 `close()` 釋放時，`fput()` 會遞減 `i_count`。如果 `i_count` 歸零，則呼叫 `iput()` 進入釋放流程。此時若 inode 仍帶有 `I_DIRTY` 或 `I_DIRTY_PAGES`，`iput()` 會觸發 `writeback_single_inode(inode, &wbc)` 進行強制回寫，這就是為什麼 `close()` 並不保證資料已落盤——它只保證「嘗試」回寫，如果回寫執行緒已經在處理此 inode，或者 BDI 佇列已滿，`close()` 仍可能在不等待 I/O 完成的情況下返回。這是許多應用程式開發者誤以為「寫入後 close 就安全」的根本原因。

#### 4. `address_space` 的 XArray 與 THP 的張力

`i_pages` 在 v5.x 之前是 Radix Tree，後來被替換為 XArray，以支援更高的並發查找與批量操作。然而，當啟用 Transparent Huge Pages（THP）時，`nr_thps` 計數器追蹤映射中的大頁數量，這與傳統 4K 頁的 reclaim 邏輯產生互動。在記憶體回收（kswapd）掃描 `i_pages` 時，如果發現 THP 頁，必須透過 `split_folio()` 將其拆分成基本頁，才能進行細粒度的逐出。這個過程涉及 `a_ops->invalidate_folio()` 與 `release_folio()` 的回撥，若檔案系統驅動未妥善實作，可能導致 page reference count 泄漏，觸發 `BUG_ON(page_ref_count(page) != 0)` 的 Oops。

### 實際應用推薦

#### 1. 髒頁回寫的 sysctl 調校

透過 `/proc/sys/vm/` 中的參數，可以根據儲存裝置特性調整回寫策略：

- `dirty_background_ratio`（預設 10%）：當髒頁佔總記憶體超過此比例，背景回寫執行緒開始工作。對於 NVMe SSD，可以降至 5% 以減少突發寫入峰值；對於低速 HDD，可提高到 20% 以減少磁頭移動。
- `dirty_ratio`（預設 20%）：當髒頁超過此比例，所有寫入行程將被阻塞，強制等待回寫完成。資料庫系統通常建議調至 40%，避免大量寫入時的停頓，但需確保有足夠的 I/O 頻寬。
- `dirty_expire_centisecs`（預設 3000，即 30 秒）：髒頁在記憶體中最長存活時間。對於日誌型系統（如 Kafka），可以縮短至 1000（10 秒），降低崩潰時的資料窗口。
- `dirty_writeback_centisecs`（預設 500，即 5 秒）：回寫執行緒的喚醒週期。調低可以增加回寫頻率，分散 I/O 壓力；調高則減少 CPU  wake-up 次數。

#### 2. 使用 ftrace 觀測回寫行為

```bash
# 追蹤標記 inode 為髒的熱點
echo 'writeback:__mark_inode_dirty' > /sys/kernel/debug/tracing/set_event
echo 'writeback:writeback_single_inode' >> /sys/kernel/debug/tracing/set_event
echo 'writeback:writeback_pages_written' >> /sys/kernel/debug/tracing/set_event
cat /sys/kernel/debug/tracing/trace_pipe
```

透過觀察 `__mark_inode_dirty` 與 `writeback_single_inode` 的時間間隔，可以判斷系統的回寫延遲是否異常。如果兩者間隔長期超過 `dirty_expire_centisecs`，表示 BDI 執行緒可能陷入 I/O 壅塞，需要檢查底層儲存裝置的佇列深度與 I/O 調度器設定。

#### 3. 診斷 `close()` 後資料遺失的經典案例

若應用程式在 `write()` + `close()` 後斷電遺失資料，排查步驟應為：

1. 確認應用是否呼叫了 `fsync()` 或 `fdatasync()`。`close()` 僅釋放 `struct file`，並不等價於 `fsync()`。
2. 檢查檔案系統掛載選項。`nobarrier`（舊版 ext4）或 `nojournal` 會削弱回寫的資料完整性保證。
3. 透過 `blocktrace` 觀察 `write_inode()` 與 `do_writepages()` 的實際下刷順序，確認 metadata journal 是否確實在資料 bio 完成後才寫入。
