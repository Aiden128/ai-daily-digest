# Linux Kernel 深度解析 — Timekeeping & Tick Scheduling：從 `ktime_get()` 到 `tick_sched_timer` 的 `clocksource` / `clock_event_device` / `tick_device` / `tick_sched` 抽象、`timekeeper` 結構、`clocksource_change_notifier` 通知鏈、`vDSO` 快速路徑、`NO_HZ` 動態 tick 抑制、`HRTIMER` 與 `hrtimer_interrupt` 的原始碼全徑

> **版本說明**：本文所有原始碼行號、結構定義與巨集皆取自 Linux **v6.13/v6.14 主線**（`torvalds/linux` master，2026 年 6 月）。核心檔案：`kernel/time/timekeeping.c`（`timekeeping` 抽象、`do_timer` 系族、`timekeeper_update_ratelimited`、`timekeeping_restore_skew`）、`kernel/time/tick-common.c`（`tick_handle_periodic`、`tick_setup_device`、`tick_check_new_device`、`tick_get_device`）、`kernel/time/tick-sched.c`（`tick_sched_timer`、`tick_nohz_tick`、`tick_nohz_idle_enter/exit`、`tick_reprogram`、`tick_sched_do_timer`、`__tick_nohz_task_switch`）、`kernel/time/tick-oneshot.c`（`tick_init_highres`、`tick_setup_oneshot`、`tick_program_event`）、`include/linux/clocksource.h`（`struct clocksource`、`clocksource_get_rating`、`clocksource_change_notifier`）、`include/linux/clockchips.h`（`struct clock_event_device`、`struct clock_event_device::event_handler`、`clockevents_set_mode`）、`include/linux/tick.h`（`struct tick_device`、`struct tick_sched`、`tick_cpu_device` per-cpu 變數）、`kernel/time/hrtimer.c`（`hrtimer_run_queues`、`hrtimer_interrupt`、`hrtimer_reprogram`、`__hrtimer_run_queues`、`hrtimer_switch_to_hres`）、`kernel/time/timeconv.c`、`kernel/vtime.c`（`account_process_tick`、`vtime_common_task_switch`）、`arch/x86/kernel/tsc.c`（`tsc_init`、`notifier` 回呼）、`arch/x86/kernel/irq_vectors.h`、`drivers/clocksource/`、`arch/x86/entry/vdso/vma.c`（`vdso_install_special_mapping`）、`arch/x86/entry/vdso/vclock_gettime.c`（`__vdso_clock_gettime` vDSO 入口）、`include/vdso/datapage.h`（`struct vdso_data`、`seq` 同步）。相關鎖：`seqcount_raw_spinlock_t`（`timekeeper_seq`）、`raw_spinlock_t tk_core_lock`、`struct hrtimer_cpu_base::lock`（`hrtimer_base` 的 base-lock）。

## 原理概述

Linux 核心的「時間子系統」是把「**時鐘源（clocksource）**」與「**時鐘事件裝置（clock_event_device）**」這兩個**完全解耦的硬體抽象**，再在其上疊了三層軟體抽象 — `tick_device`（週期性 tick 驅動）、`tick_sched`（per-CPU 的 NO_HZ 動態 tick 抑制）、`hrtimer`（高解析度 timer）— 並以 `timekeeper` 全域結構統一「**wall time**（CLOCK_REALTIME）」「**monotonic**（CLOCK_MONOTONIC）」「**raw monotonic（CLOCK_MONOTONIC_RAW）**」三條讀取路徑的換算。`timekeeper` 維護的是「**64-bit 奈秒 + cycles 的線性內插**」（`tk->tkr_mono.xtime_nsec` + `tk->tkr_mono.cycle_*`），每次 `tk_update_ktime_data` 都把上一輪 cycle 差乘上 `mult` 算到 `xtime_nsec`（本質是 `((Δcycles * mult) >> shift)` 避免 64-bit 溢位）。應用程式讀時間最快的路徑**根本不會進內核** — `vDSO` 共享一頁 `struct vdso_data`（每 CPU 一份），使用者程式在 `__vdso_clock_gettime()` 直接讀該頁內已預先換算好的 `sec/nsec`，並用 `seq` 做 `READ_ONCE` 鬆散讀法以配合 `timekeeper` 用 `seqcount_raw_spinlock_t` 的 `write_seqcount_begin/end` 寫法（lock-free 順序鎖）。`tick_sched` 動態抑制是 NO_HZ 的靈魂：當 CPU 進入 idle 且沒有 per-CPU hrtimer 即將到時，`tick_nohz_stop_sched_tick()` 會把下一次 tick 抑制到**最遠到期的 hrtimer** 那一刻，必要時甚至「**fully nohz**」（`NO_HZ_FULL`）下完全停止 tick；當 tick 真的發生時，無論是從 idle 醒來或 hrtimer 到期，核心都用 `hrtimer_interrupt()`（`kernel/time/hrtimer.c`）把 `hrtimer_cpu_base::expires_next` 取下、跑 `__hrtimer_run_queues` 收單所有到時的 hrtimer callback，再視情況呼叫 `tick_sched_timer()` 觸發 `scheduler_tick` 重排程。整個時間子系統的設計目標是「**使用者讀時間不進 syscalls，idle CPU 不被 tick 打擾，到時 timer 仍精準觸發**」，並透過 `clocksource_change_notifier` 鏈（`notifier_block_register(&clocksource_chain)`）處理 TSC 從「壞→好」、HPET 被關閉等 hot-swap 事件，最終把 `timekeeper` 重算到新 clocksource 的尺度上。

## 核心資料結構與函數（含路徑）

### 1. `struct timekeeper`（`include/linux/timekeeper_internal.h`）

`timekeeper` 是「全域單例」核心狀態，存放在 `tk_core` 全域變數（`kernel/time/timekeeping.c`）中，由 `tk_core_lock`（`raw_spinlock_t`）守護，外加 `timekeeper_seq`（`seqcount_raw_spinlock_t`）給 lock-free 讀取使用：

```c
// include/linux/timekeeper_internal.h
struct tk_read_base {
    u64             cycle_last;   // 上次 update 的 clocksource cycle 計數
    u64             mask;         // clocksource->mask（64-bit 寬度）
    u64             mult;         // cycle→ns 的乘法係數（已被 shift 處理）
    u32             shift;        // mult 的 shift 數
    u64             xtime_nsec;   // 該 base 對應的奈秒（已累積的 ns）
    ktime_t         base;         // 對映到 monotonic/xtime 那一軸的 ktime_t
    u64             (*read)(struct clocksource *cs); // 包裝成 mult/shift 對齊
    struct clocksource *cs;        // 對應的 clocksource
};

struct timekeeper {
    struct tk_read_base   tkr_mono;       // CLOCK_MONOTONIC 軸
    struct tk_read_base   tkr_raw;        // CLOCK_MONOTONIC_RAW 軸（不調整 NTP）
    struct tk_read_base   tkr_boottime;   // CLOCK_BOOTTIME 軸（系統開機以來）
    struct tk_read_base   tkr_realtime;   // CLOCK_REALTIME 軸（wall time）
    u64                 xtime_sec;         // wall time 的整數秒
    u64                 wall_to_monotonic; // wall - mono 的差（suspend 時累加）
    s64                 offs_real;         // realtime 軸的累積 offset
    s64                 offs_boot;         // boottime 軸的累積 offset
    s64                 offs_tai;          // TAI（原子鐘）軸的 offset
    s32                 tai_offset;        // NTP 設定的 leap 秒表
    unsigned int         clock_was_set_seq; // 給 vDSO 看的 wall-time 變更序號
    u64                 cycle_last;        // 上次 update 時的 cycle（給 NTP 用）
    u64                 mask;              // 與 tkr_mono.mask 同值（cache）
    u64                 mult;              // 與 tkr_mono.mult 同值
    u32                 shift;             // 與 tkr_mono.shift 同值
    struct clocksource  *clock;            // 主要 clocksource
    struct clocksource  *clock_realtime;   // 對 realtime 軸專用的替代（極少見）
    u64                 next_leap_ktime;   // 下次 leap 秒插入時間
    s64                 raw_time;          // raw monotonic 累積值
    /*...NTP 狀態...*/
    struct arch_clocksource_data  archdata;
    raw_spinlock_t     lock;               // tk_core_lock 的內嵌
    seqcount_raw_spinlock_t seq;            // 給 vDSO / lock-free 讀的順序鎖
};
```

關鍵內部函式：
- `ktime_get()` / `ktime_get_real()` / `ktime_get_boottime()` / `ktime_get_clocktai()`：四條主要讀取路徑，**hot path 用 `tk_clock_read` 順序鎖讀**（`timekeeping.c`）。
- `do_timer(ticks)`：每個 tick（`tick_handle_periodic` 或 `tick_sched_do_timer`）呼叫一次，把 `jiffies_64 += ticks`、並依 `tick_do_update_jiffies64` 條件（每 `tick_do_update_jiffies64 == 1` 個 tick 一次，正常 1）觸發 `update_wall_time()`。
- `update_wall_time()`：讀 `clocksource->read(tk->tkr_mono.cs)`，算 `Δcycle = (now - tk->cycle_last) & mask`，把 `mult/shift` 套上去得到 `Δns`，分到 `xtime_nsec`、`raw_time` 等多個 base 上，並呼叫 `ntp_tick()` 校正 NTP 漂移。
- `timekeeping_restore_skew()`：`timekeeping_suspend/resume` 期間把 `wall_to_monotonic` 累加 suspend 時長。
- `timekeeper_update_ratelimited()`：透過 `schedule_delayed_work` 限制 wall-time 寫頻率。

### 2. `struct clocksource`（`include/linux/clocksource.h`）

每個時鐘源（TSC、HPET、ACPI PM Timer、hypervisor clock、arch timer）都向核心註冊一個 `struct clocksource`：

```c
// include/linux/clocksource.h
struct clocksource {
    u64 (*read)(struct clocksource *cs);          // 讀取硬體 cycle 計數
    u64 mask;                                      // 計數寬度 mask（TSC 為 0xffffffffffffffff）
    u32 mult;                                      // cycle→ns mult（已包含 shift）
    u32 shift;                                     // mult 對應的 shift
    u64 max_idle_ns;                               // 單次 idle 容忍的最大 Δns（NO_HZ 用）
    u32 maxadj;                                    // NTP freq 調整上限
    struct arch_clocksource_data archdata;
    u64 (*read)(struct clocksource *cs);
    const char *name;                              // "tsc", "hpet", "arch_sys_counter"
    struct list_head list;                         // 鏈到全局 clocksource_list
    int rating;                                    // 品質評分（TSC=300, HPET=250, PIT=100）
    int (*enable)(struct clocksource *cs);         // 啟用 hook（可選）
    void (*disable)(struct clocksource *cs);       // 停用 hook
    void (*suspend)(struct clocksource *cs);
    void (*resume)(struct clocksource *cs);
    void (*unregister)(struct clocksource *cs);
    int (*set_state_oneshot)(struct clock_event_device *);
    int (*tick_resume)(struct clock_event_device *);
    /*...更多欄位...*/
    /* 時間管理用 */
    u32 shift;
    struct module *owner;
};
```

關鍵函式：
- `__clocksource_register_scale()` / `clocksource_register_khz()` / `clocksource_register_hz()`（`kernel/time/clocksource.c`）：把 clocksource 掛到全域鏈，呼叫 `clocksource_select` 重選最佳 source。
- `clocksource_change_rating()` / `clocksource_unregister()`：動態熱插拔。
- `clocksource_get_rating(cs)`：回傳 `cs->rating`，由 `clocksource_select` 選最大者。
- `clocksource_change_notifier`（`struct blocking_notifier_head`）：在 `timekeeping_notify` 處註冊，TSC sync 等事件觸發 `blocking_notifier_call_chain(&clocksource_chain, ...)`.

### 3. `struct clock_event_device`（`include/linux/clockchips.h`）

與 clocksource 互補的「**時鐘事件裝置**」— clocksource 只回答「現在是幾 cycle」，clock_event_device 才能「**在未來某個 cycle 觸發中斷**」。每個 CPU 通常有一個 `clock_event_device`（local APIC timer、HPET、arch_sys_counter、broadcast timer）：

```c
// include/linux/clockchips.h
struct clock_event_device {
    void (*event_handler)(struct clock_event_device *); // 到期中斷處理
    int     (*set_next_event)(unsigned long evt, struct clock_event_device *); // 設定下次到期
    int     (*set_next_event_timed)(unsigned long evt, unsigned long deadline, struct clock_event_device *);
    int     (*set_periodic)(struct clock_event_device *);
    int     (*set_state_oneshot)(struct clock_event_device *); // 進入 oneshot
    int     (*set_state_oneshot_stopped)(struct clock_event_device *);
    int     (*set_state_periodic)(struct clock_event_device *);
    int     (*set_state_shutdown)(struct clock_event_device *);
    int     (*tick_resume)(struct clock_event_device *);
    void    (*broadcast)(const struct cpumask *mask);
    void    (*suspend)(struct clock_event_device *);
    void    (*resume)(struct clock_event_device *);
    u64     next_event;                                // 下次到期 cycle
    u64     max_delta_ns;                              // 最大可程式化 Δ
    u64     min_delta_ns;                              // 最小可程式化 Δ
    u32     mult;                                      // 與 clocksource 類似
    u32     shift;
    enum clock_event_mode    mode;                     // CLOCK_EVT_MODE_PERIODIC / ONESHOT / SHUTDOWN
    unsigned int    features;                          // CLOCK_EVT_FEAT_PERIODIC / ONESHOT / C3STOP / ...
    const struct cpumask    *cpumask;                  // 此裝置服務的 CPU
    unsigned int    irq;                                // 對應的 IRQ 號
    void    *per_cpu_dev;                              // per-cpu 私有資料
    int     rating;
    int     bound_on;                                  // 給 task 的 bound
    const char    *name;
    struct list_head    list;
    /*...*/
};
```

`clockevents_set_mode()`（`kernel/time/clockevents.c`）是切換 `PERIODIC ↔ ONESHOT ↔ SHUTDOWN` 的標準入口。`tick_setup_device()` 會依裝置的 `features` 決定一開始走 PERIODIC 還是直接 `clockevents_set_mode(..., ONESHOT)`。

### 4. `struct tick_device` 與 `struct tick_sched`（`include/linux/tick.h`）

`tick_device` 是 per-CPU 變數 `tick_cpu_device`（`DEFINE_PER_CPU(struct tick_device, tick_cpu_device)`），把 `clock_event_device` 與「**目前哪個 handler**」綁在一起：

```c
// include/linux/tick.h
struct tick_device {
    struct clock_event_device *evtdev;     // 對應的 clock_event_device
    enum tick_device_mode mode;            // TICKDEV_MODE_PERIODIC / ONESHOT / REPLACE
};

enum tick_device_mode {
    TICKDEV_MODE_PERIODIC,
    TICKDEV_MODE_ONESHOT,
    TICKDEV_MODE_REPLACE,                  // 由 tick_check_new_device 內部使用
};
```

`tick_sched` 是 per-CPU 的「**高階 tick 狀態**」，掌管「**下一次真的需要 tick 的時間點**」與「**idle 狀態**」：

```c
// include/linux/tick.h
struct tick_sched {
    struct hrtimer          sched_timer;     // 模擬 PERIODIC 的 hrtimer
    unsigned long           check_clocks;    // 下次檢查 clocksource 的時機
    enum tick_nohz_mode     nohz_mode;       // NOHZ_MODE_INACTIVE / IDLE / FULL
    unsigned int            inidle:1;        // 正在 idle 中
    unsigned int            tick_stopped:1;  // tick 已完全停止
    unsigned int            idle_active:1;
    unsigned int            do_timer_last:1;
    unsigned int            got_idle_tick:1;
    unsigned int            stalled_jiffies:1;
    unsigned int            flags;           // 給 sched 看的 flags
    u64                     last_tick;       // 上次 tick 的時間
    u64                     next_tick;       // 下次 tick 的 deadline
    u64                     idle_jiffies;    // 累計 idle 期間的 jiffies
    u64                     idle_calls;      // idle 進入次數
    u64                     idle_sleeps;     // tick 停止次數
    int                     idle_waketime;   // 給 sched 的 hint
    ktime_t                 idle_entry;      // 進入 idle 的時間
    struct tick_sched       *peer;           // NO_HZ_FULL 的同儕（sibling CPU）
    struct clock_event_device *evtdev;       // 此 sched 用的 clock_event_device
    u64                     last_cpu_mask;   // 給 sched_domain 看的
};
```

`tick_sched_timer()`（`kernel/time/tick-sched.c`）：當 `sched_timer` hrtimer 到期時，**扮演 PERIODIC tick 的角色**，呼叫 `update_process_times(user_mode(get_irq_regs()) ? TIMER_SOFTIRQ : TIMER_SOFTIRQ)` → `tick_sched_do_timer` → `do_timer(1)` + `scheduler_tick()`。

### 5. `struct hrtimer` 與 `struct hrtimer_cpu_base`（`include/linux/hrtimer.h` / `kernel/time/hrtimer.c`）

`hrtimer` 是「**可程式化到期時間**」的 timer 抽象 — 應用程式透過 `timerfd_create(CLOCK_MONOTONIC, ...)` + `timerfd_settime()` 或核心內部（NET/rx 計時、RCU grace period、TCP RTO、鍵盤延遲等）使用：

```c
// include/linux/hrtimer.h
struct hrtimer {
    struct timerqueue_node      node;       // 紅黑樹節點（按 expires 排序）
    ktime_t                     _softexpires; // 軟期限（給 throttling）
    enum hrtimer_restart        (*function)(struct hrtimer *); // callback
    struct hrtimer_clock_base   *base;       // 所在 base
    u8                          state;       // HRTIMER_STATE_*
    s32                          is_rel;     // 是否相對時間
    s32                          is_soft;    // 是否 softirq 執行
    s32                          is_hard;    // hard IRQ 執行
    u8                          clockid;     // CLOCK_MONOTONIC / REALTIME / ...
    /*...*/
};

struct hrtimer_clock_base {
    struct hrtimer_cpu_base    *cpu_base;
    unsigned int                index;       // HRTIMER_BASE_MONOTONIC / REALTIME / BOOTTIME / TAI
    ktime_t                     (*get_time)(void); // 讀時間函式
    struct timerqueue_head      active;      // 紅黑樹根
    ktime_t                     offset;      // 該 base 的 offset
    seqcount_raw_spinlock_t     seq;         // 給 lock-free 讀的順序鎖
};

struct hrtimer_cpu_base {
    raw_spinlock_t              lock;
    unsigned int                cpu;
    unsigned int                active_bases; // bitmask
    unsigned int                clock_was_set_seq; // 給 NOHZ_FULL 看
    ktime_t                     (*get_time)(void);
    struct hrtimer_clock_base   clock_base[HRTIMER_MAX_CLOCK_BASES];
    unsigned int                in_hrtirq:1;
    unsigned int                hres_active:1;
    unsigned int                hang_detected:1;
    unsigned int                softirq_activated:1;
    unsigned int                online:1;
    struct hrtimer              *sched_timer;   // 給 sched 用的 tick
    struct hrtimer              *next_timer;    // cache：即將到期的 timer
    /*...*/
    ktime_t                     expires_next;  // 下一個到期的絕對時間
    /*...*/
};
```

關鍵函式：
- `hrtimer_init()` / `hrtimer_setup()`：初始化一個 `hrtimer`，設定 `function` 與 `clockid`。
- `hrtimer_start_range_ns()` / `hrtimer_start()`：把 hrtimer 掛到對應 base 的紅黑樹，必要時呼叫 `hrtimer_reprogram()` 重新程式化 `clock_event_device`。
- `hrtimer_cancel()` / `hrtimer_try_to_cancel()`：取消已掛上的 hrtimer。
- `hrtimer_run_queues()`：當 `clock_event_device` 中斷觸發時（在 `tick_handle_oneshot_broadcast` 或 local timer 入口），呼叫此函式收單所有到期 hrtimer。
- `hrtimer_interrupt(clock)`（`kernel/time/hrtimer.c`）：**核心入口**，從 local timer ISR 進來，依序跑 base 的 `active` 紅黑樹、執行 callback、必要時重新 reprog 下一個最早到期的 hrtimer。
- `__hrtimer_run_queues(cpu_base, now, flags, active)`：實際跑 callback 的內部函式。
- `hrtimer_reprogram()`：把最早到期的 hrtimer deadline 寫入 `clock_event_device` 的硬體暫存器。
- `hrtimer_switch_to_hres()`：把整個 hrtimer 子系統從 PERIODIC 切到 ONESHOT 模式（`tick_init_highres` → `tick_setup_oneshot` → `hrtimer_switch_to_hres`）。
- `hrtimer_active()` / `hrtimer_callback_running()`：給 RCU grace period 等待用的查詢 API。

### 6. 對外 API 與相關檔案

- `ktime.h`（`include/linux/ktime.h`）：`ktime_t` 為 `s64` 奈秒，型別安全包裝。
- `time.h`（`include/linux/time.h`）：`struct timespec64`、`getnstimeofday64()`、`ktime_get_real_ts64()`、`do_settimeofday64()`。
- `timekeeping.c` 的 `read_persistent_clock64()` / `read_persistent_wall_and_boot_offset()` 給 arch 實作（x86 是 `arch/x86/kernel/rtc.c`）。
- `arch/x86/kernel/tsc.c` 的 `tsc_init()` / `tsc_refine_calibration_work()` / `notifier(tsc_freq_changed)`：Tsc clocksource 的 hot 升級（如 `tsc=stable`）。
- `kernel/vtime.c` 的 `vtime_common_task_switch()` / `account_process_tick()`：vtime（virtual time，給 context switch 與 user/system tick 區分用）。
- `arch/x86/entry/vdso/vclock_gettime.c` 的 `__vdso_clock_gettime()`、`__vdso_time()`：vDSO 入口。
- `arch/vdso/datapage.h` 的 `struct vdso_data`（含 `seq`、`cycle_last`、`mult`、`shift`、`sec`、`nsec` 等）。

## 源碼流程說明

### 1. 開機時 clocksource 註冊與 timekeeper 初始化

`start_kernel()` → `timekeeping_init()`（`kernel/time/timekeeping.c`）建立第一個 `tk_core.timekeeper`，接著：

1. 各 arch 經 `of_clocksource_init()` / `clocksource_of_register()` / 各 driver 的 `clocksource_register_hz()` 把候選 clocksource 註冊到 `clocksource_list`。
2. `clocksource_select()` 跑 `select_highest_rating_and_validated_cs()` 選 rating 最高的有效 source，呼叫 `clocksource_change_notifier` 觸發 `timekeeping_notify` → `tk_unbind_tracing` / `timekeeping_update`。
3. 早期 `timekeeping_init()` 用 `read_persistent_clock64()` 拿到 wall time seed，後期由 `read_persistent_wall_and_boot_offset()` 校正。
4. `tick_setup_device(tick_evtdev)` 把第一個 `clock_event_device` 與 `tick_device` 綁定。

### 2. hrtimer 啟動與 highres 切換

1. `hrtimers_init()`（`kernel/time/hrtimer.c`）註冊 `softirq` `HRTIMER_SOFTIRQ`（由 `run_hrtimer_softirq` 處理 soft-hrtimer）。
2. 早期 `tick_setup_device` 走 PERIODIC，呼叫 `tick_set_periodic_handler` 把 `tick_handle_periodic` 設為 `event_handler`。
3. `tick_init_highres()` 嘗試升級到 ONESHOT：依序呼叫 `tick_check_preferred()` / `tick_setup_oneshot()` / `hrtimer_switch_to_hres()`。
4. 升級成功後 `event_handler` 被換成 `hrtimer_interrupt`（**直接接管 local timer ISR**），PERIODIC 由 `hrtimer` 模擬（透過 `tick_sched.sched_timer` 周期性 `hrtimer_start` 自己）。

### 3. 應用程式讀時間（vDSO fast path）

`clock_gettime(CLOCK_MONOTONIC, &ts)` 在 glibc / musl 是 `__vdso_clock_gettime`：

1. 讀 `struct vdso_data *vd = __arch_get_vdso_data()`（每 CPU 對應到 `vvar` 頁的 vd）。
2. `seq = READ_ONCE(vd->seq)`，**奇數表示 timekeeper 正在寫**，**重試**直到 `seq` 為偶數。
3. `ts = vd->sec + vd->nsec_now + (read_tsc() - vd->cycle_last) * vd->mult >> vd->shift`。
4. 再 `READ_ONCE(vd->seq)`，**確保**第二次讀到的 seq 與第一次相同（`seq` 為偶數且兩次相同 = 沒有 race）。
5. 返回結果，全程**不進 syscall**。

### 4. 應用程式讀時間（slow path — 真實 syscall）

`clock_gettime` 真的走 `sys_clock_gettime()`（`kernel/time/posix-timers.c`）時：

1. `do_clock_gettime(clockid, &ts64)` 依 `clockid` 路由到 `ktime_get_real_ts64` / `ktime_get_mono_ts64` / `ktime_get_boottime_ts64` / `ktime_get_clocktai_ts64`。
2. 內部走 `timekeeper::tk_clock_read` 的 `read_seqcount_begin(&tk->seq)` 順序鎖讀取 `tkr_mono.xtime_nsec` + `tkr_mono.cycle_last`。
3. 加 `clocksource->read()` 算 Δcycle → Δns，組合成 `s64 ns`。
4. 把 `ns` 換算成 `ts64` 並 copy_to_user。

### 5. NO_HZ idle 進入與 tick 抑制

`do_idle()` → `cpu_idle_loop()` 看到 `rcu_dynticks_in_eqs(0)` + sched tick 不需要時：

1. `tick_nohz_idle_enter()`（`kernel/time/tick-sched.c`）把 `ts->inidle = 1`、`ts->idle_entry = ktime_get()`。
2. `tick_nohz_stop_sched_tick(ts, cpu)`：
   - 計算 `next_ts` = `min(hrtimer::expires_next, RCU grace period 截止, jiffies 下一個 tick)`。
   - 呼叫 `clockevents_program_event(dev, next_ts, ktime_get())` 把 local timer 設到 `next_ts`。
   - 設 `ts->tick_stopped = 1`。
3. CPU 真正 idle（`arch_cpu_idle_enter()` / `safe_halt()`）後，硬體在 `next_ts` 觸發 local timer ISR。
4. ISR 進 `hrtimer_interrupt` → 跑 callback → 若 callback 標記 need_resched 或 hrtimer 沒了，呼叫 `tick_nohz_idle_exit()` 恢復 tick。

### 6. hrtimer 到期中斷（`hrtimer_interrupt`）

`hrtimer_interrupt(struct clock_event_device *dev)`（`kernel/time/hrtimer.c`）流程：

1. `base = this_cpu_ptr(&hrtimer_bases)`，`now = ktime_get()`。
2. 對每個 `clock_base`（MONOTONIC / REALTIME / BOOTTIME / TAI）跑 `__hrtimer_run_queues(base, now, ...)`：
   - 把 `active` 紅黑樹中 `expires <= now` 的節點移到 `local list`。
   - 依序執行 `function(timer)`；回傳 `HRTIMER_RESTART` 的 timer 重新算 `expires` 並 re-enqueue。
3. 若有 `softirq` 性質的 timer 過期，raise `HRTIMER_SOFTIRQ` 在 softirq 上下文跑。
4. 跑完後 `hrtimer_reprogram(cpu_base, dev)` 從紅黑樹最早節點讀出 `expires_next`，呼叫 `clockevents_program_event` 設下次中斷。
5. 若這次跑完有 `do_timer_last` 標記（`tick_sched_timer` 跑了 `update_process_times`），呼叫 `scheduler_tick()` 重排程。

### 7. NTP / CLOCK_REALTIME 校正

每個 tick 跑 `do_timer(1)` 時 `update_wall_time()`：

1. 讀 `clocksource->read()` 算 `Δcycle`、`Δns`。
2. `ntp_tick()` 計算 NTP 頻率 / 相位誤差，回寫到 `timekeeper::ntp_error`、`tkr_mono.mult`（受限 `maxadj`）。
3. 累加到 `tkr_mono.xtime_nsec`、`tkr_raw.xtime_nsec` 等多個 base。
4. `tk_update_ktime_data()` 把多 base 的 cycle_last / mult / shift / xtime_nsec 同步好。
5. 每 `tick_do_update_jiffies64 == 1` 個 tick `update_wall_time` 才跑一次（避免 `do_timer` 每次都跑太頻繁）。

## 設計原理與權衡

### 1. 為什麼需要「順序鎖」（`seqcount_raw_spinlock_t`）？

`timekeeper` 與 `vdso_data` 都要在「讀者很多（每個 syscall 與每個 vDSO 呼叫都是）」與「寫者極少（每 tick 一次）」的情境下保持 lock-free。**純 RCU** 適合讀多寫少但要保證「舊值讀到頭」的語意；**純 spinlock** 又太重。`seqcount_raw_spinlock_t` 是妥協：
- 寫者：`write_seqcount_begin(&tk->seq)` → 修改 → `write_seqcount_end(&tk->seq)`，**end 時把 seq 遞增到奇數再回到偶數**（確保中間讀者必能觀察到寫動作）。
- 讀者：`read_seqcount_begin(&tk->seq)` 拿到起始 seq，跑迴圈檢查「是否有並發寫」（seq 變了）並 retry；**這只保證單讀者讀到一致 snapshot，不保證 lock-free wait-free**（讀者發現衝突時要重做），但避開了 spinlock 的臨界區開銷。

### 2. 為什麼 `vDSO` 能在 ring-3 直接讀時間？

`vvar` 頁（虛擬變數頁，vDSO 的伴生映射）由核心在 `vdso_install_special_mapping` 時設為 `VM_READONLY | VM_MAYREAD | VM_USERLAND` 並透過 `VM_DONTCOPY` 標記，每 CPU 一份 `struct vdso_data`，但**所有 user task 共用同一頁**（架構上把 `vvar` 映射成 all-tasks shared）。
- **缺點**：不同 CPU 對應的 vdso_data 不同 — 這也是 vDSO 內部要呼叫 `__arch_get_vdso_data()` 取得「目前 CPU」對應的那份。
- **優點**：**完全繞過 syscall**（無模式切換、無鎖、無 cache miss on kernel text），純粹的 `mov` 與 `mul` 即可。

### 3. 為什麼 NO_HZ 是「per-CPU 動態 tick 抑制」而非「全域停掉 tick」？

- **節能**：idle CPU 不需要 scheduler tick，也不需要 hrtimer 沒排到事件時的 tick。
- **單瓶頸可達性**：用 `tick_sched` 與 `tick_sched_timer` 配合的 hrtimer，保證「最早到期的 timer 一定準時被跑」 — 不是「全域停掉 tick」那樣粗。
- **代價**：smp_mb / smp_wmb 的代價、context switch 時要把 tick_sched 狀態轉移（`__tick_nohz_task_switch`）。
- **NO_HZ_FULL**（`nohz_full=` 核心列表）：連 user 模式時也禁用 tick（除被 CPU 親和性綁定的 task）— 適合 HPC 與即時應用，代價是某些 scheduler 統計要靠別的機制（`vtime` 算 user/system/irq 時間）。

### 4. 為什麼 `hrtimer` 的 callback 必須在 hardirq / softirq 上下文跑？

- 允許 `function(struct hrtimer *)` 在中斷上下文呼叫 → 喚醒 task / 排程 work 必須用 `tasklet_hi_schedule` / `workqueue` / `wake_up_interruptible` 等 async-safe API。
- 不允許 sleep（mutex、schedule()）。
- `hrtimer_active()` 在 `function` 內**已自動 false**（內部把 `state = HRTIMER_STATE_INACTIVE` 暫時設好）以避免 `hrtimer_cancel` 與 `function` 競爭時的 deadlock。

### 5. 為什麼 `mult/shift` 是 `clocksource` 必須的？

把硬體 cycle（TSC、HPET counter）轉成奈秒需要「**整數乘法 + 右移**」的固定點運算，原始公式：
`ns = cycle * NSEC_PER_SEC / freq`
為了避免 64-bit 溢位，clocksource 註冊時用 `clocksource_hz2mult(NSEC_PER_SEC, freq, shift)` 算 mult（`mult = (NSEC_PER_SEC << shift) / freq`），後續：
`ns = (cycle * mult) >> shift`
這也是為什麼 TSC `shift=22`、HPET `shift=10` — 64-bit 乘法時 mult 越大 precision 越好，但溢位風險高，需要 shift 平衡。

### 6. TSC 熱替換：`clocksource_change_notifier` 鏈

`tsc_init()`（`arch/x86/kernel/tsc.c`）在 TSC 校驗 / 升級時，呼叫 `clocksource_change_rating(cs, ...)` → `clocksource_select()` → 觸發 `blocking_notifier_call_chain(&clocksource_chain, CLOCKSOURCE_RESELECT, NULL)`。訂閱者包含 `timekeeping_notify`（重算 `timekeeper` 對齊新 source）、`tick_notify`（重排 tick）、`cpufreq` 等。**這是 hot-swap 的核心協議**。

### 7. 權衡：精度 vs 開銷

- **精度**：TSC 提供 ns 等級精度（cycle 級），但 TSC 在 deep C-state 時可能不準 → `tsc=reliable` / `tsc=nowatchdog` / 經 `notsc` 黑名單。
- **開銷**：每個 hrtimer 維護一棵紅黑樹（4 個 clock base × 4 種 state），每個 timer `hrtimer_start` 都要 O(log n) 插入；當 timer 數量破萬時要改用 `timerfd` + `epoll` 聚合。

## 實際應用推薦

### 1. 應用程式端 — 何時用 vDSO、何時用 syscall

- **CLOCK_MONOTONIC / CLOCK_REALTIME** 90% 場景走 vDSO 即可，**不要用 `time(NULL)` / `gettimeofday` 直接呼叫**（glibc 會自動跳 vDSO）— 確認方法是 `ldd` 看 vDSO 是否有帶 `LINUX_2.6` 符號、`getauxval(AT_SYSINFO_EHDR)` 確認 vDSO 映射。
- **CLOCK_BOOTTIME / CLOCK_MONOTONIC_RAW** 在某些 glibc 版本**不支援 vDSO**（要走 syscall），需注意 syscall 開銷。
- **CLOCK_TAI**（原子鐘）需 v6.0+ 才有完整支援，TAI offset 由 NTP / `adjtimex` 設定。

### 2. 系統管理員端 — `clocksource` 與 `NO_HZ` 調優

- `cat /sys/devices/system/clocksource/clocksource0/current_clocksource` 看當前 source。
- `tsc=stable clocksource=tsc`（`/proc/cmdline`）：TSC 同步且穩定時直接用 TSC（rating 300 > HPET 250）。
- `tsc=reliable` / `tsc=nowatchdog`：繞過 TSC watchdog 檢查。
- `nohz=on` / `nohz=off`（核心組態）：動態 tick 開關；`nohz_full=0-3` 標記 full-no-hz 核心。
- `isolcpus=` + `nohz_full=` 配合可打造「**專屬 CPU + 零打擾**」的延遲敏感型應用環境（HFT、tail latency critical）。

### 3. Kernel / Driver 開發者端 — 寫新的 `clocksource` 與 `clock_event_device`

- **新增 clocksource**：建立 `struct clocksource`、實作 `read()`、呼叫 `clocksource_register_hz()`。
- **新增 clock_event_device**：建立 `struct clock_event_device`、實作 `set_next_event()`、呼叫 `clockevents_config_and_register(dev, freq, min_delta, max_delta)`。
- **善用 `clocksource_change_notifier`**：在 TSC `unstable → stable`、HPET 從 `enable → disable` 觸發時收到 `notifier_call` → 重算 timekeeper。

### 4. 高精度 timer 場景

- **核心內部**：優先用 `hrtimer` 而非 `timer_list`（舊版），`timer_setup` + `add_timer` 在新核心仍可運作但精度只到 jiffy 級。
- **NET 子系統**：`tcp_send_mss()` / `tcp_rto_min` 與 `tcp_retransmit_timer` 走 hrtimer；`tcp_pacing_delay` 由 `sch_fq` 用 hrtimer 控制發送節奏。
- **USB / 音訊**：`snd_timer` 內部用 hrtimer 模擬 ALSA timer，精度可達 1 µs。

### 5. 觀察 / 監控

- `cat /proc/timer_list`：所有 hrtimer 與 clock_event_device 列表、目前 `expires_next`、每個 `function` 的呼叫次數統計。
- `bpftrace -e 'kprobe:hrtimer_interrupt { @start[tid] = nsecs; } kretprobe:hrtimer_interrupt /@start[tid]/ { @lat = hist(nsecs - @start[tid]); delete(@start[tid]); }'`：量測 `hrtimer_interrupt` 處理時間。
- `perf stat -e cs/migrations`：追蹤 `clocksource_change` 事件。
- `bpftool map dump` 看 `tproxy_socket` / `flow_dissector` 等 BPF prog 是否用到 `bpf_ktime_get_*_ns` helper。

### 6. 為何 `tsc` 在虛擬化環境要小心

- **VMX**：客戶機看見的 TSC 是 hypervisor 模擬的「**invtsc**」（invariant TSC），但虛擬化遷移時 TSC 會跳。
- **KVM**：用 `kvmclock` 作為 guest clocksource，host-side `kvmclock_init` 把 `kvm_clock` 註冊成 clocksource；客戶機還有 `kvmclock_vcpu` 在 vDSO 內提供。
- 容器內（Docker）：**容器共享 host kernel** — 不會有獨立的 clocksource 註冊，所有時間行為與 host 一致。

### 7. 對「時間漂移」（clock drift）的處理

- **NTP / chrony**：透過 `adjtimex` syscall 調整 `timekeeper::mult` 與 `xtime_nsec`，讓 kernel 時間跟上真實時間。
- **PTP / phc2sys**：在資料中心用 PTP 硬體時鐘做納秒級同步，phc2sys 透過 `clock_adjtime(CLOCK_PTP_*)` 對 PHC 設備做 freq 調整，再把結果反映到 CLOCK_REALTIME。
- **PPS（Pulse Per Second）**：GPS / 原子鐘的 PPS 信號透過 `pps_core` 驅動 `pps_kc_bind` 把 PPS 事件餵給 `ntp` 對 `ntp_khard` 做精準校正。
- **LinuxPTP**：使用者空間工具鏈 `ptp4l + phc2sys` 與核心 `ptp_clock` 子系統互動。

### 8. 容器與 namespace

- **`time namespace`**（`CONFIG_TIME_NS`，v5.6+）讓容器內可看見「**偏移後的 CLOCK_MONOTONIC / CLOCK_REALTIME**」 — `timens_on_fork` 在 `copy_process` 把 `ns->time_offsets` 加到 per-task 的 `timens_offset` 變數上，由 `timekeeping_apply_time_offsets` 套用到讀取路徑。
- **vDSO**：在 time namespace 切換時，核心會把 vDSO datapage 的 `seq` + `cycle_last` 重新校準到新偏移，user space 仍可走 vDSO（這也是 `__vdso_clock_gettime` 不需要 re-exec 的原因）。

### 9. 對 watchdog 的影響

- **NMI watchdog**（`CONFIG_HARDLOCKUP_DETECTOR`）：用 TSC 與 hrtimer 對照偵測 hardlockup — 當核心被關中斷卡住超過 10 秒，會發 NMI。
- **softlockup watchdog**（`CONFIG_SOFTLOCKUP_DETECTOR`）：用 per-CPU hrtimer (`watchdog_timer_fn`) 偵測 soft lockup。
- 兩者都用 `hrtimer`，依賴 highres 模式的 `hrtimer_interrupt` 路徑。

### 10. vDSO 程式設計的細節

- **同 CPU 的 vDSO datapage**：`__arch_get_vdso_data()` 用 `arch_vdso_data_size`、`cpu` 偏移量，**不是 `current_cpu` 直接做 base**，而是 per-cpu 的 page（NR_CPUS × sizeof(vdso_data)）。
- **跨 CPU 上下文**：當 thread 從 CPU A 遷移到 CPU B 時，vDSO 內**仍會以 user space 為先的 read 邏輯**抓 `B` 的 vdso_data — 這是 `do_task_dead` / `context_switch` 時的 `update_vdso_data` 觸發的。
- **`vdso_data::cycle_last` + `mult/shift` 的 cycle → ns 換算**：是 `vDSO 內的 inline 函式`（arch-specific：`__arch_vdso_cycles_to_ns`）。
- **故障模式**：當 `vvar` page 因為某種原因對 user space 不可讀（kernel config、selinux 限制、page fault）時，vDSO 會 fallback 到 syscall；`/proc/self/maps` 看 `vvar` 行確認 vDSO 是否真的載入。

## 結語

Linux 的時間子系統是「**硬體抽象 + 鎖設計 + vDSO 優化 + 動態 tick 抑制**」四個層面的協作結果：硬體層由 `clocksource` 與 `clock_event_device` 解耦，使 TSC/HPET/ACPI PM timer/arch timer 之間可以熱替換（`clocksource_change_notifier`）；鎖設計上用 `seqcount_raw_spinlock_t` 把高頻讀取（每個 syscall 與 vDSO 呼叫）與低頻寫入（每個 tick）解耦；vDSO 把 `clock_gettime` 從「**每次都進 syscall**」降到「**純使用者態運算**」；`tick_sched` 與 `hrtimer` 則把「**idle CPU 不打擾**」與「**事件精準觸發**」兩個看似矛盾的需求同時滿足。理解這四個抽象層的互動（`timekeeper` 提供「現在是幾 ns」、`tick_sched` 提供「下次需要 tick 的時間」、`hrtimer` 提供「執行 callback」、`vDSO` 提供「使用者態快路徑」），就能掌握 Linux 整個時間模型的核心脈絡，也能在 debug timer storm、TSC 不準、container time namespace 行為、PTP 同步等場景下快速定位。
