## 一、頭條（過去 7 天重點）

### 1. UCX v1.22.0-rc1 釋出：fault-tolerance recovery foundation + Vera CPU 支援 + GDRCopy BAR1 export + IB/MLX5 ECE query——HPC middleware stack 的 6 月底實質升級

[UCX v1.22.0-rc1 release notes](https://github.com/openucx/ucx/releases/tag/v1.22.0-rc1)（[openucx/ucx](https://github.com/openucx/ucx)，7/1）釋出 **UCX 1.22 release candidate**，這是 HPC middleware stack 在 ISC 2026（6/22-6/26 Hamburg）結束後第一個重要的 release-grade upgrade，**新增 6 個維度的 fabric-related 改進**：

- **Fault-tolerance recovery foundation + failover support**：(a) **UCP** 新增「fault-tolerance recovery foundation」、「AM/zcopy/multi/PSN protocol failover support」、「endpoint flush failover + first-fragment retransmission support」——**這是 UCX 為「multi-rail + adaptive routing + failover」做的核心基礎**，**對 hyperscaler 100K+ GPU cluster 的「link failure → 5-second recovery」目標有關鍵意義**；(b) **GET + PUT rendezvous protocols for RMA operations**——**讓 UCX 在 RDMA RMA 路徑上可以跑 rendezvous（先 control message 協商再 data transfer）**，**降低 small-message RMA 的 overhead**；(c) **multi-lane support for device operations**——**單一 UCX endpoint 可以同時使用多條 RDMA lane**（例如 RoCE v2 + IB 雙 rail），**這是 hyperscaler 採購的關鍵 enable 技術**。
- **RDMA CORE (IB, ROCE, etc.) 新增 plugin infrastructure**：(a) **「Added plugin infrastructure for IB token query + plugin-provided RC extended operations」**——**讓 IB 設備可以透過 plugin 機制加入 vendor-specific extended operations**（例如 Mellanox/NVIDIA ConnectX-7/8 的特定 ECE / WQE 控制）；(b) **「Added per-endpoint RC transmit queue reservation for resource checks」**——**避免 RC QP 資源耗盡導致 connection failure**；(c) **「Added IB/MLX5 initiator small-fence WQE control flag」+ 「Applied ECE returned by ibv_query_ece by default」**——**讓 UCX 自動採用 MLX5 NIC 報告的 ECE（Enhanced Connection Establishment）值**，**這是 RoCE v2 + IB 在 hyperscaler 採購的關鍵 interoperability 功能**。
- **GPU-direct + CUDA 整合**：(a) **「Added GDRCopy PCIe BAR1 export option」**——**讓 GDRCopy 可以 export GPU 的 PCIe BAR1 address space**，**讓 RDMA NIC 可以直接寫入 GPU memory**，**這是 NVIDIA GPUDirect RDMA 的關鍵底層技術**；(b) **「Added v2 operations on proxy and wireup endpoints」**——**讓 UCX 在 proxy/wireup 階段可以走 v2 API**，**降低 endpoint establishment 的 latency**。
- **Vera CPU 支援 + 新平台 build coverage**：(a) **「Added Vera CPU support」**——**UCX 已準備好支援 NVIDIA 的 Vera CPU**（預期 2026 H2-2027 H1 開始 sampling 給 hyperscaler 客戶）；(b) **「Added Ubuntu 26.04, TencentOS 4.4, and GCC 15.2 build coverage」+ 「Added GB300/aarch64 DL cluster test pipeline coverage」**——**UCX 已開始在 NVIDIA GB300 + aarch64 DL cluster 上做 nightly test**，**這是 NVIDIA GB300 NVL72 rack-scale 整合的關鍵信號**。
- **Software GET responder + perftest 改進**：(a) **「Added software GET responder progress support in perftest」**——**讓 perftest 可以測量 software GET（不靠 hardware RMA）的 throughput**，**這是評估 UCX 在 no-RDMA-hardwar 環境（如 DPU emulation）的關鍵**；(b) **「Enabled on-demand DRP testing for release pipelines」**——**讓 release pipeline 可以做 dynamic resource provisioning test**。
- **對 2026 H2 AI fabric 採購者的 practical 含義**：(i) **UCX 1.22 預計 8 月中旬 GA**——**新購 hyperscaler HPC cluster 應以 UCX ≥ 1.22 為 baseline**，**確保 fault-tolerance + multi-lane + IB/MLX5 ECE + GDRCopy BAR1 等 fabric 改良可用**；(ii) **UCX + rdma-core + MLNX_OFED + UEC 1.0.2 的 interoperability 會在 8 月 UCX 1.22 GA + 9 月 GTC 2026 + 11 月 SC 2026 的 cycle 中達到「production-ready」的水準**；(iii) **Vera CPU 支援 + GB300 aarch64 DL cluster 整合** 顯示 **UCX 已在為 NVIDIA 2026 H2-2027 H1 的 GB300 + Vera CPU + NVLink 6 平台做底層準備**。

- **對 2026 H2 AI fabric 採購者的 practical 含義**：(i) **bcc v0.37.0 + p4c v1.2.5.15 + rdmatop v0.1.19 構成「P4 programmable data plane + eBPF kernel tracing + RDMA cross-provider observability」 的「fabric observability stack」**——**新購 hyperscaler / 主權 AI 基建 cluster 應把這個 stack 視為「fabric observability baseline」**；(ii) **rdmatop 的 traffic recording 對 RoCE v2 / IB 跨 provider interoperability testing 與 DC fabric incident response 是 critical feature**——**這讓 hyperscaler 可以 record + replay RoCE v2 / IB 封包做 offline analysis**；(iii) **bcc v0.37.0 + kernel 7.1 支援 對 Linux kernel 7.1 LTS 採用時間表（預期 2026 H2-2027 H1 進入 stable）有關鍵意義**。

## 二、Research Spotlight（已整理內容的延伸觀察）

### Spotlight 1. The Next Platform 6/30〈Optical Scale-Up Fabrics Are Limited By Manufacturing, Not Architecture〉（已在 07-05/07-06 整理）——本週 actionable 結論：**rack-scale co-packaged optics + silicon photonics 在 2027 H1 量產前，hyperscaler 不應採購 100K+ GPU scale-up cluster**

[The Next Platform〈Optical Scale Up Fabrics Are Limited By Manufacturing, Not Architecture〉](https://www.nextplatform.com/connect/2026/06/30/optical-scale-up-fabrics-are-limited-by-manufacturing-not-architecture/5264399)（[The Next Platform](https://www.nextplatform.com)，6/30，**已在 07-05/07-06 digest 整理**）指出 **AI 資料中心 scale-up fabric 的 constraint 已從「architecture」轉移到「manufacturing」**。**本週的延伸 actionable 結論**：

- **「2026 H2 不應採購 100K+ GPU scale-up cluster」 的工程理由**：(a) **rack-scale co-packaged optics（CPO）+ silicon photonics 在 2026 H2 仍處於 early deployment 階段**——**NVIDIA Spectrum-X 1600G + Tomahawk 6 + CPO 的「2027 H1 量產」 計劃可能 delay**（silicon photonics 雷射陣列的量產工藝瓶頸是 6/30 文章的核心訊息）；(b) **hyperscaler 採購 100K+ GPU scale-up cluster 的 TCO 上限 由 co-packaged optics + silicon photonics 的量產 yield 決定**——**量產 yield 不達標 → 採購單價超支 20-40%**；(c) **2026 H2 採購 100K+ GPU scale-up cluster 等於「押注 2027 H1 量產準時 + 採購單價在預算內」 兩個 high-risk assumption**——**對 hyperscaler 而言，這是 high-risk 押注**。
- **「2026 H2 應該採購什麼」 的 actionable framework**：(i) **新購 100K+ GPU hyperscaler cluster**——**Spectrum-X 1600G + Tomahawk 6 + Co-packaged Optics 應在 2027 H1 量產前不採購**（等 photonic 量產 ready）；(ii) **新購 1K-10K GPU scale-up cluster**（NVL36 / NVL72 / UALink）——**「rack-scale co-packaged optics」 是 2026 H2 採購的 reference design**（已 ready）；(iii) **新購 prosumer multi-box cluster**——**Strix Halo + USB4 thunderbolt-ibverbs**（已在 07-03/07-05 整理）**仍是 entry-level reference**；(iv) **新購主權 AI 基建 cluster**（1-3 GW initial deployment）——**Spectrum-X 800G/1600G + Tomahawk 5 + 自有 Photonic Interconnect 是 2026 H2 採購的 reference design**（已 ready，量產 risk 低）。

### Spotlight 2. The Next Platform 6/23〈AMD And Nvidia Are Neck And Neck In HPC Supercomputing〉（已在 06-24 整理）——本週延伸觀察：**AMD ROCm + UALink + MI400 + Pensando DPU 對 NVIDIA NVLink + Spectrum-X + Quantum-X 的競爭軸線**

[The Next Platform 6/23〈AMD And Nvidia Are Neck And Neck In HPC Supercomputing〉](https://www.nextplatform.com/hpc/2026/06/23/amd-and-nvidia-are-neck-and-neck-in-hpc-supercomputing/5260202)（[The Next Platform](https://www.nextplatform.com)，6/23，**已在 06-24 digest 整理**）指出 **AMD + NVIDIA 在 HPC 超級計算領域進入「neck and neck」 的競爭階段**。**本週的延伸觀察**：

- **AMD 2026 H2 fabric 採購 ecosystem**：(a) **AMD MI400 + Pensando DSC-200/Pensando Pollara 400 DPU**——**預期 2026 H2-2027 H1 進入 hyperscaler 量產**，**與 NVIDIA B200/GB300 + ConnectX-8/BlueField-3 競爭**；(b) **UALink v1.0**——**UALink Consortium 2025 年發布 1.0 spec**，**2026 H2 進入 product 階段**，**對 NVIDIA NVLink 6 是 5%-10% bandwidth 級的競爭**；(c) **AMD ROCm 7.x**——**ROCm 7.0 已開始整合 UALink + MI400**，**2026 H2 進入「ROCm + UALink + MI400 + Pensando」 完整 stack 採購週期**。
- **NVIDIA 2026 H2 fabric 採購 ecosystem**：(a) **NVIDIA Spectrum-X 1600G + Quantum-X800**——**2026 H2 量產**，**hyperscaler 採購 reference**；(b) **NVIDIA NVLink 6 + NVSwitch 6**——**GB300 rack-scale 整合**；(c) **NVIDIA BlueField-3 DPU + ConnectX-8 NIC**——**hyperscaler 採購 reference**。
- **對 2026 H2 AI fabric 採購的 practical 含義**：(i) **hyperscaler 應採購「dual-vendor」 strategy**——**主 fabric 為 NVIDIA Spectrum-X + Quantum-X + NVLink，**副 fabric 為 Broadcom Tomahawk 5/6 + Marvell OCTEON 10 + AMD Pensando**——**避免單一 vendor lock-in**；(ii) **「主權 AI 基建」 採購應考慮 AMD + UALink + ROCm 7.x 的 alternative stack**——**避免被 NVIDIA 單一 vendor lock-in**；(iii) **2026 H2 預期 NVIDIA + AMD 在 HPC fabric 採購的競爭會更激烈**——**對 hyperscaler 採購 frame price negotiation 利好**。
