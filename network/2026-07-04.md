## 一、頭條（過去 7 天重點）

### 1. Cisco Nexus One 正式 architecture 化（2026-07-02）：多晶片、多 OS、多 control 平面 + IETF GPO 標準 + Spectrum-X 認證

[Cisco Nexus One, next-generation data center networking architecture](https://blogs.cisco.com/datacenter/cisco-nexus-one-next-generation-data-center-networking-architecture)（7/2，10 min read，Will Eatherton）是 Cisco 在 Cisco Live 2026 Las Vegas 之後的第一份 **architecture-level blog**，把原本散落在 6/4 [job-aware scaling](https://blogs.cisco.com/datacenter/from-tenant-aware-to-job-aware-scaling-shared-ai-clusters-with-cisco-nexus-one) 與 6/18 [secure AI networking with NVIDIA](https://blogs.cisco.com/datacenter/powering-the-future-of-ai-ciscos-breakthroughs-in-secure-ai-networking-with-nvidia) 的功能集收斂成 **「**四層開放、跨廠商、IETF 標準化**」** 的資料中心 fabric reference architecture。**為何重要**：

- **Silicon 層首次納入 NVIDIA Spectrum-X**：從「**Cisco Cloud Scale + Cisco Silicon One 二選一**」 變成「**Cisco Cloud Scale + Cisco Silicon One + NVIDIA Spectrum-X Ethernet switch silicon 三選一**」。Spectrum-X 是 NVIDIA 專為 AI 訓練設計的 Ethernet platform（含 Spectrum-4 / Spectrum-6 系列 + Spectrum-X 銀級/金級/鉑金級 QoS），Cisco **直接 sell 進 reference architecture** 意味著 AI 客戶可以**用 Spectrum-X 為底、但由 Cisco 提供 L2-L7 policy + control + observability**。這對 NVIDIA 與 Cisco 從 NVIDIA 收購 Mellanox 後的「**Silicon + Control 上 Cisco 是配角**」 走向「**Silicon 是 Cisco 架構內第一級選項**」 是結構性翻轉。
- **軟體層新增 SONiC**：Nexus One 在原本的 **ACI + NX-OS** 之外，正式把 **SONiC** 拉成 third OS option。Cisco 6 月初已公告 [Cisco 將在 N9000 series 支援 SONiC](https://blogs.cisco.com/datacenter/cisco-nexus-one-next-generation-data-center-networking-architecture)，這次 architecture blog 把 SONiC 收進 reference list，意味 SONiC 在 enterprise data center 不再只是 hyperscaler/SONiC-ready 廠商（如 Edgecore、Celestica、Arista 7800R3）的選項，而是 **「**SONiC 可以跟 ACI 共存於同一 fabric 透過 BGW 互通**」**。
- **Control 層：Nexus Dashboard（on-premises）+ Nexus Hyperfabric（cloud-native SaaS）雙管齊下**，並透過 **MCP server API** 串接 **Cisco Cloud Control** 的 **AI Canvas**（AgenticOps）。AI agents 可以在 Cloud Control 內直接操作 Nexus One controllers 進行 diagnostic / triage / issue resolution，這是「**AI-driven network operations**」 從 marketing 走向 **「**AI agent 真的可以透過 MCP 改 fabric state**」** 的第一步。
- **IETF Group Policy Object（GPO）標準**：Cisco 把 ACI 2014 推出的 ESG（Endpoint Security Group）policy model 透過三個 IETF drafts 開放化 — `draft-smith-vxlan-group-policy`（VXLAN header 內 encode Group Policy ID）、`draft-wlin-bess-group-policy-id-extended-community`（BGP extended community 傳遞 GPO）、`draft-lrss-bess-evpn-group-policy`（綁定 data plane + control plane）。**這是 06-23 整理過的 realcoder-panel fact-check 重點（"Cisco Group-Based Policy (GBP)" 不是 RFC，是 IETF draft）— 今日 Cisco 正式把這 3 個 draft 推上 IETF 工作組層級**。**多 fabric 互通**：NX-OS、ACI、SONiC、Nexus Hyperfabric 透過 **enhanced EVPN Border Gateways**（基於 RFC 9014 + draft-sharma-bess-multi-site-evpn）可無縫互通且保留 GPO-based segmentation，跨 fabric migrate workload 不需要 IP/ARP/TCP 重連線。
- **Cisco N9300 Smart Switch + DPU 整合**：Nexus One + N9300 透過 DPU built-in 執行 stateful microsegmentation；Cisco Live Protect 提供 CVE shields（policy enforcement 在硬體層而非軟體層）。

**對 2026 H2 採購者的 practical takeaway**：(i) 計畫**新購 AI fabric** 的 enterprise customer 不再需要 lock-in 單一 silicon/OS — 可以在 **Spectrum-X + SONiC** 與 **Silicon One + NX-OS** 兩個 stack 間選擇，且透過 BGW + GPO 互通；(ii) **AI agent + MCP** 進入 fabric operations 意味 NetOps 團隊必須開始學 MCP client 配置，否則會被「**AI agent 自己改 fabric**」 的運維模式淘汰；(iii) **Spectrum-X 進入 Cisco reference architecture** 對 NVIDIA 是 **「**Spectrum-X 從 hyperscaler 走向 enterprise AI fabric 主流**」** 的通路勝利。

### 2. Three HPC Gurus（Jack Dongarra + Torsten Hoefler + Satoshi Matsuoka）預告 arXiv 論文《Do We Still Need GPUs?》— LineShine LX2 vs A64FX Fugaku all-CPU 路線

[The Next Platform: Three HPC Gurus Ask: Do We Still Need GPUs?](https://www.nextplatform.com/compute/2026/06/30/three-hpc-gurus-ask-do-we-still-need-gpus/5264552)（6/30，Timothy Prickett Morgan）報導 **Jack Dongarra**（UT/ORNL）、**Torsten Hoefler**（ETH Zurich + CSCS chief architect for AI/ML）、**Satoshi Matsuoka**（RIKEN + Tokyo Institute of Technology）三位 HPC 教父即將聯手發表 arXiv + ACM 旗艦期刊論文《**Do We Still Need GPUs? Rethinking AI and Scientific Computing on Matrix-Enhanced CPUs**》，論文核心論點是 **「**all-CPU HPC supercomputer 已經在 AI 與 scientific computing 兩個 workload 同時達到 GPU cluster 的可競爭水準**」**。**為何重要**：

- **觸發事件**：6 月份 [Top500 排名](https://www.top500.org/) 顯示中國自研的 **LineShine** all-CPU 系統（含華為自研 [LX2 Arm server CPU + LingQi 自研光互連](https://www.nextplatform.com/2026/06/25/lineshine-lx2-interconnect-deep-dive/)）衝上 Top500 #1，且 ISC 2026 上 RIKEN 的 Fugaku 仍是 all-CPU design。論文把 A64FX/Fugaku（2021）vs LineShine/LX2（2025）並列比較，論點是 **「**矩陣增強 CPU（matrix-enhanced CPU，含 SVE/SME、HBM、integrated interconnect）的 AI/HPC 性能已經達到 GPU cluster 的可競爭 threshold**」**。
- **對 NVIDIA 的策略壓力**：過去 10 年 NVIDIA 的 AI fabric 論述是「**GPU > CPU 5-10x for AI training**」，但 LineShine 在 Top500 HPL + HPCG + HPL-MxP 三項 mixed-precision benchmark 都達到 NVIDIA H200 cluster 規模的 70-80%，且 **all-CPU 系統的 power efficiency（每瓦 FLOPS）是 GPU cluster 的 2-3 倍**。**三位 HPC 教父的論文代表學術 consensus 開始正視「**matrix-enhanced CPU 是 GPU 的 credible alternative**」**，對 NVIDIA 2026 H2 的 GB300 / Vera Rubin 銷售論述是明顯壓力。
- **對中國 self-built HPC 路線的驗證**：06-26 digest 已整理 LineShine 細節（LX2 chiplet、384 cores、1.55 GHz/690W、HBM + LingQi 4-layer fat-tree、22,680 nodes、80.35% computational efficiency、42.2 MW）。今日 Dongarra/Hoefler/Matsuoka 的論文是 **「**西方 HPC 學術界正式認真看待中國 all-CPU 路線**」** 的 signpost — 過去此類論文多半聚焦 NVIDIA/Cray/HPE 路線，LineShine 進入 arXiv 等級的學術論文是 2025-2026 中國半導體自主可控在 HPC 領域最具象徵意義的時刻。
- **對 AI fabric 採購的 practical 含義**：(i) **「**GPU only**」** 的 AI infrastructure 規劃開始需要 **「**matrix-enhanced CPU**」** 的 second-source 評估；(ii) 計畫 2026 H2 - 2027 H1 採購 **Grace Hopper (GH200) 或 GB300 NVL72 rack** 的 hyperscaler 必須正面回應 **「**若 LineShine 模式擴展到西方供應鏈，是否 GPU 的 TCO 仍然最佳**」** 的問題；(iii) **CXL / UALink / Samsung Memory Module 等 memory-centric interconnect 標準** 在 all-CPU 架構下反而比 GPU cluster 更易整合，2026 H2 - 2027 H1 是 CXL 2.0 在 all-CPU HPC 落地的重要觀察窗口。

### 3. arXiv 過去 7 天：SIGCOMM/OSDI 雙 deadline cooldown 持續，149 篇篩出 0 篇核心 DC fabric 論文

- **2606.29986 HMA-Serve**（[arXiv](https://arxiv.org/abs/2606.29986)，v1 06-29，in window）— Memory-Heterogeneous Accelerator 跨廠商 LLM serving，把 GDDR-based accelerator 配 HBM-based GPU 做 prefill/decode disaggregation。**3.2× goodput 提升 + 4.8× goodput-per-dollar**。**對 DC fabric 的意義**：這是 **「**disaggregated LLM serving 走向 cross-vendor memory hierarchy**」** 的新基準 — 過去 12 個月 disaggregation 主軸是 **「**同廠商 GPU pool**」**（例如 NVIDIA H100 pool + decode prefill split），今日 HMA-Serve 走 **「**GDDR (低成本 prefill) + HBM (高效能 decode)**」** 的 **cross-memory-tier** 路線。**對 RDMA / fabric 的 practical 含義**：HMA-Serve 在 KV cache transfer 必須透過 **GPUDirect RDMA + NVLink + RoCEv2** 跨節點傳輸，paper 報導 **「**deferred dequantization shipping raw quantized bytes**」** 是 **「**用降低 network bandwidth 換降低 HBM usage**」** 的 design choice，但需要 **high-bandwidth low-latency fabric**（≥400 GbE per node）。對 **「**AI cluster 升級 400G → 800G/1.6T**」** 是 **「**不只是 throughput 升級，是 LLM serving 演算法的 network-bandwidth-sensitive design**」** 的新維度。
- **2606.29611 V2I AoI**（[arXiv](https://arxiv.org/abs/2606.29611)，v1 06-28，in window）— V2X/vehicular，不是 DC fabric，列為 reference 而非 headline。
- **2606.26138 AROM**（[arXiv](https://arxiv.org/abs/2606.26138)，v1 06-18，**STALE**，已過 7-day window，drop）。

**今日 arXiv 主軸結論**：「**SIGCOMM/OSDI post-deadline cooldown 持續 2 週**」，符合 06-26 整理的學術發表 cycle 觀察。**預期**：2026-07-08 ~ 07-12 隨 SIGCOMM 2027 rebuttal 結束 + OSDI 2026 final notification，cs.NI 將恢復產出。

## 三、SmartNIC 與 DPU 焦點

### Cisco N9300 Smart Switch + DPU 整合進入 reference architecture

Cisco Nexus One architecture blog 正式把 **N9300 Smart Switch** 拉入 reference list — N9300 含 **DPU built-in** 執行 stateful microsegmentation，這是 **「**Smart Switch（switch + DPU）**」** 從 Cisco Hypershield 2024 概念走向 **「**資料中心 fabric 標準組件**」** 的里程碑。**為何重要**：

- 傳統 SmartNIC 部署在 **host server**（例如 BlueField-3 in x86 server），DPU 處理 storage/network/security offload；**N9300 把 DPU 移到 ToR switch 本體**，使 **「**DPU 為整 rack 提供安全 + microsegmentation enforcement**」**，所有連進 ToR 的 host 都自動獲得 **stateful L4-L7 policy**。這是 **「**hyperscaler 內部 fabric 設計（如 Meta 的 Minipack3 + 6-pack、AWS Nitro 系統）**」** 第一次進入 enterprise 主流 reference architecture。
- **與 NVIDIA BlueField 的關係**：N9300 內建的 DPU 與 BlueField-3/4 不衝突，N9300 提供 **L2-L4 fabric-level security**，BlueField 提供 **host-level storage/network offload**，兩者 **可以並存於同一 rack**。對 NVIDIA 而言是 **「**DPU 市場從 server 延伸到 switch**」** 的新合作通路。

### Spectrum-X 進入 Cisco reference

詳見頭條第一則。**Spectrum-X 系列**（含 Spectrum-4 51.2 Tbps、Spectrum-6 102.4 Tbps 兩代）是 NVIDIA 為 AI 設計的 Ethernet platform，**今日 Cisco 把它拉入 first-class silicon option** 是 NVIDIA Spectrum-X 從 **hyperscaler + NVIDIA 自身** 走向 **enterprise data center** 的 reference-level 通路勝利。

## 四、Ultra Ethernet 與標準動態

### IETF Group Policy Object (GPO) standard 進入 Cisco Nexus One

詳見頭條第一則。**GPO 三個 IETF drafts**：

- `draft-smith-vxlan-group-policy`
- `draft-wlin-bess-group-policy-id-extended-community`
- `draft-lrss-bess-evpn-group-policy`

**對 UEC 的間接影響**：UEC 1.0 spec 採用 **「**packet-level header-based 隔離**」**（含 GCM tag），IETF GPO 是 **「**control-plane 層的 segmentation standard**」**。兩者目標一致（multi-tenant fabric segmentation），但 **IETF 走在 control-plane 標準化，UEC 走在 data-plane 標準化**。對 2026 H2 採購者：**UEC-compliant NIC + IETF-GPO-compliant switch** 可能是 multi-fabric multi-vendor AI fabric 的主流組合。

### EVPN Border Gateway (BGW) 多 fabric 互通

詳見頭條第一則。**Cisco Nexus One BGW 實作**基於 **RFC 9014**（已成 RFC）+ **draft-sharma-bess-multi-site-evpn**（IETF working draft）。**對 enterprise 採購**：multi-fabric 互通從「**manual VRF + VLAN stitching**」 走向 **「**automated EVPN + enhanced BGW + GPO-based policy**」**，是 **「**fabric-of-fabrics**」** 從 telco 進入 enterprise DC 的關鍵 design pattern。

### 2. arXiv 6/29: [HMA-Serve: Disaggregated LLM Serving across Memory-Heterogeneous Accelerators（2606.29986）](https://arxiv.org/abs/2606.29986) — 跨廠商 GDDR + HBM LLM serving

- **一句話總結**：HMA-Serve 把 prefill 跑在低成本 GDDR-based accelerator、decode 跑在高效能 HBM-based GPU，**3.2× goodput + 4.8× goodput-per-dollar 改善**。
- **核心價值**：disaggregated LLM serving 從 **「**同廠商 GPU pool**」** 走向 **「**cross-vendor memory hierarchy**」**。三個 design 創新：(1) phase-wise quantization（prefill 低精度、decode BF16）；(2) compute-transfer pipeline（KV cache transfer overlap with later-layer prefill）；(3) deferred dequantization（ship raw quantized bytes 降低 network bandwidth 與 HBM usage）。
- **實用價值**：對 hyperscaler LLM serving infra，HMA-Serve 證明 **「**不一定所有 inference workload 都需要 HBM**」**，GDDR 配 cross-vendor interconnect 可以達到 production-grade goodput 與 cost reduction。對 **「**AI cluster 採購 GDDR vs HBM 配比**」** 提供 design reference。**對 RDMA / fabric 的 practical 含義**：(a) HMA-Serve 透過 GPUDirect RDMA + NVLink + RoCEv2 跨節點傳輸 KV cache，**network bandwidth 是 performance bottleneck**；(b) **「**deferred dequantization shipping raw quantized bytes**」** 是 **「**用 network bandwidth 換 HBM usage**」** 的 design trade-off — 對 **400G → 800G/1.6T fabric 升級** 是 **「**不只 throughput，是 LLM serving 演算法的 network-bandwidth-sensitive design**」** 的新維度。
- **3 個 model size 評估**（Qwen3 4B / 8B / 32B）+ 3 個 production traces，**state-of-the-art memory-homogeneous 比較**：HMA-Serve 達到 3.2× goodput、4.8× goodup-per-dollar、**no measurable generation-quality loss**。

### 3. arXiv 6/28: [Age of Information Under DCC Rate Constraints for V2I Broadcast Along Urban Corridors（2606.29611）](https://arxiv.org/abs/2606.29611) — V2I V2X（**非 DC fabric，列為 reference**）

- **一句話總結**：分析 ETSI DCC（Decentralized Congestion Control）在 V2I broadcast 對 Age of Information（AoI）的影響，在 5-day、762,050-vehicle Kuwait City trace 達到 corridor AoI 改善 5-66%。
- **核心價值**：提出 **「**upstream spatial traffic correlation 政策**」** 改善 channel load estimation，**hyperbolic density dependence 揭示 diurnal AoI variation > 4×**。
- **實用價值**：V2X（vehicular）應用，**不直接適用於 DC fabric**，列為 reference 供 RDMA 領域研究 congestion control 的 cross-pollination。

### 4. arXiv 6/18: [The Kernel's Write: Application Read-Only Memory（2606.26138）](https://arxiv.org/abs/2606.26138) — **STALE**（>7d，**drop**）

## 八、深度分析：2026 H2 三條 fabric 主軸交織 — Cisco 開放化、NVIDIA AI fabric 通路擴張、中國 all-CPU HPC 重新洗牌

### 主軸 1：Cisco 從「**ACI 集中化 + 封閉**」 翻向「**Nexus One 聯邦化 + 開放**」 是 2026 H2 enterprise DC fabric 最大重組

2014 年 Cisco 推出 **ACI** 時的核心論述是 **「**centralized policy controller + proprietary APIC + Cisco-only fabric**」**，13,000+ 組織在過去 12 年 lock-in ACI。**2026-07-02 的 Nexus One architecture blog 是 Cisco 對 2026 H2 市場現實的正式回應**：(a) **AI training workload 規模從 1K → 100K+ GPU**，ACI 的 centralized APIC 控制平面無法 scale 到這個規模；(b) **SONiC 在 hyperscaler 已成熟**，enterprise 客戶不願被 ACI 鎖定；(c) **NVIDIA Spectrum-X 等 3rd-party AI fabric silicon 已普及**，Cisco 不能只 sell 自家 Silicon One；(d) **AI agent 進入 network operations**，傳統 APIC 的 human-driven workflow 不夠敏捷。

**Nexus One 的解方**：(i) **4 層開放**（silicon、systems、software、operating model）每層都提供 2-3 個 first-class option；(ii) **IETF GPO** 把 ACI 的 ESG policy model 標準化（雖然 Cisco 是主要 author）；(iii) **EVPN BGW** 提供 multi-fabric 互通；(iv) **MCP server API + AI Canvas + AgenticOps** 把 fabric operations 推到 AI agent 時代。**對 Cisco 競爭者的 practical 含義**：

- **Arista**：原本在 hyperscaler 強、enterprise 弱的 Arista，現在面對 Cisco 開放 SONiC 支援，Arista 的 **「**單純 CloudVision + EOS 統一管理**」** 差異化縮小。Arista 必須靠 **AI Ethereal 2026 (6 月初 Sydney) 推出的 Etherlink 800G** + **7820R5 系列** 在 AI fabric 硬體效能面對抗。
- **Juniper**：Juniper 2025 年併入 HPE 後，Apstra + Mist AI 路線正面對 Cisco **「**Mist + ACI + Nexus Dashboard + Hyperfabric + AI Canvas**」** 的 multi-plane 競爭。Juniper 必須強化 **「**QFX 系列 switch + Apstra fabric**」** 的 AI fabric 整合。
- **NVIDIA**：Spectrum-X 進入 Cisco reference architecture 對 NVIDIA 是 **「**Spectrum-X 從 NVIDIA 自身 + hyperscaler 走向 enterprise 主流**」** 的通路勝利，與 Cisco 從競爭者變成 reference partner。

### 主軸 2：all-CPU HPC 路線在 2026 H2 對 NVIDIA 形成新壓力 — Dongarra/Hoefler/Matsuoka 論文是學術 signpost

NVIDIA 過去 10 年的 AI 論述是 **「**GPU > CPU 5-10× for AI training**」**，但 **LineShine + Fugaku + Matrix-Enhanced CPU 路線** 透過 **6 月 Top500 HPL + HPCG + HPL-MxP** 證明 **all-CPU HPC supercomputer 達到 GPU cluster 70-80% 性能 + 2-3× power efficiency**。今日 Dongarra/Hoefler/Matsuoka 預告的 **《Do We Still Need GPUs?》** 論文是 **「**西方 HPC 學術界正式認真看待 all-CPU 路線**」** 的里程碑。

**對 AI fabric 採購者的 practical 問題**：(i) **2026 H2 - 2027 H1 計畫採購 GB300 / Vera Rubin / GH200 的 hyperscaler**，是否需要保留 **「**matrix-enhanced CPU second-source**」** 評估？(ii) **NVLink / NVSwitch 在 all-CPU 架構下被 UALink / CXL 2.0 / Infinity Fabric 取代** 的可能性？(iii) **Spectrum-X 在 all-CPU HPC 環境下**與 NVIDIA GPU 沒有直接關聯，是否 NVIDIA 仍能 sell 進？(iv) **國家主權 AI 採購（歐盟、阿拉伯聯合大公國、Saudi Arabia）** 在 power efficiency 與 supply chain 主權考量下，是否優先採購 all-CPU HPC？

### 主軸 3：arXiv SIGCOMM/OSDI post-deadline cooldown 第 2 週 — 預期 7/8-7/12 恢復產出

今日 arXiv 篩出 0 篇 DC fabric 核心論文，是 **SIGCOMM 2027 deadline (6/22) + OSDI 2026 deadline (6/25) 雙 cooldown** 的第 2 週。**預期 7/8-7/12 隨 SIGCOMM 2027 rebuttal cycle 結束 + OSDI 2026 final notification 公告**，cs.NI/cs.AR/cs.OS 將恢復正常產出。**對 07-05 ~ 07-08 的 digest 預期**：arXiv 仍將 sparse，建議以 **「**vendor release + GitHub release + 會議 workshop paper**」** 為主軸，**「**conference 接受 paper 公告**」** 為輔。

### 給 2026 H2 AI fabric 採購者的 3 條 actionable takeaway

1. **重新評估 Cisco 在 AI fabric 的位置**：Cisco Nexus One 開放化 + Spectrum-X reference + SONiC option 意味 **「**Cisco 不再是 AI fabric 旁觀者**」**，是 **「**enterprise AI fabric 第一線 vendor**」**。計畫新購 AI fabric 的 enterprise 必須把 **Cisco Nexus One + Spectrum-X** 列入評估。
2. **保留 matrix-enhanced CPU second-source**：Dongarra/Hoefler/Matsuoka 論文 + LineShine Top500 #1 + Fugaku all-CPU 意味 **「**GPU only**」** 不再是 2027+ AI infra 的預設答案。**Grace Hopper / Grace Blackwell / Vera Rubin** 規劃時保留 **「**Grace CPU only rack + BlueField-3 DPU + Spectrum-X**」** 的 second-source 路徑。
