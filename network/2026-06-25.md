**arXiv 2606.24079 — Aquifer: Hierarchical Memory Pooling with CXL and RDMA for MicroVM Snapshots（06-23 發表）** —— 6 月 23 日新發的 arXiv 2606.24079（[連結](https://arxiv.org/abs/2606.24079)）提出 **Aquifer**，**第一個用 CXL+RDMA 雙層 memory pool 服務 MicroVM 快照的系統**。**核心問題**：「**Memory stranding wastes 25-35% of installed DRAM in production cloud clusters. Memory pooling over CXL and RDMA offers a remedy, but neither technology alone suffices: CXL provides low-latency, load/store-transparent access limited to a pod, while RDMA provides cluster-wide reach at higher latency with software overhead.**」**Aquifer 設計**：(a) **hotness-based snapshot format**——**characterization 顯示 snapshot pages 大部分是 zero 或 cold**，所以格式上 **eliminate zero pages + 只把 hot working set 放 CXL pool + cold pages 放 RDMA pool**；(b) **ownership-based coherence protocol**——在 CXL 2.0 multi-headed devices（缺乏硬體 cache coherence）上 **across-host sharing** 需要 software-defined coherence；(c) **copy-based page serving**——**pre-install hot pages from CXL memory before MicroVM resume + demand-page cold pages asynchronously from RDMA**。**實驗結果**——在 **emulated CXL+RDMA hardware** 上，**end-to-end invocation time 達 2.2× geometric-mean speedup over Firecracker + 1.1× over the next best alternative**。

> 深度分析：Aquifer 是 **2026 年中「CXL+RDMA 雙層 memory fabric 從學術研究進入 MicroVM 真實 workload」最具落地性的研究**。具體地：(1) **CXL 2.0 multi-headed + 跨 host share**——CXL 2.0 支援 **multi-headed devices（多 host 共享同一 CXL device）**，但 **缺乏硬體 cache coherence**——這是 CXL 2.0 spec 對 memory pooling 的最大限制。Aquifer 設計 **ownership-based coherence protocol** 補上這個 gap：每個 MicroVM 對 hot page 的 ownership 由 metadata track，**避免同時多 host 寫入同一 page 的 race condition**。對 **CXL 2.0 ecosystem**：Aquifer 的 coherence protocol 是 **「CXL 2.0 multi-headed + software coherence」reference design**，預期 2026-2027 將有 open-source 實作（如 Aquifer 開源）成為 CXL 2.0 memory pool 的標準 software stack；對 **CXL 3.0**（支援 hardware-coherent multi-host sharing）：Aquifer 的 software coherence 設計在 CXL 3.0 普及後可被硬體取代，但 **CXL 3.0 設備量產時間表是 2027-2028**——Aquifer 填補了 CXL 2.0 過渡到 3.0 的「software coherence」空窗。(2) **25-35% memory stranding 浪費**——這個數字代表 **hyperscaler data center 安裝的 DRAM 中有 25-35% 處於閒置狀態**（典型場景：某 host 升級後留下的閒置 DIMM、無法跨 host 利用）。Aquifer 透過 **CXL+RDMA 雙層 pool** 把閒置 DRAM 整合成 cluster-wide memory fabric，**2.2× speedup over Firecracker** 代表 **memory pool 化把 MicroVM cold-start latency 降到接近 local CXL access 的水平**。對 **hyperscaler ROI**：memory 是 cloud data center 第二大 capex 項目（僅次於 GPU），**25-35% memory utilization 提升** 等於 **capex 投資 1.4-1.6× 等效擴容**——Aquifer 的 CXL+RDMA 雙層 fabric 是 **2026 年中 hyperscaler memory capex 優化最具體的學術方案**。對 **AWS Nitro / Azure Boost / GCP Titanium**：三家 hyperscaler 雖已各自有 DPU + memory pool 設計，但 **Aquifer 論文級的「CXL 2.0 + RDMA 雙層 + MicroVM」** 是 **第一個 academic 完整 reference design**——預期 2026-2027 hyperscaler 內部 roadmap 會參考 Aquifer 設計。(3) **MicroVM serverless 場景**——serverless 是 hyperscaler 增長最快的 workload（AWS Lambda、Azure Functions、GCP Cloud Run 每年 50%+ growth），**cold-start latency 是 serverless user experience 的瓶頸**。Aquifer 把 MicroVM snapshot restore latency 從 1 秒級降到 100ms 級，**「sub-second serverless cold-start」** 對 LLM serving（每個 inference 啟動一個 MicroVM）的 total latency 影響巨大——預期 2026 下半年將有 LLM serving 框架（vLLM、TGI、SGLang）採用 Aquifer 風格的 CXL+RDMA snapshot 設計。

**arXiv 2606.23969 — The Serialized Bridge: Understanding and Recovering LLM Serving Performance under Blackwell GPU Confidential Computing（06-22 發表）** —— 6 月 22 日發表的 arXiv 2606.23969（[連結](https://arxiv.org/abs/2606.23969)）首次系統量化 **GPU-CC 在 Blackwell 平台上的「VM-GPU bridge bottleneck」**。**核心發現**：「**GPU Confidential Computing (GPU-CC) now preserves GPU-local performance: on NVIDIA B300, BF16 matmul runs at 0.998x of non-confidential performance. Yet LLM serving under Intel TTDX plus GPU-CC still loses 13-27% of throughput, and KV-cache restore latency can more than double.**」**Root cause 定位**——「**the confidential VM-GPU bridge, not GPU compute**」：(a) **GPU-CC 把 host/device movement 變成 serialized、high-setup-cost channel**；(b) **Secure copies 不在 context 內得到 CUDA-stream concurrency**；(c) **asynchronous transfers 在 runtime boundary block**；(d) **small crossings 付 fixed toll**。**量化數字**——**vLLM dense decode 觀察到 44× 慢的 small alloc-and-copy operations**；**targeted patches reject alternative explanations**。**Recovery 方法**：(i) **scheduling flag** 恢復 **57% of the gap**；(ii) **worker-thread drain** 在 qualified high-concurrency 場景恢復 **up to 92%**。**KV-cache restore penalty +131%**；**model-load slowdown 34×**。**Blackwell 獨特發現**——**confidential tenancy unit 改變**：在 **B300 HGX** 上 qualify **confidential multi-GPU NVSwitch tenants（510 GB/s NVLink P2P inside a CVM）+ concurrent isolated tenants**，identify **remaining fabric-attestation gap for production confidential AI platforms**。

> 深度分析：Serialized Bridge 是 **2026 年中「confidential AI fabric 的 VM-GPU bridge 是真實瓶頸」最完整的 paper 級論據**。具體地：(1) **GPU-CC 已經 preserve GPU-local performance（0.998× of non-confidential）但 VM-GPU bridge 仍然慢**——這個 finding 拆解了「**GPU-CC overhead = GPU compute 慢**」的常見誤解：**GPU compute 已經零 overhead，但 host/device data movement（KV-cache restore、weight loading、intermediate activation transfer）才是真正的瓶頸**。對 **NVIDIA Blackwell B300 / RTX Pro 6000 confidential computing 部署**：confidential AI cluster 的 throughput 不是被 GPU 卡住，而是被 **CPU↔GPU 通道**卡住，這代表 **「confidential AI cluster 的硬體優化重心應放在 PCIe Gen 6 / NVLink bridge + secure DMA engine」** 而非 GPU 算力。對 **Intel TDX / AMD SEV / Arm CCA**：三家 CPU 廠商的 confidential computing extension 必須在 **「VM-GPU bridge 的 secure DMA engine」** 與 NVIDIA 合作設計——Intel TDX 當前在 LLM serving 場景 lose 13-27% throughput 是 **TDX 對 GPU-CC 的 host/device channel 設計不夠高效** 的硬體限制。(2) **44× slow small alloc-and-copy**——這個數字是 **「modern inference runtime 對 DMA 假設錯誤」** 的具體證據：vLLM 內部 **小塊記憶體的 alloc + copy**（典型 KV-cache 增量、attention intermediate buffer）在 confidential 環境下因為 **每個 allocation 都要做 secure channel setup** 而付 44× fixed toll。對 **vLLM / TGI / SGLang**：三個主流 LLM serving framework 必須重新設計 **「confidential-aware memory allocation」**——把 small alloc 合併成 large block copy、或用 **persistent CUDA Graph capture** 避免 small alloc 的 setup overhead；對 **NVIDIA CUDA-X**：CUDA-X libraries 需要新增 **「confidential-aware DMA」** API，讓 user-space 程式可以 hint 「this is a small alloc, please batch」。(3) **NVSwitch tenants inside CVM（510 GB/s NVLink P2P）**——這是 **2026 年中 confidential AI fabric 從「單 GPU confidential」推進到「多 GPU confidential」最關鍵的硬體里程碑**。Blackwell B300 在 CVM 內部支援 **510 GB/s NVLink P2P**（這是 NVLink 4.0 / NVSwitch 3 的 peak），代表 **multi-GPU LLM training/serving 可以在 confidential 環境下保持 NVLink 全部 bandwidth**。對 **confidential AI 部署**：這個發現讓 **「confidential multi-GPU LLM training」** 在 B300 + Intel TDX 平台上 **技術上可行**——**scheduling flag + worker-thread drain 92% recovery** 把「13-27% throughput loss」縮小到 **1-2%**，**「confidential AI 接近非 confidential AI 的 performance」** 在 2026 年中是 B300 平台的真實水平。對 **fabric attestation**：「**remaining fabric-attestation gap**」代表 **NVSwitch 與 CVM 的硬體 attestation protocol 尚未完整**——預期 NVIDIA 將在 2026 下半年至 2027 上半年補上這個 attestation protocol（可能透過 Hopper/Blackwell Confidential Computing Mode 的 firmware 更新），讓 **confidential multi-tenant GPU cluster** 可以 **production deploy**。

## 供應商與標準

**UCX v1.21.0 正式發布（06-24）：GDA (GPU Direct Async) transport 全面成熟 + `UCX_IB_GDA_RETAIN_INACTIVE_CTX` + GDA WQE ordering 用 CAS-based readiness marking** —— 6 月 24 日，UCX 團隊在 [openucx/ucx v1.21.0](https://github.com/openucx/ucx/releases/tag/v1.21.0) 正式發布 v1.21.0，定位為 **「GDA path 從 GDAKI 推進到 production-grade GDA transport」** 的版本。**Features**（from UCX NEWS）：(i) **UCP**——新增 `UCX_PROTO_EMULATION_ENABLE` 強制 zero-copy RMA protocol selection、新增 `UCX_MAX_HCA_PER_GPU` 限制 GPU memory registrations 到 nearest HCAs、新增 **device lanes that can access host memory for GPU transfer fallback**、**啟用 gdr_copy for memtype endpoint transport**；(ii) **UCT**——新增 device channel pool、新增 CPU memory as AMO local buffer for device operations；(iii) **RDMA CORE**——新增 `UCX_IB_GDA_RETAIN_INACTIVE_CTX` 控制 GDAKI 的 inactive CUDA context retention、新增 configure option 啟用/停用 GGA transport；(iv) **Build**——新增 `--without-gda` configure option、cuRAND 變成 optional dependency。**Bugfixes**（highlight）：(a) **GDA WQE ordering 改用 CAS-based readiness marking**——這是 **GDA transport 從 GDAKI (GPU Direct Async Kernel Interface) 推進到 production GDA** 最關鍵的穩定性 fix；(b) **GDAKI CUDA context handling 修正**；(c) **CUDA IPC accessibility cache separation for local and remote rkeys**；(d) **GDAKI NIC/GPU mapping 修正 when CUDA_VISIBLE_DEVICES hides physical GPUs**。

> 深度分析：UCX v1.21.0 是 **2026 年中「UCX 的 GDA 路徑從 GDAKI 進入 production-grade GDA transport」** 的 release 級里程碑。具體地：(1) **GDA WQE ordering 用 CAS-based readiness marking**——這個 bugfix 直接解決 **GDA 在 multi-GPU 場景下 WQE out-of-order 問題**：傳統 RC (Reliable Connection) transport 用 send queue 與 receive queue 的硬體 ordering 保證，但 **GDA 用 doorbell + WQE 寫入** 時如果有 race condition 會導致 WQE 完成順序錯亂。CAS (Compare-And-Swap) based readiness marking 是 **GDA 在 production 部署必須的 ordering primitive**——v1.21.0 把這個穩定化補上代表 **GDA 從「實驗性 transport」進入「可 production deploy」**。對 **AI training 場景**：GDA production 化代表 **UCX 在 NCCL 之外提供第二個「GPU-aware collective」transport stack**——對 NVIDIA 自家 NCCL 雖仍是主流，但 **AMD ROCm / Intel GPU / 中國自研 NPU 透過 UCX GDA 跑 collective** 是 2026 年中「**NCCL 之外第二個 GPU collective transport**」的關鍵；對 **hyperscaler AI cluster**：GDA 在 UCX production 等於 **AWS EFA / Azure MANA 等 hyperscaler 自研 NIC 與 NVIDIA/AMD GPU 的整合路徑可以走 UCX**——EFA 已經是 UCX provider，Azure MANA 預期 2026 下半年也會加入。(2) **`UCX_MAX_HCA_PER_GPU` 限制 GPU memory registrations 到 nearest HCAs**——這個 policy 控制 **GPU memory pinning 範圍**：傳統 UCX 會把 GPU memory register 到所有可達的 HCA（Host Channel Adapter），但 **多 HCA 場景下 GPU memory 過度 registration 會浪費 HCA 的 MR (Memory Region) 資源**。`UCX_MAX_HCA_PER_GPU` 讓 application 限制只 register 到「nearest」HCA——對 **8×H100 + 8×ConnectX-7** 這類 high-density AI server 是 **HCA MR cache 命中率與 RDMA 性能的關鍵調校**。對 **hyperscaler AI cluster**：這個 policy 讓 **multi-tenant GPU cluster 可以把 GPU memory 嚴格限制在「local HCA」範圍**，避免 tenant 間 memory access 互踩。(3) **`gdr_copy` enabled for memtype endpoint transport**——`gdr_copy` 是 NVIDIA GPUDirect RDMA 的 **CPU-assisted copy fallback 路徑**（GPU memory 不能直接 DMA 時用 CPU copy）；之前在 `memtype` transport 上是 disabled，v1.21.0 啟用代表 **UCX 在「GPU memory 跨 NUMA node」場景有完整 fallback 路徑**。對 **multi-socket GPU server**：2-socket server 的 GPU 跨 socket 訪問時若用 NVLink，gdr_copy 是 backup；對 **AI training large cluster**：gdr_copy 啟用降低 **「GPU memory 跨 NUMA 訪問失敗」** 機率，提升 training reliability。

**arXiv 2606.17716 — DPDS: A DPDK-Based Packet Delayer and Spacer（v2 06-22 更新）** —— 6 月 16 日 v1、6 月 22 日 v2 更新的 arXiv 2606.17716（[連結](https://arxiv.org/abs/2606.17716)）是 **DPDK 應用於 link emulation 的 state-of-the-art**。**核心問題**：「**Naive approaches either add more delay than desired or cause packet reordering, both of which are undesirable.**」**DPDS 設計**——**adaptive delay correlation**：**(i) 輸入 mean delay + standard deviation (jitter) + half-life period** 三個參數；(ii) **positively correlated delays**——避免 packet reordering；(iii) **half-life period 控制 delay dynamics**。**實作**——DPDK-based packet delayer and spacer (DPDS)，**與 NetEm 與 MoonEm 兩個既有 DPDK emulator 比較**。**性能結果**：(a) **zero-loss throughput of 95 Gbit/s for constant delay**；(b) **with spacing enabled, 85 Gbit/s for varying delay with 3 ms jitter**；(c) **支援 packet reordering**——**zero-loss throughput of 73 Gbit/s (constant) 與 58 Gbit/s (varying delay)**；(d) **支援 policing + 兩種 packet loss models**。

> 深度分析：DPDS 是 **2026 年中「DPDK 在 link emulation / network testing 場景的 state-of-the-art」**——95 Gbit/s zero-loss 與 85 Gbit/s 3ms jitter 對 link testing 來說是 **「線速 (line-rate) 模擬 + 高精度 jitter 控制」** 的硬體保證。具體地：(1) **NetEm 是 Linux kernel 內建的 link emulator**，缺點是 **kernel 上下文切換 overhead 與 packet reorder**；**MoonEm 是基於 DPDK 的 emulator**，缺點是 **varying delay 場景 throughput 下降明顯**；DPDS 的 **adaptive delay correlation + half-life period** 設計同時解決 **packet reordering** 與 **varying delay throughput 下降** 兩個問題。對 **network equipment testing**：DPDS 95 Gbit/s 對應 **100 GbE 線速**——這是 **「在單一 server 上模擬 100 GbE link 帶有 3ms 精準 jitter」** 的能力，對 **Arista / Cisco / Juniper 這類 network switch 廠商在出廠前的 100 GbE 介面驗證** 極為重要；對 **AI training network simulation**：DPDK-based emulator 可用來 **模擬 AI training cluster 的 long-tail latency + jitter**（如 99th percentile FCT + 3ms jitter），這是 **hyperscaler AI training fabric design 時的 network simulation 工具**。(2) **half-life period**——這個參數是 **「jitter correlation 時間常數」** 的精準控制：half-life 短代表 jitter 變化快（類似 Internet 抖動），half-life 長代表 jitter 平滑（類似 datacenter 內部 network）。DPDS 推薦 **half-life period 配置** 是 **「模擬真實 production network 的 jitter autocorrelation」** 的關鍵——對 **AI training fabric 設計**：DPDS 讓 network engineer 可以在 **「hyperscaler 內部 latency profile」**（如 AWS EFA、Azure MANA 的實測 jitter）下測試 NCCL collective 的 tail latency，這是 **2026 年中「AI training fabric 設計從 throughput-only 進入 jitter-aware」** 的工具基礎。

## 技術深潛：HPC fabric 在 2026 年中的「Ethernet vs InfiniBand vs 自研 ASIC」三極化 — 從 HPE Slingshot 400 與 LineShine LQLink 看見的市場結構

6 月 23-25 日的 HPC fabric 訊號呈現 **「三極化」** 結構：HPE Slingshot 400 把 Ethernet 推到 260K endpoints 規模、中國 LineShine 以自研 LQLink 重返 TOP500 #1、NVIDIA Quantum-X800 + Vera Rubin 在 Cray GX5000 上做 InfiniBand 選項。從市場結構、技術路線、地緣政治三個維度分析：

**一、Slingshot 400 把 Ethernet 推到「exascale 級 endpoint 規模」——UEC 推動 Ethernet fabric 在 HPC 取代 InfiniBand 的硬體里程碑**。Slingshot 400 的 260K endpoints + 3-level network 對比 InfiniBand fat-tree 典型 hyperscaler 部署的 10K-50K endpoints 是 **「5-25× 規模優勢」**。HPE 公開聲稱「a lot better than the scale of InfiniBand」代表 **HPE 認為 Ethernet 已經在 endpoint 規模上超越 InfiniBand**——這對 UEC 推動 Ethernet 在 HPC 是 **硬體級 validation**。對 **Broadcom Tomahawk 6 / Cisco Silicon One G300**：兩家 hyperscaler 自研 ASIC 雖在 100K+ endpoint 規模部署，但 **Slingshot 400 整合進 Cray EX4000/GX5000/XD/ProLiant 全產品線** + **Cray Supercomputing Storage E2000 平行檔案系統 pre-integrated** 是 **「pre-integrated full-stack HPC fabric」** 的獨特價值。對 **NVIDIA Quantum-X800**：Quantum-X800 雖仍是 376/500 TOP500 系統的 fabric 標準，但 **Ethernet 在 endpoint 規模上超越** 代表 **UEC 1.0 規格必須在 2026-2027 推出 200/400 GbE 級 silicon 才能保住 Ethernet 在 HPC 的競爭力**。**Slingshot 400 是 2026 年中 Ethernet HPC fabric 的 state-of-the-art**，對 Aurora/Frontier/El Capitan 下一代（Perlmutter-X 路線圖？）的 fabric 選項是關鍵參考。

**二、中國 LineShine 的「LX2 + LQLink」自主可控 exascale——HPC 算力的地緣政治三極化**。LineShine 奪回 TOP500 #1 是 **2024 年 11 月 El Capitan 奪冠後首次由非美製系統奪冠**——這個時間點 + 21.5% 領先幅度 + Armv9 304-core 自主 CPU + 自研 LQLink 互連 4 個事實組合，**代表中國 HPC 在「CPU 設計 + 互連 ASIC + 系統整合」三層都已自主可控**。對 **美中 HPC 拉鋸**：AMD + NVIDIA 加速系統 35.3M cores vs NVIDIA 38.9M cores 是 **「美中算力 1:1 拉鋸」**——美中 HPC 不再是「中國追趕美國」而是「中國已並駕齊驅」。對 **美國出口管制**：NVIDIA H20 / B30 等中國特供版 + AMD MI308 / MI250 中國版的出口管制 **無法阻止中國自研 CPU+互連**——LineShine 證明 **「中國不再需要 NVIDIA / AMD GPU 加速」** 也可以達到 exascale HPL。對 **NVIDIA / AMD GPU 加速護城河**：「**純 CPU + vector + 自研互連達到 GPU 加速 80% 能效密度**」的 finding 對 GPU 加速 HPC 是 **護城河被侵蝕的訊號**——NVIDIA 與 AMD 必須在 **「HPC + AI convergence workload」**（如 LLM training on HPC）找到純 CPU 無法匹敵的優勢才能保持 TOP500 領先。

**三、UCX v1.21.0 的 GDA production-grade + Aquifer 的 CXL+RDMA + Serialized Bridge 的 confidential AI fabric**——**2026 年中「AI fabric 從 throughput-only 進入 jitter/confidential/memory-aware」的技術典範轉移**。UCX v1.21.0 的 GDA production 化代表 **GPU collective 從 NCCL 單一選擇進入「UCX + GDA + NCCL」多 transport 競爭**；Aquifer 的 CXL+RDMA 雙層 pool 代表 **memory fabric 從「per-server DIMM」進入「cluster-wide pool」**；Serialized Bridge 的 VM-GPU bridge bottleneck 量化代表 **confidential AI fabric 從「GPU 算力 0.998×」進入「end-to-end 1-2% overhead」**。對 **2026 下半年的 AI fabric 採購者**：(i) **CXL 2.0 設備量產**——2026 下半年將有 CXL 2.0 multi-headed 設備量產；(ii) **confidential AI**——B300 + Intel TDX 在 scheduling flag + worker-thread drain 修復後 **接近 non-confidential performance**，confidential AI cluster 進入 production；(iii) **AI training fabric jitter-aware design**——DPDS 等 jitter-aware simulator 讓 network engineer 在 AI training fabric design 時可以 **模擬 real-world production jitter profile**。

**對 2026 下半年的 HPC + AI fabric 採購者的具體建議**：(i) **國家級 HPC 標案**——**Vera Rubin + Quantum-X800 InfiniBand 仍是 2026-2028 的「事實配方」**（LANL Mission/Veritas/Vision 三機驗證），但 **Cray GX5000 + Slingshot 400 雙軌選項** 在 2026 下半年會給 HPC 採購者更彈性的 fabric 選擇；(ii) **超大規模 AI cluster**——**UCX v1.21.0 GDA production** + **Aquifer CXL+RDMA 雙層** + **Serialized Bridge confidential CC** 三個研究一起看，**2026 下半年 AI cluster 設計必須把 memory pool + GPU CC + UCX transport 一起考慮**，而非只關注 GPU 算力；(iii) **中國地緣政治風險**——LineShine 自主可控代表 **中國 HPC market 對 NVIDIA / AMD 的依賴快速下降**，跨國企業在中國的 HPC 投資必須考慮「**中國自主 CPU+互連 vs NVIDIA GPU 加速**」的長期 TCO 比較；(iv) **Ethernet HPC fabric 升級路徑**——**Slingshot 400 + Cray EX4000/GX5000** 是 2026 下半年 Ethernet 在 HPC 的 reference deployment，hyperscaler 與 Tier-1 HPC 中心若要推 Ethernet fabric 可直接採購 HPE 整櫃交付；(v) **confidential AI 部署**——**B300 + scheduling flag + worker-thread drain** 把 GPU-CC overhead 從 13-27% 壓到 1-2%，**confidential AI cluster 在 B300 平台已 production-ready**，金融、醫療、政府等受規管產業在 2026 下半年可正式部署 confidential AI。
