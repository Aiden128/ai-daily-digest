## 1. Headlines

### 1.1 rdma-core v64.0 master-branch consolidation：111 commits、CoCo DMA-bounce、ibv_buf provider-aware buffers、DMA-buf heap（07-08）

linux-rdma/rdma-core 於 2026-07-08T13:06:08Z 釋出 v64.0，是 master branch 在 07-07 5-branch coordinated backport 後的下一個 release cycle。**這與 5-branch backport 是不同事件類型**——backport 是 18 秒內把 reliability 修補同步到 v59.2 / v60.2 / v61.1 / v62.1 / v63.1（bnxt_re / rxe / mlx5 / librdmacm 等），而 v64.0 在 master 端引入新的 user-space API surface，共 111 commits：

- **libibverbs（13 commits）**：新增 `struct ibv_buf` 通用 buffer 描述子、`ibv_alloc_buf/ibv_free_buf` verbs API、`ibv_reg_buf_mr()` provider-aware 註冊介面、`ibv_cmd_create_qp_ex2()` driver chain 擴充。引入內部 DMA-buf heap allocator library。
- **CoCo DMA-bounce 旗標**：新增 `IBV_PD_UNPROTECTED_ALLOC` 與 `CoCo DMA bounce` device capability flag，讓 confidential-computing guest 在不需 protection domain 包裝的情況下配置 DMA buffer，配合 mlx5 `dmabuf UMEM attrs` kernel 端路徑。
- **mlx5（5 commits）**：實作 `ibv_alloc_buf/ibv_free_buf` ops、新增 DMA-buf heap 與 CoCo shared allocation 支援、adopt `struct ibv_buf` 於內部 buffer 配置。
- **bnxt_re（7 commits）、irdma（8 commits，Intel Ethernet 800 系列）、efa（3 commits，AWS EFA + `query_port_speed` verb）**：reliability hardening 與 query port speed 介面擴充，呼應 07-07 5-branch backport 的 Broadcom/Intel reliability 主軸。
- **pyverbs（8 commits）**：provider-aware buffer 測試與 ParentDomain CC unprotected 支援。
- **librdmacm preload.c**、**libibnetdisc（2）**、**libibmad**、**infiniband-diags**、**libhns（HiSilicon，3）**、**providers/rxe（2）**：小幅 reliability 與測試覆蓋率。

**實務意涵**：對 procurement 而言，v64.0 把 CoCo guest 與 DMA-buf heap 整合到 user-space verbs 層，把 GPU-direct / CXL.mem / shared memory fabric 的 RDMA 抽象化往前推一步。對 Broadcom Stingray（bnxt_re）使用者，意味著在 v64.0 master + v59.2-v63.1 5-branch backport 雙重 reliability hardening 後，2026 H2 是 Stingray PSIF 在 production 替換 ConnectX 的時機窗。對 Intel IPU/E2000 客戶，irdma 的 8 commits 意味著 800 系列 Ethernet adapter 的 RDMA 軟體堆疊進入 active maintenance。

- 來源：https://github.com/linux-rdma/rdma-core/releases/tag/v64.0
- 已在 2026-07-09 digest 整理 v59.2-v63.1 5-branch 18 秒 backport 事件；v64.0 是 master-branch consolidation + new APIs 的新事件，視為獨立 headline。

### 1.3 Cisco Nexus One（07-02）+ Cisco Cloud Control（07-09）：後 ACI 時代的 data center 架構與統一管理 plane

Cisco 兩個相隔一週的公告拼出完整的下一代 data center 策略：

- **Nexus One（07-02）**：Cisco 13,000+ ACI 客戶的下一代 data center 架構。Will Eatherton（ACI 創始人）撰文定義 Nexus One 為「架構而非產品」，承襲 ACI 的 group-based segmentation、service chaining、deep observability 並將其標準化到 IETF。設計目標是 AI-ready data center、AI-driven security threat 防護、architectural flexibility。
- **Cloud Control（07-09）**：Cisco Live 2026 公布的統一管理 plane，Jeetu Patel 主導。整合 Nexus One + Intersight 兩個生態到單一 console，**針對 agentic AI operations** 設計（cross-domain、context-rich）。美國商用客戶 controlled availability 今日，general availability 預計年底。

**實務意涵**：在 NVIDIA Spectrum-X / Broadcom Tomahawk / Marvell OCTEON 競爭下，Cisco 的策略是用「架構標準化 + 統一管理 plane」而非純 ASIC throughput 對抗。對 enterprise DC 客戶，Nexus One 是把 ACI 部署遷移到 AI fabric 的橋樑；對 hyperscaler，Nexus One 不直接競爭。UEC 1.0 + IETF 標準化 + Cisco Cloud Control 三條線在 2026 H2 交會。

- 來源：https://blogs.cisco.com/datacenter/cisco-nexus-one-next-generation-data-center-networking-architecture

### 1.4 IDC Q1 2026：Ethernet switch 成長 39.8% > server 30.4%；data center Ethernet 暴增 61%（Next Platform 07-06）

## 5. Conference & Research Papers

> **今日 arXiv 概況**：cs.NI / cs.DC / cs.OS / cs.AR 合計 ~140 篇 raw entries，經 strict_terms 篩選後僅 8 篇進入 in-scope 候選，再經人工 review 後**僅 3 篇**符合 data center fabric 標準。延續 SIGCOMM 2026 rebuttal + OSDI 2026 notification 等待期。下一波學術內容高峰預估 7/19-7/25。

### 5.1 UBEP: Re-architecting Expert Parallelism Communication Library for Production Superpods（cs.NI 2607.06202）
- **一句話**：把 MoE expert parallelism 通訊層從「all-to-all token dispatch + all-to-all combine」重新架構，目標是 NVIDIA NVL72/576 與 Huawei CloudMatrix384 等 superpod 的 production 部署。
- **核心價值**：在 NVL72/576 + CloudMatrix384 的 unified global address space + high-bandwidth fabric 環境下，MoE expert routing 引入的 collective 與 point-to-point 混合通訊是 bottleneck；UBEP 重新設計 comm library 把 expert parallelism throughput 提升至接近 native NVLink/RoCE 頻寬上限。
- **實務價值**：對 MoE 訓練（Mixtral / DeepSeek-MoE / Qwen-MoE）團隊，提供 MoE-aware comm primitive 實作參考；對 NVL72 / NVL576 / CloudMatrix384 的 system architect，這是 2026 H2 production MoE 部署的 reference design。

### 5.2 Adaptive Space-efficient Collectives for Dynamic and Unstructured Sparsity on GPU Platforms（cs.DC 2607.04676）
- **一句話**：NCCL 等 collective comm library 主要優化 dense data；本文針對 dynamic unstructured sparsity（如 MoE 的 sparse dispatch、sparse attention）設計 space-efficient collective primitive。
- **核心價值**：現有 NCCL/RCCL 假設 contiguous dense tensor，sparse MoE dispatch 浪費大量頻寬；新方法用 adaptive topology-aware 壓縮把 sparse collective 頻寬需求降到 ~30-50%。
- **實務價值**：對千億參數 MoE 訓練（尤其 dynamic expert routing），可省下 30-50% NVLink/RoCE collective 頻寬。

### 5.3 GORIO: GPU-Centered Remote I/O for Graph ANNS over NVMe-oF（cs.DC 2607.04415）
- **一句話**：GPU server 透過 NVMe-oF（NVMe over Fabrics）做 graph-based approximate nearest neighbor search（ANNS）的 remote I/O 路徑優化。
- **核心價值**：vector database / RAG 的 graph ANNS index 常超過單 GPU 記憶體；NVMe-oF 是 storage disaggregation 方案，但目前 remote I/O 對 GPU direct 路徑不友善。GORIO 重新設計 GPU → NVMe-oF target 的 I/O pipeline。
- **實務價值**：對 hyperscaler RAG infrastructure，提供 GPU-CPU-NVMe-oF 三層 I/O 整合參考，呼應 Spectrum-X / BlueField 在 storage fabric 的市場機會。

### 5.4 Cross-IP Request Coalescing: Relocating the Fan-out Point in Virtualized I/O（cs.DC 2607.02969）
- **一句話**：在 multi-tenant 虛擬化 I/O 路徑中，把 fan-out 點從 VM 內部上移到 hypervisor，降低 AI workload 在 storage I/O 的 request amplification。
- **核心價值**：AI workload 在 multi-tenant 環境下，storage request 在 vhost / virtio / NVMe driver 多層 fan-out，造成 3-10× request amplification；Cross-IP Coalescing 在 hypervisor 層把相同 underlying block 的多個 VM request 合併。
- **實務價值**：對 BlueField / DPU 上的 storage virtio offload 設計有直接 reference 價值。

> 註：2607.02112（A 2048-spin bulk acoustic wave Ising machine）為 cs.AR 物理光學 computing，雖通過「optical」strict term，但主題與 data center fabric 無關，列為非候選。2607.00616 / 2607.00292 / 2607.06804 分別為 stochastic geometry / LLM topology design / supply-chain accountability，與 fabric 弱相關或無關，不納入 Research Spotlight。

## 8. Deep Analysis

**2026-07-11 是 mid-summer 安靜期第五週。** 五週的 fabric 內容空窗驗證了 2026-07-05 的預測——SIGCOMM 2026 rebuttal 與 OSDI 2026 notification 確實在 7/12-7/20 之間才會釋出，arXiv cs.NI/cs.DC 的 post-deadline cooldown 持續到 7/19 之前。HN 在 5 週內對 fabric 議題的「冷感」是學術週期與產品週期交疊的訊號：Q2 結束後業界進入半年度規劃期，Q3 早期沒有 major conference 與 product launch。

但 fabric 標準化與 AI 推動的 Ethernet 加速兩個大方向在本週仍在持續推進，且都走向「2026 H2 收斂」：

**(1) Ethernet for AI fabric 的 IDC Q1 數字落地。** Timothy Prickett Morgan 在 Next Platform 7/6 文章把 IDC Q1 2026 的數字整理得很清楚：data center Ethernet switch +61% vs edge/campus +12.3%，是 Q1 2026 最具體的市場訊號。這個成長率背後是 NVIDIA Spectrum-X、Broadcom Tomahawk 5 / 6、Marvell OCTEON 10、Cisco Silicon One 等 ASIC 在 AI cluster 的出貨加速。**111.2 Tbit/s 的 DriveNets-WhiteFiber 跨 52 英里 AI supercluster（Light Reading 7/9）正是這個趨勢的 reference deployment**——long-reach Ethernet 在 AI fabric 的可行性首次在 production 等級被驗證。

**(2) RDMA 軟體堆疊的兩條收斂路徑。** rdma-core v64.0（07-08）把 CoCo guest、DMA-buf heap、GPU-direct 在 user-space verbs 層抽象化，是「RDMA 走向多元化 interconnect target」的關鍵節點。**過去 RDMA 主要是 InfiniBand + RoCE v2 兩條 target 路徑，現在新增 DMA-buf heap + CoCo bounce 兩條路徑**——意味著 RDMA 軟體堆疊開始為 CXL.mem、shared memory fabric、confidential computing 三個新場景做準備。這是 UEC 1.0 spec 之外，軟體層的「infrastructure for AI fabric beyond InfiniBand」重要訊號。

**(3) Cisco Nexus One + Cloud Control 雙線推進的策略意涵。** Cisco 13,000+ ACI 客戶的 migration 路徑在 7/2 與 7/9 兩篇 Cisco 官方 blog 中已經清晰：**架構標準化（IETF 提交）+ 統一管理 plane（Cisco Cloud Control）+ agentic AI operations**。這是 Cisco 在 NVIDIA Spectrum-X / Broadcom Tomahawk 夾擊下的「不與 hyperscaler 在 throughput 競爭，改與 enterprise DC 在 operations 競爭」策略。對中小規模 enterprise DC 與 telco edge DC 客戶，Nexus One + Cloud Control 的吸引力高於 NVIDIA Spectrum-X 純 ASIC 銷售；對 hyperscaler，UEC 1.0 + IETF 標準化是長期較量的主場。

- 7/12-7/20：SIGCOMM 2026 rebuttal / OSDI 2026 notification 結果釋出，學術週期啟動。
