- **OpenAI 與 Microsoft 揭露萬卡級 AI 叢集網路韌性設計：MRC 傳輸協定搭配 SRv6 靜態源路由，讓訓練作業在網路故障中「無感續航」**（May 9）：arXiv 論文〈Resilient AI Supercomputer Networking using MRC and SRv6〉首度公開兩家公司在最大規模訓練叢集中的網路架構細節。研究團隊提出三管齊下策略：(1) 全新 RDMA 傳輸協定 MRC（Multi-path Reactive Congestion control）透過多路徑噴灑與主動負載平衡消除 flow collision；(2) 採用多平面 Clos 拓樸，讓超過 10 萬 GPU 的訓練叢集得以維持兩層拓樸並提升實體冗餘；(3) 以 SRv6 靜態源路由讓 MRC 自主繞過故障節點。該系統已投入生產環境，用於訓練最新一代 frontier model。[連結](https://arxiv.org/abs/2605.04333)

- **Blink：將 LLM 推論服務堆疊完全卸載至 GPU 與 SmartNIC，P99 TTFT 降低 8.47 倍、每 token 能耗減少 48.6%**（May 4）：現有 LLM 推論架構將 host CPU 置於關鍵路徑，導致效能對 CPU 干擾極度敏感。Blink 提出端到端無 CPU 推論架構：SmartNIC 負責請求處理並透過 RDMA 直接將輸入寫入 GPU 記憶體，再以 persistent GPU kernel 執行批次調度與 KV-cache 管理。相較 TensorRT-LLM、vLLM 與 SGLang，Blink 在隔離環境下已達最佳效能，面對 CPU 干擾時現有系統效能暴跌兩個數量級，Blink 卻維持穩定。[連結](https://arxiv.org/abs/2604.07609)

- **SCENIC：開源 200G SmartNIC 將網路資料路徑視為「串流計算基底」，彌合商業與研究型 SmartNIC 的鴻溝**（April 21）：現有商業 SmartNIC 頻寬高但可程式化能力有限；研究型 SmartNIC 則頻寬低、軟體相容性差。SCENIC 是一款開源資料中心 SmartNIC，實作 200G 網路資料路徑（含卸載 TCP/IP 與 RDMA 堆疊），並在資料路徑上整合 Stream Compute Units（SCU）與 ARM 核心，可直接存取 GPU 與 SSD。SCENIC 完整整合 Linux 網路與 RDMA verb 介面，讓既有應用無需修改即可使用，同時支援可程式化壅塞控制與使用者定義卸載。[連結](https://arxiv.org/abs/2604.15128)

- **PITA：協定無關的傳輸架構，讓同一套 NIC 硬體資料路徑同時跑 TCP 與 RoCE 且保留各自行為**（May 4）：隨著傳輸層日益移入 NIC 硬體，部署新協定的難度大增。PITA（Protocol-Independent Transport Architecture）透過統一的事件、狀態與指令抽象層重構資料路徑，並重新設計排程、封包生成與資料重組等核心元件。在 Alveo U250 FPGA 上的合成結果顯示，PITA 能以 250MHz 達到線速效能，硬體開銷適中。[連結](https://arxiv.org/abs/2605.02210)

## SmartNIC 與 DPU 焦點

今日 SmartNIC/DPU 領域由 Blink 與 SCENIC 兩篇論文主導，分別從「應用卸載」與「開源硬體架構」兩個角度推進。

**Blink** 的核心洞察是：LLM 推論服務的成本結構中，CPU 干擾是一個被低估的風險因子。現有系統（TensorRT-LLM、vLLM、SGLang）在 CPU 被其他服務佔用時，延遲會惡化兩個數量級，這意味著資料中心必須為 LLM 推論保留大量 CPU headroom，造成資源閒置。Blink 的解法是將請求處理、批次調度、KV-cache 管理全部移出 CPU：SmartNIC 透過 RDMA 直接將輸入送入 GPU 記憶體，GPU 內的 persistent kernel 自主完成後續流程。評估顯示 P99 TTFT 降低達 8.47 倍、P99 TPOT 降低達 3.40 倍、解碼吞吐量提升 2.1 倍、每 token 能耗降低 48.6%。這對於希望在同一台伺服器上共置多個服務的雲端業者而言，是極具吸引力的架構——它讓 LLM 推論從「CPU 敏感型」變成「CPU 免疫型」。

**SCENIC** 則從硬體設計角度填補了商業與研究型 SmartNIC 之間的鴻溝。商業 SmartNIC（如 NVIDIA BlueField、AMD Pensando）提供高頻寬與完善的軟體生態，但資料路徑封閉；研究型 SmartNIC（如 Corundum、IPU 學術原型）可程式化程度高，但頻寬往往只有 10-40G，且缺乏標準 RDMA 支援。SCENIC 以 200G 開源 FPGA 實作，同時提供卸載 TCP/IP 與 RDMA 堆疊、資料路徑上的 Stream Compute Units、以及直連 GPU/SSD 的能力。其 Linux 網路與 RDMA verb 介面的原生整合，意味著現有應用無需修改即可執行，這對研究社群而言是一大突破——過去研究型 SmartNIC 往往需要撰寫專屬驅動程式，導致研究成果難以複現與比較。

此外，**PITA** 雖然定位為協定無關傳輸架構，但其對 SmartNIC 設計也有深遠意涵。PITA 證明同一套 NIC 硬體可以在不犧牲線速效能的前提下，同時支援 TCP 與 RoCE 的語意差異。這挑戰了「NIC 硬體必須為特定傳輸協定客製化」的傳統假設，為未來多協定資料中心網路（例如同時運行 RDMA 與標準 TCP 流量）提供了硬體架構參考。

## 學術論文速覽

- **Resilient AI Supercomputer Networking using MRC and SRv6**（arXiv:2605.04333, May 9）
  - **白話摘要**：這篇論文揭露 OpenAI 與 Microsoft 在最大規模訓練叢集中的網路韌性設計。MRC 傳輸協定透過多路徑噴灑與主動負載平衡消除 flow collision；多平面 Clos 拓樸讓 10 萬 GPU 叢集維持兩層架構；SRv6 靜態源路由則讓網路故障時無需人工介入即可自動繞路。
  - **核心價值**：過去超大規模 AI 叢集的網路故障往往導致訓練中斷數小時；MRC + SRv6 的組合就像是為資料中心網路配備了自動駕駛系統，不僅能在正常路況下選擇最佳路線，還能在道路封閉時即時規劃替代路徑。
  - **實務價值**：對於正在規劃萬卡級叢集的架構師，這篇論文提供了經過生產驗證的拓樸與協定選擇依據。兩層 Clos + SRv6 的組合簡化了網路管理，同時提升了物理冗餘度，這對總擁有成本（TCO）有直接影響。

- **Blink: CPU-Free LLM Inference by Delegating the Serving Stack to GPU and SmartNIC**（arXiv:2604.07609, May 4）
  - **白話摘要**：Blink 將 LLM 推論的請求處理、批次調度與 KV-cache 管理全部從 host CPU 卸載到 SmartNIC 與 GPU，SmartNIC 透過 RDMA 直寫 GPU 記憶體，GPU 以 persistent kernel 自主運作。在 CPU 干擾下，現有系統延遲暴增兩個數量級，Blink 卻維持穩定。
  - **核心價值**：現有 LLM 推論像是雇了一位必須時刻待在現場的監工（CPU）；Blink 則像是把監工的職責拆給自動門禁（SmartNIC）與自律機器人（GPU persistent kernel），監工可以離開現場去處理其他事務，生產線依然順暢運轉。
  - **實務價值**：雲端業者可在 LLM 推論伺服器上安全地共置其他 CPU 密集型服務（如日誌處理、監控代理），無需保留大量 CPU headroom。每 token 能耗降低 48.6% 的數字對於追求碳中和的超大規模資料中心極具吸引力。

- **SCENIC: Stream Computation-Enhanced SmartNIC**（arXiv:2604.15128, April 21）
  - **白話摘要**：SCENIC 是一款開源 200G SmartNIC，將網路資料路徑視為串流計算基底，整合卸載 TCP/IP 與 RDMA、Stream Compute Units（SCU）、ARM 控制核心，以及直連 GPU/SSD 的能力，同時原生支援 Linux 網路與 RDMA verb 介面。
  - **核心價值**：商業 SmartNIC 像是一輛封閉駕駛艙的跑車，速度快但不能改裝；研究型 SmartNIC 像是可以任意改裝的卡丁車，但速度有限。SCENIC 則像是一輛開源設計的賽車，既有跑車的速度（200G），又保留改裝彈性（SCU + 可程式化壅塞控制）。
  - **實務價值**：對於研究社群與新創團隊，SCENIC 提供了一個可與商業產品直接比較的開源基準。論文展示的 offloaded collective communication 與 network-to-GPU hash-based data partitioning 用例，為 SmartNIC 在 AI 訓練中的應用開闢了新方向。

- **A Protocol-Independent Transport Architecture**（arXiv:2605.02210, May 4）
  - **白話摘要**：PITA 提出協定無關的 NIC 硬體傳輸架構，透過統一的事件、狀態與指令抽象層，讓同一套資料路徑同時實作 TCP 與 RoCE，並保留各自的端對端語意，在 Alveo U250 上以 250MHz 達到線速。
  - **核心價值**：現有 NIC 設計像是為特定樂曲定製的管風琴，每種協定需要一套獨立的音管；PITA 則像是一套模組化合成器，透過統一的訊號流程與可替換的音色模組，同一台硬體可以演奏完全不同的樂曲。
  - **實務價值**：隨著 UEC 推動 Ethernet 成為 AI 叢集標準，資料中心將長期處於「RDMA + 傳統 TCP 共存」的過渡期。PITA 證明協定無關的 NIC 硬體是可行的，這可能影響未來 SmartNIC/DPU 的設計路線圖。

- **MatchRDMA: A Segmented and Rate-Matched Long-Haul RDMA Scheme for Geo-distributed LLM Training over OTN**（arXiv:2604.23932, April 2025）
  - **白話摘要**：針對跨資料中心 LLM 訓練的長途 RDMA 場景，MatchRDMA 透過主動協調源端與目的端 OTN 速率，將跨 DC 吞吐量提升最高 20 倍，並降低目的端 OTN 緩衝區佔用率 62.7%。
  - **核心價值**：傳統 RDMA 在長途 WAN 上如同一位不顧路況猛踩油門的駕駛；MatchRDMA 則像是一位會與前方交通管制中心即時通訊的司機，根據路段限速動態調整車速，避免在收費站（OTN 緩衝區）大排長龍。
  - **實務價值**：隨著 AI 訓練叢集規模超越單一資料中心，地理分散訓練成為趨勢。MatchRDMA 的速率匹配機制為跨資料中心 RDMA 網路提供了可部署的效能優化方案，特別適合擁有自有光傳輸網路的大型雲端業者。

- **GICC: A High-Performance Runtime for GPU-Initiated Communication and Coordination in Modern HPC Systems**（arXiv:2604.22126, April 2025）
  - **白話摘要**：GICC 讓 GPU kernel 能直接觸發 NIC 操作而無需 host CPU 介入，在 HPE Slingshot 上將協調延遲降低最高 229 倍，弱擴展效率提升最高 25%；在 InfiniBand 上達到比 NVSHMEM 低 1.95 倍的 put 延遲。
  - **核心價值**：現有 GPU 分散式通訊像是每封郵件都必須由秘書（host CPU）蓋章才能寄出；GICC 則讓業務員（GPU thread）擁有直撥電話（直接觸發 NIC），一旦邊界資料計算完成即可立即發送，無需等待秘書空閒。
  - **實務價值**：對於運行 stencil 計算、AI 訓練等需要頻繁 halo exchange 的 HPC 應用，GICC 的細粒度計算-通訊重疊能顯著提升擴展效率。在 64 AMD MI250X GCD 上的工業級 stencil proxy 中，GICC 的平行效率達 42%，顯著優於 GPU-aware MPI 的 35.4%。

- **Characterizing the Impact of Congestion in Modern HPC Interconnects**（arXiv:2604.11432, April 2025）
  - **白話摘要**：這篇論文對四種主流 HPC 網路（EDR/HDR/NDR InfiniBand、Cray Slingshot、新興 Ethernet fabric）進行全面的壅塞行為特性分析，涵蓋穩定壅塞與多種突發流量模式，並探討規模效應對集體通訊效能的影響。
  - **核心價值**：過去對 HPC 網路壅塞的理解多基於單一 fabric 的經驗；這篇論文則像是一份橫跨多個品牌的汽車碰撞測試報告，讓架構師能在同一套基準下比較不同互連技術的韌性。
  - **實務價值**：研究發現不同 fabric 對突發流量的反應差異極大，且規模越大，壅塞的規模相關性行為越明顯。這些洞察可直接指導採購決策與壅塞控制演算法的設計，尤其對於正在評估 InfiniBand 與 UEC/Ethernet 路線的資料中心而言，是極具參考價值的實證資料。

- **Varuna: Enabling Failure-Type Aware RDMA Failover**（arXiv:2603.28001, March 2025）
  - **白話摘要**：RDMA 鏈路故障時，傳統做法一律對所有飛行中請求進行重傳，造成不必要的恢復開銷。Varuna 根據故障類型（transient vs persistent）採取不同恢復策略，將恢復時間與效能影響最小化。
  - **核心價值**：現有容錯機制像是一位不論病情輕重一律送急診的醫護人員；Varuna 則像是一位經驗豐富的分診護士，能根據症狀判斷是暫時性不適（transient）還是需要住院（persistent），並給予恰當處置。
  - **實務價值**：在大規模 RDMA 網路中，鏈路抖動頻繁但多為暫時性。Varuna 的故障類型感知機制可避免過度反應，對生產環境中追求高可用性的儲存與 AI 訓練網路有直接幫助。

## 深度觀點

今日的多篇論文共同描繪了一個清晰趨勢：AI 叢集網路正從「以 CPU 為中心」加速轉向「以 GPU 與 SmartNIC 為中心」的架構。Blink 與 GICC 從應用層面證明，移除 host CPU 對於降低延遲、提升資源利用率具有變革性意義；SCENIC 與 PITA 則從硬體層面提供了實現這一願景的基礎。

Blink 的設計哲學尤其值得深思。它並非第一個嘗試將推論服務卸載到 SmartNIC 的研究，但它是少數同時達成「無 CPU 運作」與「超越現有 SOTA 效能」的系統。其核心設計——SmartNIC 透過 RDMA 直寫 GPU 記憶體，GPU persistent kernel 自主完成批次調度——本質上是在重新定義「伺服器」的概念：傳統伺服器以 CPU 為核心，GPU 與 NIC 為周邊；Blink 架構則以 GPU 為核心，SmartNIC 為前置閘道，CPU 淪為「開機與管理用輔助處理器」。這與多年前磁碟陣列控制器從主機板獨立出來的歷程驚人地相似：當某個周邊任務的效能與複雜度達到一定程度，它就會從主處理器的管轄範圍中獨立出來，形成自己的生態系統。

與此同時，SCENIC 的出現填補了長期以來的基礎設施缺口。商業 SmartNIC（BlueField、Pensando）雖然效能優異，但其封閉性讓學術界難以驗證新想法；研究型 SmartNIC 雖然開放，但頻寬與軟體相容性往往不足以支撐真實 AI workload。SCENIC 以 200G 開源設計搭配原生 Linux RDMA verb 支援，首次讓研究社群能在與商業產品同級的硬體上進行實驗。這對於壅塞控制、網內計算、可程式化卸載等領域的研究至關重要——過去這些研究多在模擬器或低速原型上進行，結果能否推廣到生產環境始終存疑；SCENIC 讓「實驗室發現 → 生產驗證」的轉化路徑變得可行。

MRC + SRv6 的組合則從另一個維度——超大規模韌性——補足了這張拼圖。當叢集規模從千級 GPU 擴展到十萬級，網路故障從「罕見事件」變成「統計必然」。OpenAI 與 Microsoft 的經驗表明，傳統的兩層或三層 Clos 拓樸搭配靜態 ECMP 已不足以支撐 frontier model 的訓練需求。MRC 的多路徑噴灑與主動負載平衡，結合 SRv6 的靈活源路由，讓網路層具備了類似於儲存層 RAID 的容錯能力——不是避免故障，而是讓故障對上層應用透明。這種「反脆弱」設計理念，很可能成為下一代 AI 叢集網路的標準配置。

最後，PITA 的協定無關架構為這一切提供了硬體抽象層的統一視角。當資料中心同時運行 RDMA（AI 訓練）、TCP（傳統服務）、以及未來 UEC 標準化的新協定時，為每種協定配備專屬 NIC 的經濟性顯然不可持續。PITA 證明單一硬體平台可以透過適當的抽象層同時支援多種協定語意，這對 SmartNIC/DPU 的長期演進方向具有指標意義。

綜合來看，今天的論文集群指向一個共同的未來：網路硬體（SmartNIC、交換器、互連 fabric）正變得越來越「聰明」與「自主」，而 host CPU 的角色正在從「指揮中心」退位為「後勤支援」。這不是漸進式改良，而是架構典範的轉移——就像從集中式主機走向分散式叢集一樣，AI 叢集的網路架構也正在經歷一場去中心化革命。
