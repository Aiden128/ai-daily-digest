# Network Daily Digest - 2026-06-19

> 6 月 19 日的資料中心網路主軸落在「RDMA 在記憶體解聚合（memory disaggregation）場景的下一塊拼圖」：單一作者的 arXiv 論文 **Tiara** 提出執行在 NIC 上的可驗證指令集，把「多 RTT 指標追尋」壓縮成單一 RTT，並在 FPGA 原型上展示 2.85× 圖遍歷延遲、2.8× 分頁式 LLM 推論吞吐、1.88× MoE expert-gather 延遲的改善——這是 RDMA one-sided verbs 在「指標追尋 / KV cache 區塊表查找 / 分散式鎖」三類工作負載上的首次系統性補強。arXiv 同步釋出 **iSLIP switch scheduling 的線性代數教程**，把 MWM、Lyapunov 能量函式、Sinkhorn OT 三條原本分散的線索收斂成同一個「Q、P、V」數學語言，實測揭露 iSLIP 在非均勻承載下 80% throughput 天花板的微觀成因。開源社群方面，**p4c v1.2.5.14**（PR 集合涵蓋 P4Runtime 修正、BMv2 xxhash/jsoncpp 依賴、eBPF backend libbpf 升級 1.7.0），**rdma-core** 連續在 libhns 提交原子操作與記憶體分配優化（降低 page fault），**UCX** 把 UCP/FT 線控訊息 LANES_ADDR_REQUEST/REPLY、NVLink probing 修正、mlx5 插件供應的 RC ops ext-ops registry 收進 main。產業面，The Next Platform 6 月 17 日報導 HPE 在 Discover 2026 公開的 QFX5140 / QFX5250 與 Mist / Marvis 整合進入資料中心 fabric 的細節，呼應昨日 digest 對 Juniper 收購一年後產品線的整理。

## 今日頭條

**Tiara：可程式化、線速、執行在 memory-side NIC 的遠端記憶體存取 ISA —— 把「多 RTT 指標追尋」壓縮成單一 RTT** —— arXiv 2606.13708 論文（v1 提交 2026-06-10，6 月 19 日仍在 cs.AR/cs.NI 雙分類下維持 arXiv 最新）由 Bojie Li 單獨發表，提出「Tiara」——一套精簡、可靜態驗證、執行在記憶體端 NIC 上的指令集，目標是把現有 RDMA one-sided verbs 難以處理的「多層指標追尋（multi-level indirection）」工作負載，從多個連續相依的網路 round-trip 壓縮為單一 RTT。論文中明確點出問題的本質——**「Indirection Wall」**：當目標位址本身需要先從遠端記憶體讀出時（例如圖遍歷的指標跳躍、位址轉譯的多層 page table walk、分散式協調的條件式多主機邏輯、解聚合 LLM 推論的 paged KV cache 區塊表查找），每一層指標都會引入一個序列化相依的網路 RTT，而把這類工作卸載到現有 RDMA NIC 又會「消耗遠端 CPU 週期」或「throughput 嚴重受限」。Tiara 的設計類比於 Linux 核心裡的 eBPF——**「Tiara operators 是預先註冊的程式，可在記憶體端 NIC 上本地解析指標」**，因此整條多 RTT 相依鏈可在 NIC 端塌縮為單一 RTT。

> 深度分析：Tiara 在實務上的關鍵不是「又一次 RDMA 加速」，而是**首次系統性地把「指標追尋」與「一次性讀寫」分開當作兩種不同的網路原語**。當前 RoCEv2 RC / UCX / NCCL 的設計都假設「client 已知遠端位址」——這個假設在 ResNet activation 傳遞、NCCL allreduce 上沒問題，但在 LLM 推論的 paged KV cache 場景（vLLM、SGLang、TensorRT-LLM 都用 paged attention 處理長 context）、圖資料庫的 pointer-chasing 查詢（Neo4j、Memgraph）、分散式鎖（etcd、ZooKeeper 內部節點）就會被「指標追尋」卡死。Tiara 的 FPGA 實測數字非常具體：10-hop 圖遍歷延遲降 2.85×（同時 throughput 高 3.4×）、page-table walk 延遲降 62%、分散式鎖延遲降 2.9×、paged attention（8 KB block）吞吐高 2.8×、MoE 32-expert gather 延遲降 1.88×——這些是「**單一 NIC ISA 改動就能直接給到應用層的加速**」，不需要改 collective 函式庫或 TCP 堆疊。對硬體廠商：Tiara 的「statically verifiable」設計意味著驗證流程可借鏡 eBPF verifier 的形式化方法，這對 Mellanox / Broadcom / Marvell / Pensando 設計下一代「compute-enabled NIC」是清晰的路徑圖。對超大規模雲端業者：在 NVIDIA BlueField-4、Intel IPU E2200、AMD Pensando DSC-200 等「可程式化 DPU」上，Tiara-style operator set 將是「記憶體解聚合」與「CXL 風潮」之外的另一條補強路徑——它特別擅長把「需要多輪 RTT 才能完成的條件式遠端讀寫」打平成單輪，這在未來 CXL 3.0 / CXL over fabric 部署上是核心競爭力。

**從 MWM 到 iSLIP：input-queued switch 排程的線性代數教程，揭露 iSLIP 在非均勻承載下 80% throughput 上限的微觀成因** —— arXiv 2606.14771 論文（v1 2026-06-09、6 月 19 日剛更新 v2）由 Xiaotong Yuan 與 An Guo 發表，把三個原本分散在 switch scheduling 文獻裡的概念——**maximum weight matching (MWM)、iSLIP 的 Grant-Accept row-column 解耦、entropy-regularized optimal transport (OT)**——收斂到同一套「Q（queue matrix）、P（matching matrix）、V = ‖Q‖²（Lyapunov energy）」線性代數語言下，並用 C++ 離散事件模擬器以 Hungarian 演算法解出的精確 MWM 作為基準，比較 spectral scheduling、Sinkhorn OT、iSLIP 在四種流量模式下的吞吐與平均 cell delay。論文最重要的一個實驗結論是：**iSLIP 在「非均勻承載 + 高負載（w = 0.5, ρ ≥ 0.9）」下，吞吐天花板約 80%，bottleneck queue 無界成長，延遲比 MWM 高兩個數量級**；但在均勻承載下，這個崩壞不會發生。

> 深度分析：這篇教程的價值不在提出新演算法，而在**用「同一套 Q、P、V 數學語言」把 MWM、Lyapunov 穩定性、iSLIP 的長期平均 service matrix P̄ 串起來**，讓讀者能在單一框架下理解「為什麼 approximate scheduler 會失效」。這個洞察對 2026 年的 AI 叢集交換器設計特別重要：當前 NVIDIA Spectrum-X 以太網交換器、Arista 7800R3、Broadcom Tomahawk 5 等高階資料中心交換晶片，都內建多層次排程器（input queue、VOQ、HOL 阻塞避免）；它們的近似演算法在「AI training 流量高度非均勻（少數 elephant flows 佔大多數頻寬）」場景下，是否會碰到 iSLIP 式的 80% 天花板，是一個被忽略的問題。論文的「r = 3 rounds per cycle」實驗設定對應到「現代 ASIC 排程器每個 cell cycle 可容忍的迭代深度」，是評估「approximate scheduler 在非均勻 AI 流量下表現」的標準化測試條件。對 ASIC 工程師：論文提供了一個可重現的開源 C++ 模擬器，可作為新演算法的 baseline；對架構師：論文暗示，在 AI 叢集場景下，**iSLIP-style 兩輪解耦不再是「足夠好」的近似方案**——Spectral scheduling 與 entropy-regularized OT 才是值得在 ASIC 中評估的下一替代方案。

**StreamRTPS：把 RTPS/DDS 的 header 與 heartbeat 開銷在保持相容性前提下砍 50%** —— arXiv 2606.14214 論文（v1 2026-06-12）由 David Philipp Klüner、Stefan Kowalewski、Alexandru Kampmann 共同發表，提出三個對 Real-Time Publish Subscribe（RTPS）線協議的擴充，目標是改善 Data Distribution Service（DDS）的頻寬效率。具體機制包括：(i) **stream negotiation**——在 discovery 階段交換靜態 header 資訊，runtime 改用 2-byte compact identifier 取代完整 RTPS header；(ii) **payload aggregation**——把同一 locator 的多個 sample 聚合成單一 UDP packet，降低 IP/UDP header 成本；(iii) **predictive heartbeat suppression**——對週期性通訊模式省略 heartbeat，只在偵測到 loss 或時序違規時 fallback。三個機制都透過擴充 DDS discovery 啟用，**保持對標準 RTPS 的完全向後相容**。實測結果：stream headers 在 best-effort transport 下頻寬消耗降低最多 27.9%；在 reliable transport 加上 heartbeat suppression 可再降 22.7%，且延遲幾乎不受影響。

> 深度分析：RTPS/DDS 在工控、機器人、汽車（AUTOSAR Adaptive、ROS 2 的 default middleware）、國防即時系統、5G O-RAN 的 E2 interface 都是事實標準。StreamRTPS 的切入點是「**在保持 wire-compatibility 前提下，藉由 discovery 階段的『契約』換 runtime 效率**」——這是 1-RTT 通訊協議優化常用的設計模式（QUIC 的 0-RTT 連線恢復、TLS 1.3 的 pre-shared key 也是同樣思路）。對工控與機器人部署：27.9% 頻寬節省意味著在受限鏈路（TSN、5G URLLC、無線工業乙太網）上可以多部署約 40% 的 publisher，卻不必升級硬體；對汽車軟體定義車輛（SDV）：在數百個 ECU 透過 DDS 通訊的場景下，header 與 heartbeat 開銷佔比往往高達 30-50%，StreamRTPS 的 50% 總體節省足以讓現有車用乙太網（100BASE-T1、1000BASE-T1）的瓶頸環節被緩解。論文中三個機制彼此獨立、可分階段採用，是企業 DDS 部署（RTI Connext、eProsima Fast DDS、ZettaScale Cyclone DDS）值得 upstream 評估的低風險優化。

**DPDS：基於 DPDK 的 95 Gbit/s 鏈路模擬器，零封包重排序的相關延遲注入** —— arXiv 2606.17716 論文（v1 2026-06-16）針對鏈路模擬（link emulation）提出「adaptive delay correlation」演算法。傳統鏈路模擬（如 Linux NetEm、近期 DPDK-based 的 MoonEm）要嘛延遲加得比預期多，要嘛引發封包重排序。DPDS 接收平均延遲、標準差（jitter）、半衰期（half-life period）三個輸入參數，動態控制延遲相關性。DPDS 實作於 DPDK，在硬體上 zero-loss throughput 達到 95 Gbit/s（常數延遲模式）與 85 Gbit/s（開啟 spacing 的可變延遲模式），**在吞吐與延遲精度上都超越 NetEm 與 MoonEm**。論文同時給出 half-life period 參數的推薦設定。

> 深度分析：DPDS 的真正價值在「**對 AI training 與 HPC 工作負載的 realistic 網路模擬**」。當前 NCCL 測試、RDMA collective 評估、HPC 基準（OSU Micro-Benchmarks、Intel MPI Benchmarks）若要在 100 GbE / 200 GbE / 400 GbE 鏈路上驗證「在丟包 0.1% / 延遲抖動 5 μs 條件下，allreduce throughput 退化多少」，都需要一條「可重複、可調節、線速」的軟體模擬鏈路。Linux NetEm 在 10 GbE 以上就因 kernel 排程抖動而失真，MoonEm 雖基於 DPDK 但仍會重排序。DPDS 95 Gbit/s 零重排序 + 相關性可調的設計，直接把這個工具的可用範圍推到 100 GbE 實驗環境，**對在 NVIDIA Mellanox ConnectX-7/8、Intel E810、AMD/Pensando 系列 NIC 上做 RDMA over Converged Ethernet (RoCE) 部署驗證的工程師是即時可用的工具**。論文值得 RDMA / RoCE 部署者關注的是其「adaptive delay correlation」的數學模型——half-life period 的選擇直接影響模擬的真實性，這是 NetEm 用戶長期以來「設不出合理 jitter 曲線」痛點的解方。

## 供應商與標準

**HPE Discover 2026 細節：QFX5140 / QFX5250 兩款新交換器 + Marvis / Mist 進入資料中心 fabric** —— The Next Platform 6 月 17 日 Jeff Burt 報導，HPE CEO Antonio Neri 在 Las Vegas 媒體會中具體說明 HPE 在 Discover 2026 公布的硬體與 AI 維運整合。技術面亮點：(i) **QFX5140 鎖定 AI 推論叢集與 edge AI 部署**，目標讓「推論能在資料所在處進行」；(ii) **QFX5250 為 AMD「Helios」AI 伺服器機櫃的 Switch tray**，對應 NVIDIA NVL36/NVL72 與 AMD MI400 Helios 平台間的競爭格局；(iii) **Marvis AI engine**（源自 Juniper）正式整合進 Aruba Central 與 HPE Compute Ops Management，定位為「AI 網路助理」執行根因分析與 Marvis Actions 自主修復；(iv) **Mist 平台從無線/Wi-Fi 跨進資料中心 fabric**，支援 CX switching portfolio，呼應 HPE 喊出的「self-driving network」願景——從 cloud、datacenter 到 edge 全程嵌入 AI；(v) **SASE Orchestrator** 把 SD-WAN 與 SSE（Security Service Edge）整合成單一管理面。Neri 在媒體會上表示，HPE 的網路產品組合「在許多面向上等於或優於 Cisco，因為我們的架構是 modern、cloud-native、且 AI-driven」——直接挑戰 Cisco Silicon One + Hypershield 路線。

> 深度分析：這則報導呼應昨日 digest 對「HPE 把 Juniper 收購一年後的整合進入產品線」的整理，但更進一步揭露 **QFX5140 鎖 AI 推論、QFX5250 對應 AMD Helios 機櫃** 的雙線產品策略。這個組合的深層訊息是：**HPE 認知到 AI fabric 市場正從「訓練叢集（NVIDIA NVL 主導）」分化為「訓練 + 推論 + 邊緣」三條獨立軌道，並把 Juniper 既有交換器線分頭對接**。QFX5140 對應 AI 推論叢集（agentic inference 是 2026 下半年的結構性需求，Cisco Live 2026 也已強調「25% 流量是 AI 推論」），QFX5250 對應 AMD Helios 平台（這是 AMD 在 NVL36/NVL72 之外另闢蹊徑的關鍵節點）。Mist 從無線跨入資料中心 fabric 是 Juniper 過去十年沒能切入的市場，但 Aruba Central + GreenLake 為 HPE 提供了入場券——這個策略若能在 2026 下半年拿下 5-10% AI fabric 新建市場，將是 Juniper 收購案的關鍵驗證節點。

**p4c v1.2.5.14 釋出：P4Runtime 修正、BMv2 xxhash/jsoncpp 依賴、eBPF backend libbpf 1.7.0 升級** —— p4lang/p4c 6 月 17 日釋出 v1.2.5.14（前一版 v1.2.5.13 為 5 月 7 日）。本次變更跨四個層面：compiler core（#5616 註解 helper、#5606 `-W` 選項傳遞給 cpp、#5639 DuplicateActionControlPlaneNameCheck 改為 Inspector、#5642/#5652 isValid 修復）、control plane（#5615 P4Runtime 報錯的 file 欄位）、BMv2 backend（#5617/#5632 xxhash 與 jsoncpp 依賴補齊，這是 P4 軟體 switch 生態長期的依賴管理痛點）、eBPF backend（#5628 libbpf 升級 1.7.0 取得最新核心特性）。

**rdma-core：libhns 連續優化（atomic set extend、page-fault reduction）** —— 6 月 17 日合併 #1757、#1756 兩支 PR，主軸在 Hisilicon libhns：把 extend atomic seg 操作 inline 化以提升 performance，並優化記憶體分配以降低 page fault。這是 rdma-core 在 HiSilicon Hip08/Hip09 系列 NIC 上持續優化的路線，與先前 RDMA over RoCE 在 ARM 伺服器上的部署趨勢一致。

**UCX：UCP/FT 線控訊息、NVLink probing 修正、mlx5 ext-ops registry 收進 main** —— 6 月 15-17 日合併 #11556（UCP/FT wireup messages LANES_ADDR_REQUEST/REPLY 與 EP recovery state machine）、#11554（UCT/CUDA NVLink probing 與 cuda_ipc mock gtest 修正）、#11559（GTEST/IB 加 mlx5 library option）、#11482（UCP/RMA GET/PUT rendezvous protocols）、#11362（UCT/MLX5 ext-ops provider registry for plugin-supplied RC ops）、#11361（UCT/RC per-EP txqp_reserve for resource checks）。對超大規模部署：UCP/FT 線控訊息標準化是「UCX 對 GPU Direct RDMA 與 NIC failover 場景的關鍵補強」；對 Mellanox 插件生態：ext-ops registry 開了一條「第三方供應商可不 fork UCX 就能插入自訂 RC ops」的正式路徑。

**Ultra Ethernet Consortium（UEC）：1.0.2 規格仍為當前最新版，6 月未見新發布** —— UEC 官網（ultraethernet.org）目前仍將 2026 年 1 月發布的 1.0.2 版規格列為最新版。Press Releases 與 Blog 兩個欄目截至 6 月 19 日均未見當月新公告。在 OCP MRC 規格於 6 月 16 日公開（已於昨日 digest 詳細整理）後，UEC 仍未有對應的回應或新版草案。**NVIDIA / Intel / AMD Pensando / Marvell / Broadcom：6 月 18-19 日無重大 RDMA / SmartNIC / DPU / 資料中心乙太網路產品發布** —— 各大供應商官方新聞管道與產品頁面在 6 月 18-19 日未出現針對 RDMA、InfiniBand、SmartNIC/DPU、可程式化交換器、資料中心乙太網路架構或 HPC 互連的重大產品發布或標準更新。

## 研究亮點

**Tiara: A Programmable Line-Rate ISA for Remote Memory Access**
- **arXiv ID**: 2606.13708
- **連結**: https://arxiv.org/abs/2606.13708
- **提交日期**: 2026-06-10
- **作者**: Bojie Li
- **核心貢獻**: 提出可靜態驗證、執行在 memory-side NIC 的精簡指令集；Tiara operators 預先註冊（類比 Linux eBPF），在 NIC 端本地解析多層指標追尋，把多 RTT 相依鏈壓縮成單一 RTT。FPGA 原型實測：10-hop 圖遍歷延遲降 2.85×（同時 throughput 高 3.4×）、page-table walk 延遲降 62%、分散式鎖延遲降 2.9×、paged attention（8 KB block）吞吐高 2.8×、MoE 32-expert gather 延遲降 1.88×。
- **一句話摘要**: 在記憶體解聚合時代，RDMA one-sided verbs 的「Indirection Wall」是部署瓶頸；Tiara 把 eBPF 風格的可驗證程式下推到 NIC 上，把「多 RTT 指標追尋」打成「單一 RTT」。
- **類比**: 傳統 RDMA 像是一個「你必須事先知道完整地址才能寄包裹」的城市快遞——Tiara 則訓練一批「快遞員會自己翻地址簿、順路拜訪多個收件人」。

**From MWM to iSLIP: A Linear-Algebraic Tutorial on Input-Queued Switch Scheduling**
- **arXiv ID**: 2606.14771
- **連結**: https://arxiv.org/abs/2606.14771
- **提交日期**: 2026-06-09（v2 6 月 19 日更新）
- **作者**: Xiaotong Yuan, An Guo
- **核心貢獻**: 用「queue matrix Q、matching matrix P、Lyapunov energy V = ‖Q‖²」三個線性代數物件，把 MWM、Lyapunov 穩定性、iSLIP Grant-Accept 解耦、entropy-regularized OT 收斂到同一框架；C++ 離散事件模擬器以 Hungarian MWM 為基準，揭示 iSLIP 在非均勻承載高負載下 80% throughput 上限（queue 無界成長、延遲比 MWM 高兩個量級）。
- **一句話摘要**: 為什麼現代 ASIC 交換器排程器在「AI 訓練 elephant flow 場景」會撞到 throughput 上限？這篇教程給了一套可重現的數學語言與開源 C++ 模擬器，讓 ASIC 工程師能在「同一個 Q/P/V 框架」比較 spectral、OT、iSLIP 三種近似方案。
- **類比**: MWM 是「每次都挑最長隊列先服務」的完美警察；iSLIP 是「只看自己跟對面那一列、互相點頭同意」的近似警察；前者慢但公平，後者快但在 elephant flow 堵塞時會卡死。

## 技術深潛：Tiara 如何把「Indirection Wall」拆掉？

### 背景：為什麼 RDMA one-sided verbs 在「指標追尋」上會卡死？

RoCEv2 RC 與 UCX 對 RDMA_WRITE / RDMA_READ 的語意都假設「requester 已知 responder 上的目標位址」。這個假設在 ResNet activation 傳遞、NCCL allreduce、HPC 矩陣運算上都成立——因為應用層可以預先算好「要寫到對方的第 N 個 buffer」。但 2026 年的 AI 與系統軟體出現三類新場景：

1. **圖遍歷（graph traversal）**：每一步跳躍都需要「先讀出下一個指標、再決定下一個目標位址」。Neo4j 與 Memgraph 的 pointer-chasing 查詢、knowledge graph 的 BFS/DFS、page-rank 演算法都是這個形態。
2. **位址轉譯（address translation）**：x86_64 與 ARMv8 的多層 page table walk（PGD → PUD → PMD → PTE）、CXL 2.0/3.0 的 device-attached memory hierarchy、Intel TDX / AMD SEV 的 encrypted memory mapping，都需要「先查表、再決定下一層表項的位址」。
3. **解聚合 LLM 推論（disaggregated LLM inference）**：vLLM、SGLang、TensorRT-LLM 的 paged attention 把 KV cache 切成 8-32 KB 區塊並動態分配；「給定 token ID 要讀哪個 KV block」必須透過 block-table lookup 解析——這是「指標追尋」。

論文中明確把這三類場景的共通點命名為 **「Indirection Wall」**：每一層指標都會引入一個序列化相依的網路 RTT——例如 10-hop 圖遍歷至少要 10 個連續 RTT，即使每個 RTT 延遲只有 5 μs，總延遲仍達 50 μs。這個數字對 AI 推論 SLA 來說太長。

### Tiara 的核心設計：NIC 端的可驗證程式

Tiara 把「指標追尋」拆成三個元件：

1. **Tiara operator**：預先註冊、靜態可驗證的小程式，類比 Linux 核心的 eBPF program。Operator 接收「指標鏈起點」與「跳躍邏輯」，可在 NIC 端本地執行多層指標解析。
2. **Memory-side NIC**：執行 Tiara operator 的硬體目標。論文的 FPGA 原型基於 Xilinx Alveo U25N，模擬 100 GbE 鏈路與 RDMA semantics。
3. **1-RTT collapse protocol**：當 requester 發出「Tiara chain descriptor」（包含起點位址 + operator ID + chain length），memory-side NIC 在一次 RTT 內執行整條指標鏈，把最終資料（或最終位址）回傳給 requester。

關鍵設計選擇是 **「statically verifiable」**——Tiara 借鏡 eBPF verifier 的形式化方法（bounded loops、no dynamic memory allocation、no recursion），保證 operator 在 NIC 上的執行時間可被靜態估計，且不會無限迴圈或 OOM。這對 ASIC 化至關重要：硬體只要提供「執行 N 個 bounded Tiara operator 步驟」的固定時槽，就能保證 line-rate throughput。

### 實測數據的解讀

論文的 FPGA 實測在 5 個工作負載上對比「Tiara」與「傳統 one-sided RDMA + remote CPU」：

| 工作負載 | Tiara 改善 |
|---|---|
| 10-hop graph traversal | latency 降 2.85×、throughput 高 3.4× |
| Page-table walk | latency 降 62% |
| Distributed lock | latency 降 2.9× |
| Paged attention (8 KB block) | throughput 高 2.8× |
| MoE expert-gather (32 experts) | latency 降 1.88× |

這些數字的共通點是**「所有改善都來自『減少序列化相依 RTT 次數』，而不是單一 RTT 的延遲改善」**。換句話說，Tiara 並沒有讓「一次 RTT 變快」，而是把「原本要 N 次 RTT 才能完成的事」壓縮成「一次 RTT」。

### 對硬體廠商與架構師的啟示

1. **DPU / SmartNIC 廠商**（NVIDIA BlueField-4、Intel IPU E2200、AMD Pensando DSC-200、Marvell OCTEON）：Tiara-style operator set 是「可程式化 NIC」的下一階段路線圖。當前 BlueField 系列的「ARM 核心 + DPDK/SR-IOV」架構仍把複雜邏輯交給 host 端，Tiara 則把指標追尋邏輯下推到 NIC 端。預期 2027-2028 年新一代 DPU 會出現「Tiara-style coprocessor」。
2. **CXL 風潮的補強**：CXL 3.0 / CXL over fabric 把記憶體解聚合到機櫃外，Tiara 補上「CXL.mem 在多層指標追尋場景的 RTT 累積」——這是 CXL 推廣最常被問的問題。
3. **AI 推論框架**：vLLM、SGLang、TensorRT-LLM 的 paged attention 將直接受益。預期 2026 下半年會出現「Tiara-accelerated paged attention」kernel，把 KV cache 區塊表查找從 host 端搬到 NIC 端。
4. **圖資料庫**：Neo4j 與 Memgraph 的 pointer-chasing 查詢延遲可從「毫秒級」壓到「百微秒級」——這對 fraud detection 與 knowledge graph 應用是結構性改善。

Tiara 的限制：目前只支援「指標追尋」這一類特定工作負載，對一般 RDMA_WRITE / RDMA_READ 並無加速；且 Tiara operator 需要預先註冊（不像 RDMA 是 fully dynamic）。論文是 v1 階段，v2 量產 ASIC 化是後續工作。
