# Network Daily Digest - 2026-05-14

## 今日頭條

- **Cisco 發布 Silicon One G200：首個支持「智能網路感知」的數據中心交換機**（May 14）— [Cisco Blog](https://blogs.cisco.com/datacenter/silicon-one-g200)
  - Silicon One G200 是 Cisco 為 AI/ML 工作負載設計的新一代交換機芯片，其核心創新是「網路感知推進」（Network-Aware Offload）——交換機芯片內置了一個輕量化的 NPU，可以運行由用戶定義的「數據包處理程序」（packet processing programs）。這意味著交換機不再只是「轉發數據包」，還可以「理解數據包」。
  - 在 AI 訓練場景中，這個能力可以實現「集合通信卸載」（collective communication offload）：當 GPU 需要進行 all-reduce 操作時，交換機可以直接在芯片內完成部分 reduce 計算，而不需要將所有數據傳輸到 GPU 再處理。Cisco 的測試顯示，這種「在網路中計算」的方法可以將 all-reduce 的延遲降低 35%。
  - 技術上，Silicon One G200 的「可編程數據平面」（Programmable Data Plane）使用了類似 P4 的語言，但增加了對 RDMA 和 MPI 語義的原生支持。開發者可以寫一個簡單的程序來告訴交換機：「當看到這種類型的 RDMA 寫操作時，不要轉發到目的端，而是先與本地暫存的值做 reduce，然後只轉發結果。」這種「近源計算」（near-source computation）對於大規模集群通信是革命性的。

- **Marvell 宣布 Teralynx 12：專為「東西向」AI 流量優化的 800G 交換機**（May 13）— [Marvell](https://www.marvell.com/products/ethernet-switches/teralynx-12.html)
  - Teralynx 12 針對 AI 集群中特有的「東西向」（East-West）流量模式做了深度優化。在傳統的數據中心中，流量主要是「南北向」（North-South）——從用戶到服務器；而在 AI 訓練集群中，80% 以上的流量是 GPU 之間的「東西向」通信。Teralynx 12 的交換架構針對這種模式做了重新設計：每個端口都有獨立的「東西向隊列」，避免南北向流量干擾東西向流量的延遲。
  - 另一個關鍵特性是「動態虛擬通道」（Dynamic Virtual Channels）——系統可以根據當前流量的實時特徵，動態調整虛擬通道的數量和優先級。例如，在訓練過程的「梯度同步」階段，系統可以自動為梯度數據分配高優先級通道；而在「數據加載」階段，則為數據預處理流量分配更多帶寬。

## 技術深耕

- **SmartNIC 的「DPU 化」趨勢：NVIDIA BlueField-4 與 AMD Pensando Pollara 4 對比分析**（May 14）— [The Next Platform](https://www.nextplatform.com/2026/05/14/smartnic-dpu-bluefield-4-pollara-4/)
  - 隨著 AI 訓練集群規模的擴大，SmartNIC 正在從「網路卸載卡」進化為「數據處理單元」（DPU）。NVIDIA BlueField-4 和 AMD Pensando Pollara 4 是這個趨勢的代表產品。BlueField-4 的核心是「GPU 直連」——通過 NVLink-C2C 接口，BlueField-4 可以直接與 GPU 共享內存，避免了「GPU → CPU → NIC」的數據拷貝路徑。Pollara 4 則強調「開放性」——它支持標準的 CXL 2.0 接口，可以與任何廠商的 GPU 或加速器配合使用。
  - 在性能方面，BlueField-4 的 RDMA 延遲低至 0.8μs（從 GPU 到 GPU），這對於需要極低延遲的強化學習訓練至關重要。Pollara 4 則在「可編程性」上更勝一籌——它的 ARM core 集群可以運行完整的 Linux，開發者可以在 SmartNIC 上部署自定義的數據處理管道（如加密、壓縮、協議轉換）。
  - 對資料中心架構師來說，選擇 BlueField-4 還是 Pollara 4，本質上是在「性能最大化」和「供應商獨立性」之間做權衡。如果你的集群全部是 NVIDIA GPU，BlueField-4 的集成優勢是無法抗拒的；但如果你採用多廠商策略（如 AMD GPU + Intel 加速器），Pollara 4 的開放性可能更有價值。

## 深度觀點

今日網路硬體的兩個重大發布——Cisco Silicon One G200 和 Marvell Teralynx 12——揭示了資料中心網路正在經歷的「應用感知化」轉型。

過去的網路設備是「應用無關」的：交換機只管轉發數據包，至於數據包裡是 HTTP 請求還是 RDMA 寫操作，對交換機來說沒有區別。這種「一視同仁」的設計在通用計算時代是合理的，但在 AI 訓練時代變成了瓶頸。

Silicon One G200 的「網路感知推進」打破了這個傳統。它讓交換機「知道」數據包是 all-reduce 的一部分，並直接在芯片內完成計算。這相當於把「計算」從服務器端「推進」到了網路設備中，是「在網路中計算」（In-Network Computing）概念的商業化實現。

Teralynx 12 的「東西向優化」則是另一個維度的應用感知。它讓交換機「知道」當前處於訓練的哪個階段，並動態調整資源分配。這種「階段感知」調度對於提高集群利用率至關重要——過去，由於網路資源的靜態分配，AI 訓練集群的網路利用率通常只有 30-40%；而動態調度可以將這個數字提升到 70% 以上。

這兩個趨勢的結合，預示著未來的資料中心網路將是「AI 原生」的——不僅是為 AI 提供帶寬，而且是為 AI 提供「智能」。這對網路工程師提出了新的要求：除了傳統的路由和交換知識，還需要理解 AI 訓練的流量模式、通信語義和性能瓶頸。「AI 網路工程師」可能成為未來幾年最搶手的職位之一。
