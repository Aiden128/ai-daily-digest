## 二、Research Spotlight（已整理內容的延伸觀察 + 7/9 新 arXiv）

### Spotlight 1. arXiv 2607.04676〈Adaptive Space-efficient Collectives for Dynamic and Unstructured Sparsity on GPU Platforms〉（cs.DC, 7/6）——NCCL 在 sparse data 上的 gap：AI 推論負載的 collective communication fabric 改良

[arXiv 2607.04676〈Adaptive Space-efficient Collectives for Dynamic and Unstructured Sparsity on GPU Platforms〉](https://arxiv.org/abs/2607.04676)（cs.DC, **7/6**, v1）**針對 NCCL (NVIDIA Collective Communication Library) 在 sparse data 上的 gap**——**state-of-the-art collective communication libraries (NCCL) 僅針對 dense data 做最佳化**，**但在 AI 推論 / sparse workloads 下，sparse data 不應傳送 zero**，**可以顯著降低 collective communication volume**。**論文核心**：

- **NCCL dense-only optimization 在 sparse workloads 的問題**：(a) **NCCL 假設所有 participants 都有 dense tensors**——**但 sparse workloads (e.g. sparse attention, MoE routing, sparse embedding) 經常 zero-heavy**；(b) **直接用 NCCL 傳 sparse data = 浪費頻寬傳 zero**；(c) **explicitly handling sparsity 又會引入「**format conversion overhead + densification during collectives**」**。
- **論文提出的「**adaptive space-efficient collectives**」**：(a) **避開 NCCL dense assumption**，**直接設計 sparse-friendly collective primitives**；(b) **減少 format conversion overhead**；(c) **保持 dense + sparse hybrid path**。
- **對 2026 H2 AI fabric 的 practical 含義**：(i) **NCCL 是 NVIDIA AI fabric 的「**collective communication de facto standard**」**——**新購 NVIDIA AI cluster 應以 NCCL ≥ current version 為 baseline**；(ii) **AI 推論負載 (e.g. LLM serving, MoE routing) 的 sparse pattern 對 collective communication volume 影響巨大**——**一個 100B+ parameter MoE model 每個 token 只需 activate 8 個 experts**，**但 NCCL 仍會傳送所有 expert tensors**；(iii) **這篇論文的 approach 可能會被 NCCL upstream 採納**——**hyperscaler 應追蹤 NCCL 後續版本是否加入 sparse collective support**；(iv) **「**sparse collective**」 對 fabric 採購的 critical 含義**——**AI fabric 的 effective bandwidth 取決於「**collective algorithm × workload sparsity**」**，**而非「**switch 物理 bandwidth**」**。**新購 100K+ GPU AI fabric 應同時評估 switch 物理 bandwidth + NCCL / sparse collective 演算法 bandwidth efficiency**。
- **與 07-08 rdmatop v0.1.22 cross-vendor GPU 互連觀測的整合**：(a) **rdmatop v0.1.22 提供 NVLink + XGMI + RoCE v2 / IB 觀測**——**可以驗證 sparse collective 在不同 fabric 上的有效 bandwidth**；(b) **「**NCCL sparse collective algorithm + rdmatop cross-vendor 觀測**」 是 2026 H2 fabric 採購的「**observability × algorithm efficiency**」 整合 framework**。

### Spotlight 2. arXiv 2607.05116〈Communication-Aware Placement and Pruning for Efficient Mixture-of-Experts Inference〉（cs.DC, 7/6）——MoE expert placement 是 AI cluster fabric 的「**跨節點 communication volume**」 決策

[arXiv 2607.05116〈Communication-Aware Placement and Pruning for Efficient Mixture-of-Experts Inference〉](https://arxiv.org/abs/2607.05116)（cs.DC, **7/6**, v1）**CAP (Communication-Aware Assignment and Pruning) 框架**——**MoE model scaling 到 hundreds of experts 時**，**expert placement 與 pruning 決策 直接影響 inter-device 與 inter-node communication volume**。**論文核心**：

- **MoE model scaling 的 fabric 問題**：(a) **MoE model scaling 到 hundreds of experts**——**每個 token 只 activate top-k experts**；(b) **「**expert placement + routing**」 決策 直接決定「**inter-device 與 inter-node communication volume**」**；(c) **若不考慮 communication 進行 placement**，**MoE inference 的 fabric bandwidth 會爆量**。
- **CAP 框架 3 個 component**：(1) **Co-activation driven expert placement**——**將 frequently co-activated experts 放在同一 device**；(2) **Communication-computation trade-off adjustment**——**生成不同 computational load 與 communication volume 的 placement options**；(3) **Communication-aware expert pruning**——**selectively removes routing destinations**。
- **對 2026 H2 AI cluster fabric 採購的 practical 含義**：(i) **MoE 是 2026 H2 LLM 的主流架構**（Mixtral、DeepSeek-V3、Qwen-MoE 等）——**新購 MoE-serving AI cluster 應把「**expert placement strategy**」 視為 fabric 設計的 first-class concern**；(ii) **「**Co-activation driven expert placement**」 與「**NVLink domain size**」 直接相關**——**NVL72 (72 個 GPU 在 NVLink switch 內) 的 co-location 應與 expert co-activation pattern 對齊**；(iii) **「**Communication-aware pruning**」 是 fabric-aware algorithm design 的先驅**——**未來 1-2 年 AI cluster fabric 採購者應要求 vendor 提供「**fabric-aware MoE deployment framework**」**；(iv) **與 Spotlight 1 sparse collectives 整合**——**「**sparse collective × expert placement × fabric topology**」 是 2026 H2 AI cluster 三大優化維度**。
