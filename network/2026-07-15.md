### 1.1 Next Platform 07-13〈The Aspirations Of HPE And Dell In The Quantum-Classical HPC Datacenter〉——Cisco Universal Quantum Switch + HPE Cray 整合五大 quantum vendor，非 NVIDIA scale-up fabric 生態成形（07-13）

Jeff Burt 2026-07-13 17:44 UTC 發布於 The Next Platform，**首次系統性整理 HPE / Dell / Cisco 三家非 NVIDIA 廠商在 hybrid quantum-classical HPC datacenter 的整合策略**。文章引述的關鍵設計訊號有三個層次：

第一層是 **Cisco 的 vendor-neutral quantum networking layer**。Cisco 在 4 月公布 Universal Quantum Switch prototype，從 architecture 到 prototype 全端設計「作為 quantum computing 的 vendor-neutral networking layer」。這是 Cisco 從 enterprise routing/switching 進入 quantum-classical fabric 互連的關鍵一步——相對於 NVIDIA 的 CUDA-Q + DGX-Quantum + cuQuantum 完整 stack，Cisco 選擇「**不建 QPU，只建 networking 與 control plane**」的 positioning，與它在 AI fabric 端的 Spectrum-X（Broadcom Tomahawk 為主）策略形成互補：Broadcom silicon 提供 switching plane，Cisco 提供 control plane + 與 quantum control systems 的介面。

第二層是 **HPE Discover 2026 的 Cray 整合路線**。HPE 在 Discover 2026 公布與 Intel、IQM Quantum Computers、Quantinuum、QuEra、Rigetti 五大 quantum vendor 的合作，目標是 **為 hybrid quantum-classical HPC datacenter 建構整合 testbed**——涵蓋 hybrid algorithm 設計、software interoperability、HPC-quantum workflow 基準。HPE SVP & GM of HPC and AI infrastructure Trish Damkroger 在 The Next Platform 的引述特別值得注意：「**If you look at rack-scale now, we're not even designing the rack, we are manufacturing it, but Nvidia is giving us a reference design, and then we add what we can to differentiate around that. We will not make the quantum devices, just like we don't make the silicon. I look at quantum as another accelerator. We will be putting the network to** [work connecting them].」這段話明確揭示 **HPE 在 rack-scale 已經不是 architecture designer 而是 OEM**——NVIDIA 給 reference design、HPE 在上面做 differentiation；但 **在 quantum 端，HPE 把自己定位為「另一種 accelerator 的 networking 整合者」**。這個「**NVIDIA reference rack + HPE differentiation + quantum accelerator + Cisco networking**」的 four-way 結構，是 2026 H2 非 NVIDIA scale-up fabric 生態最具體的 blueprint。

第三層是 **NVIDIA 的 hybrid classical-quantum 程式模型**。Jensen Huang 在去年公開表示：「**We don't build quantum computers, and yet we are deeply integrated into the quantum computing industry and we create libraries. CUDA-Q is the programming model for hybrid classical accelerated quantum. We have cuQuantum, libraries that help you simulate quantum circuits, and DGX-Quantum, to do error correction in quantum computers. We partner with them, we support them, we help them in any possible way.**」這段話印證了 NVIDIA 在 quantum-HPC 整合的 positioning：**不搶 QPU 市場，但掌握 hybrid classical-quantum 程式模型 (CUDA-Q) + quantum simulation (cuQuantum) + error correction 加速 (DGX-Quantum) 三層**。這個 positioning 對 UEC + Spectrum-X + BlueField 的意義是：quantum 整合會沿著 NVIDIA 既有的 fabric 介面（NVLink、CXL、BlueField）延伸到 quantum control plane，**而不是從零開始一個獨立的 quantum fabric 標準**。

**對 fabric-side 的意義**：這篇文章揭示三個 independent 訊號共同指向「**2026 H2 scale-up fabric 進入 multi-vendor 整合階段**」：(1) Cisco 的 Universal Quantum Switch 證明 enterprise networking 廠商有進入 quantum fabric 的明確路徑；(2) HPE 的 Cray + 五大 quantum vendor 整合證明 HPC OEM 已建立實際的 hybrid datacenter testbed；(3) NVIDIA 的 CUDA-Q 程式模型延伸到 quantum 證明 GPU 廠商的 fabric 介面會成為 quantum 整合的底層。**三者交集的設計議題是「quantum-classical fabric 的 control plane + memory semantics + networking primitives 共同設計」**——這是 2026 H2 至 2027 H1 UEC post-1.0 roadmap（CSIG / PCM / header-half）需要正式處理的議題。

**與昨日 digest 的關係**：昨日 07-14 整理的 ABTRDA3（kernel-bypass stack）+ LiteSwitch（CXL cycle harvesting） + Chinese NVLink reverse-engineering（supply chain）三條主軸都隱含「**fabric 端到端 stack 重新設計**」的訊號。今日 Next Platform 文章把這個「**重新設計**」延伸到 **quantum 整合**——AI 與 quantum 是 2026 H2 fabric 設計的兩個新主軸，共同推動 scale-up fabric 從「**GPU-centric 互連**」進化到「**GPU + QPU + CXL memory + kernel-bypass transport + control plane**」的 multi-primitive 整合。

### 1.2 ABTRDA3 3-day 跟進 + LiteSwitch 5-day 跟進：cross-transport + cross-memory-tier 的 fabric 設計訊號交叉驗證（07-12 / 07-10）

07-14 digest 已深度整理 ABTRDA3 跨 NIC 跨 transport 24h P50/P99.999 延遲基準（DPDK median 3.587 μs vs AF_XDP zero-copy 6.231 μs on Mellanox ConnectX-4 Lx 25G）以及 LiteSwitch 在 < 20 ns 內 context-switch 收割 CXL memory stall、回收 80% CXL access latency 損失。今日 3-day / 5-day 跟進從 cross-vendor + cross-memory-tier 的角度交叉驗證：

**ABTRDA3 端**：3 天後社群觀察的關鍵是 ABTRDA3 把 driver bugs 文件化到 `docs/Known_driver_issues.md`——這個決定比基準數字本身更值得追蹤。**對 hyperscaler 採購 ConnectX / BlueField NIC 時的 driver reliability 評估而言，這份文件是 independent 驗證信號源**。當 NVIDIA 透過 Spectrum-X 推動 ConnectX-7 / BlueField-4 為 AI fabric 預設 NIC 時，**driver bug transparency 變成競爭優勢**——ABTRDA3 的 1.0 釋出（07-12）後 3 天內社群 engagement 仍極為有限，反映 mid-summer 安靜期 + 工具類開源專案的 natural adoption curve，但 **`Known_driver_issues.md` 作為正式文件的結構是 2026 H1 之後 hyperscaler 採購 RDMA NIC 的 new baseline**。

**LiteSwitch 端**：5 天後與今日 1.1 Next Platform HPE/Dell/Cisco quantum-HPC 文章的交叉訊號是 **CXL memory pool 作為 L3 memory tier 的 cycle harvesting 機制可能延伸到 quantum control plane**——quantum error correction 需要大量 redundant physical qubit state 的即時存取，這個存取延遲 pattern 與 CXL memory pool 的 μs 等級延遲是同一個尺度。**LiteSwitch 的 < 20 ns context switch 機制如果被 port 到 quantum control plane 軟體 stack，可讓 QPU 與 GPU 之間的 memory sharing 達到接近 CXL L3 的有效 throughput**。這是 07-14 沒明說但今日可以延伸的觀察：CXL 不只是 DRAM-tier 延伸，而是 **跨 classical-quantum memory fabric 的 primitive**。

**聯合訊號**：ABTRDA3 提供 transport 層的 cross-vendor / cross-NIC / cross-kernel-bypass-stack 基準；LiteSwitch 提供 memory tier 層的 cross-host / cross-accelerator 機制。**兩者合在一起暗示 2026 H2 fabric 設計的 emerging pattern 是「**transport + memory + control plane 三層共同設計**」**——不再是 2024-2025 年「**先把頻寬拉高，應用層自己想辦法**」的單維度競爭。UEC post-1.0 roadmap 的 PCM（packet-level credit-based flow control 對 collective primitive 的支援）+ CSIG（collective semantics in group）+ header-half（packet header 壓縮以容納更多 control 訊息）三項提案都呼應這個 multi-layer 共同設計趨勢。

## 4. 企業前沿動態

### 4.1 HPE + 五大 quantum vendor 整合（Cray 為骨幹）——HPE Discover 2026 主要宣布

HPE 在 Discover 2026 公布與 Intel、IQM Quantum Computers、Quantinuum、QuEra、Rigetti 五大 quantum vendor 的合作，**為 hybrid quantum-classical HPC datacenter 建構整合 testbed**。HPE 透過 Cray supercomputer 家族作為 classical 端骨幹，並把 Cray 的 high-speed interconnect（Slingshot 系列，源自 HPE Cray EX）延伸到 quantum control plane。SVP Trish Damkroger 明確把 quantum 定位為「**另一種 accelerator**」——HPE 不自製 QPU，但負責 networking 整合。**對 fabric 端訊號**：HPE Slingshot 在 HPC 端已建立的 topology-aware adaptive routing 機制，可能成為 quantum-classical fabric 的雛形。

### 4.2 Cisco Universal Quantum Switch——vendor-neutral quantum networking layer

Cisco 在 2026 年 4 月公布 Universal Quantum Switch prototype，定位為「**vendor-neutral quantum networking layer**」。Cisco 不搶 QPU 市場，但**負責 quantum control plane 與 classical networking 之間的介面**。這個 positioning 與 Cisco 在 enterprise networking 端的強項（IOS-XR、SD-WAN、ACI）一致——Cisco 把 quantum 視為 enterprise 客戶的下一個 networking 端點。**對 fabric 端訊號**：Cisco 在 AI 端已透過 Silicon One 與 Broadcom Tomahawk 競爭，在 quantum 端則選擇不同 positioning——這是 **AI fabric + quantum fabric 的雙軌 networking 策略**。

### 4.3 NVIDIA CUDA-Q + DGX-Quantum——hybrid classical-quantum 程式模型

NVIDIA 的 CUDA-Q 已是 hybrid classical-quantum 程式模型事實標準；cuQuantum 是 quantum circuit simulation library；DGX-Quantum 是專用於 quantum error correction 的加速器。**Jensen Huang 的明確 positioning：「**We don't build quantum computers, and yet we are deeply integrated into the quantum computing industry and we create libraries**」**——NVIDIA 透過 fabric 介面（NVLink、BlueField、CUDA-Q 跨 QPU/GPU/CPU 統一記憶體模型）成為 quantum 整合的隱形控制者。**對 fabric 端訊號**：UEC + Spectrum-X + BlueField 構成的 NVIDIA-centric AI fabric 生態會延伸到 quantum 整合，**不會從零開始一個獨立的 quantum fabric 標準**。

### 4.4 Apple + Broadcom $30B 多年採購協議——AI fabric silicon 端 capital 加深綁定（07-08，carryover）

Apple 與 Broadcom 2026-07-08 公布多年 $30B 採購協議（HN 48838930），歷史上以 iPhone RF 與客製化 silicon 為主。**今日 networking 端維度延伸**：Broadcom 是 Tomahawk 5/6 + Jericho 系列 AI fabric switching silicon 的主要供應商——當 Apple 對 Broadcom 整體 chip stack 的依賴加深，**Broadcom 在 AI 資料中心 fabric silicon 端的資本支出與 R&D 預算會同步強化**。Marvell（OCTEON）、Intel（IPU）、以及 NVIDIA Spectrum-X 內部 silicon 的競爭壓力都會上升。**對 fabric 端訊號**：AI fabric switching silicon 進入 Apple + Broadcom 深化綁定新階段。

### 4.5 QuiX Quantum 公布 fault-tolerant photonic 架構（07-07，STALE，8d）

QuiX Quantum 2026-07-07 公布 fault-tolerant photonic 架構（Next Platform，STALE 超過 7d 視窗一天，仍以 vendor reference 形式提及）。架構重點是 photonic qubit 在傳統 HPC datacenter 的適配——與 superconducting / trapped-ion 路線相比，**photonic 路線的最大優勢是不需要稀釋制冷（dilution refrigerator），可整合進 standard datacenter rack**。QuiX 規劃 2028 年在 Amazon Braket 上提供 Libra 系統。**對 fabric 端訊號**：photonic quantum 與 photonic memory（如 QuiX Quantum 與 07-13 整理的 QuiX Dedalo delay-line memory）屬於同一個 photonic 技術族群——**L3 memory tier 與 quantum-tier memory 可能共享 photonic 物理層**。

## 7. 深度觀點

2026-07-15 的 deep dive 把第八週安靜期的觀察群壓縮到三條主軸——非 NVIDIA scale-up fabric 生態成形、cross-transport + cross-memory-tier fabric 設計、與 AI fabric supply chain 三分法——這三條主軸在今日之前都是隐性觀察，**今日 Next Platform 07-13 HPE/Dell/Cisco quantum-HPC 文章把三條主軸的交織點明確化為「**2026 H2 fabric 端到端 stack 重新設計**」**。

第一條主軸是 **scale-up fabric 從 NVIDIA-centric 走向 multi-vendor 整合**。Jeff Burt 在 The Next Platform 引述的 Trish Damkroger 對 rack-scale 的描述——「**we are manufacturing it, but Nvidia is giving us a reference design, and then we add what we can to differentiate around that**」——是 2026 H1 結束時最重要的一段 OEM 證詞。HPE 明確承認 rack-scale 的 architecture 設計主導權在 NVIDIA 手上，這是 NVIDIA 從 GPU 廠商走向 system architecture 主導者的關鍵轉折。但 **quantum 端，HPE 把自己重新定位為「**networking 整合者**」**——這個 positioning 暗示 non-NVIDIA 廠商在 quantum 端有機會成為 architecture designer，而不只是 OEM。**Cisco Universal Quantum Switch 進一步印證這個 path**——Cisco 在 enterprise networking 的強項（control plane、SD-WAN、policy enforcement）可以延伸到 quantum networking layer，**這是 enterprise networking 廠商第一次在 quantum 端取得「**architecture designer**」位置**。三件事的共同訊號是 **2026 H2 是 enterprise networking 廠商從「**OEM for NVIDIA rack-scale**」走向「**architecture designer for non-NVIDIA fabric**」的轉捩點**。UEC + OpenSHMEM + CXL 共同構成的 open standard 生態是這個轉捩點的設計基礎。

第二條主軸是 **cross-transport + cross-memory-tier 的 fabric 端到端 stack 重新設計**。ABTRDA3 提供 transport 層的 cross-vendor / cross-NIC / cross-kernel-bypass-stack 24h P50/P99.999 延遲基準，LiteSwitch 提供 memory tier 層的 cross-host / cross-accelerator cycle harvesting 機制。**兩者合在一起的訊號是 fabric 設計的 emerging 維度從單純的「**頻寬拉高**」變成「**transport + memory + control plane 三層共同設計**」**。當頻寬從 100 Gb/s 升到 400 Gb/s 再升到 800 Gb/s / 1.6 Tb/s 時，頻寬本身的進步速度比應用層的 model parallelism / pipeline parallelism 解構速度更快，**新的 fabric 設計瓶頸不是 raw bandwidth，而是「**多層共同設計**」**——具體設計議題包括 packet-level credit-based flow control 對 collective primitive 的支援（UEC PCM）、collective semantics in group（UEC CSIG）、packet header 壓縮以容納更多 control metadata（UEC header-half）。ABTRDA3 + LiteSwitch 從不同層面驗證這個多層共同設計的必要性：kernel-bypass stack 選錯（DPDK vs AF_XDP vs PACKET_MMAP）造成 42% 延遲差距，**CXL memory pool cycle harvesting 機制缺失造成 80% CXL access latency 損失**——兩者都證明「**單一維度最佳化**」的舊思維已經過時。

第三條主軸是 **AI fabric supply chain 三分法**。Apple + Broadcom $30B 採購協議加深 Broadcom 在 AI fabric switching silicon 的資本與 R&D 強化，**這強化 Broadcom 在 UEC 陣營的主導地位**；Chinese NVLink reverse-engineering 6-day 觀察顯示訊號存在但工程細節未公開，**這強化中國社群對 UEC 開放標準的興趣（避開 NVIDIA 鎖定 + Broadcom 鎖定）**；NVIDIA Spectrum-X + UEC Spec 1.0 持續推進，**這強化 NVIDIA 陣營在 hyperscaler 市場的既有優勢**。**三分法是 NVIDIA 陣營（含 NVLink/Spectrum-X/BlueField）vs UEC 開放陣營（含 Broadcom Tomahawk/Marvell OCTEON/Cisco Silicon One）vs 中國自製 NVLink-equivalent 介面**。Hyperscaler 採購決策不再只是「**單一廠商綁定**」，而是「**multi-fabric portable application stack**」——這對 UCX / libfabric / OpenSHMEM / Collective Communication Library 等 communication library 是長期 positive 訊號。

**三條主軸的交織點是 2026 H2 fabric 設計的 emerging pattern：multi-vendor 整合 + 多層共同設計 + supply chain 三分法共同推動 scale-up fabric 從 GPU-centric 走向 multi-primitive 整合**。這個 pattern 不是預測，是 **觀察**：HPE Discover 2026 公布 + Cisco Universal Quantum Switch 公布 + NVIDIA CUDA-Q 延伸到 quantum + ABTRDA3 / LiteSwitch / Chinese NVLink reverse-engineering 6 個 independent 訊號共同指向同一個方向。**2026 H2 至 2027 H1 的 fabric 設計議題不再是「**頻寬多高**」而是「**多層共同設計 + multi-vendor 整合 + supply chain 三分法**」**——這個議題轉變是 8 週安靜期內最值得追蹤的 fabric 設計典範轉移。

下一波 fabric 設計議題的高密度觀察期預期在 **2026-07-19 至 2026-07-25**——SIGCOMM 2026 結果通知 + OSDI 2026 接受信 + 暑假前業界新聞密集出貨三個 trigger 共同啟動。**第八週安靜期的延長不變**——8 週連續觀察確認學術會議通知週期是 fabric 設計議題密度的唯一主導訊號。
